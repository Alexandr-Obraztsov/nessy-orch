# Примеры поручений и схемы работы

Каждое поручение должно быть самодостаточным: цель, контекст, границы, источники, формат результата,
критерий готовности, строка статуса. Ниже — проверенные заготовки, подставляй свои значения.

## 1. Вопрос по коду чужого репозитория (1 агент)

```bash
nessy-orch spawn --space ~/tmp --role code-explorer --name refund-explorer --wait "
Цель: понять, как сервис shippy считает комиссию при возврате, чтобы оценить правку.
Контекст: репозиторий shippy в GitLab (группа payments), ветка main.
Границы: только чтение, ничего не коммитить; клон удалить в конце.
Результат: 3–5 предложений + список файл:строка с пояснением + цепочка вызовов от API до расчёта.
Готово, когда: найдена функция расчёта и все её вызывающие.
В конце: строка «Статус: …»."
```

## 2. Сбор из независимых источников (параллельно)

```bash
nessy-orch spawn --space ~/Projects/shippy --role jira-analyst --name pay-jira "
Цель: собрать открытые баги компонента payments за последние 30 дней.
Границы: только чтение Jira.
Результат: таблица ключ | заголовок | статус | исполнитель | приоритет, отсортированная по приоритету.
В конце: строка «Статус: …»."

nessy-orch spawn --space ~/Projects/shippy --role wiki-researcher --name pay-wiki "
Цель: найти в Wiki регламент релиза payments и список ответственных.
Результат: 5–10 пунктов со ссылками на страницы; если данные противоречат друг другу, укажи обе версии.
В конце: строка «Статус: …»."

nessy-orch inbox --wait 600     # повторять, пока не придут оба ответа
```

Сводка пользователю: общий вывод, затем по разделам («Jira (pay-jira)», «Wiki (pay-wiki)»), что не удалось
найти.

## 3. Изменение кода: план → исполнение → проверка

```bash
# 1) план
nessy-orch spawn --space ~/Projects/shippy --role analyst --name retry-plan --wait "
Цель: план добавления повторных попыток в клиент платёжного шлюза (задача PAY-812).
Контекст: репозиторий ~/Projects/shippy, модуль src/gateway/.
Границы: ничего не менять, только план.
Результат: шаги с файлами, риски, как проверить (какие тесты).
В конце: строка «Статус: …»."

# 2) исполнение — план передаёшь в поручении целиком
nessy-orch spawn --space ~/Projects/shippy --role executor --name retry-impl --wait "
Цель: реализовать план ниже. Не коммитить и не пушить.
План: <вставь план из retry-plan>
Готово, когда: тесты из плана проходят, вывод команды приложен.
В конце: строка «Статус: …»."

# 3) независимая проверка — другим агентом
nessy-orch spawn --space ~/Projects/shippy --role verifier --name retry-verify --wait "
Цель: независимо проверить изменения в рабочем дереве ~/Projects/shippy по задаче PAY-812.
Заявлено исполнителем: <краткий отчёт retry-impl>. Не доверяй отчёту — проверь по коду и запуском тестов.
Результат: что подтверждено (с доказательством), что нет, найденные проблемы по важности.
В конце: строка «Статус: …»."
```

Если `verifier` нашёл проблемы, отправь их исполнителю (`send retry-impl --wait "…"`), затем повтори проверку
тем же `verifier` (`send retry-verify --wait "перепроверь"`).

## 4. Ревью MR

```bash
nessy-orch spawn --space ~/Projects/shippy --role gitlab-mr-reviewer --name mr-1234 --wait "
Цель: ревью MR !1234 в проекте payments/shippy.
Контекст: MR закрывает PAY-812 — проверь соответствие задаче.
Границы: НЕ публиковать комментарии в GitLab, только черновики в ответе.
Результат: вердикт, замечания по важности (блокер / важно / мелочь) с файл:строка и текстом комментария.
В конце: строка «Статус: …»."
```

Для крупного MR запусти параллельно `security-reviewer` и, при нужде, `code-explorer` (как изменение
влияет на вызывающих), затем сведи замечания и убери дубли.

## 5. Расследование инцидента

```bash
nessy-orch spawn --space ~/Projects/shippy --role debugger --name inc-504 --wait "
Цель: найти причину роста 504 у shippy с 14:00 сегодня.
Источники: Sage (логи и метрики shippy и gateway), последние деплои в GitLab, задачи Jira с меткой incident.
Границы: ничего не менять и не перезапускать.
Результат: хронология, гипотезы с доказательствами (подтверждена / опровергнута), наиболее вероятная причина,
что сделать дальше.
В конце: строка «Статус: …»."
```

## Как отвечать агентам

- `NEEDS_CONTEXT`: `send <агент> --wait "<недостающее: ключ, ссылка, решение>"`.
- `BLOCKED`: поменяй подход. Сузь задачу, дай другой источник, смени роль или спроси пользователя.
- Уточнение во время работы: `send <агент> --queue "…"` (не прерывает).
- Нужно остановить и перенаправить: `send <агент> "Стоп. Новая цель: …"` (прерывает текущий ход).
