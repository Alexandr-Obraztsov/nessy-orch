# nessy-orch: как работать с агентами nessy

nessy-orch — уже запущенный сервис. Он поднимает агентов nessy в рабочих каталогах (пространствах) и пересылает
им сообщения. Ты — главная нода «you»: создаёшь агентов, пишешь им и получаешь ответы. Все команды выполняются
через Bash и бинарь `nessy-orch`. Если `nessy-orch` нет в PATH, используй `~/Projects/nessy-orch/bin/nessy-orch`.

**Работай только через CLI.** Не читай исходники оркестратора, не лезь в `~/.nessy-orch/`, не ходи в HTTP API
руками, не запускай `nessy serve` сам. Для задачи достаточно команд ниже.

## Когда использовать

- Нужны GitLab, Jira, Sage или Wiki: у nessy есть эти инструменты, у тебя нет.
- Нужна долгая автономная работа в другом репозитории (исследование, правки, прогон команд), пока ты занят своим.
- Пользователь явно просит обратиться к nessy или к уже запущенному агенту.

Не используй nessy для того, что быстро сделаешь сам, и вместо своих субагентов (Task).

## Основной сценарий: спросить и дождаться ответа

```bash
nessy-orch ask ~/Projects/shippy "Найди в Jira открытые баги по компоненту payments, дай список ключей с заголовками"
```

`ask` создаёт агента в каталоге (пространство поднимется само), отправляет задачу и ждёт ответа. В stdout
выводится только ответ агента, служебные строки идут в stderr. Агент остаётся жить: ему можно писать дальше.

Агента с именем, чтобы потом к нему обращаться:

```bash
nessy-orch spawn --space ~/Projects/shippy --name jira-scout --wait "Найди открытые баги по payments в Jira"
nessy-orch send jira-scout --wait "Теперь сгруппируй их по исполнителю"
```

## Фоновый сценарий: несколько задач параллельно

```bash
nessy-orch spawn --space ~/Projects/shippy --name reviewer "Проверь MR !1234 в GitLab, перечисли замечания"
nessy-orch spawn --space ~/Projects/docs   --name wiki "Найди в Wiki страницу про деплой shippy, перескажи шаги"
nessy-orch inbox --wait 600        # блокируется до прихода ответов; повторяй, пока не соберёшь все
```

`inbox` возвращает новые сообщения тебе и сдвигает курсор, так что повторный вызов не покажет их снова.
`--peek` показывает без сдвига курсора.

## Справочник команд

| Команда | Что делает |
|---|---|
| `ask <путь\|пространство> "задача"` | Создать агента и дождаться ответа (короткий путь) |
| `spawn [--space S] [--name N] [--wait] ["задача"]` | Создать агента; с `--wait` дождаться ответа |
| `send <агент> "текст" [--wait]` | Написать существующему агенту (по имени или id) |
| `inbox [--wait СЕК] [--peek]` | Новые ответы тебе |
| `ls` | Список агентов: id, имя, статус, пространство, последнее действие |
| `show <агент> [-n 40]` | Последние события агента: что делал, какие инструменты, ошибки |
| `cancel <агент>` | Прервать текущий ход |
| `kill <агент>` | Удалить агента |
| `feed [-n 30]` | Общая лента всей переписки |
| `space ls` / `space add <путь> [--name N]` | Пространства (обычно создаются сами по пути) |
| `status` | Жив ли оркестратор |

Флаг `--json` есть у всех команд, используй его, если результат нужно разобрать. `--timeout СЕК` задаёт время
ожидания для `--wait` и `ask` (по умолчанию 600 с).

## Правила

1. **Пиши задачу самодостаточно.** Агент не видит твой контекст: укажи ключи задач, ссылки, ветки, пути,
   ожидаемый формат ответа («дай список», «ответ до 10 строк»). Один агент — одна тема.
2. **Переиспользуй агентов.** Уточнения по той же теме отправляй через `send` тому же агенту, у него уже есть
   контекст. Новый агент нужен для новой темы или другого каталога. Перед созданием посмотри `ls`.
3. **Короткие вопросы — с `--wait`, долгие — в фоне** с `inbox --wait`. Не опрашивай `ls` в цикле.
4. **Таймаут — не ошибка.** Код выхода 3 значит, что ответа ещё нет, но агент продолжает работать. Дальше
   `inbox --wait 600` или `show <агент>`. Повторно задачу не отправляй.
5. **Проверяй ответы.** Агент может ошибаться. Важное (номера задач, факты из Wiki) сверь или попроси агента
   привести ссылки.
6. **Прибирай за собой.** Когда тема закрыта и агент больше не нужен — `kill <агент>`.
7. **Не пересылай сообщения по кругу** между агентами без нужды: цепочки ограничены (8 переходов), частота тоже
   (30 сообщений в минуту на пару).

## Ошибки и что делать

| Симптом | Действие |
|---|---|
| «оркестратор недоступен» | Сам не запускай. Попроси пользователя: `node ~/Projects/nessy-orch/dist/src/main.js` или `launchctl kickstart -k gui/$(id -u)/com.nessy.orch` |
| Код выхода 3 (таймаут) | Агент ещё работает: `inbox --wait 600` или `show <агент>` |
| `[name_taken]` | Агент с таким именем уже есть — пиши ему через `send` или выбери другое имя |
| `[no_agent]` | Проверь имя или id через `ls` |
| Ответ с пометкой ошибки, статус `dead` | `show <агент>`, чтобы увидеть причину; создай нового агента (`spawn`) и повтори задачу |
| `[hop_limit]`, `[rate_limit]`, `[deadlock]` | Остановись, не повторяй в цикле, переформулируй задачу или сообщи пользователю |
| Код выхода 2 | Ошибка в аргументах команды: сверься с `nessy-orch --help` |

## Веб-интерфейс

Пользователь видит всё то же в браузере: <http://127.0.0.1:4337> (граф агентов, общая лента, чат с каждым
агентом). Если он хочет понаблюдать за работой, предложи `nessy-orch open`. Тебе самому интерфейс не нужен.
