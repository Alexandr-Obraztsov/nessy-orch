# nessy-orch

Оркестратор агентов nessy: HTTP/SSE API на `127.0.0.1:4337`, нативное macOS-приложение «TClaude-Orch» (`app/`, SwiftUI), CLI `nessy-orch`. Через него ты (Claude) делегируешь
задачи агентам nessy, у которых есть dp-инструменты (GitLab, Jira, Sage, Wiki) и долгая автономная работа.

## Использование сервиса: ты — оркестратор

При любой задаче через nessy-orch (GitLab, Jira, Sage, Wiki, чужой репозиторий, «спроси nessy») **сначала
загрузи скилл `nessy-orch`** (плагин `nessy`: `plugins/nessy/skills/nessy-orch/SKILL.md`, в этом репозитории
доступен и как `.claude/skills/nessy-orch` — симлинк) и работай по его циклу: сессия вкладки уже есть (`NESSY_ORCH_SESSION`; вне
приложения `nessy-orch session new "<цель>"` один раз на разговор и ссылка `nessy-orch://session/<id>` пользователю) → осмотрись
(`ls --all`, `role ls`) → раздели задачу на **много маленьких** частей (у агентов малое окно контекста; новая задача — новый агент) →
выбери роль → напиши самодостаточное поручение → запусти каждого агента командой `spawn` **в фоне** (независимое — параллельно) →
проверь результат (отдельным `verifier`) → сведи ответ → вне приложения в конце `session done <id> --summary "<итог>"`.
С момента загрузки скилла ты **только оркестратор**: сам не пишешь код и не делаешь работу руками (мелочи тоже поручаешь агенту),
не используешь своих субагентов для исполнения — всё делают агенты nessy, ты планируешь, проверяешь и сводишь.
Пользователь просит сделать самому: одной строкой объясни, что так работа видна во вкладке, и поручи агенту; настаивает повторно —
сделай, как он просит, и скажи, что этой работы во вкладке не будет.
(Это относится к работе через nessy-orch, а не к разработке самого этого репозитория.)

```bash
nessy-orch spawn --role <роль> --name <имя> --title "<3–7 слов>" "<поручение>"   # ждёт ответ агента и печатает его: запускай Bash-вызовом в фоне
nessy-orch send <агент> "уточнение"                           # то же, для уточнения той же задачи
nessy-orch wait <агент>                                       # снова дождаться (код 3: время вышло, агент ещё работает)
nessy-orch ls                                                 # кто чем занят и сколько контекста съел
```

`spawn`, `send`, `wait` ждут результат сами; запускай их только в фоне (Bash `run_in_background: true`), Claude Code разбудит тебя по завершении, пока
агенты работают, продолжай разговор с пользователем. Ящика входящих и опросов нет; хук плагина SessionStart сам привязывает чат к сессии (после `/clear` и `/resume` сессия новая) и велит загрузить скилл nessy-orch, хук PreToolUse на Agent напоминает поручать работу агентам nessy, хук UserPromptSubmit (`hook prompt`) подсказывает плейбук фонового обучения: если запрос похож на задачу накопленного плейбука, в контекст добавляется просьба загрузить его скилл `nessy-playbooks:<id>` инструментом Skill (все три только в терминале приложения; подсказка с бюджетом 1,5 с, при ошибке молчит).

В плагине один скилл `nessy-orch` (правила оркестратора, декомпозиция, поручения), команда `/nessy:status` и три хука (SessionStart, UserPromptSubmit, PreToolUse на Agent); приложение подключает плагин при запуске и само перезапускает службу оркестратора, если она перестала отвечать.

Готовые роли лежат в `roles/*.md` и загружаются командой `nessy-orch role import`. Например, `code-explorer`
изучает чужой репозиторий: клонирует его, ищет по коду (`rg`), отвечает и удаляет клон.
Если команда падает с «оркестратор недоступен», сам его не запускай: ты в песочнице, и сервер с агентами
оказались бы в ней же. Попроси пользователя выполнить в обычном терминале `bin/nessy-orch install` (сервис
launchd, запускается через login shell с окружением терминала) или `node ~/Projects/nessy-orch/dist/src/main.js`.

## Разработка в этом репозитории

- Устройство проекта описано в README.md (архитектура, API, CLI) и в `docs/` (требования, API, контракт nessy serve,
  `design/` — архитектура (`architecture-v5.md`) и дизайн приложения, `research-orchestrators.md` — исследование аналогов).
- Сервер на TypeScript без рантайм-зависимостей, слои `domain → application → infrastructure → interfaces`.
  Типы лежат только в `types.ts`, `*.types.ts` и `ports.ts`. Контракт с клиентами находится в `shared/types/`.
- Сессия оркестратора (`session`: один разговор Claude) и сессия nessy (`nessyId`, `sessionId` в протоколе) — разные вещи;
  в коде агента сессия nessy называется `nessyId`.
- Приложение: `app/` — SwiftPM (`NessyKit` — модель, API, SSE, состояние, тесты `swift test`; `NessyOrch` — SwiftUI, macOS 26).
  Сборка `.app`: `app/scripts/build-app.sh`. Схема для ссылок: `nessy-orch://session/<id>`, `nessy-orch://agent/<id>`.
- Фоновое обучение (этап 1 готов, этапы 2–3 — плейбуки и вкладка «Фон» — впереди): сервис `src/application/learning/` (`LearningService`, `JobQueue`), чистая логика в `src/domain/` (`case-*`, `collector`, `transcript`, `learning-*`), хранилище `src/infrastructure/persistence/learning-store.ts` и `transcript-scan.ts`, API `routes/learning.routes.ts`, CLI `learn`/`case`. Кейсы лежат в `~/.nessy-orch/cases/<id>/`, настройки — в `learning.json`, очередь — `learning/jobs.json`; описание — README, «Фоновое обучение».
- Проверки: `npm run check` (typecheck + lint + тесты сервера), `cd app && swift test` (тесты NessyKit).
- Стиль: табы, без точек с запятой, одинарные кавычки, комментарии по-русски. `any` и `@ts-ignore` запрещены.
