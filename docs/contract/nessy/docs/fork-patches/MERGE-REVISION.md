# Ревизия fork-патчей под мердж upstream

Рабочая таблица для ответа на три вопроса по каждому патчу из `docs/fork-patches`:

1. **Есть в апстриме?** — не решена ли задача уже в upstream (тогда патч можно свернуть или удалить).
2. **Оставляем как есть?** — приемлема ли текущая форма патча с точки зрения мерджа.
3. **Изолируем?** — можно ли перенести логику в собственные файлы, чтобы правки не лежали в апстримном коде.

Цель — не ревизия функциональности, а сокращение поверхности конфликта: чем меньше правок внутри
файлов, которые существуют в upstream, тем дешевле каждое обновление.
