# Навык: Проверка и исправление синхронизации документации

Этот навык **автоматически проверяет и исправляет** расхождения между английской и русской версией документации.

## Когда использовать

- После обновления английской документации нужно проверить, что русская версия синхронизирована
- Перед релизом проверить качество перевода ключевых файлов
- При подозрении на расхождения между версиями

## Методология проверки

### 1. Структурная проверка

**Сравнение количества разделов:**
```bash
# Проверить количество разделов второго уровня
grep -c "^## " docs/file.md
grep -c "^## " docs-ru/users/work/features/file.md

# Должно совпадать
```

**Сравнение структуры разделов:**
```bash
# Вывести все заголовки для сравнения
grep -E "^##|^###" docs/file.md
grep -E "^##|^###" docs-ru/users/work/features/file.md
```

### 2. Проверка длины разделов

**Сравнение построчно для каждого раздела:**
```bash
# Для каждого раздела проверить количество строк
sed -n '/^## Section Name/,/^## /p' docs/file.md | wc -l
sed -n '/^## Название раздела/,/^## /p' docs-ru/users/work/features/file.md | wc -l

# Допустимая разница: 10-15% (русский текст компактнее)
# Если разница >20% — проверить раздел на пропуски
```

### 3. Поиск недостающих блоков

**Типичные места пропусков:**
- Вступления и описания после заголовков
- Списки возможностей (bullet points)
- Блоки с предупреждениями (notes/warnings)
- Примеры кода между шагами
- Заключительные разделы ("What's next" и аналоги)

**Команда для поиска:**
```bash
# Сравнить количество элементов списка
grep -c "^- \*\*" docs/file.md
grep -c "^- \*\*" docs-ru/users/work/features/file.md
```

### 4. Проверка терминологии

**Ключевые термины для проверки:**
- "headless mode" → "режим без интерфейса" (НЕ "безголовый режим")
- "daemon" → "демон"
- "bearer token" → "bearer-токен" (НЕ "токен носителя")
- "workspace" → "рабочее пространство"
- "session" → "сессия"
- "loopback" → "loopback" (НЕ переводить)
- "SSE", "MCP", "ACP", "API" → не переводить

**Проверка экранирования:**
- CLI флаги: `--flag` (одиночные backticks, НЕ ``--flag``)
- Пути: `/path/to/file` (одиночные backticks)
- Названия команд: `nessy serve` (одиночные backticks)

### 5. Проверка кода и примеров

**Что проверять:**
- Все ли примеры кода скопированы (команды, curl-запросы)
- Сохранена ли структура блоков кода
- Переведены ли комментарии (опционально)
- Сохранены ли ссылки на файлы и URL

### 6. Финальная сверка

**Итоговые метрики:**
```bash
# Общая разница в строках
wc -l docs/file.md docs-ru/users/work/features/file.md

# Разница <10% — хорошо
# Разница 10-20% — проверить критичные разделы
# Разница >20% — требуется детальная проверка
```

## Чек-лист проверки

- [ ] Количество разделов (##) совпадает
- [ ] Количество подразделов (###) совпадает
- [ ] Все bullet points переведены
- [ ] Все примеры кода на месте
- [ ] Ссылки на файлы и URL сохранены
- [ ] Терминология консистентна
- [ ] Backticks расставлены верно
- [ ] Общая разница в строках <20%

## Типичные проблемы

1. **Пропущенные блоки после шагов** — часто блоки описания между шагами Quickstart выпадают
2. **Неправильное экранирование** — двойные backticks вместо одинарных
3. **Потерянные bullet points** — особенно в разделах "What it gives you"
4. **Непереведённые термины** — "headless", "daemon" требуют перевода
5. **Слишком короткий перевод** — разница >20% указывает на пропуски

## Алгоритм исправления

### Шаг 1: Локализовать проблему

```bash
# Найти раздел с наибольшей разницей
# Для каждого раздела сравнить количество строк
sed -n '/^## Section/,/^## /p' docs/file.md | wc -l
sed -n '/^## Раздел/,/^## /p' docs-ru/.../file.md | wc -l
```

### Шаг 2: Извлечь недостающий контент из оригинала

```bash
# Выделить конкретный раздел из английского файла
sed -n '/^## Quickstart/,/^## Authentication/p' docs/file.md > /tmp/en_section.txt

# Выделить соответствующий раздел из русского файла
sed -n '/^## Быстрый старт/,/^## Аутентификация/p' docs-ru/.../file.md > /tmp/ru_section.txt

# Сравнить визуально или через diff
diff /tmp/en_section.txt /tmp/ru_section.txt
```

### Шаг 3: Перевести и вставить

**Для пропущенных блоков:**
1. Найти место вставки по контексту (предыдущий/следующий заголовок)
2. Перевести блок, сохраняя:
   - Структуру markdown (списки, код, ссылки)
   - Технические термины (SSE, MCP, API — не переводить)
   - CLI флаги в одинарных backticks (`--flag`)
3. Вставить через `edit` tool с точным совпадением контекста

**Для исправления экранирования:**
```bash
# Найти проблемы с backticks
grep -n "``" docs-ru/.../file.md  # двойные backticks
grep -n "\`\`[^`]*\`\`" docs-ru/.../file.md  # неправильное экранирование
```

**Для терминологии:**
- Заменить "безголовый режим" → "режим без интерфейса"
- Заменить "токен носителя" → "bearer-токен"
- Оставить "loopback", "SSE", "MCP", "ACP" без перевода

### Шаг 4: Проверить результат

```bash
# Пересчитать количество строк в разделе
sed -n '/^## Раздел/,/^## /p' docs-ru/.../file.md | wc -l

# Убедиться, что разница <15%
# Проверить git diff на корректность изменений
git diff docs-ru/.../file.md | head -50
```

### Шаг 5: Финальная валидация

- [ ] Все разделы синхронизированы
- [ ] Разница в строках <10% для ключевых разделов
- [ ] Нет синтаксических ошибок markdown
- [ ] Ссылки на файлы ведут на правильные пути
- [ ] Код в примерах не искажён

при `sessionScope: 'single'` по умолчанию

## Автоматические скрипты

### sync-check.sh — Проверка синхронизации

**Использование:**
```bash
cd .nessy/skills/docs-sync-verify/scripts
./sync-check.sh docs/file.md docs-ru/users/work/features/file.md
```

**Что проверяет:**
- Количество разделов (##) и подразделов (###)
- Общее количество строк и процент различий
- Количество bullet points
- Наличие двойных backticks
- Неправильную терминологию
- Детальную статистику по каждому разделу

**Вывод:** Таблица с оценкой по каждому разделу (✅/⚠️/❌)

### auto-fix.sh — Автоматическое исправление

**Использование:**
```bash
cd .nessy/skills/docs-sync-verify/scripts
./auto-fix.sh docs-ru/users/work/features/file.md
```

**Что исправляет автоматически:**
- Двойные backticks ``--flag`` → одинарные `--flag`
- "безголовый режим" → "режим без интерфейса"
- "токен носителя" → "bearer-токен"
- "аутентификация носителя" → "bearer-аутентификация"
- Неправильные кавычки в markdown

**Безопасность:**
- Создаёт backup-копию (.bak) перед изменением
- Работает только с указанным файлом
- Выводит статистику изменений через git diff

## Полный рабочий процесс

### Вариант 1: Быстрая проверка

```bash
# 1. Запустить проверку
./scripts/sync-check.sh docs/file.md docs-ru/.../file.md

# 2. Если есть проблемы — запустить авто-исправление
./scripts/auto-fix.sh docs-ru/.../file.md

# 3. Проверить результат
git diff docs-ru/.../file.md
```

### Вариант 2: Ручное исправление сложных случаев

```bash
# 1. Запустить проверку для выявления проблемных разделов
./scripts/sync-check.sh docs/file.md docs-ru/.../file.md

# 2. Для разделов с ⚠️ или ❌ — извлечь контент
sed -n '/^## Quickstart/,/^## Authentication/p' docs/file.md > /tmp/en.txt
sed -n '/^## Быстрый старт/,/^## Аутентификация/p' docs-ru/.../file.md > /tmp/ru.txt

# 3. Сравнить и найти пропуски
diff /tmp/en.txt /tmp/ru.txt

# 4. Перевести недостающие блоки и вставить через edit tool

# 5. Запустить авто-исправление для терминологии
./scripts/auto-fix.sh docs-ru/.../file.md

# 6. Финальная проверка
./scripts/sync-check.sh docs/file.md docs-ru/.../file.md
```
