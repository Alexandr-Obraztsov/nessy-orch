# Дизайн: Кастомизация области баннера

## Обзор

Этот документ описывает дизайн для кастомизации области баннера в Nessy CLI TUI. Область баннера — это верхняя часть интерфейса, которая показывает информацию о сессии, статусе модели и другие контекстные данные.

## Мотивация

Текущая область баннера имеет фиксированную компоновку, которая не адаптируется к различным сценариям использования:

1. **Ограниченное пространство**: На узких терминалах баннер занимает слишком много вертикального пространства
2. **Недостаточная информация**: Некоторые пользователи хотят видеть больше контекста (например, текущий проект, режим одобрения)
3. **Отсутствие гибкости**: Нет возможности настроить, какие элементы отображать

## Цели дизайна

1. **Настраиваемая высота**: Пользователи могут выбирать между компактным (1 строка) и расширенным (2-3 строки) баннером
2. **Селективное отображение**: Пользователи могут выбирать, какие элементы отображать в баннере
3. **Адаптивная компоновка**: Баннер автоматически адаптируется к ширине терминала
4. **Сохранение настроек**: Конфигурация баннера сохраняется между сессиями

## Элементы баннера

### Базовые элементы (всегда отображаются)

| Элемент       | Описание                          | Приоритет |
| ------------- | --------------------------------- | --------- |
| Session ID    | Уникальный идентификатор сессии   | High      |
| Model name    | Текущая модель                    | High      |
| Status        | Статус подключения к модели       | High      |

### Опциональные элементы

| Элемент              | Описание                           | Приоритет | По умолчанию |
| -------------------- | ---------------------------------- | --------- | ------------ |
| Project name         | Имя текущего проекта               | Medium    | Show         |
| Approval mode        | Текущий режим одобрения            | Medium    | Show         |
| Token usage          | Использование токенов в сессии     | Low       | Hide         |
| Cost estimate        | Примерная стоимость сессии         | Low       | Hide         |
| Compact mode status  | Статус компактного режима          | Low       | Hide         |
| Memory status        | Статус системы памяти              | Low       | Hide         |

## Конфигурация

### Схема настроек

```json
{
  "ui": {
    "banner": {
      "height": "compact" | "expanded" | "auto",
      "elements": {
        "sessionId": true,
        "modelName": true,
        "status": true,
        "projectName": true,
        "approvalMode": false,
        "tokenUsage": false,
        "costEstimate": false,
        "compactModeStatus": false,
        "memoryStatus": false
      }
    }
  }
}
```

### Режимы высоты

| Режим         | Поведение                                                                 |
| ------------- | ------------------------------------------------------------------------- |
| `compact`     | Всегда 1 строка, показывает только элементы наивысшего приоритета        |
| `expanded`    | 2-3 строки, показывает все выбранные элементы                            |
| `auto`        | Адаптируется к ширине терминала: compact если < 80 колонок, expanded иначе |

## Варианты компоновки

### Компактная компоновка (1 строка)

```
│ Nessy CLI │ qwen3.5-coder │ ● Connected │ my-project │
```

Приоритет отображения в компактном режиме:
1. Session indicator (Nessy CLI)
2. Model name
3. Status
4. Project name (если помещается)

### Расширенная компоновка (2-3 строки)

```
│ Nessy CLI │ qwen3.5-coder │ ● Connected │
│ Project: my-project │ Approval: auto-edit │
│ Tokens: 12.5k │ Cost: $0.02 │ Compact: on │
```

## Поведение

### Адаптация к ширине терминала

Баннер должен адаптироваться к доступной ширине:

```typescript
function getBannerLayout(terminalWidth: number): BannerLayout {
  if (terminalWidth < 60) {
    return 'minimal'; // Только model + status
  } else if (terminalWidth < 80) {
    return 'compact'; // 1 строка
  } else {
    return 'expanded'; // 2-3 строки
  }
}
```

### Скрытие элементов при нехватке места

Когда терминал узкий, элементы скрываются по приоритету (от low к high):

1. Cost estimate
2. Token usage
3. Memory status
4. Compact mode status
5. Approval mode
6. Project name

### Интеграция с настройками

```typescript
// AppContainer.tsx
const bannerConfig = useBannerConfig();
const settings = useSettings();

useEffect(() => {
  if (settings.ui?.banner) {
    setBannerConfig(settings.ui.banner);
  }
}, [settings.ui?.banner]);
```

## Миграция

Для существующих пользователей:

1. По умолчанию баннер остаётся в текущем виде (expanded со всеми элементами)
2. При первом запуске с новой версией, показывается подсказка о новой возможности
3. Пользователь может настроить баннер через `/settings` или напрямую в settings.json

## Будущие расширения

### Приоритет P2

- **Динамические элементы**: Элементы, которые меняются на основе контекста (например, показывать token usage только когда > 50k)
- **Пользовательские элементы**: Возможность добавлять custom элементы через extensions
- **Темы баннера**: Разные визуальные стили для баннера (colors, borders)

### Приоритет P3

- **Интерактивный баннер**: Клик на элементах баннера для быстрых действий (например, клик на model name для смены модели)
- **Мини-графики**: Визуализация token usage trends прямо в баннере

## Риски

1. **Сложность UI**: Слишком много опций может запутать пользователей
   - Митигация: Разумные defaults, прогрессивное раскрытие сложности

2. **Производительность**: Частые перерисовки баннера при изменении размера
   - Митигация: Debounce resize events, кэширование layout calculations

3. **Совместимость**: Старые терминалы могут не поддерживать некоторые символы
   - Митигация: Fallback на ASCII символы для старых терминалов
