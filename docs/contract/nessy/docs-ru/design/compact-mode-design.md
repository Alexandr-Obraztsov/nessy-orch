# Compact Mode Design: Конкурентный анализ и оптимизация

> Ctrl+O переключение compact/verbose режима — конкурентный анализ с Claude Code, обзор текущей реализации и рекомендации по оптимизации.
>
> Пользовательская документация: [Settings — ui.compactMode](../users/work/configuration/settings.md).

## 1. Краткое резюме

Nessy CLI и Claude Code оба предоставляют горячую клавишу Ctrl+O для переключения между компактным и детальным отображением вывода инструментов, но **философия дизайна, состояние по умолчанию и модель взаимодействия фундаментально отличаются**. Этот документ предоставляет глубокий анализ на уровне исходного кода, выявляет пробелы в UX и предлагает оптимизации для Nessy CLI.

| Измерение                          | Claude Code                                          | Nessy CLI                                     |
| ---------------------------------- | ---------------------------------------------------- | --------------------------------------------- |
| Режим по умолчанию                 | Compact (verbose=false)                              | Verbose (compactMode=false)                   |
| Семантика переключения             | Временный просмотр деталей                           | Постоянное переключение предпочтений          |
| Сохранение                         | Только сессия, сброс при перезапуске                 | Сохраняется в settings.json                   |
| Область действия                   | Глобальное переключение экрана (prompt ↔ transcript) | Переключение рендеринга на уровне компонентов |
| Замороженный снимок                | Нет (нет концепции)                                  | Нет (удалено)                                 |
| Подсказка расширения на инструмент | Да ("ctrl+o to expand")                              | Да ("Press Ctrl+O to show full tool output")  |

## 2. Анализ реализации Claude Code

### 2.1 Архитектура

Claude Code использует подход **на основе экрана**, а не переключение рендеринга на уровне компонентов:

```
┌──────────────────────────────────┐
│         AppState (Zustand)       │
│  verbose: boolean (по умолчанию: false)│
│  screen: 'prompt' | 'transcript' │
└──────────┬───────────────────────┘
           │
     ┌─────┴──────┐
     │  Ctrl+O    │  переключает режим экрана
     │  Handler    │  НЕ флаг рендеринга
     └─────┬──────┘
           │
     ┌─────▼──────────────┐
     │    REPL.tsx         │
     │  screen='prompt'  → компактный вид (по умолчанию)
     │  screen='transcript'→ детальный вид
     └────────────────────┘
```

### 2.2 Ключевые исходные файлы

| Компонент               | Файл                                               | Ключевая логика                                        |
| ----------------------- | -------------------------------------------------- | ------------------------------------------------------ |
| Обработчик переключения | `src/hooks/useGlobalKeybindings.tsx:90-132`        | Переключает `screen` между `'prompt'` и `'transcript'` |
| Горячая клавиша         | `src/keybindings/defaultBindings.ts:44`            | `app:toggleTranscript`                                 |
| Определение состояния   | `src/state/AppStateStore.ts:472`                   | `verbose: false` (только сессия)                       |
| Подсказка расширения    | `src/components/CtrlOToExpand.tsx:29-46`           | Текст "(ctrl+o to expand)" на каждом инструменте       |
| Фильтр сообщений        | `src/components/Messages.tsx:93-151`               | `filterForBriefTool()` для компактного режима          |
| Разрешение              | `src/components/permissions/PermissionRequest.tsx` | Отображается в слое overlay, никогда не скрывается     |

### 2.3 Решения дизайна

1. **Compact по умолчанию.** Пользователи видят чистый интерфейс из коробки; детали — по желанию.
2. **Только сессия.** `verbose` сбрасывается до `false` в каждой новой сессии — Claude Code предполагает, что пользователи обычно предпочитают компактный вид и нуждаются в деталях временно.
3. **Переключение уровня экрана.** Ctrl+O не меняет, как компоненты рендерятся; он переключает весь дисплей между экраном "prompt" (компактный) и экраном "transcript" (детальный).
4. **Нет замороженного снимка.** Нет концепции заморозки снимка. При переключении дисплей немедленно обновляется текущим состоянием.
5. **Диалоги разрешений отдельны.** Утверждения инструментов рендерятся в выделенном слое overlay, на который никогда не влияет переключение verbose/compact.
6. **Подсказка на инструмент.** Компонент `CtrlOToExpand` показывает контекстную подсказку на отдельных инструментах, когда они производят большой вывод, подавляется в sub-agents.

### 2.4 Поток пользователя

```
Начало сессии → compact режим (по умолчанию)
     │
     ├─ Выводы инструментов суммируются в одну строку
     ├─ Большой вывод инструмента показывает подсказку "(ctrl+o to expand)"
     │
     ├─ Пользователь нажимает Ctrl+O
     │     └─→ Экран переключается на transcript (детальный вид)
     │         └─ Пользователь видит весь вывод инструмента, размышления и т.д.
     │
     ├─ Пользователь нажимает Ctrl+O снова
     │     └─→ Экран переключается обратно на prompt (компактный)
     │
     └─ Сессия заканчивается → verbose сбрасывается до false
```

## 3. Анализ реализации Nessy CLI

### 3.1 Архитектура

Nessy CLI использует **флаг рендеринга на уровне компонентов**, который каждый UI-компонент читает из контекста:

```
┌─────────────────────────────────────┐
│      CompactModeContext             │
│  compactMode: boolean (по умолчанию: false)│
│  setCompactMode: (v) => void        │
└──────────┬──────────────────────────┘
           │
     ┌─────┴──────┐
     │  Ctrl+O    │  переключает compactMode
     │  Handler    │  сохраняет в settings
     └─────┬──────┘
           │
     ┌─────▼──────────────────┐
     │  Каждый компонент читает  │
     │  compactMode и       │
     │  решает, как рендерить │
     └────────────────────────┘
           │
     ┌─────▼──────────────────────────────┐
     │  ToolGroupMessage                   │
     │    showCompact = compactMode        │
     │      && !hasConfirmingTool          │
     │      && !hasErrorTool               │
     │      && !isEmbeddedShellFocused     │
     │      && !isUserInitiated            │
     └────────────────────────────────────┘
```

### 3.2 Ключевые исходные файлы

| Компонент               | Файл                                  | Ключевая логика                                              |
| ----------------------- | ------------------------------------- | ------------------------------------------------------------ |
| Обработчик переключения | `AppContainer.tsx:1684-1690`          | Переключает `compactMode`, сохраняет в settings              |
| Контекст                | `CompactModeContext.tsx`              | `compactMode`, `setCompactMode`                              |
| Группа инструментов     | `ToolGroupMessage.tsx:105-110`        | `showCompact` с 4 условиями принудительного расширения       |
| Сообщение инструмента   | `ToolMessage.tsx:346-350`             | Скрывает `displayRenderer` в compact режиме                  |
| Compact отобращение     | `CompactToolGroupDisplay.tsx:49-108`  | Однострочное резюме со статусом + подсказка                  |
| Подтверждение           | `ToolConfirmationMessage.tsx:113-147` | Упрощённое компактное утверждение с 3 опциями                |
| Подсказки               | `Tips.tsx:14-29`                      | Вращение подсказок запуска включает подсказку compact режима |
| Синхронизация настроек  | `SettingsDialog.tsx:189-193`          | Синхронизирует с CompactModeContext + refreshStatic          |
| MainContent             | `MainContent.tsx:60-76`               | Рендерит live pendingHistoryItems                            |
| Размышления             | `HistoryItemDisplay.tsx:123-133`      | Скрывает `gemini_thought` в compact режиме                   |

### 3.3 Решения дизайна

1. **Verbose по умолчанию.** Пользователи видят весь вывод инструмента и размышления по умолчанию.
2. **Постоянное предпочтение.** `compactMode` сохраняется в `settings.json` и переживает сессии.
3. **Рендеринг на уровне компонентов.** Каждый компонент читает `compactMode` из контекста и корректирует свой собственный рендеринг.
4. **Защита принудительного расширения.** Четыре условия переопределяют compact режим для обеспечения видимости критических элементов UI (подтверждения, ошибки, shell, инициированные пользователем).
5. **Нет заморозки снимка.** Переключение всегда показывает live-вывод — нет замороженных снимков.
6. **Синхронизация диалога настроек.** Переключение compact режима из настроек немедленно обновляет React-состояние через `setCompactMode`.
7. **Ненавязчивая обнаруживаемость.** Compact режим представляется через вращение подсказок запуска, а не постоянный индикатор в футере, избегая загромождения UI.

### 3.4 Поток пользователя

```
Начало сессии → verbose режим (по умолчанию)
     │
     ├─ Весь вывод инструмента, размышления, детали видны
     │
     ├─ Пользователь нажимает Ctrl+O (или переключает в настройках)
     │     └─→ compactMode = true, сохранено
     │         ├─ Группы инструментов показывают однострочное резюме
     │         ├─ Содержимое размышлений/мыслей скрыто
     │         └─ Подтверждения, ошибки, shell всё ещё расширены
     │
     ├─ Пользователь нажимает Ctrl+O снова
     │     └─→ compactMode = false, сохранено
     │         └─ Все детали видны снова
     │
     └─ Следующая сессия → тот же режим, что и в последней сессии
```

## 4. Глубокое погружение в ключевые различия

### 4.1 Философия режима по умолчанию

| Аспект                 | Claude Code (compact по умолчанию)                       | Nessy CLI (verbose по умолчанию)                       |
| ---------------------- | -------------------------------------------------------- | ------------------------------------------------------ |
| Первое впечатление     | Чистый, минимальный — профессиональное ощущение          | Информативно-богатый — полная прозрачность             |
| Кривая обучения        | Пользователь должен изучить Ctrl+O для просмотра деталей | Пользователь может немедленно увидеть всё              |
| Целевая аудитория      | Опытные пользователи, доверяющие инструменту             | Пользователи, желающие понять, что происходит          |
| Перегрузка информацией | Избегается по умолчанию                                  | Возможно для новых пользователей                       |
| Обнаруживаемость       | Подсказки "(ctrl+o to expand)" на инструментах           | Вращение подсказок запуска + ? горячие клавиши + /help |

**Анализ:** Compact по умолчанию Claude Code работает, потому что его пользовательская база — обычно опытные разработчики, доверяющие инструменту и не нуждающиеся видеть каждый вызов инструмента. Verbose по умолчанию Nessy CLI уместен на его ранней стадии, где построение доверия пользователя через прозрачность важно.

### 4.2 Модель сохранения

| Аспект                | Claude Code                | Nessy CLI                                      |
| --------------------- | -------------------------- | ---------------------------------------------- |
| Сохранено?            | Нет — только сессия        | Да — в settings.json                           |
| Обоснование           | Verbose временно смотрит   | Режим — предпочтение пользователя              |
| Поведение перезапуска | Всегда запускается compact | Запускается с последним использованным режимом |

**Анализ:** Claude Code рассматривает просмотр деталей как моментальную потребность — вы смотрите, затем возвращаетесь обратно. Nessy CLI рассматривает это как стабильное предпочтение — некоторые пользователи всегда хотят детали, другие всегда хотят compact. Оба валидны; подход Nessy CLI более гибок.

### 4.3 Защита подтверждения

| Аспект                       | Claude Code                                       | Nessy CLI                                                |
| ---------------------------- | ------------------------------------------------- | -------------------------------------------------------- |
| Механизм                     | Слой overlay/modal (структурно отделён)           | Условия принудительного расширения в `showCompact`       |
| Покрытие                     | Полное — утверждения никогда не могут быть скрыты | Полное — 4 условия покрывают все интерактивные состояния |
| UI компактного подтверждения | N/A (overlay всегда полный)                       | Упрощённый RadioButtonSelect с 3 опциями                 |

**Анализ:** Архитектурное разделение Claude Code (слой overlay) более надёжно. Подход принудительного расширения Nessy CLI эффективен, но требует, чтобы каждое новое интерактивное состояние было явно добавлено в список условий.

### 4.4 Подход к рендерингу

| Аспект               | Claude Code                          | Nessy CLI                                     |
| -------------------- | ------------------------------------ | --------------------------------------------- |
| Область переключения | Уровень экрана (prompt ↔ transcript) | Уровень компонентов (каждый компонент решает) |
| Гранулярность        | Всё или ничего                       | Тонкозернисто на компонент                    |
| Гибкость             | Низкая — глобальное переключение     | Высокая — компоненты могут переопределять     |
| Согласованность      | Гарантирована                        | Зависит от реализации каждого компонента      |

**Анализ:** Подход на уровне компонентов Nessy CLI более гибок (например, принудительное расширение для специфичных условий), но требует больше дисциплины для поддержания согласованности. Подход на уровне экрана Claude Code проще и гарантирует согласованное поведение.

## 5. Рекомендации по оптимизации

### 5.1 [P0] Оставить Verbose по умолчанию — изменения не нужны

Verbose по умолчанию Nessy CLI — правильный выбор для его текущей стадии. Пользователи, новые для инструмента, нуждаются в прозрачности для построения доверия. По мере созревания продукта рассмотрите compact по умолчанию (как Claude Code).

### 5.2 [P1] Расширение на инструмент для больших выводов

Claude Code показывает "(ctrl+o to expand)" на отдельных инструментах, производящих большой вывод. Nessy CLI в настоящее время имеет только глобальное переключение. Рассмотрите:

- Когда один инструмент производит вывод, превышающий N строк, показывать подсказку "expand" на инструменте в compact режиме.
- Область: будущее улучшение, не текущий приоритет.

### 5.3 [P2] Рассмотреть переопределение на сессию

Некоторые пользователи могут хотеть compact режим по умолчанию, но иногда нуждаться в verbose для специфичной сессии. Рассмотрите поддержку обоих:

- `settings.json` → постоянное по умолчанию (текущее поведение)
- Ctrl+O во время сессии → временное переопределение только для текущей сессии (поведение Claude Code)
- При перезапуске сессии → возврат к значению settings.json

Это даёт пользователям лучшее из обоих миров. Реализация потребует разделения "по умолчанию настроек" от состояния "переопределения сессии".

### 5.4 [P2] Структурное разделение для подтверждений

В настоящее время защита подтверждений полагается на условия `showCompact` в `ToolGroupMessage`. Рассмотрите более надёжный подход:

- Рендерить подтверждения в отдельном слое (как подход overlay Claude Code).
- Это сделает архитектурно невозможным влияние compact режима на подтверждения.
- Меньший приоритет, так как текущий подход принудительного расширения работает корректно.
