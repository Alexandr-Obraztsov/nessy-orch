# Дизайн системы заголовков сессий

> Заголовок сессии из 3-7 слов в формате sentence case, генерируемый быстрой моделью после первого ответа ассистента. Сохраняется в JSONL-файле сессии с тегом `titleSource: 'auto' | 'manual'`, отображается в селекторе сессий и может быть перегенерирован по требованию через `/rename --auto`.

## Обзор

`/rename` (#3093) позволяет пользователю присвоить имя сессии для последующего поиска в селекторе, но до его запуска селектор показывает первый промпт пользователя — часто обрезанный на полуслове или описывающий вводный вопрос, а не то, чем сессия фактически стала. Ручное переименование — опциональное действие, которое большинство пользователей никогда не выполняют.

Цель — сделать имена сессий **полезными по умолчанию**:

- **Описательные**: то, что сессия фактически достигла, а не просто открывающая строка. 3-7 слов, sentence case, в стиле заголовка git-коммита.
- **Best-effort**: запускается в фоне после первого ответа; если не удаётся — пользователь не видит ошибки.
- **Уважительные к пользователю**: никогда не перезаписывают титул `/rename`, выбранный пользователем намеренно, даже между вкладками CLI на одной сессии.
- **Явно перегенерируемые**: через `/rename --auto` для случая «автозаголовок устарел / хочу свежий».

## Триггеры

| Триггер    | Условия                                                                                                                                                                                  | Реализация                                                     |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| **Авто**   | После срабатывания `recordAssistantTurn`. Пропускается, если титул уже установлен, идёт другая попытка, достигнут лимит, неинтерактивный режим, отключено средой или нет быстрой модели. | `ChatRecordingService.maybeTriggerAutoTitle` — fire-and-forget |
| **Ручной** | Пользователь запускает `/rename --auto`                                                                                                                                                  | `renameCommand.ts` через `tryGenerateSessionTitle`             |

Оба пути сходятся в единую функцию — `tryGenerateSessionTitle(config, signal)` — что гарантирует идентичный промпт, схему, выбор модели и санитизацию. Авто-триггер — это фоновый вызов best-effort; ручной `/rename --auto` — блокирующее действие пользователя, которое показывает конкретную ошибку при неудаче.

## Дизайн промпта

### Системный промпт

Заменяет системный промпт основного агента для этого единственного вызова, чтобы модель только маркировала сессию, а не вела себя как кодинг-ассистент.

Пункты ниже соответствуют 1:1 с `TITLE_SYSTEM_PROMPT`:

- 3-7 слов, sentence case (только первое слово и собственные имена с заглавной).
- Без завершающей пунктуации, без markdown, без кавычек.
- Соответствовать доминирующему языку разговора; для китайского — бюджет примерно 12-20 символов.
- Быть конкретным о фактической цели пользователя — называть фичу, баг или предметную область. Избегать расплывчатых обобщений вроде «Изменения кода» или «Запрос помощи».
- Четыре хороших примера (три английских + один китайский) и четыре плохих (слишком расплывчатые / слишком длинные / неверный регистр / завершающая пунктуация).
- Возвращать только JSON-объект с единственным ключом `title`.

### Структурированный вывод (JSON schema)

Вместо обёртки вывода в теги (как делает session-recap), используем `BaseLlmClient.generateJson` со схемой function-calling:

```ts
const TITLE_SCHEMA = {
  type: 'object',
  properties: {
    title: {
      type: 'string',
      description:
        'Краткий sentence-case заголовок сессии, 3-7 слов, без завершающей пунктуации.',
    },
  },
  required: ['title'],
};
```

Почему function calling, а не свободный текст + парсинг тегов:

1. Надёжность across-провайдеров — OpenAI-совместимые эндпоинты, Gemini и нативный tool-calling Nessy реализуют function calling; парсинг тегов полагался бы на то, что каждая модель соблюдает текстовое соглашение.
2. Нет утечки reasoning-preamble — аргументы function call возвращаются структурированно, поэтому параграф «размышлений» перед ответом не может попасть в титул.
3. Проще пост-обработка — единственная проверка `typeof result.title === 'string'` плюс `sanitizeTitle` покрывают любой реалистичный дрейф модели.

Модель всё ещё может вернуть что-то, что схема разрешает, но UX отвергает (пустая строка, только whitespace, 500 символов, markdown-ограждение, контрольные символы). `sanitizeTitle` обрабатывает всё это и возвращает `''` → сервис возвращает `{ok: false, reason: 'empty_result'}`.

### Параметры вызова

| Параметр          | Значение                        | Причина                                                                                                                         |
| ----------------- | ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `model`           | `getFastModel()` — без fallback | Авто-титлинг на токенах основной модели слишком дорог для тихого выполнения.                                                    |
| `schema`          | `TITLE_SCHEMA`                  | Принуждает `{title: string}`; фильтрует дрейф формы на транспортном уровне.                                                     |
| `maxOutputTokens` | `100`                           | Более чем достаточно для 7 слов плюс overhead схемы.                                                                            |
| `temperature`     | `0.2`                           | Преимущественно детерминировано — заголовки сессий выигрывают от стабильности при регенерации.                                  |
| `maxAttempts`     | `1`                             | Титулы — best-effort косметические метаданные; повторные попытки встали бы в очередь за видимым пользователю основным трафиком. |

Контраст с session-recap, который фоллбэчится на основную модель. Генерация титула срабатывает автоматически и часто; тихая трата токенов основной модели без опта пользователя — реальный сюрприз в счёте. Ручной `/rename --auto` явно фейлится с `no_fast_model`, а не фоллбэчится — заставляя пользователя сознательно выбрать быструю модель.

## Фильтрация истории

`geminiClient.getChat().getHistory()` возвращает `Content[]`, включающий tool call'ы, tool response'ы (часто 10K+ токенов контента файлов) и model thought части. Подача этого сырого в LLM титула сместила бы лейбл к шуму реализации вроде «Called grep on auth module».

`filterToDialog` оставляет только записи `user` / `model` с непустым текстом и без `thought` / `thoughtSignature` частей. `takeRecentDialog` срезает последние 20 сообщений и отказывается стартовать на висящем model/tool ответе. `flattenToTail` конвертирует в строки «Role: text» и срезает последние 1000 символов.

### Срез хвоста в 1000 символов

Сессия, начинающаяся с `help me debug X`, но переходящая в рефакторинг Y, должна быть озаглавлена про Y. Титулирование по голове фиксирует открывающий фрейминг; титулирование по хвосту захватывает то, чем сессия стала.

### Обработка UTF-16 суррогатов

`.slice(-1000)` на границе UTF-16 code-unit может оторвать high или low суррогат, если CJK supplementary char или emoji обрезается. Некоторые провайдеры отвечают на невалидный UTF-16 400-й ошибкой — что без обработки сожгло бы попытку без причины. `flattenToTail` отбрасывает висящий low суррогат в начале; `sanitizeTitle` также скраббит любой осиротевший суррогат после trim'а максимальной длины на выходном пути.

## Персистентность

### Форма записи

`CustomTitleRecordPayload` растит опциональное поле `titleSource: 'auto' | 'manual'`:

```jsonc
{
  "type": "system",
  "subtype": "custom_title",
  "systemPayload": {
    "customTitle": "Debug login button on mobile",
    "titleSource": "auto",
  },
}
```

Поле опционально, и отсутствующие в legacy-записях трактуются как `undefined`. `SessionPicker` затемняет строки только при строгом `=== 'auto'` — ранее выбранный пользователем титул `/rename` никогда молча не переклассифицируется как догадка модели.

### Resume hydration

При resume конструктор `ChatRecordingService` вызывает `sessionService.getSessionTitleInfo(sessionId)` для чтения **и** титула, **и** источника. Без гидратации источника `finalize()` (перезапись, запускаемая на каждом событии жизненного цикла сессии) переписывала бы auto как manual на каждом цикле resume — молча стирая dim-аффорданс.

### Атомарное парное чтение

`extractLastJsonStringFields` возвращает `customTitle` и `titleSource` из **одной совпавшей строки** за один проход. Два отдельных вызова `readLastJsonStringFieldSync` могли попасть на разные записи, если более старая строка имеет только первичное поле, давая рассогласованную пару. Экстрактор также требует закрывающую кавычку на первичном значении, поэтому crash-обрезанная trailing-запись не может выиграть latest-match гонку.

### Лимит полного сканирования файла

Phase-2 (когда fast-path tail-окна промахивается) стримит весь файл 64KB чанками. Ограничено `MAX_FULL_SCAN_BYTES = 64 MB`, чтобы коррумпированный multi-GB JSONL не заморозил селектор сессий на главном event loop. Латентный конверт селектора выживает при коррупции.

### Защита от ссылок

Чтения сессии открываются с `O_NOFOLLOW` (fallback на plain read-only на Windows, где константа не экспонирована). Защита в глубину, чтобы symlink, посаженный в `~/.nessy/projects/<proj>/chats/`, не мог перенаправить чтение метаданных на нерелевантный файл.

## Конкурентность и крайние случаи

### Порядок guard'ов триггера

`maybeTriggerAutoTitle` проверяет 6 условий в этом точном порядке — каждый short-circuit'ит остальные, чтобы дешёвые выполнялись первыми:

1. `currentCustomTitle` установлен → пропуск. Никогда не перезаписывать manual / prior auto.
2. `autoTitleController !== undefined` → пропуск. Одна попытка за раз.
3. `autoTitleAttempts >= 3` → пропуск. Лимит общих потерь.
4. `!config.isInteractive()` → пропуск. Headless `nessy -p` / CI никогда не тратит токены быстрой модели на one-off сессию.
5. `autoTitleDisabledByEnv()` → пропуск. `NESSY_DISABLE_AUTO_TITLE=1` явный opt-out.
6. `!config.getFastModel()` → пропуск. Нет быстрой модели → no-op.

### Почему лимит 3, а не 1

Первый ответ ассистента может быть чистым tool-call без видимого пользователю текста (например, модель открывает `grep`). `tryGenerateSessionTitle` возвращает `{ok: false, reason: 'empty_history'}` в этом случае. Без retry-окна весь шанс сессии на титул сгорел бы на ходе 1 до того, как пользователь сказал что-то интересное. Лимит в 3 покрывает обычный случай «первый ход — шум», всё ещё ограничивая runaway-попытки на персистентно фейлящейся быстрой модели.

### Cross-process race ручного rename

Две CLI-вкладки на одном файле сессии могут разойтись в памяти. Вкладка A запускает `/rename foo` и пишет `titleSource: manual`. Вкладка B имеет `currentCustomTitle = undefined` и наивно перезаписала бы авто-титулом.

После того как LLM-вызов разрешается, IIFE перечитывает JSONL через `sessionService.getSessionTitleInfo`. Если файл показывает `source: 'manual'`, IIFE прерывается И синхронизирует своё in-memory состояние, чтобы последующие ходы также уважали rename. Цена: одно 64KB tail-чтение на успешную генерацию; пренебрежимо.

### Propagation abort на `finalize()`

`autoTitleController` удваивается как in-flight флаг. `finalize()` (запускается при переключении сессии и shutdown процесса) вызывает `autoTitleController.abort()` перед перезаписью титула. Socket LLM отменяется promptly; переключение сессии не ждёт медленный fast-model вызов. `finally`-блок IIFE очищает `autoTitleController` только если он всё ещё активный, поэтому finalize mid-flight не гоняется с concurrent `recordAssistantTurn`.

### Ручной `/rename` попадает mid-flight

Между завершением `await` в IIFE и вызовом `recordCustomTitle('auto')` пользователь мог запустить `/rename foo`. IIFE перепроверяет `this.currentTitleSource === 'manual'` и прерывается. In-process проверка И cross-process перечитывание выполняются оба; manual побеждает на обоих слоях.

## Конфигурация

### Пользовательские ручки

| Настройка / env var          | По умолчанию | Эффект                                                                                        |
| ---------------------------- | ------------ | --------------------------------------------------------------------------------------------- |
| `fastModel`                  | unset        | Требуется для авто-титлинга. Unset → no-op (без main-model fallback).                         |
| `NESSY_DISABLE_AUTO_TITLE=1` | unset        | Opt out из авто-триггера без unset `fastModel`. `/rename --auto` всё ещё работает по запросу. |

Нет `settings.json` тогла — env var единственный user-visible выключатель. Рационал: фича косметическая и дешёвая; settings toggle добавил бы UI surface для чего-то, что может жить как one-time env export для немногих пользователей, желающих отключить.

### Почему авто не фоллбэчится на основную модель

Авто-титлинг срабатывает безусловно после каждого ответа ассистента. Если пользователь без быстрой модели молча зарядится токенами основной модели для титула каждой новой сессии, дельта стоимости невидима до прихода месячного счёта. Тихий фейл (no-op, нет титула, нет стоимости) — более безопасный дефолт. `/rename --auto` surfaced `no_fast_model` как actionable ошибку, чтобы пользователь мог установить быструю модель при желании.

## Обсервабельность

`createDebugLogger('SESSION_TITLE')` эмитит `debugLogger.warn` из catch-блока генератора. Феилы полностью прозрачны для пользователя — авто-титул вспомогательная фича и никогда не бросает в UI.

Разработчики могут grep'ить по тегу `[SESSION_TITLE]` в debug логе (`~/.nessy/debug/<sessionId>.txt`; `latest.txt` symlink'ится на текущую сессию). Рабочий end-to-end вызов не выдаёт логового вывода; фейлящийся получает одну WARN линию с сообщением об ошибке.

## Харденинг безопасности

Значение титула рендерится verbatim в терминале (селектор сессий) И персистится в user-readable JSONL файле. Обе поверхности attack reachable, если компрометированная или prompt-injected быстрая модель возвращает враждебный текст.

| Проблема                                       | Guard                                                                                                                                   |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| ANSI / OSC-8 / CSI инъекция                    | `stripTerminalControlSequences` перед JSONL записью и picker рендером.                                                                  |
| Clickable-link smuggle через OSC-8             | То же — OSC последовательности стираются как целые единицы, не только ESC байт.                                                         |
| Невалидные UTF-16 суррогаты                    | Скраббятся в `flattenToTail` (LLM input) и `sanitizeTitle` (LLM output после max-length trim).                                          |
| Subtype-line спуфинг через контент сообщения   | `lineContains: '"subtype":"custom_title"'` — пользовательский текст, случайно содержащий литеральную фразу, не затенит реальную запись. |
| Symlink redirect на чтениях сессий             | `O_NOFOLLOW` (no-op на Windows, где константа отсутствует).                                                                             |
| Обрезанная trailing JSONL запись               | `extractLastJsonStringFields` требует закрывающую кавычку перед тем, как запись выиграет latest-match гонку.                            |
| Патологический размер файла, морозящий picker  | `MAX_FULL_SCAN_BYTES = 64 MB` лимит на Phase-2 full-file scan.                                                                          |
| Спаренные CJK bracket декораторы (`【Draft】`) | Стираются как единица, чтобы одиночный закрывающий bracket не висел.                                                                    |

## Вне области

| Пункт                                         | Почему нет                                                                                                                                                |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Авто-регенерация при устаревании титула       | `/rename --auto` — явный user-triggered путь. Молчаливые mid-session свапы титулов запутали бы пользователей, скроллящих назад по picker.                 |
