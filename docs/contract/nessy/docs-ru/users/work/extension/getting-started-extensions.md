# Начало работы с расширениями Nessy CLI

Это руководство проведёт вас через создание вашего первого расширения Nessy CLI. Вы узнаете, как настроить новое расширение, добавить пользовательский инструмент через MCP-сервер, создать пользовательскую команду и предоставить контекст модели с файлом `NESSY.md`.

## Предварительные требования

Перед началом убедитесь, что у вас установлен Nessy CLI и есть базовое понимание Node.js и TypeScript.

## Шаг 1: Создание нового расширения

Самый простой способ начать — использовать один из встроенных шаблонов. Мы будем использовать пример `mcp-server` в качестве основы.

Выполните следующую команду, чтобы создать новый каталог `my-first-extension` с файлами шаблона:

```bash
nessy extensions new my-first-extension mcp-server
```

Это создаст новый каталог со следующей структурой:

```
my-first-extension/
├── example.ts
├── nessy-extension.json
├── package.json
└── tsconfig.json
```

## Шаг 2: Изучение файлов расширения

Давайте рассмотрим ключевые файлы в вашем новом расширении.

### `nessy-extension.json`

Это файл манифеста вашего расширения. Он сообщает Nessy CLI, как загружать и использовать ваше расширение.

```json
{
  "name": "my-first-extension",
  "version": "1.0.0",
  "mcpServers": {
    "nodeServer": {
      "command": "node",
      "args": ["${extensionPath}${/}dist${/}example.js"],
      "cwd": "${extensionPath}"
    }
  }
}
```

- `name`: Уникальное имя вашего расширения.
- `version`: Версия вашего расширения.
- `mcpServers`: Этот раздел определяет один или несколько MCP-серверов (Model Context Protocol). MCP-серверы — это способ добавить новые инструменты для использования моделью.
  - `command`, `args`, `cwd`: Эти поля указывают, как запустить ваш сервер. Обратите внимание на использование переменной `${extensionPath}`, которую Nessy CLI заменяет на абсолютный путь к каталогу установки вашего расширения. Это позволяет вашему расширению работать независимо от того, где оно установлено.

### `example.ts`

Этот файл содержит исходный код вашего MCP-сервера. Это простой сервер Node.js, использующий `@modelcontextprotocol/sdk`.

```typescript
/**
 * @license
 * Copyright 2025 Google LLC
 * SPDX-License-Identifier: Apache-2.0
 */

import { McpServer } from '@modelcontextprotocol/sdk/server/mcp.js';
import { StdioServerTransport } from '@modelcontextprotocol/sdk/server/stdio.js';
import { z } from 'zod';

const server = new McpServer({
  name: 'prompt-server',
  version: '1.0.0',
});

// Регистрирует новый инструмент с именем 'fetch_posts'
server.registerTool(
  'fetch_posts',
  {
    description: 'Получает список публикаций из публичного API.',
    inputSchema: z.object({}).shape,
  },
  async () => {
    const apiResponse = await fetch(
      'https://jsonplaceholder.typicode.com/posts',
    );
    const posts = await apiResponse.json();
    const response = { posts: posts.slice(0, 5) };
    return {
      content: [
        {
          type: 'text',
          text: JSON.stringify(response),
        },
      ],
    };
  },
);

// ... (регистрация prompt опущена для краткости)

const transport = new StdioServerTransport();
await server.connect(transport);
```

Этот сервер определяет один инструмент под названием `fetch_posts`, который получает данные из публичного API.

### `package.json` и `tsconfig.json`

Это стандартные конфигурационные файлы для проекта TypeScript. Файл `package.json` определяет зависимости и скрипт `build`, а `tsconfig.json` настраивает компилятор TypeScript.

## Шаг 3: Сборка и линковка расширения

Перед использованием расширения нужно скомпилировать код TypeScript и линковать расширение с вашей установкой Nessy CLI для локальной разработки.

1.  **Установите зависимости:**

    ```bash
    cd my-first-extension
    npm install
    ```

2.  **Соберите сервер:**

    ```bash
    npm run build
    ```

    Это скомпилирует `example.ts` в `dist/example.js`, который указан в вашем `nessy-extension.json`.

3.  **Линкуйте расширение:**

    Команда `link` создаёт символическую ссылку из каталога расширений Nessy CLI в ваш каталог разработки. Это означает, что любые изменения будут отражены немедленно без необходимости переустановки.

    ```bash
    nessy extensions link .
    ```

Теперь перезапустите сеанс Nessy CLI. Новый инструмент `fetch_posts` будет доступен. Вы можете протестировать его, спросив: «fetch posts».

## Шаг 4: Добавление пользовательской команды

Пользовательские команды предоставляют способ создания ярлыков для сложных запросов. Давайте добавим команду, которая ищет шаблон в вашем коде.

1.  Создайте каталог `commands` и подкаталог для вашей группы команд:

    ```bash
    mkdir -p commands/fs
    ```

2.  Создайте файл `commands/fs/grep-code.md`:

    ```markdown
    ---
    description: Поиск шаблона в коде и суммаризация результатов
    ---

    Пожалуйста, суммаризируйте результаты для шаблона `{{args}}`.

    Результаты поиска:
    !{grep -r {{args}} .}
    ```

    Эта команда `/fs:grep-code` примет аргумент, запустит shell-команду `grep` с ним и передаст результаты в prompt для суммаризации.

> **Примечание:** Команды используют формат Markdown с опциональным YAML frontmatter. TOML формат устарел, но всё ещё поддерживается для обратной совместимости.

После сохранения файла перезапустите Nessy CLI. Теперь вы можете запустить `/fs:grep-code "some pattern"` для использования вашей новой команды.

## Шаг 5: Добавление пользовательских навыков и субагентов (опционально)

Расширения также могут предоставлять пользовательские навыки и субагентов для расширения возможностей Nessy CLI.

### Добавление пользовательского навыка

Навыки — это возможности, вызываемые моделью, которые ИИ может автоматически использовать, когда это уместно.

1.  Создайте каталог `skills` с подкаталогом навыка:

    ```bash
    mkdir -p skills/code-analyzer
    ```

2.  Создайте файл `skills/code-analyzer/SKILL.md`:

    ```markdown
    ---
    name: code-analyzer
    description: Анализирует структуру кода и предоставляет информацию о сложности, зависимостях и потенциальных улучшениях
    ---

    # Code Analyzer

    ## Инструкции

    При анализе кода фокусируйтесь на:

    - Сложность кода и поддерживаемость
    - Зависимости и связывание
    - Потенциальные проблемы производительности
    - Предложения по улучшениям

    ## Примеры

    - «Проанализируй сложность этой функции»
    - «Какие зависимости у этого модуля?»
    ```

### Добавление пользовательского субагента

Субагенты — это специализированные ИИ-ассистенты для конкретных задач.

1.  Создайте каталог `agents`:

    ```bash
    mkdir -p agents
    ```

2.  Создайте файл `agents/refactoring-expert.md`:

    ```markdown
    ---
    name: refactoring-expert
    description: Специализирован на рефакторинге кода, улучшении структуры кода и поддерживаемости
    tools:
      - read_file
      - write_file
      - read_many_files
    ---

    Вы — специалист по рефакторингу, сфокусированный на улучшении качества кода.

    Ваша экспертиза включает:

    - Идентификация code smells и антипаттернов
    - Применение принципов SOLID
    - Улучшение читаемости и поддерживаемости кода
    - Безопасный рефакторинг с минимальным риском

    Для каждой задачи рефакторинга:

    1. Проанализируйте текущую структуру кода
    2. Идентифицируйте области для улучшения
    3. Предложите шаги рефакторинга
    4. Реализуйте изменения инкрементально
    5. Проверьте, что функциональность сохранена
    ```

После перезапуска Nessy CLI ваши пользовательские навыки будут доступны через `/skills`, а субагенты — через `/agents manage`.

## Шаг 6: Добавление пользовательского `NESSY.md`

Вы можете предоставить постоянный контекст модели, добавив файл `NESSY.md` в корень вашего расширения. Это полезно для предоставления модели инструкций о том, как себя вести, или информации об инструментах вашего расширения. Обратите внимание, что это не всегда нужно для расширений, созданных для предоставления команд и prompt.

1.  Создайте файл с именем `NESSY.md` в корневом каталоге вашего расширения:

    ```markdown
    # Инструкции моего первого расширения

    Вы — опытный помощник разработчика. Когда пользователь просит получить публикации, используйте инструмент `fetch_posts`. Будьте кратки в своих ответах.
    ```

2.  Обновите ваш `nessy-extension.json`, чтобы сообщить CLI загружать этот файл:

    ```json
    {
      "name": "my-first-extension",
      "version": "1.0.0",
      "contextFileName": "NESSY.md",
      "mcpServers": {
        "nodeServer": {
          "command": "node",
          "args": ["${extensionPath}${/}dist${/}example.js"],
          "cwd": "${extensionPath}"
        }
      }
    }
    ```

Перезапустите CLI снова. Теперь модель будет иметь контекст из вашего файла `NESSY.md` в каждом сеансе, где активно расширение.

## Шаг 7: Публикация вашего расширения

Когда вы довольны своим расширением, вы можете поделиться им с другими. Два основных способа публикации расширений — через Git-репозиторий или через GitHub Releases. Использование публичного Git-репозитория — самый простой метод.

Для подробных инструкций по обоим методам обратитесь к [руководству по публикации расширений](extension-releasing.md).

- Добавить пользовательские инструменты с MCP-сервером.
- Создать удобные пользовательские команды.
- Добавить пользовательские навыки и субагенты.
- Предоставить постоянный контекст модели.
