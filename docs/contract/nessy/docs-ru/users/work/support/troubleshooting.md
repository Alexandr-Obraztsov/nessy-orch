# Устранение неполадок

Это руководство предоставляет решения распространённых проблем и советы по отладке, включая темы:

- Ошибки аутентификации или входа
- Часто задаваемые вопросы (FAQs)
- Советы по отладке
- Существующие GitHub Issues, похожие на ваш, или создание новых Issues

## Ошибки аутентификации или входа

- **Ошибка: `UNABLE_TO_GET_ISSUER_CERT_LOCALLY`, `UNABLE_TO_VERIFY_LEAF_SIGNATURE` или `unable to get local issuer certificate`**
  - **Причина:** Вы можете находиться в корпоративной сети с фаерволом, который перехватывает и инспектирует SSL/TLS трафик.
  - **Решение:** Nessy CLI автоматически использует встроенный корпоративный CA-сертификат. Если ошибка сохраняется, обратитесь к сетевому администратору или в команду Nessy CLI.

- **Проблема: Невозможно отобразить UI после сбоя аутентификации**
  - **Причина:** Если аутентификация не удалась после выбора типа аутентификации, настройка `security.auth.selectedType` может быть сохранена в `settings.json`. При перезапуске CLI может застрять, пытаясь аутентифицироваться с неудачным типом аутентификации и не отобразить UI.
  - **Решение:** Очистите элемент конфигурации `security.auth.selectedType` в вашем файле `settings.json`:
    - Откройте `~/.nessy/settings.json` (или `./.nessy/settings.json` для специфичных для проекта настроек)
    - Удалите поле `security.auth.selectedType`
    - Перезапустите CLI, чтобы позволить ему снова запросить аутентификацию

## Часто задаваемые вопросы (FAQs)

- **В: Как обновить Nessy CLI до последней версии?**
  - О: Если вы установили его глобально через `npm`, обновите его командой `npm install -g @nestor/nessy-cli@latest`. Если вы скомпилировали его из исходного кода, получите последние изменения из репозитория, а затем пересоберите командой `npm run build`.

- **В: Где хранятся файлы конфигурации или настроек Nessy CLI?**
  - О: Конфигурация Nessy CLI хранится в двух файлах `settings.json`:
    1. В вашем домашнем каталоге: `~/.nessy/settings.json`.
    2. В корневом каталоге вашего проекта: `./.nessy/settings.json`.

    Обратитесь к [Конфигурация Nessy CLI](../configuration/settings.md) для получения дополнительной информации.

- **В: MCP-серверы Т-Банка (Jira, Wiki, GitLab и т.п.) не подключаются, я получаю ошибку `Cannot perform dynamic registration without authorization URL`, хотя `/auth` показывает успешную авторизацию.**
  - **О:** MCP-серверы Т-Банка стартуют через утилиту `dp` (Spirit CLI). Если она не установлена или сильно устарела, Nessy не может их инициализировать — при этом ошибка выглядит как проблема с OAuth и вводит в заблуждение.
  - **Что делать:**
    1. Установите Spirit CLI из SelfService.
    2. В терминале выполните `dp update`. Команда либо ответит «всё актуально», либо обновит бинарь.
    3. Перезапустите Nessy CLI и повторите подключение MCP-серверов.

## Распространённые сообщения об ошибках и решения

- **Ошибка: `EADDRINUSE` (Адрес уже используется) при запуске MCP сервера.**
  - **Причина:** Другой процесс уже использует порт, к которому пытается привязаться MCP сервер.
  - **Решение:**
    Либо остановите другой процесс, использующий порт, либо настройте MCP сервер на использование другого порта.

- **Ошибка: Команда не найдена (при попытке запустить Nessy CLI с `nessy`).**
  - **Причина:** CLI установлен неправильно или его нет в `PATH` вашей системы.
  - **Решение:**
    Обновление зависит от того, как вы установили Nessy CLI:
    - Если вы установили `nessy` глобально, проверьте, что глобальный бинарный каталог `npm` находится в вашем `PATH`. Вы можете обновить командой `npm install -g @nestor/nessy-cli@latest`.
    - Если вы запускаете `nessy` из исходного кода, убедитесь, что используете правильную команду для его вызова (например, `node packages/cli/dist/index.js ...`). Для обновления получите последние изменения из репозитория, а затем пересоберите командой `npm run build`.

- **Ошибка: `MODULE_NOT_FOUND` или ошибки импорта.**
  - **Причина:** Зависимости установлены неправильно или проект не собран.
  - **Решение:**
    1. Запустите `npm install` для обеспечения наличия всех зависимостей.
    2. Запустите `npm run build` для компиляции проекта.
    3. Проверьте, что сборка завершилась успешно с `npm run start`.

- **Ошибка: "Operation not permitted", "Permission denied" или подобное.**
  - **Причина:** Когда песочница включена, Nessy CLI может пытаться выполнить операции, которые ограничены вашей конфигурацией песочницы, такие как запись вне каталога проекта или системного временного каталога.
  - **Решение:** Обратитесь к документации [Конфигурация: Песочница](../features/sandbox.md) для получения дополнительной информации, включая как настроить вашу конфигурацию песочницы.

- **Nessy CLI не работает в интерактивном режиме в окружениях "CI"**
  - **Проблема:** Nessy CLI не входит в интерактивный режим (не появляется подсказка), если установлена переменная окружения, начинающаяся с `CI_` (например, `CI_TOKEN`). Это потому, что пакет `is-in-ci`, используемый базовым UI-фреймворком, обнаруживает эти переменные и предполагает неинтерактивное CI-окружение.
  - **Причина:** Пакет `is-in-ci` проверяет наличие `CI`, `CONTINUOUS_INTEGRATION` или любой переменной окружения с префиксом `CI_`. Когда любая из них найдена, это сигнализирует, что окружение неинтерактивное, что предотвращает запуск CLI в его интерактивном режиме.
  - **Решение:** Если переменная с префиксом `CI_` не нужна для работы CLI, вы можете временно снять её для команды. например, `env -u CI_TOKEN nessy`

- **Режим DEBUG не работает из файла .env проекта**
  - **Проблема:** Установка `DEBUG=true` в файле `.env` проекта не включает режим отладки для CLI.
  - **Причина:** Переменные `DEBUG` и `DEBUG_MODE` автоматически исключаются из файлов `.env` проекта для предотвращения вмешательства в поведение CLI.
  - **Решение:** Используйте файл `.nessy/.env` вместо этого или настройте параметр `advanced.excludedEnvVars` в вашем `settings.json` для исключения меньшего количества переменных.

## Коды выхода

Nessy CLI использует специфичные коды выхода для указания причины завершения. Это особенно полезно для скриптов и автоматизации.

| Код выхода | Тип ошибки                 | Описание                                                                                           |
| ---------- | -------------------------- | -------------------------------------------------------------------------------------------------- |
| 41         | `FatalAuthenticationError` | Произошла ошибка во время процесса аутентификации.                                                 |
| 42         | `FatalInputError`          | Был предоставлен некорректный или отсутствующий ввод CLI. (только неинтерактивный режим)           |
| 44         | `FatalSandboxError`        | Произошла ошибка с окружением песочницы (например, Docker, Podman или Seatbelt).                   |
| 52         | `FatalConfigError`         | Файл конфигурации (`settings.json`) некорректен или содержит ошибки.                               |
| 53         | `FatalTurnLimitedError`    | Достигнуто максимальное количество разговорных оборотов для сессии. (только неинтерактивный режим) |

## Советы по отладке

- **Отладка CLI:**
  - Используйте флаг `--verbose` (если доступен) с командами CLI для более детального вывода.
  - Проверьте логи CLI, часто находящиеся в специфичном для пользователя конфигурационном или кэш-каталоге.

- **Отладка core:**
  - Проверьте вывод консоли сервера на наличие сообщений об ошибках или трассировок стека.
  - Увеличьте детализацию логирования, если настраиваемо.
  - Используйте инструменты отладки Node.js (например, `node --inspect`), если вам нужно пошагово пройти серверный код.

- **Проблемы с инструментами:**
  - Если конкретный инструмент не работает, попробуйте изолировать проблему, запустив простейшую версию команды или операции, которую выполняет инструмент.
  - Для `run_shell_command` сначала проверьте, что команда работает напрямую в вашей оболочке.
  - Для _инструментов файловой системы_ проверьте, что пути корректны и проверьте разрешения.

- **Пре-полётные проверки:**
  - Всегда запускайте `npm run preflight` перед коммитом кода. Это может поймать много распространённых проблем, связанных с форматированием, линтингом и ошибками типов.

## Сбор диагностики

При обращении по проблеме с Nessy CLI Desktop прикладывайте отчёт диагностики, сформированный на затронутой машине. Выполните соответствующую команду ниже и прикрепите полученный файл `nessy-*-diagnostics-<timestamp>.txt`.

**macOS** (скачивает и запускает коллектор напрямую из S3, установка не требуется):

```bash
curl -fsSL https://s3-msk.tinkoff.ru/nestor-companion/diagnostic/collect-macos-diagnostics.sh | bash
# чтобы сохранить отчёт по конкретному пути:
curl -fsSL https://s3-msk.tinkoff.ru/nestor-companion/diagnostic/collect-macos-diagnostics.sh | bash -s -- --output /tmp/nessy-diagnostics.txt
```

**Windows** (PowerShell):

```powershell
$f="$env:TEMP\nessy-diagnostics.ps1"; irm "https://s3-msk.tinkoff.ru/nestor-companion/diagnostic/collect-windows-diagnostics.ps1" -OutFile $f; powershell.exe -NoProfile -ExecutionPolicy Bypass -File $f
```

> **Внимание:** отчёт может содержать токены, пароли, приватные URL, значения окружения, пользовательские пути и другие секреты. Передавайте его только доверенным сотрудникам поддержки Nessy CLI.

## Обновление стандартного расширения без отдельного Nessy CLI

Если вы используете Nessy CLI Desktop и у вас не установлен отдельный `nessy` CLI в `PATH`, вы всё равно можете обновить встроенное `nessy-default-extension`, запустив обновление через Bun и `cli.js`, входящие в состав Desktop-приложения. Скрипт ниже находит установку, определяет встроенные Bun и CLI и выполняет `extensions update nessy-default-extension` в синхронном режиме, чтобы итоговый результат был виден.

**macOS** (скачивает и запускает напрямую из S3, установка не требуется):

```bash
curl -fsSL https://s3-msk.tinkoff.ru/nestor-companion/diagnostic/update-default-extension.sh | bash
```

**Windows** (PowerShell):

```powershell
$f="$env:TEMP\update-default-extension.ps1"; irm "https://s3-msk.tinkoff.ru/nestor-companion/diagnostic/update-default-extension.ps1" -OutFile $f; powershell.exe -NoProfile -ExecutionPolicy Bypass -File $f
```

> **Примечание:** при первом запуске может появиться строка прогресса `bufferutil [1/1]` во время подготовки зависимостей расширения. Это нормально — дождитесь завершения скрипта. Сообщение `Extension "nessy-default-extension" is already up to date.` означает, что расширение уже актуально; `... successfully updated: X → Y` — что обновление применено.
