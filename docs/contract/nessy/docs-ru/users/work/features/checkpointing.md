# Чекпоинты (Checkpointing)

Nessy CLI включает функцию чекпоинтов, которая автоматически сохраняет снимок состояния вашего проекта перед любыми изменениями файлов, сделанными AI-инструментами. Это позволяет вам безопасно экспериментировать и применять изменения кода, зная, что вы можете мгновенно откатиться к состоянию перед запуском инструмента.

## Как это работает

Когда вы утверждаете инструмент, который изменяет файловую систему (например, `write_file` или `edit`), CLI автоматически создаёт "чекпоинт". Этот чекпоинт включает:

1.  **Git-снимок**: Коммит делается в специальном, теневом Git-репозитории, расположенном в вашей домашней директории (`~/.nessy/history/<project_hash>`). Этот снимок захватывает полное состояние файлов вашего проекта в этот момент. Он **не** вмешивается в ваш собственный Git-репозиторий проекта.
2.  **История разговора**: Весь разговор, который вы вели с агентом до этого момента, сохраняется.
3.  **Вызов инструмента**: Специфический вызов инструмента, который должен был быть выполнен, также сохраняется.

Если вы хотите отменить изменение или просто вернуться назад, вы можете использовать команду `/restore`. Восстановление чекпоинта будет:

- Откатывать все файлы в вашем проекте к состоянию, захваченному в снимке.
- Восстанавливать историю разговора в CLI.
- Повторно предлагать оригинальный вызов инструмента, позволяя вам запустить его снова, изменить или просто проигнорировать.

Все данные чекпоинта, включая Git-снимок и историю разговора, хранятся локально на вашей машине. Git-снимок хранится в теневом репозитории, в то время как история разговора и вызовы инструментов сохраняются в JSON-файле во временной директории вашего проекта, обычно расположенной в `~/.nessy/tmp/<project_hash>/checkpoints`.

## Включение функции

Функция чекпоинтов отключена по умолчанию. Чтобы включить её, вы можете использовать флаг командной строки или отредактировать файл `settings.json`.

### Использование флага командной строки

Вы можете включить чекпоинты для текущей сессии, используя флаг `--checkpointing` при запуске Nessy CLI:

```bash
nessy --checkpointing
```

### Использование файла `settings.json`

Чтобы включить чекпоинты по умолчанию для всех сессий, вам нужно отредактировать файл `settings.json`.

Добавьте следующий ключ в ваш `settings.json`:

```json
{
  "general": {
    "checkpointing": {
      "enabled": true
    }
  }
}
```

## Использование команды `/restore`

После включения чекпоинты создаются автоматически. Для управления ими используйте команду `/restore`.

### Список доступных чекпоинтов

Чтобы увидеть список всех сохранённых чекпоинтов для текущего проекта, просто запустите:

```
/restore
```

CLI отобразит список доступных файлов чекпоинтов. Эти имена файлов обычно состоят из временной метки, имени изменяемого файла и имени инструмента, который должен был быть запущен (например, `2025-06-22T10-00-00_000Z-my-file.txt-write_file`).

### Восстановление конкретного чекпоинта

Чтобы восстановить ваш проект к конкретному чекпоинту, используйте файл чекпоинта из списка:

```
/restore <checkpoint_file>
```

Например:

```
/restore 2025-06-22T10-00-00_000Z-my-file.txt-write_file
```

После запуска команды ваши файлы и разговор будут немедленно восстановлены к состоянию, в котором они были при создании чекпоинта, и оригинальная подсказка инструмента появится снова.
