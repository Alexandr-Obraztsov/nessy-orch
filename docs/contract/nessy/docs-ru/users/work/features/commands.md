# Команды

Этот документ детализирует все команды, поддерживаемые Nessy CLI, помогая вам эффективно управлять сессиями, настраивать интерфейс и контролировать его поведение.

Команды Nessy CLI запускаются через специфичные префиксы и делятся на три категории:

| Тип префикса              | Описание функции                                          | Типичный случай использования                                    |
| ------------------------- | --------------------------------------------------------- | ---------------------------------------------------------------- |
| Slash-команды (`/`)       | Мета-уровень управления самим Nessy CLI                   | Управление сессиями, изменение настроек, получение помощи        |
| At-команды (`@`)          | Быстрое внедрение содержимого локальных файлов в разговор | Позволяет ИИ анализировать указанные файлы или код в каталогах   |
| Exclamation-команды (`!`) | Прямое взаимодействие с системной оболочкой               | Выполнение системных команд, таких как `git status`, `ls` и т.д. |

## 1. Slash-команды (`/`)

Slash-команды используются для управления сессиями Nessy CLI, интерфейсом и базовым поведением.

### 1.6 Побочный вопрос (`/btw`)

Команда `/btw` позволяет задавать быстрые побочные вопросы, не прерывая и не влияя на основной поток разговора.

| Команда             | Описание                                       |
| ------------------- | ---------------------------------------------- |
| `/btw <ваш вопрос>` | Задать быстрый побочный вопрос                 |
| `?btw <ваш вопрос>` | Альтернативный синтаксис для побочных вопросов |

**Как это работает:**

- Побочный вопрос отправляется как отдельный API-вызов с недавним контекстом разговора (до последних 20 сообщений)
- Ответ отображается над Composer — вы можете продолжать печатать во время ожидания
- Основной разговор **не заблокирован** — он продолжается независимо
- Ответ на побочный вопрос **не** становится частью основной истории разговора
- Ответы рендерятся с полной поддержкой Markdown (блоки кода, списки, таблицы и т.д.)

**Горячие клавиши (интерактивный режим):**

| Горячая клавиша       | Действие                                                      |
| --------------------- | ------------------------------------------------------------- |
| `Escape`              | Отменить (во время загрузки) или отклонить (после завершения) |
| `Space` или `Enter`   | Отклонить ответ (когда ввод пуст)                             |
| `Ctrl+C` или `Ctrl+D` | Отменить побочный вопрос в полете                             |

**Пример:**

```
(Пока основной разговор о рефакторинге кода)

> /btw В чём разница между let и var в JavaScript?

  ╭──────────────────────────────────────────────╮
  │ /btw В чём разница между let                 │
  │     и var в JavaScript?                      │
  │                                              │
  │ + Ответ...                                   │
  │ Нажмите Escape, Ctrl+C или Ctrl+D для отмены │
  ╰──────────────────────────────────────────────╯
  > (Composer остаётся активным — продолжайте печатать)

(После получения ответа)

  ╭───────────────────────────────────────────────────────────╮
  │ /btw В чём разница между let                              │
  │     и var в JavaScript?                                   │
  │                                                           │
  │ `let` имеет блочную область видимости, а `var`            │
  │ имеет область видимости функции. `let` был представлен    │
  │ в ES6 и не поднимается (hoist) так же.                    │
  │                                                           │
  │ Нажмите Space, Enter или Escape для отклонения            │
  ╰───────────────────────────────────────────────────────────╯
  > (Composer всё ещё активен)
```

**Поддерживаемые режимы выполнения:**

| Режим                | Поведение                                            |
| -------------------- | ---------------------------------------------------- |
| Интерактивный        | Показывает над Composer с рендерингом Markdown       |
| Неинтерактивный      | Возвращает текстовый результат: `btw> вопрос\nответ` |
| ACP (Agent Protocol) | Возвращает async generator stream_messages           |

:::tip
Используйте `/btw`, когда вам нужен быстрый ответ без отвлечения от основной задачи. Это особенно полезно для уточнения концепций, проверки фактов или получения быстрых объяснений, оставаясь сфокусированным на основном рабочем процессе.
:::

### 1.7 Пересказ сессии (`/recap`)

Команда `/recap` генерирует краткое резюме «где вы остановились» для текущей сессии, чтобы вы могли возобновить старый разговор без прокрутки страниц истории.

| Команда  | Описание                                         |
| -------- | ------------------------------------------------ |
| `/recap` | Сгенерировать и показать краткий пересказ сессии |

**Как это работает:**

- Использует настроенную быструю модель (настройка `fastModel`), когда доступна, с запасным вариантом основной модели сессии. Достаточно небольшой, дешёвой модели для пересказа.
- Недавний разговор (до 30 сообщений, только текст — вызовы инструментов и ответы инструментов отфильтровываются) отправляется модели с плотным системным промптом.
- Пересказ отображается тусклым цветом с префиксом `❯`, чтобы он отличался от реальных ответов ассистента.
- Отказывается с встроенной ошибкой, если ход модели в процессе или другая команда обрабатывается. Если нет полезного разговора или базовая генерация не удаётся, `/recap` показывает короткое информационное сообщение вместо пересказа — ручная команда всегда отвечает чем-то.

**Авто-триггер при возвращении после отсутствия:**

Если терминал размыт на **5+ минут** и снова получает фокус, пересказ генерируется и показывается автоматически (только когда ответ модели не в процессе; иначе ждёт завершения текущего хода и затем запускается). В отличие от ручной команды, авто-триггер полностью молчалив при неудаче: если генерация выдаёт ошибку или нечего резюмировать, сообщение не добавляется в историю. Управляется настройкой `general.showSessionRecap` (по умолчанию: `true`); ручная команда `/recap` всегда работает независимо от этой настройки.

**Пример:**

```
> /recap

❯ Рефакторинг loopDetectionService.ts для устранения OOM в длинных сессиях, вызванного неограниченным streamContentHistory и contentStats. Следующий шаг — реализовать опцию B (LRU скользящее окно с FNV-1a) в ожидании подтверждения.
```

:::tip
Настройте быструю модель через `/model --fast <model>` (например, `qwen3-coder-flash`), чтобы сделать `/recap` быстрым и дешёвым. Установите `general.showSessionRecap` в `false`, чтобы отказаться от авто-триггера, сохранив ручную команду доступной.
:::

### 1.10 Использование квот (`/quota`)

Команда `/quota` показывает текущие лимиты использования LLM для вашей учётной записи. Она доступна, когда Nessy CLI использует DP Auth.

| Команда  | Описание                                       |
| -------- | ---------------------------------------------- |
| `/quota` | Показать все активные квоты для учётной записи |

Для каждой квоты выводятся:

- название и необязательное описание;
- процент использования и индикатор прогресса;
- текущее состояние доступности;
- дата и время сброса, если они переданы бэкендом;
- тип и значения области действия, например учётная запись, модель или режим.

Подробная информация о квотах сейчас выводится на русском языке независимо от выбранного языка интерфейса.

**Поддерживаемые режимы выполнения:**

| Режим                | Поведение                                                  |
| -------------------- | ---------------------------------------------------------- |
| Интерактивный        | Показывает каждую квоту с цветовым обозначением состояния  |
| Неинтерактивный      | Возвращает сведения о квотах в виде обычного текста        |
| ACP (Agent Protocol) | Передаёт сведения о квотах в подключённую среду разработки |

В интерактивном режиме Nessy CLI также проверяет квоты при запуске новой сессии и после завершённых ответов модели. Короткое уведомление появляется, когда квота впервые приближается к лимиту или исчерпана. Оно не повторяется, пока наблюдаемое состояние квоты не изменится. При запуске новой сессии состояние уведомлений сбрасывается, поэтому актуальное предупреждение может быть показано в ней один раз. Выполните `/quota` в любой момент, чтобы посмотреть подробную информацию.

:::note
Команда `/quota` недоступна для методов аутентификации, отличных от DP Auth.
:::

## 2. @ Команды (Введение файлов)

@ команды используются для быстрого добавления содержимого локального файла или каталога в разговор.

| Формат команды       | Описание                                            | Примеры                                                   |
| -------------------- | --------------------------------------------------- | --------------------------------------------------------- |
| `@<путь к файлу>`    | Внедрить содержимое указанного файла                | `@src/main.py Пожалуйста, объясните этот код`             |
| `@<путь к каталогу>` | Рекурсивно прочитать все текстовые файлы в каталоге | `@docs/ Резюмируйте содержимое этого документа`           |
| Одиночный `@`        | Используется при обсуждении самого символа `@`      | `@ Для чего этот символ используется в программировании?` |

Примечание: Пробелы в путях должны быть экранированы обратной косой чертой (например, `@My\ Documents/file.txt`)

## 3. Exclamation-команды (`!`) - Выполнение команд оболочки

Exclamation-команды позволяют выполнять системные команды напрямую внутри Nessy CLI.

| Формат команды        | Описание                                                                         | Примеры                               |
| --------------------- | -------------------------------------------------------------------------------- | ------------------------------------- |
| `!<команда оболочки>` | Выполнить команду в под-оболочке                                                 | `!ls -la`, `!git status`              |
| Одиночный `!`         | Переключить режим оболочки, любой ввод выполняется напрямую как команда оболочки | `!`(ввод) → Ввод команды → `!`(выход) |

Переменные окружения: Команды, выполненные через `!`, установят переменную окружения `NESSY_CLI=1`.

## 4. Пользовательские команды

Сохраняйте часто используемые подсказки как короткими команды для повышения эффективности работы и обеспечения согласованности.

:::note
Пользовательские команды теперь используют формат Markdown с опциональным YAML frontmatter. Формат TOML устарел, но всё ещё поддерживается для обратной совместимости. При обнаружении TOML файлов будет отображена подсказка об автоматической миграции.
:::

### Краткий обзор

| Функция            | Описание                                        | Преимущества                                    | Приоритет | Применимые сценарии                                                 |
| ------------------ | ----------------------------------------------- | ----------------------------------------------- | --------- | ------------------------------------------------------------------- |
| Пространство имён  | Подкаталог создаёт команды с двоеточием в имени | Лучшая организация команд                       |           |                                                                     |
| Глобальные команды | `~/.nessy/commands/`                            | Доступно во всех проектах                       | Низкий    | Личные часто используемые команды, межпроектное использование       |
| Проектные команды  | `<корневой каталог проекта>/.nessy/commands/`   | Специфичные для проекта, контролируемые версией | Высокий   | Командное совместное использование, специфичные для проекта команды |

Правила приоритета: Проектные команды > Пользовательские команды (проектная команда используется при одинаковых именах)

### Правила именования команд

#### Таблица соответствия пути файла имени команды

| Расположение файла                       | Сгенерированная команда | Пример вызова           |
| ---------------------------------------- | ----------------------- | ----------------------- |
| `~/.nessy/commands/test.md`              | `/test`                 | `/test Параметр`        |
| `<проект>/.nessy/commands/git/commit.md` | `/git:commit`           | `/git:commit Сообщение` |

Правила именования: Разделитель путей (`/` или `\`) преобразуется в двоеточие (`:`)

### Спецификация формата файлов Markdown (рекомендуется)

Пользовательские команды используют файлы Markdown с опциональным YAML frontmatter:

```markdown
---
description: Опциональное описание (отображается в /help)
---

Содержимое вашей подсказки здесь.
Используйте {{args}} для внедрения параметров.
```

| Поле           | Обязательно | Описание                                  | Пример                                      |
| -------------- | ----------- | ----------------------------------------- | ------------------------------------------- |
| `description`  | Опционально | Описание команды (отображается в /help)   | `description: Инструмент анализа кода`      |
| Тело подсказки | Обязательно | Содержимое подсказки, отправляемое модели | Любое содержимое Markdown после frontmatter |

### Формат файлов TOML (устарел)

:::warning
**Устарел:** Формат TOML всё ещё поддерживается, но будет удалён в будущей версии. Пожалуйста, мигрируйте на формат Markdown.
:::

| Поле          | Обязательно | Описание                                  | Пример                                               |
| ------------- | ----------- | ----------------------------------------- | ---------------------------------------------------- |
| `prompt`      | Обязательно | Содержимое подсказки, отправляемое модели | `prompt = "Пожалуйста, проанализируй код: {{args}}"` |
| `description` | Опционально | Описание команды (отображается в /help)   | `description = "Инструмент анализа кода"`            |

### Механизм обработки параметров

| Метод обработки                   | Синтаксис             | Применимые сценарии                    | Особенности безопасности                  |
| --------------------------------- | --------------------- | -------------------------------------- | ----------------------------------------- |
| Внедрение с учётом контекста      | `{{args}}`            | Нужен точный контроль параметров       | Автоматическое экранирование Shell        |
| Обработка параметров по умолчанию | Без специальных меток | Простые команды, добавление параметров | Добавление как есть                       |
| Внедрение команд Shell            | `!{command}`          | Нужно динамическое содержимое          | Требуется подтверждение перед выполнением |

#### 1. Внедрение с учётом контекста (`{{args}}`)

| Сценарий        | Конфигурация TOML                      | Способ вызова            | Фактический эффект             |
| --------------- | -------------------------------------- | ------------------------ | ------------------------------ |
| Сырое внедрение | `prompt = "Исправить: {{args}}"`       | `/fix "Проблема кнопки"` | `Исправить: "Проблема кнопки"` |
| В команде Shell | `prompt = "Поиск: !{grep {{args}} .}"` | `/search "hello"`        | Выполнить `grep "hello" .`     |

#### 2. Обработка параметров по умолчанию

| Ситуация ввода | Метод обработки                                              | Пример                                          |
| -------------- | ------------------------------------------------------------ | ----------------------------------------------- |
| Есть параметры | Добавить в конец подсказки (разделено двумя разрывами строк) | `/cmd параметр` → Исходная подсказка + параметр |
| Нет параметров | Отправить подсказку как есть                                 | `/cmd` → Исходная подсказка                     |

🚀 Внедрение динамического содержимого

| Тип внедрения     | Синтаксис         | Порядок обработки         | Назначение                                   |
| ----------------- | ----------------- | ------------------------- | -------------------------------------------- |
| Содержимое файла  | `@{путь к файлу}` | Обрабатывается первым     | Внедрить статические файлы ссылок            |
| Команды Shell     | `!{command}`      | Обрабатывается посередине | Внедрить результаты динамического выполнения |
| Замена параметров | `{{args}}`        | Обрабатывается последним  | Внедрить параметры пользователя              |

#### 3. Выполнение команд Shell (`!{...}`)

| Операция                              | Взаимодействие с пользователем |
| ------------------------------------- | ------------------------------ |
| 1. Разобрать команду и параметры      | -                              |
| 2. Автоматическое экранирование Shell | -                              |
| 3. Показать диалог подтверждения      | ✅ Подтверждение пользователя  |
| 4. Выполнить команду                  | -                              |
| 5. Внедрить вывод в подсказку         | -                              |

Пример: Генерация сообщения коммита Git

````markdown
---
description: Генерировать сообщение коммита на основе staged изменений
---

Пожалуйста, сгенерируй сообщение коммита на основе следующего diff:

```diff
!{git diff --staged}
```
````

#### 4. Внедрение содержимого файла (`@{...}`)

| Тип файла       | Статус поддержки               | Метод обработки                   |
| --------------- | ------------------------------ | --------------------------------- |
| Текстовые файлы | ✅ Полная поддержка            | Прямое внедрение содержимого      |
| Изображения/PDF | ✅ Поддержка мультимодальности | Кодировать и внедрить             |
| Бинарные файлы  | ⚠️ Ограниченная поддержка      | Может быть пропущено или обрезано |
| Каталог         | ✅ Рекурсивное внедрение       | Следовать правилам .gitignore     |

Пример: Команда ревью кода

```markdown
---
description: Ревью кода на основе лучших практик
---

Ревью {{args}}, справочные стандарты:

@{docs/code-standards.md}
```

### Практический пример создания

#### Таблица шагов создания команды "Рефакторинг в чистую функцию"

| Операция                            | Команда/Код                                |
| ----------------------------------- | ------------------------------------------ |
| 1. Создать структуру каталогов      | `mkdir -p ~/.nessy/commands/refactor`      |
| 2. Создать файл команды             | `touch ~/.nessy/commands/refactor/pure.md` |
| 3. Редактировать содержимое команды | См. полный код ниже.                       |
| 4. Протестировать команду           | `@file.js` → `/refactor:pure`              |

```markdown
---
description: Рефакторинг кода в чистую функцию
---

Пожалуйста, проанализируй код в текущем контексте, рефакторируй в чистую функцию.
Требования:

1. Предоставь рефакторенный код
2. Объясни ключевые изменения и реализацию характеристик чистой функции
3. Сохрани функцию неизменной
```

## 5. CLI-подкоманды

### Управление сессиями

```bash
nessy sessions list
nessy sessions list --limit 50
nessy sessions list --format json
```

По умолчанию выводятся последние 20 сессий; лимит и JSON-формат удобны для
скриптов.

| Механизм безопасности    | Эффект защиты                   | Операция пользователя         |
| ------------------------ | ------------------------------- | ----------------------------- |
| Экранирование Shell      | Предотвратить внедрение команд  | Автоматическая обработка      |
| Подтверждение выполнения | Избегать случайного выполнения  | Подтверждение диалогом        |
| Отчёт об ошибках         | Помочь диагностировать проблемы | Просмотр информации об ошибке |
