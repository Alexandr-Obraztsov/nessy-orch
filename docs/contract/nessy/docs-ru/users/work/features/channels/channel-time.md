# Channel Time

Это руководство описывает настройку канала Nessy CLI на платформе Channel Time (совместимой с Mattermost).

## Предварительные требования

- Сервер Channel Time с доступом к API
- Учётная запись бота или персональный токен доступа (см. ниже)

## Создание учётной записи бота

1. Перейдите в **System Console** > **Integrations** > **Bot Accounts** и включите создание учётных записей ботов
2. Перейдите в **Integrations** > **Bot Accounts** > **Add Bot Account**
3. Заполните данные бота (имя пользователя, отображаемое имя, описание) и создайте его
4. Скопируйте сгенерированный токен доступа — сохраните его в надёжном месте

## Поиск идентификаторов пользователей

Для использования `senderPolicy: "allowlist"` требуются идентификаторы пользователей Channel Time:

1. Откройте **System Console** > **Users** и найдите нужного пользователя
2. Нажмите на его профиль — идентификатор пользователя отображается в URL и деталях профиля
3. Идентификаторы пользователей представляют собой 26-символьные альфанумерические строки (например, `dkh8tozwwfnudqfwtbh61pur8y`)

## Конфигурация

Добавьте канал в `~/.nessy/settings.json`:

```json
{
  "channels": {
    "my-ct": {
      "type": "time",
      "serverUrl": "$CT_SERVER_URL",
      "token": "$CT_BOT_TOKEN",
      "senderPolicy": "allowlist",
      "allowedUsers": ["YOUR_USER_ID"],
      "sessionScope": "thread",
      "cwd": "/path/to/your/project",
      "instructions": "You are a concise coding assistant. Keep responses short.",
      "groupPolicy": "disabled",
      "groups": {
        "*": { "requireMention": true }
      }
    }
  }
}
```

Задайте переменные окружения:

```bash
export CT_SERVER_URL=https://time.tbank.ru
export CT_BOT_TOKEN=<your-bot-access-token>
```

### Опции канала

| Опция       | Обязательна | Описание                                                                                               |
| ----------- | ----------- | ------------------------------------------------------------------------------------------------------ |
| `serverUrl` | Да          | Полный URL сервера Channel Time (например, `https://time.tbank.ru`). Поддерживает синтаксис `$ENV_VAR` |
| `token`     | Да          | Токен доступа бота или персональный токен доступа. Поддерживает синтаксис `$ENV_VAR`                   |

## Запуск

```bash
# Запустить только канал Channel Time
nessy channel start my-ct

# Или запустить все настроенные каналы одновременно
nessy channel start
```

Затем отправьте личное сообщение боту в Channel Time. Вы увидите индикатор набора текста и реакцию «глаза», пока агент обрабатывает запрос, после чего последует ответ.

## Групповые чаты / публичные каналы

Для использования бота в каналах Channel Time:

1. Установите для `groupPolicy` значение `"allowlist"` или `"open"` в конфигурации канала
2. Добавьте бота в нужный канал (или пригласите его)
3. При использовании `groupPolicy: "allowlist"` добавьте идентификатор канала в `groups` в вашей конфигурации
4. По умолчанию бот требует @mention для ответа в каналах. Установите `"requireMention": false` для конкретных каналов, чтобы он отвечал на все сообщения

```json
{
  "groupPolicy": "open",
  "groups": {
    "*": { "requireMention": true },
    "specific-channel-id": { "requireMention": false }
  }
}
```

### Поиск идентификатора канала

Чтобы найти идентификатор канала для allowlist:

1. Откройте канал в Channel Time
2. Нажмите на название канала вверху, чтобы открыть детали канала

## Потоки (Threads)

Channel Time нативно поддерживает потоки сообщений. Адаптер автоматически:

- Определяет, когда сообщение является ответом в потоке
- Отвечает в том же потоке, что и исходное сообщение
- Создаёт отдельные сессии агента для каждого потока при настроенном `sessionScope: "thread"` (рекомендуется)

Это делает `sessionScope: "thread"` естественным выбором для Channel Time — каждый поток разговора получает собственный изолированный контекст агента.

## Изображения и файлы

**Изображения:** Отправьте изображение боту, и агент проанализирует его с помощью возможностей компьютерного зрения. Настройте мультимодальную модель (например, `"model": "qwen3.5-plus"`) для поддержки изображений. Первое изображение передаётся модели напрямую; дополнительные изображения сохраняются как вложения файлов.

**Файлы:** Отправьте любой документ (файлы кода, PDF, текстовые файлы и т.д.). Бот загружает его во временный каталог, чтобы агент мог прочитать его с помощью файловых инструментов. Это работает с любой моделью.

## Индикаторы работы

Пока агент обрабатывает ваше сообщение:

- **Индикатор набора текста** — «Bot is typing...» появляется в чате и обновляется каждые 4 секунды
- **Реакция** — к вашему сообщению добавляется реакция «глаза», которая удаляется после готовности ответа

## Советы

- **Используйте `sessionScope: "thread"`** — естественным образом сопоставляется с потоками Channel Time. Каждый поток получает собственную сессию агента.
- **Ограничьте доступ** — используйте `senderPolicy: "allowlist"` для известных пользователей или `"pairing"` для потока утверждения.
- **Длинные сообщения** — адаптер автоматически разбивает ответы, превышающие 16 383 символа (лимит сообщения Mattermost), по границам абзацев.
- **Markdown** — Channel Time поддерживает стандартный Markdown в сообщениях. Ответы агента отправляются как есть, без преобразования.

## Устранение неполадок

### Бот не отвечает

- Проверьте правильность `serverUrl` и доступность сервера оттуда, где запущен Nessy CLI
- Убедитесь, что токен бота действителен: `curl -H "Authorization: Bearer $CT_BOT_TOKEN" "$CT_SERVER_URL/api/v4/users/me"`
- Проверьте, что ваш идентификатор пользователя добавлен в `allowedUsers`, если используется `senderPolicy: "allowlist"`
- Проверьте вывод терминала на наличие ошибок подключения WebSocket

### Бот не отвечает в каналах

- Убедитесь, что `groupPolicy` установлен в `"allowlist"` или `"open"` (по умолчанию `"disabled"`)
- При использовании `"allowlist"` проверьте, что идентификатор канала указан в конфигурации `groups`
- По умолчанию бот требует @mention. Отправьте `@botusername hello` для проверки

### Частые отключения WebSocket

- Проверьте подключение к сети к серверу Channel Time
- Адаптер автоматически выполняет повторное подключение с экспоненциальной задержкой (до 10 попыток)
- Если отключения продолжаются, проверите конфигурацию WebSocket и таймауты на стороне сервера

### Ошибки «Mattermost API ... 401»

- Токен бота мог истечь или быть отозван
- Сгенерируйте токен заново и обновите переменную окружения
