# Подключение Nessy CLI к инструментам через MCP

Nessy CLI может подключаться к внешним инструментам и источникам данных через [Model Context Protocol (MCP)](https://modelcontextprotocol.io/introduction). MCP серверы дают Nessy CLI доступ к вашим инструментам, базам данных и API.

## Что вы можете делать с MCP

С подключенными MCP серверами вы можете попросить Nessy CLI:

- Работать с файлами и репозиториями (чтение/поиск/запись, в зависимости от включённых инструментов)
- Запрашивать базы данных (инспекция схемы, запросы, отчётность)
- Интегрировать внутренние сервисы (оборачивать ваши API как MCP инструменты)
- Автоматизировать рабочие процессы (повторяемые задачи, представленные как инструменты/подсказки)

:::tip
Если вы ищете «одну команду для начала», перейдите к [Быстрый старт](#быстрый-старт).
:::

## Быстрый старт

Nessy CLI загружает MCP серверы из `mcpServers` в вашем `settings.json`. Вы можете конфигурировать серверы либо:

- Путём редактирования `settings.json` напрямую
- Путём использования команд `nessy mcp` (смотрите [Справочник CLI](#nessy-mcp-cli))

### Добавьте ваш первый сервер

1. Добавьте сервер (пример: удалённый HTTP MCP сервер):

```bash
nessy mcp add --transport http my-server http://localhost:3000/mcp
```

2. Откройте диалог управления MCP для просмотра и управления серверами:

```bash
nessy mcp
```

3. Перезапустите Nessy CLI в том же проекте (или запустите его, если он ещё не работал), затем попросите модель использовать инструменты с этого сервера.

## Где хранится конфигурация (области)

Большинству пользователей нужны только эти две области:

- **Область проекта (по умолчанию)**: `.nessy/settings.json` в корне вашего проекта
- **Пользовательская область**: `~/.nessy/settings.json` во всех проектах на вашей машине

Запись в пользовательскую область:

```bash
nessy mcp add --scope user --transport http my-server http://localhost:3000/mcp
```

:::tip
Для расширенных слоёв конфигурации (системные настройки по умолчанию/системные настройки и правила приоритета) смотрите [Настройки](../configuration/settings.md).
:::

## Конфигурация серверов

### Выбор транспорта

| Транспорт | Когда использовать                                                                  | Поля JSON                                      |
| --------- | ----------------------------------------------------------------------------------- | ---------------------------------------------- |
| `http`    | Рекомендуется для удалённых сервисов; хорошо работает для облачных MCP серверов     | `httpUrl` (+ опционально `headers`)            |
| `sse`     | Устаревшие/неподдерживаемые серверы, которые поддерживают только Server-Sent Events | `url` (+ опционально `headers`)                |
| `stdio`   | Локальный процесс (скрипты, CLI, Docker) на вашей машине                            | `command`, `args` (+ опционально `cwd`, `env`) |

:::note
Если сервер поддерживает оба, предпочитайте **HTTP** вместо **SSE**.
:::

### Конфигурация через `settings.json` или `nessy mcp add`

Оба подхода создают одинаковые записи `mcpServers` в вашем `settings.json` — используйте тот, который вам предпочтительнее.

#### Stdio сервер (локальный процесс)

JSON (`.nessy/settings.json`):

```json
{
  "mcpServers": {
    "pythonTools": {
      "command": "python",
      "args": ["-m", "my_mcp_server", "--port", "8080"],
      "cwd": "./mcp-servers/python",
      "env": {
        "DATABASE_URL": "$DB_CONNECTION_STRING",
        "API_KEY": "${EXTERNAL_API_KEY}"
      },
      "timeout": 15000
    }
  }
}
```

CLI (записывает в область проекта по умолчанию):

```bash
nessy mcp add pythonTools -e DATABASE_URL=$DB_CONNECTION_STRING -e API_KEY=$EXTERNAL_API_KEY \
  --timeout 15000 python -m my_mcp_server --port 8080
```

#### HTTP сервер (удалённый потоковый HTTP)

JSON:

```json
{
  "mcpServers": {
    "httpServerWithAuth": {
      "httpUrl": "http://localhost:3000/mcp",
      "headers": {
        "Authorization": "Bearer your-api-token"
      },
      "timeout": 5000
    }
  }
}
```

CLI:

```bash
nessy mcp add --transport http httpServerWithAuth http://localhost:3000/mcp \
  --header "Authorization: Bearer your-api-token" --timeout 5000
```

#### SSE сервер (удалённый Server-Sent Events)

JSON:

```json
{
  "mcpServers": {
    "sseServer": {
      "url": "http://localhost:8080/sse",
      "timeout": 30000
    }
  }
}
```

CLI:

```bash
nessy mcp add --transport sse sseServer http://localhost:8080/sse --timeout 30000
```

## Прогрессивная доступность и таймауты обнаружения

Nessy CLI обнаруживает MCP серверы в фоновом режиме после того, как UI уже становится
интерактивным. Вы видите первый промпт CLI в течение нескольких сотен
миллисекунд, даже если один из ваших MCP серверов занимает несколько секунд
(или никогда не отвечает), и список инструментов модели обновляется в течение примерно
одного кадра (~16 мс) после завершения каждым сервером рукопожатия обнаружения.

- **Интерактивный режим**: UI появляется немедленно; индикатор статуса MCP в
  нижнем правом углу показывает `N/M MCP servers ready`, пока обнаружение находится
  в процессе. Отправка промпта до завершения MCP просто означает, что модель
  видит инструменты, которые готовы _в этот момент_; последующие промпты видят
  больше инструментов по мере подключения серверов.
- **Неинтерактивный режим** (`--prompt`, stream-json, ACP): Nessy CLI всё ещё
  ожидает завершения обнаружения MCP перед отправкой первого промпта, поэтому
  скриптовые/конвейерные вызовы видят тот же полный набор инструментов, который
  производит легаси-синхронное поведение.

### `discoveryTimeoutMs` для каждого сервера

Каждый MCP сервер получает таймаут только для обнаружения, который ограничивает, как долго
начальное рукопожатие (`connect` + `tools/list` + `prompts/list` +
`resources/list`) может выполняться. Значения по умолчанию:

- **stdio серверы**: 30 с
- **удалённые HTTP/SSE серверы**: 5 с (риск сети выше)

Переопределите для сервера при необходимости:

```jsonc
{
  "mcpServers": {
    "slow-stdio": {
      "command": "node",
      "args": ["./slow-server.js"],
      "discoveryTimeoutMs": 60000,
    },
    "flaky-remote": {
      "httpUrl": "https://example.com/mcp",
      "discoveryTimeoutMs": 10000,
    },
  },
}
```

Существующее поле `timeout` — это **таймаут вызова инструмента** (используется для каждого
запроса `tools/call`, по умолчанию 10 минут) и не зависит от
`discoveryTimeoutMs` — длительный вызов инструмента не является патологией запуска.

## Использование MCP prompts и resources

### Prompts (slash-команды)

Опубликованные сервером prompts доступны как slash-команды. Аргументы можно
передавать позиционно; справка показывает имена и описания аргументов.

### Resources

Resources позволяют серверу предоставлять CLI файлы, схемы и другой контекст по
URI. Nessy загружает ресурс по запросу и передаёт содержимое модели.

Если вам нужно старое синхронное поведение (Nessy CLI ожидает каждый MCP сервер
перед показом любого UI), установите `NESSY_CLI_LEGACY_MCP_BLOCKING=1` в вашем
окружении. Это сохраняется как аварийный выход как минимум на один релиз.

## Безопасность и контроль

### Доверие (пропуск подтверждений)

- **Доверие серверу** (`trust: true`): обходит запросы подтверждения для этого сервера (использовать с осторожностью).

### OAuth-аутентификация

Nessy CLI поддерживает OAuth 2.0 аутентификацию для MCP серверов. Это полезно при доступе к удалённым серверам, требующим аутентификации.

#### Базовое использование

При добавлении MCP сервера с OAuth-учётными данными Nessy CLI автоматически обрабатывает поток аутентификации:

```bash
nessy mcp add --transport sse oauth-server https://api.example.com/sse/ \
  --oauth-client-id your-client-id \
  --oauth-redirect-uri https://your-server.com/oauth/callback \
  --oauth-authorization-url https://provider.example.com/authorize \
  --oauth-token-url https://provider.example.com/token
```

#### Важно: конфигурация URI перенаправления

OAuth-поток требует URI перенаправления, куда провайдер авторизации отправляет код аутентификации.

- **Локальная разработка**: по умолчанию Nessy CLI использует `http://localhost:7777/oauth/callback`. Это работает при запуске Nessy CLI на локальной машине с локальным браузером.

- **Удалённые/облачные развёртывания**: при запуске Nessy CLI на удалённых серверах, облачных IDE или веб-терминалах, перенаправление `localhost` по умолчанию **не сработает**. Вы **должны** настроить `--oauth-redirect-uri` так, чтобы он указывал на общедоступный URL, который может получить OAuth-callback.

Пример для удалённых серверов:

```bash
nessy mcp add --transport sse remote-server https://api.example.com/sse/ \
  --oauth-redirect-uri https://your-remote-server.example.com/oauth/callback
```

#### Ручная конфигурация через settings.json

Вы также можете настроить OAuth, отредактировав `settings.json` напрямую:

```json
{
  "mcpServers": {
    "oauthServer": {
      "url": "https://api.example.com/sse/",
      "oauth": {
        "enabled": true,
        "clientId": "your-client-id",
        "clientSecret": "your-client-secret",
        "authorizationUrl": "https://provider.example.com/authorize",
        "tokenUrl": "https://provider.example.com/token",
        "redirectUri": "https://your-server.com/oauth/callback",
        "scopes": ["read", "write"]
      }
    }
  }
}
```

Свойства конфигурации OAuth:

| Свойство           | Описание                                                                                                                                     |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `enabled`          | Включить OAuth для этого сервера (boolean)                                                                                                   |
| `clientId`         | Идентификатор OAuth-клиента (string, опционально при динамической регистрации)                                                               |
| `clientSecret`     | Секрет OAuth-клиента (string, опционально для публичных клиентов)                                                                            |
| `authorizationUrl` | Конечная точка авторизации OAuth (string, автообнаружение, если опущено)                                                                     |
| `tokenUrl`         | Конечная точка токена OAuth (string, автообнаружение, если опущено)                                                                          |
| `scopes`           | Требуемые OAuth-области (массив строк)                                                                                                       |
| `redirectUri`      | Пользовательский URI перенаправления (string). **Критично для удалённых развёртываний**. По умолчанию `http://localhost:7777/oauth/callback` |
| `tokenParamName`   | Имя параметра запроса для токенов в SSE URLs (string)                                                                                        |
| `audiences`        | Аудитории, для которых действителен токен (массив строк)                                                                                     |

#### Управление токенами

OAuth-токены автоматически:

- **Хранятся безопасно** в `~/.nessy/mcp-oauth-tokens.json`
- **Обновляются** при истечении срока действия (если доступны refresh-токены)
- **Проверяются** перед каждой попыткой подключения

Используйте команду `/mcp auth` внутри Nessy CLI для интерактивного управления OAuth-аутентификацией.

### Фильтрация инструментов (разрешить/запретить инструменты для каждого сервера)

Используйте `includeTools` / `excludeTools` для ограничения инструментов, предоставляемых сервером (с точки зрения Nessy CLI).

Пример: включить только несколько инструментов:

```json
{
  "mcpServers": {
    "filteredServer": {
      "command": "python",
      "args": ["-m", "my_mcp_server"],
      "includeTools": ["safe_tool", "file_reader", "data_processor"],
      "timeout": 30000
    }
  }
}
```

### Глобальные списки разрешения/запрета

Объект `mcp` в вашем `settings.json` определяет глобальные правила для всех MCP серверов:

- `mcp.allowed`: список разрешённых имён MCP серверов (ключи в `mcpServers`)
- `mcp.excluded`: список запрещённых имён MCP серверов

Пример:

```json
{
  "mcp": {
    "allowed": ["my-trusted-server"],
    "excluded": ["experimental-server"]
  }
}
```

### Автоодобрение вызовов MCP инструментов

MCP инструменты также можно контролировать через `permissions.allow`,
`permissions.ask` и `permissions.deny`. Правила разрешений для MCP используют
формат зарегистрированного имени инструмента:

```text
mcp__<server-name>__<tool-name>
```

Примеры:

```json
{
  "permissions": {
    "allow": [
      "mcp__puppeteer__puppeteer_navigate",
      "mcp__puppeteer__*",
      "mcp__nessy-team-*__team_list_models",
      "mcp__nessy-team-*__*"
    ]
  }
}
```

- `mcp__puppeteer__puppeteer_navigate` разрешает один конкретный MCP инструмент.
- `mcp__puppeteer` или `mcp__puppeteer__*` разрешает все инструменты одного сервера.
- `mcp__nessy-team-*__team_list_models` разрешает один инструмент для динамических
  имён серверов вида `nessy-team-<uuid>`.
- `mcp__nessy-team-*__*` разрешает все инструменты всех подходящих динамических
  серверов.

Когда вы выбираете вариант “always allow” для MCP инструмента, чей сервер
заканчивается UUID, Nessy CLI предлагает и точное нормализованное правило
инструмента, и wildcard-правило для динамического префикса сервера.

## Устранение неполадок

- **Сервер показывает «Disconnected» в `nessy mcp list`**: проверьте правильность URL/команды, затем увеличьте `timeout`.
- **Stdio сервер не запускается**: используйте абсолютный путь к `command` и дважды проверьте `cwd`/`env`.
- **Переменные окружения в JSON не разрешаются**: убедитесь, что они существуют в окружении, где запускается Nessy CLI (окружения оболочки и GUI-приложений могут отличаться).

## Справочник

### Структура `settings.json`

#### Конфигурация конкретного сервера (`mcpServers`)

Добавьте объект `mcpServers` в ваш файл `settings.json`:

```json
// ... файл содержит другие объекты конфигурации
{
  "mcpServers": {
    "serverName": {
      "command": "path/to/server",
      "args": ["--arg1", "value1"],
      "env": {
        "API_KEY": "$MY_API_TOKEN"
      },
      "cwd": "./server-directory",
      "timeout": 30000,
      "trust": false
    }
  }
}
```

Свойства конфигурации:

Обязательные (одно из следующего):

| Свойство  | Описание                                                         |
| --------- | ---------------------------------------------------------------- |
| `command` | Путь к исполняемому файлу для транспорта Stdio                   |
| `url`     | URL конечной точки SSE (например, `"http://localhost:8080/sse"`) |
| `httpUrl` | URL конечной точки потоковой передачи HTTP                       |

Опциональные:

| Свойство               | Тип/По умолчанию                    | Описание                                                                                                                                                                                                                                                                                 |
| ---------------------- | ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `args`                 | array                               | Аргументы командной строки для транспорта Stdio                                                                                                                                                                                                                                          |
| `headers`              | object                              | Пользовательские HTTP заголовки при использовании `url` или `httpUrl`                                                                                                                                                                                                                    |
| `env`                  | object                              | Переменные окружения для процесса сервера. Значения могут ссылаться на переменные окружения, используя синтаксис `$VAR_NAME` или `${VAR_NAME}`                                                                                                                                           |
| `cwd`                  | string                              | Рабочий каталог для транспорта Stdio                                                                                                                                                                                                                                                     |
| `timeout`              | number<br />(по умолчанию: 600,000) | Таймаут запроса в миллисекундах (по умолчанию: 600,000 мс = 10 минут)                                                                                                                                                                                                                    |
| `trust`                | boolean<br />(по умолчанию: false)  | Когда `true`, обходит все подтверждения вызовов инструментов для этого сервера (по умолчанию: `false`)                                                                                                                                                                                   |
| `includeTools`         | array                               | Список имён инструментов для включения из этого MCP сервера. Когда указано, только перечисленные здесь инструменты будут доступны с этого сервера (поведение белого списка). Если не указано, все инструменты сервера включены по умолчанию.                                             |
| `excludeTools`         | array                               | Список имён инструментов для исключения из этого MCP сервера. Инструменты, перечисленные здесь, не будут доступны модели, даже если они предоставлены сервером.<br />Примечание: `excludeTools` имеет приоритет над `includeTools` — если инструмент в обоих списках, он будет исключён. |
| `targetAudience`       | string                              | OAuth Client ID из белого списка в защищённом приложении IAP, к которому вы пытаетесь получить доступ. Используется с `authProviderType: 'service_account_impersonation'`.                                                                                                               |
| `targetServiceAccount` | string                              | Email адрес учётной записи службы Google Cloud для имитации. Используется с `authProviderType: 'service_account_impersonation'`.                                                                                                                                                         |

<a id="nessy-mcp-cli"></a>

### Управление MCP серверами с `nessy mcp`

Вы всегда можете настроить MCP серверы, вручную редактируя `settings.json`, но CLI обычно быстрее.

#### Добавление сервера (`nessy mcp add`)

```bash
nessy mcp add [options] <name> <commandOrUrl> [args...]
```

| Аргумент/Опция              | Описание                                                                    | По умолчанию                           | Пример                                                             |
| --------------------------- | --------------------------------------------------------------------------- | -------------------------------------- | ------------------------------------------------------------------ |
| `<name>`                    | Уникальное имя для сервера.                                                 | —                                      | `example-server`                                                   |
| `<commandOrUrl>`            | Команда для выполнения (для `stdio`) или URL (для `http`/`sse`).            | —                                      | `/usr/bin/python` или `http://localhost:8`                         |
| `[args...]`                 | Опциональные аргументы для команды `stdio`.                                 | —                                      | `--port 5000`                                                      |
| `-s`, `--scope`             | Область конфигурации (пользователь или проект).                             | `project`                              | `-s user`                                                          |
| `-t`, `--transport`         | Тип транспорта (`stdio`, `sse`, `http`).                                    | `stdio`                                | `-t sse`                                                           |
| `-e`, `--env`               | Установить переменные окружения.                                            | —                                      | `-e KEY=value`                                                     |
| `-H`, `--header`            | Установить HTTP заголовки для транспортов SSE и HTTP.                       | —                                      | `-H "X-Api-Key: abc123"`                                           |
| `--timeout`                 | Установить таймаут соединения в миллисекундах.                              | —                                      | `--timeout 30000`                                                  |
| `--trust`                   | Доверять серверу (обходить все запросы подтверждения вызовов инструментов). | — (`false`)                            | `--trust`                                                          |
| `--description`             | Установить описание для сервера.                                            | —                                      | `--description "Local tools"`                                      |
| `--include-tools`           | Разделённый запятыми список инструментов для включения.                     | все инструменты включены               | `--include-tools mytool,othertool`                                 |
| `--exclude-tools`           | Разделённый запятыми список инструментов для исключения.                    | нет                                    | `--exclude-tools mytool`                                           |
| `--oauth-client-id`         | OAuth client ID для аутентификации MCP сервера.                             | —                                      | `--oauth-client-id your-client-id`                                 |
| `--oauth-client-secret`     | OAuth client secret для аутентификации MCP сервера.                         | —                                      | `--oauth-client-secret your-client-secret`                         |
| `--oauth-redirect-uri`      | OAuth redirect URI для callback аутентификации.                             | `http://localhost:7777/oauth/callback` | `--oauth-redirect-uri https://your-server.com/oauth/callback`      |
| `--oauth-authorization-url` | OAuth authorization URL.                                                    | —                                      | `--oauth-authorization-url https://provider.example.com/authorize` |
| `--oauth-token-url`         | OAuth token URL.                                                            | —                                      | `--oauth-token-url https://provider.example.com/token`             |
| `--oauth-scopes`            | OAuth scopes (разделённые запятой).                                         | —                                      | `--oauth-scopes scope1,scope2`                                     |

> Флаги `--oauth-*` применяются только к `--transport sse` и `--transport http`. Комбинирование их с `--transport stdio` отклоняется.

#### Удаление серверов (`nessy mcp remove`)

```bash
nessy mcp remove <name>
```
