# Поддержка Language Server Protocol (LSP)

Nessy CLI предоставляет нативную поддержку Language Server Protocol (LSP), обеспечивая расширенные функции анализа кода, такие как переход к определению, поиск ссылок, диагностика и действия с кодом. Эта интеграция позволяет ИИ-агенту глубже понимать ваш код и предоставлять более точную помощь.

## Обзор

Поддержка LSP в Nessy CLI работает путём подключения к языковым серверам, которые понимают ваш код. Когда вы работаете с TypeScript, Python, Go или другими поддерживаемыми языками, Nessy CLI может автоматически запустить соответствующий языковой сервер и использовать его для:

- Навигации к определениям символов
- Поиска всех ссылок на символ
- Получения информации при наведении (документация, информация о типах)
- Просмотра диагностических сообщений (ошибки, предупреждения)
- Доступа к действиям с кодом (быстрые исправления, рефакторинги)
- Анализа иерархий вызовов

## Быстрый старт

LSP — это экспериментальная функция в Nessy CLI. Вы можете включить её двумя способами:

**Способ 1: Через settings.json (рекомендуется для постоянного включения)**

Добавьте в `~/.nessy/settings.json` или `.nessy/settings.json`:

```json
{
  "experimental": {
    "lsp": true
  }
}
```

**Способ 2: Через флаг командной строки (временно для текущей сессии)**

```bash
nessy --experimental-lsp
```

Для большинства распространённых языков Nessy CLI автоматически обнаружит и запустит соответствующий языковой сервер, если он установлен в вашей системе.

### Необходимые условия

Вам нужно установить языковой сервер для вашего языка программирования:

| Язык                  | Языковой сервер            | Команда установки                                                                       |
| --------------------- | -------------------------- | --------------------------------------------------------------------------------------- |
| TypeScript/JavaScript | typescript-language-server | `npm install -g typescript-language-server typescript`                                  |
| Python                | pylsp                      | `pip install python-lsp-server`                                                         |
| Go                    | gopls                      | `go install golang.org/x/tools/gopls@latest`                                            |
| Rust                  | rust-analyzer              | [Руководство по установке](https://rust-analyzer.github.io/manual.html#installation)    |
| C#                    | csharp-language-server     | `dotnet tool install --global csharp-ls`                                                |
| C/C++                 | clangd                     | Install LLVM/clangd via your package manager                                            |
| Java                  | jdtls                      | Install JDTLS and a JDK                                                                 |
| Kotlin                | kotlin-lsp                 | [Руководство по установке](https://github.com/Kotlin/kotlin-lsp#install-kotlin-lsp-cli) |

## Конфигурация

### Конфигурация C# (csharp-language-server)

Зависимости:

- Должен быть установлен .NET SDK.
- Установите языковой сервер: `dotnet tool install --global csharp-ls`

Пример конфигурации:

```json
{
  "csharp": {
    "command": "csharp-ls",
    "trustRequired": false,
    "extensionToLanguage": {
      ".cs": "csharp",
      ".csx": "csharp",
      ".cshtml": "csharp"
    }
  }
}
```

### Файл `.lsp.json`

Вы можете конфигурировать языковые серверы с помощью файла `.lsp.json` в корне вашего проекта. Это использует формат с ключами языков, описанный в [справочнике конфигурации LSP плагина Claude Code](https://code.claude.com/docs/en/plugins-reference#lsp-servers).

**Базовый формат:**

```json
{
  "typescript": {
    "command": "typescript-language-server",
    "args": ["--stdio"],
    "extensionToLanguage": {
      ".ts": "typescript",
      ".tsx": "typescriptreact",
      ".js": "javascript",
      ".jsx": "javascriptreact"
    }
  }
}
```

### Конфигурация C/C++ (clangd)

Зависимости:

- clangd (LLVM) должен быть установлен и доступен в PATH.
- Для получения точных результатов требуется база данных компиляции (compile_commands.json) или файл compile_flags.txt.

Пример:

```json
{
  "cpp": {
    "command": "clangd",
    "args": [
      "--background-index",
      "--clang-tidy",
      "--header-insertion=iwyu",
      "--completion-style=detailed"
    ]
  }
}
```

### Конфигурация Java (jdtls)

Зависимости:

- JDK установлен и доступен в PATH (java).
- JDTLS установлен и доступен в PATH (jdtls).

Пример:

```json
{
  "java": {
    "command": "jdtls",
    "args": ["-configuration", ".jdtls-config", "-data", ".jdtls-workspace"]
  }
}
```

### Конфигурация Kotlin (kotlin-lsp)

Зависимости:

- JDK установлен и доступен в PATH (java).
- Language Server for Kotlin установлен и доступен в PATH (kotlin-lsp).

Пример:

```json
{
  "kotlin": {
    "command": "kotlin-lsp",
    "args": ["--stdio"],
    "extensionToLanguage": {
      ".kt": "kotlin",
      ".kts": "kotlin"
    },
    "transport": "stdio",
    "initializationOptions": {},
    "settings": {},
    "startupTimeout": 60000,
    "maxRestarts": 3
  }
}
```

### Опции конфигурации

#### Обязательные поля

| Опция     | Тип    | Описание                                             |
| --------- | ------ | ---------------------------------------------------- |
| `command` | string | Команда для запуска LSP сервера (должна быть в PATH) |

#### Опциональные поля

| Опция                   | Тип      | По умолчанию | Описание                                                   |
| ----------------------- | -------- | ------------ | ---------------------------------------------------------- |
| `args`                  | string[] | `[]`         | Аргументы командной строки                                 |
| `transport`             | string   | `"stdio"`    | Тип транспорта: `stdio` или `socket`                       |
| `env`                   | object   | -            | Переменные окружения                                       |
| `initializationOptions` | object   | -            | Опции инициализации LSP                                    |
| `settings`              | object   | -            | Настройки сервера через `workspace/didChangeConfiguration` |
| `extensionToLanguage`   | object   | -            | Сопоставляет расширения файлов идентификаторам языков      |
| `workspaceFolder`       | string   | -            | Переопределение папки рабочего пространства                |
| `startupTimeout`        | number   | `10000`      | Таймаут запуска в миллисекундах                            |
| `shutdownTimeout`       | number   | `5000`       | Таймаут остановки в миллисекундах                          |
| `restartOnCrash`        | boolean  | `false`      | Автоматический перезапуск при сбое                         |
| `maxRestarts`           | number   | `3`          | Максимальное количество попыток перезапуска                |
| `trustRequired`         | boolean  | `true`       | Требуется доверенное рабочее пространство                  |

### Транспорт TCP/Socket

Для серверов, использующих транспорт TCP или Unix socket:

```json
{
  "remote-lsp": {
    "transport": "tcp",
    "socket": {
      "host": "127.0.0.1",
      "port": 9999
    },
    "extensionToLanguage": {
      ".custom": "custom"
    }
  }
}
```

## Доступные операции LSP

Nessy CLI предоставляет функциональность LSP через унифицированный инструмент `lsp`. Вот доступные операции:

### Навигация по коду

#### Переход к определению

Найти, где определён символ.

```
Операция: goToDefinition
Параметры:
  - filePath: Путь к файлу
  - line: Номер строки (1-based)
  - character: Номер столбца (1-based)
```

#### Поиск ссылок

Найти все ссылки на символ.

```
Операция: findReferences
Параметры:
  - filePath: Путь к файлу
  - line: Номер строки (1-based)
  - character: Номер столбца (1-based)
  - includeDeclaration: Включить само объявление (опционально)
```

#### Переход к реализации

Найти реализации интерфейса или абстрактного метода.

```
Операция: goToImplementation
Параметры:
  - filePath: Путь к файлу
  - line: Номер строки (1-based)
  - character: Номер столбца (1-based)
```

### Информация о символах

#### Наведение

Получить документацию и информацию о типе для символа.

```
Операция: hover
Параметры:
  - filePath: Путь к файлу
  - line: Номер строки (1-based)
  - character: Номер столбца (1-based)
```

#### Символы документа

Получить все символы в документе.

```
Операция: documentSymbol
Параметры:
  - filePath: Путь к файлу
```

#### Поиск символов рабочего пространства

Поиск символов по всему рабочему пространству.

```
Операция: workspaceSymbol
Параметры:
  - query: Строка поискового запроса
  - limit: Максимальное количество результатов (опционально)
```

### Иерархия вызовов

#### Подготовка иерархии вызовов

Получить элемент иерархии вызовов в позиции.

```
Операция: prepareCallHierarchy
Параметры:
  - filePath: Путь к файлу
  - line: Номер строки (1-based)
  - character: Номер столбца (1-based)
```

#### Входящие вызовы

Найти все функции, которые вызывают данную функцию.

```
Операция: incomingCalls
Параметры:
  - callHierarchyItem: Элемент из prepareCallHierarchy
```

#### Исходящие вызовы

Найти все функции, которые вызывает данная функция.

```
Операция: outgoingCalls
Параметры:
  - callHierarchyItem: Элемент из prepareCallHierarchy
```

### Диагностика

#### Диагностика файла

Получить диагностические сообщения (ошибки, предупреждения) для файла.

```
Операция: diagnostics
Параметры:
  - filePath: Путь к файлу
```

#### Диагностика рабочего пространства

Получить все диагностические сообщения по всему рабочему пространству.

```
Операция: workspaceDiagnostics
Параметры:
  - limit: Максимальное количество результатов (опционально)
```

### Действия с кодом

#### Получение действий с кодом

Получить доступные действия с кодом (быстрые исправления, рефакторинги) в расположении.

```
Операция: codeActions
Параметры:
  - filePath: Путь к файлу
  - line: Номер начальной строки (1-based)
  - character: Номер начального столбца (1-based)
  - endLine: Номер конечной строки (опционально, по умолчанию line)
  - endCharacter: Номер конечного столбца (опционально, по умолчанию character)
  - diagnostics: Диагностика для получения действий (опционально)
  - codeActionKinds: Фильтр по типу действия (опционально)
```

Типы действий с кодом:

- `quickfix` - Быстрые исправления для ошибок/предупреждений
- `refactor` - Операции рефакторинга
- `refactor.extract` - Извлечь в функцию/переменную
- `refactor.inline` - Встроить функцию/переменную
- `source` - Исходные действия с кодом
- `source.organizeImports` - Организовать импорты
- `source.fixAll` - Исправить все автоматически исправляемые проблемы

## Безопасность

Языковые серверы запускаются только в доверенных рабочих пространствах по умолчанию. Это потому, что языковые серверы работают с разрешениями вашего пользователя и могут выполнять код.

### Управление доверием

- **Доверенное рабочее пространство**: Языковые серверы запускаются автоматически
- **Недоверенное рабочее пространство**: Языковые серверы не запускаются, если `trustRequired: false` не установлено в конфигурации сервера

Чтобы пометить рабочее пространство как доверенное, используйте команду `/trust` или настройте доверенные папки в настройках.

### Переопределение доверия для каждого сервера

Вы можете переопределить требования доверия для конкретных серверов в их конфигурации:

```json
{
  "safe-server": {
    "command": "safe-language-server",
    "args": ["--stdio"],
    "trustRequired": false,
    "extensionToLanguage": {
      ".safe": "safe"
    }
  }
}
```

## Устранение неполадок

### Сервер не запускается

1. **Проверьте, установлен ли сервер**: Запустите команду вручную для проверки
2. **Проверьте PATH**: Убедитесь, что бинарный файл сервера находится в PATH вашей системы
3. **Проверьте доверие рабочего пространства**: Рабочее пространство должно быть доверенным для LSP
4. **Проверьте логи**: Ищите сообщения об ошибках в выводе консоли
5. **Проверьте флаг --experimental-lsp**: Убедитесь, что вы используете флаг при запуске Nessy CLI

### Медленная производительность

1. **Большие проекты**: Рассмотрите возможность исключения `node_modules` и других больших каталогов
2. **Таймаут сервера**: Увеличьте `startupTimeout` в конфигурации сервера для медленных серверов

### Нет результатов

1. **Сервер не готов**: Сервер может всё ещё индексировать
2. **Файл не сохранён**: Сохраните ваш файл, чтобы сервер подхватил изменения
3. **Неправильный язык**: Проверьте, запущен ли правильный сервер для вашего языка

### Отладка

Включите отладочное логирование для просмотра связи LSP:

```bash
DEBUG=lsp* nessy --experimental-lsp
```

Или проверьте руководство по отладке LSP в `packages/cli/LSP_DEBUGGING_GUIDE.md`.

## Совместимость с Claude Code

Nessy CLI поддерживает файлы конфигурации `.lsp.json` в стиле Claude Code в формате с ключами языков, определённом в [справочнике плагинов Claude Code](https://code.claude.com/docs/en/plugins-reference#lsp-servers). Если вы мигрируете с Claude Code, используйте макет с языком в качестве ключа в вашей конфигурации.

### Формат конфигурации

Рекомендуемый формат следует спецификации Claude Code:

```json
{
  "go": {
    "command": "gopls",
    "args": ["serve"],
    "extensionToLanguage": {
      ".go": "go"
    }
  }
}
```

LSP плагины Claude Code также могут предоставлять `lspServers` в `plugin.json` (или ссылочном `.lsp.json`). Nessy CLI загружает эти конфигурации при включении расширения, и они должны использовать тот же формат с ключами языков.

## Лучшие практики

1. **Устанавливайте языковые серверы глобально**: Это обеспечивает их доступность во всех проектах
2. **Используйте специфичные для проекта настройки**: Конфигурируйте опции сервера для каждого проекта при необходимости через `.lsp.json`
3. **Держите серверы обновлёнными**: Регулярно обновляйте ваши языковые серверы для лучших результатов
4. **Доверяйте мудро**: Доверяйте только рабочим пространствам из доверенных источников

## FAQ

### В: Как включить LSP?

Используйте флаг `--experimental-lsp` при запуске Nessy CLI:

```bash
nessy --experimental-lsp
```

### В: Как узнать, какие языковые серверы запущены?

Используйте команду `/lsp status` для просмотра всех настроенных и запущенных языковых серверов.

### В: Могу ли я использовать несколько языковых серверов для одного типа файлов?

Да, но только один будет использоваться для каждой операции. Первый сервер, который вернёт результаты, побеждает.

### В: Работает ли LSP в режиме песочницы?

Языковые серверы запускаются вне песочницы для доступа к вашему коду. Они подлежат управлению доверием рабочего пространства.
