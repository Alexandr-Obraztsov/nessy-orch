# Песочница

Этот документ объясняет, как запускать Nessy CLI внутри песочницы для уменьшения риска, когда инструменты выполняют команды оболочки или модифицируют файлы.

## Необходимые условия

Перед использованием песочницы вам нужно установить и настроить Nessy CLI:

```bash
npm install -g @nestor/nessy-cli
```

Для проверки установки:

```bash
nessy --version
```

## Обзор песочницы

Песочница изолирует потенциально опасные операции (такие как команды оболочки или модификации файлов) от вашей хост-системы, предоставляя барьер безопасности между CLI и вашим окружением.

Преимущества песочницы включают:

- **Безопасность**: Предотвращает случайное повреждение системы или потерю данных.
- **Изоляция**: Ограничивает доступ к файловой системе каталогом проекта.
- **Согласованность**: Обеспечивает воспроизводимые окружения на разных системах.
- **Безопасность**: Уменьшает риск при работе с ненадёжным кодом или экспериментальными командами.

:::note
**Примечание об именовании:** Некоторые переменные окружения, связанные с песочницей, исторически могли использовать префикс `NESSY_*`. Все новые переменные окружения используют префикс `NESSY_*`.
:::

## Методы песочницы

Ваш идеальный метод песочницы может отличаться в зависимости от вашей платформы и предпочитаемого решения контейнеризации.

### 1. macOS Seatbelt (только macOS)

Лёгкая, встроенная песочница с использованием `sandbox-exec`.

**Профиль по умолчанию**: `permissive-open` — ограничивает запись вне каталога проекта, но разрешает большинство других операций и исходящий сетевой доступ.

**Лучше для**: Быстрой песочницы, не требует Docker, сильные ограничения для записи файлов.

### 2. Контейнерная (Docker/Podman)

Кроссплатформенная песочница с полной изоляцией процессов.

По умолчанию Nessy CLI использует опубликованный образ песочницы (настроенный в пакете CLI) и загрузит его по мере необходимости.

Контейнерная песочница монтирует ваше рабочее пространство и каталог `~/.nessy` в контейнер, чтобы аутентификация и настройки сохранялись между запусками.

**Лучше для**: Сильной изоляции на любой ОС, согласованные инструменты внутри известного образа.

### Выбор метода

- **На macOS**:
  - Используйте Seatbelt, когда хотите лёгкую песочницу (рекомендуется для большинства пользователей).
  - Используйте Docker/Podman, когда вам нужна полная Linux userland (например, инструменты, требующие Linux бинарников).
- **На Linux/Windows**:
  - Используйте Docker или Podman.

## Быстрый старт

```bash
# Включить песочницу с флагом команды
nessy -s -p "analyze the code structure"

# Или включить песочницу для вашей shell сессии (рекомендуется для CI / скриптов)
export NESSY_SANDBOX=true   # true автоматически выбирает провайдера (смотрите заметки ниже)
nessy -p "run the test suite"

# Конфигурировать в settings.json
{
  "tools": {
    "sandbox": true
  }
}
```

:::tip
**Заметки о выборе провайдера:**

- На **macOS**, `NESSY_SANDBOX=true` обычно выбирает `sandbox-exec` (Seatbelt), если доступно.
- На **Linux/Windows**, `NESSY_SANDBOX=true` требует, чтобы `docker` или `podman` были установлены.
- Для принудительного выбора провайдера установите `NESSY_SANDBOX=docker|podman|sandbox-exec`.
:::

## Конфигурация

### Включение песочницы (в порядке приоритета)

1. **Переменная окружения**: `NESSY_SANDBOX=true|false|docker|podman|sandbox-exec`
2. **Флаг/аргумент команды**: `-s`, `--sandbox` или `--sandbox=<provider>`
3. **Файл настроек**: `tools.sandbox` в вашем `settings.json` (например, `{"tools": {"sandbox": true}}`).

:::important
Если установлен `NESSY_SANDBOX`, он **переопределяет** флаг CLI и `settings.json`.
:::

### Конфигурация образа песочницы (Docker/Podman)

- **Флаг CLI**: `--sandbox-image <image>`
- **Переменная окружения**: `NESSY_SANDBOX_IMAGE=<image>`

Если вы не установите ни одно из них, Nessy CLI использует образ по умолчанию, настроенный в пакете CLI (например, `ghcr.io/nessylm/nessy:<version>`).

### Профили macOS Seatbelt

Встроенные профили (устанавливаются через переменную окружения `SEATBELT_PROFILE`):

- `permissive-open` (по умолчанию): Ограничения записи, сеть разрешена
- `permissive-closed`: Ограничения записи, сеть запрещена
- `permissive-proxied`: Ограничения записи, сеть через прокси
- `restrictive-open`: Строгие ограничения, сеть разрешена
- `restrictive-closed`: Максимальные ограничения
- `restrictive-proxied`: Строгие ограничения, сеть через прокси

:::tip
Начните с `permissive-open`, затем ужесточите до `restrictive-closed`, если ваш рабочий процесс всё ещё работает.
:::

### Пользовательские профили Seatbelt (macOS)

Для использования пользовательского профиля Seatbelt:

1. Создайте файл с именем `.nessy/sandbox-macos-<profile_name>.sb` в вашем проекте.
2. Установите `SEATBELT_PROFILE=<profile_name>`.

### Пользовательские флаги песочницы

Для контейнерной песочницы вы можете внедрить пользовательские флаги в команду `docker` или `podman` с помощью переменной окружения `SANDBOX_FLAGS`. Это полезно для расширенных конфигураций, таких как отключение функций безопасности для конкретных случаев использования.

**Пример (Podman)**:

Для отключения маркировки SELinux для монтирования томов вы можете установить следующее:

```bash
export SANDBOX_FLAGS="--security-opt label=disable"
```

Несколько флагов могут быть предоставлены как строка, разделённая пробелами:

```bash
export SANDBOX_FLAGS="--flag1 --flag2=value"
```

### Сетевой прокси (все методы песочницы)

Если вы хотите ограничить исходящий сетевой доступ списком разрешённых, вы можете запустить локальный прокси вместе с песочницей:

- Установите `NESSY_SANDBOX_PROXY_COMMAND=<command>`
- Команда должна запускать прокси-сервер, который слушает `:::8877`

Это особенно полезно с профилями Seatbelt `*-proxied`.

Рабочий пример прокси со списком разрешений смотрите: [Пример скрипта прокси](../../../developers/work/examples/proxy-script.md).

## Обработка UID/GID в Linux

В Linux Nessy CLI по умолчанию включает сопоставление UID/GID, чтобы песочница работала от вашего пользователя (и повторно использовала смонтированную `~/.nessy`). Переопределите с помощью:

```bash
export SANDBOX_SET_UID_GID=true   # Принудительно установить UID/GID хоста
export SANDBOX_SET_UID_GID=false  # Отключить сопоставление UID/GID
```

## Устранение неполадок

### Распространённые проблемы

**"Operation not permitted"**

- Операция требует доступа вне песочницы.
- На macOS Seatbelt: попробуйте более разрешающий `SEATBELT_PROFILE`.
- На Docker/Podman: проверьте, что рабочее пространство смонтировано, и ваша команда не требует доступа вне каталога проекта.

**Отсутствующие команды**

- Контейнерная песочница: добавьте их через `.nessy/sandbox.Dockerfile` или `.nessy/sandbox.bashrc`.
- Seatbelt: ваши хост-бинарники используются, но песочница может ограничить доступ к некоторым путям.

**Проблемы с сетью**

- Проверьте, что профиль песочницы разрешает сеть.
- Проверьте конфигурацию прокси.

### Режим отладки

```bash
DEBUG=1 nessy -s -p "debug command"
```

**Примечание:** Если у вас есть `DEBUG=true` в файле `.env` проекта, это не повлияет на CLI из-за автоматического исключения. Используйте файлы `.nessy/.env` для настроек отладки специфичных для Nessy CLI.

### Инспекция песочницы

```bash
# Проверить окружение
nessy -s -p "run shell command: env | grep SANDBOX"

# Список монтирований
nessy -s -p "run shell command: mount | grep workspace"
```

## Заметки по безопасности

- Песочница уменьшает, но не устраняет все риски полностью.
- Используйте самый строгий профиль, который позволяет вашу работу.
- Накладные расходы контейнера минимальны после первой загрузки/сборки.
- GUI приложения могут не работать в песочницах.
