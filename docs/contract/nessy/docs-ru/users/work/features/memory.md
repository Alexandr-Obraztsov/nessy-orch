# Память

Каждая сессия Nessy CLI начинается с чистого контекстного окна. Два механизма переносят знания между сессиями, чтобы вам не приходилось объяснять себя заново каждый раз:

- **NESSY.md** — инструкции, которые _вы_ пишете один раз, и Nessy читает каждую сессию
- **Auto-memory** — заметки, которые Nessy пишет сам на основе того, что узнаёт от вас

---

## NESSY.md: ваши инструкции для Nessy

NESSY.md — это текстовый файл, куда вы записываете вещи, которые Nessy должен всегда знать о вашем проекте или ваших предпочтениях. Думайте об этом как о постоянном брифинге, который загружается в начале каждого разговора.

### Что помещать в NESSY.md

Добавляйте вещи, которые иначе пришлось бы повторять каждую сессию:

- Команды сборки и тестирования (`npm run test`, `make build`)
- Соглашения по кодированию, которым следует ваша команда («все новые файлы должны иметь комментарии JSDoc»)
- Архитектурные решения («мы используем паттерн repository, никогда не вызываем базу данных напрямую из контроллеров»)
- Личные предпочтения («всегда использовать pnpm, а не npm»)

Не включайте вещи, которые Nessy может выяснить, читая ваш код. NESSY.md работает лучше всего, когда он короткий и конкретный — чем длиннее он становится, тем менее надёжно Nessy ему следует.

### Где создать NESSY.md

| Файл                       | Кому применяется                                           |
| -------------------------- | ---------------------------------------------------------- |
| `~/.nessy/NESSY.md`        | Вам, во всех ваших проектах                                |
| `NESSY.md` в корне проекта | Всей вашей команде (закоммитьте в систему контроля версий) |

Вы можете иметь оба. Nessy загружает все файлы NESSY.md, которые находит при запуске сессии — ваш личный и любые в проекте.

Если в вашем репозитории уже есть файл `AGENTS.md` для других AI-инструментов, Nessy читает и его. Нет необходимости дублировать инструкции.

### Сгенерировать автоматически с `/init`

Запустите `/init`, и Nessy проанализирует вашу кодовую базу для создания стартового NESSY.md с командами сборки, инструкциями по тестированию и соглашениями, которые он найдёт. Если файл уже существует, он предложит дополнения вместо перезаписи.

### Ссылка на другие файлы

Вы можете указать в NESSY.md на другие файлы, чтобы Nessy читал и их:

```markdown
Смотрите @README.md для обзора проекта.

# Соглашения

- Git workflow: @docs/git-workflow.md
```

Используйте `@путь/к/файлу` в любом месте NESSY.md. Относительные пути разрешаются относительно файла NESSY.md.

## Auto-memory: что Nessy узнаёт о вас

Auto-memory работает в фоновом режиме. После каждого разговора Nessy тихо сохраняет полезные вещи, которые он узнал — ваши предпочтения, обратную связь, которую вы дали, контекст проекта — чтобы он мог использовать их в будущих сессиях без необходимости повторять себя.

Это отличается от NESSY.md: вы не пишете это, Nessy делает.

### Что Nessy сохраняет

Nessy ищет четыре типа вещей, которые стоит запомнить:

| Что                     | Примеры                                                                         |
| ----------------------- | ------------------------------------------------------------------------------- |
| **О вас**               | Ваша роль, бэкграунд, как вы любите работать                                    |
| **Ваша обратная связь** | Исправления, которые вы сделали, подходы, которые вы подтвердили                |
| **Контекст проекта**    | Текущая работа, решения, цели, не очевидные из кода                             |
| **Внешние ссылки**      | Панели мониторинга, трекеры задач, ссылки на документацию, которые вы упомянули |

Nessy сохраняет не всё — только вещи, которые действительно будут полезны в следующий раз.

### Где это хранится

Файлы auto-memory находятся в `~/.nessy/projects/<project>/memory/`. Все ветки и worktrees одного репозитория используют одну и ту же папку памяти, поэтому то, что Nessy узнаёт в одной ветке, доступно в других.

Всё сохранённое — это обычный markdown — вы можете открыть, отредактировать или удалить любой файл в любое время.

### Периодическая очистка

Nessy периодически просматривает сохранённые воспоминания для удаления дубликатов и очистки устаревших записей. Это работает автоматически в фоновом режиме раз в день после накопления достаточного количества сессий. Вы можете запустить это вручную с `/dream`, если хотите запустить сейчас.

Пока идёт очистка, в углу экрана появляется **✦ dreaming**. Ваша сессия продолжается нормально.

### Включение и выключение

Auto-memory включено по умолчанию. Для переключения откройте `/memory` и используйте переключатели вверху. Вы можете отключить только автоматическое сохранение, только периодическую очистку или оба.

Вы также можете установить их в `~/.nessy/settings.json` (применяется ко всем проектам) или `.nessy/settings.json` (только этот проект):

```json
{
  "memory": {
    "enableManagedAutoMemory": true,
    "enableManagedAutoDream": true
  }
}
```

## Команды

### `/memory`

Открывает панель памяти. Отсюда вы можете:

- Включить или выключить сохранение auto-memory
- Включить или выключить периодическую очистку (dream)
- Открыть ваш личный NESSY.md (`~/.nessy/NESSY.md`)
- Открыть проект NESSY.md
- Просмотреть папку auto-memory

### `/init`

Генерирует стартовый NESSY.md для вашего проекта. Nessy читает вашу кодовую базу и заполняет команды сборки, инструкции по тестированию и соглашения, которые он обнаруживает.

### `/remember <text>`

Немедленно сохраняет что-то в auto-memory без ожидания, пока Nessy подхватит это автоматически:

```
/remember всегда использовать snake_case для имён переменных Python
/remember тестовое окружение находится на staging.example.com
```

### `/forget <text>`

Удаляет записи auto-memory, которые соответствуют вашему описанию:

```
/forget старое обходное решение для бага входа
```

### `/dream`

Запускает очистку памяти сейчас вместо ожидания автоматического расписания:

```
/dream
```

## Troubleshooting

### Nessy не следует моему NESSY.md

Откройте `/memory`, чтобы увидеть, какие файлы загружены. Если вашего файла нет в списке, Nessy не может его видеть — убедитесь, что он находится в корне проекта или `~/.nessy/`.

Инструкции работают лучше, когда они конкретны:

- ✓ `Использовать 2-пробельную индентацию для файлов TypeScript`
- ✗ `Форматировать код красиво`

Если у вас несколько файлов NESSY.md с конфликтующими инструкциями, Nessy может вести себя непоследовательно. Просмотрите их и удалите любые противоречия.

### Я хочу увидеть, что сохранил Nessy

Запустите `/memory` и выберите **Open auto-memory folder**. Все сохранённые воспоминания — это читаемые markdown-файлы, которые вы можете просматривать, редактировать или удалять.

### Nessy продолжает забывать вещи

Если auto-memory включено, но Nessy, кажется, не помнит вещи между сессиями, попробуйте запустить `/dream` для принудительной очистки. Также проверьте `/memory`, чтобы подтвердить, что оба переключателя включены.

Для вещей, которые вы всегда хотите, чтобы Nessy помнил, добавьте их в NESSY.md вместо этого — auto-memory это best-effort, NESSY.md гарантирован.
