# Навыки агента

> Создавайте, управляйте и делитесь навыками для расширения возможностей Nessy CLI.

Это руководство показывает вам, как создавать, использовать и управлять навыками агента в **Nessy CLI**. Навыки — это модульные возможности, которые расширяют эффективность модели через организованные каталоги, содержащие инструкции (и опционально скрипты/ресурсы).

## Необходимые условия

- Nessy CLI (последняя версия)
- Базовое знакомство с Nessy CLI ([Быстрый старт](../../quickstart.md))

## Что такое навыки агента?

Навыки агента упаковывают экспертизу в обнаруживаемые возможности. Каждый навык состоит из файла `SKILL.md` с инструкциями, которые модель может загрузить, когда это релевантно, плюс опциональные вспомогательные файлы, такие как скрипты и шаблоны.

### Как вызываются навыки

Навыки **вызываются моделью** — модель автономно решает, когда использовать их на основе вашего запроса и описания навыка. Это отличается от slash-команд, которые **вызываются пользователем** (вы явно вводите `/команда`).

Если вы хотите вызвать навык явно, используйте slash-команду `/skills`:

```bash
/skills <имя-навыка>
```

Используйте автодополнение для просмотра доступных навыков и описаний.

### Преимущества

- Расширяйте Nessy CLI для ваших рабочих процессов
- Делитесь экспертизой в вашей команде через git
- Уменьшайте повторяющиеся подсказки
- Компонуйте несколько навыков для сложных задач

## Создание навыка

Навыки хранятся как каталоги, содержащие файл `SKILL.md`.

### Личные навыки

Личные навыки доступны во всех ваших проектах. Храните их в `~/.nessy/skills/`:

```bash
mkdir -p ~/.nessy/skills/имя-моего-навыка
```

Используйте личные навыки для:

- Ваших индивидуальных рабочих процессов и предпочтений
- Навыков, которые вы разрабатываете
- Личных помощников продуктивности

### Проектные навыки

Проектные навыки доступны вашей команде. Храните их в `.nessy/skills/` в вашем проекте:

```bash
mkdir -p .nessy/skills/имя-моего-навыка
```

Используйте проектные навыки для:

- Командных рабочих процессов и соглашений
- Специфичной для проекта экспертизы
- Совместных утилит и скриптов

Проектные навыки могут быть добавлены в git и автоматически становятся доступными для товарищей по команде.

## Написание `SKILL.md`

Создайте файл `SKILL.md` с YAML frontmatter и Markdown содержимым:

```yaml
---
name: имя-вашего-навыка
description: Краткое описание того, что делает этот навык и когда его использовать
---

# Имя вашего навыка

## Инструкции
Предоставьте чёткие, пошаговые руководства для Nessy CLI.

## Примеры
Покажите конкретные примеры использования этого навыка.
```

### Требования полей

Nessy CLI в настоящее время проверяет, что:

- `name` — непустая строка, соответствующая `/^[\p{L}\p{N}_:.-]+$/u` — буквы и цифры Unicode (китайские/кириллица/латиница с акцентами — всё ок), плюс `_`, `:`, `.`, `-`. Пробелы, слеши, скобки и другие структурно небезопасные символы отклоняются при парсинге.
- `description` — непустая строка
- `priority` — опционально. Если присутствует, должно быть конечным числом. Более высокие значения сортируются раньше только в списке `/skills` — завершение slash-команды (ввод `/`) и просмотр пользовательских команд `/help` остаются алфавитными, поэтому навык с высоким приоритетом никогда не переупорядочивает встроенные команды. Пропущенные или невалидные значения считаются неустановленными, что ведёт себя как `0`.

Рекомендуемые соглашения:

- Предпочитайте строчные ASCII с дефисами для общих имён (например, `tsx-helper`)
- Делайте `description` конкретным: включайте как **что** делает навык, так и **когда** его использовать (ключевые слова, которые пользователи будут естественно упоминать)
- Используйте `priority` экономно для навыков, которые должны надёжно появляться перед стандартным алфавитным порядком в `/skills`. Отрицательные приоритеты разрешены и сортируются ниже неустановленных навыков.

### Опционально: ограничение навыка по путям файлов (`paths:`)

Для навыков, которые важны только для определённых частей кодовой базы, добавьте список glob-паттернов `paths:`. Навык остаётся вне списка доступных навыков модели, пока вызов инструмента не затронет соответствующий файл:

```yaml
---
name: tsx-helper
description: Помощник по React TSX компонентам
paths:
  - 'src/**/*.tsx'
  - 'packages/*/src/**/*.tsx'
---
```

Примечания:

- Glob-паттерны сопоставляются относительно корня проекта с помощью [picomatch](https://github.com/micromatch/picomatch); файлы вне корня проекта никогда не активируют навык.
- Навык с ограничением по путям **остаётся активированным до конца сессии**, как только затронут соответствующий файл. Новая сессия или `refreshCache`, вызванный редактированием любого файла навыка, сбрасывает активации.
- `paths:` ограничивает только обнаружение **моделью**, и только на уровне списка SkillTool. Вы всегда можете вызвать навык с ограничением по путям самостоятельно через `/<имя-навыка>` или выборщик `/skills` — этот пользовательский путь запускает тело навыка независимо от состояния активации. Однако сторона модели остаётся ограниченной, пока не будет затронут соответствующий файл: вызов slash-командой **не** разблокирует активацию на стороне модели, поэтому если вы хотите, чтобы модель цеплялась за ваш вызов (вызывала `Skill { skill: ... }` сама), также получите доступ к файлу, соответствующему `paths:` навыка.
- Комбинирование `paths:` с `disable-model-invocation: true` разрешено, но ограничение не имеет эффекта — навык скрыт от модели в любом случае, поэтому активация по путям никогда не рекламирует его.

## Добавление вспомогательных файлов

Создайте дополнительные файлы рядом с `SKILL.md`:

```text
my-skill/
├── SKILL.md (обязательно)
├── reference.md (опциональная документация)
├── examples.md (опциональные примеры)
├── scripts/
│   └── helper.py (опциональная утилита)
└── templates/
    └── template.txt (опциональный шаблон)
```

Ссылайтесь на эти файлы из `SKILL.md`:

````markdown
Для продвинутого использования смотрите [reference.md](reference.md).

Запустите вспомогательный скрипт:

```bash
python scripts/helper.py input.txt
```
````

## Просмотр доступных навыков

Nessy CLI обнаруживает навыки из:

- Личные навыки: `~/.nessy/skills/`
- Проектные навыки: `.nessy/skills/`
- Навыки расширений: навыки, предоставленные установленными расширениями

### Навыки расширений

Расширения могут предоставлять пользовательские навыки, которые становятся доступны при включении расширения. Эти навыки хранятся в каталоге `skills/` расширения и следуют тому же формату, что и личные и проектные навыки.

Навыки расширений автоматически обнаруживаются и загружаются при установке и включении расширения.

Чтобы увидеть, какие расширения предоставляют навыки, проверьте файл `nessy-extension.json` расширения на наличие поля `skills`.

Чтобы просмотреть доступные навыки, спросите напрямую у Nessy CLI:

```text
Какие навыки доступны?
```

> **Внимание — модель vs пользователь.** Запрос модели показывает только навыки, которые модель видит в данный момент. Если навык использует `paths:` (см. "Опционально: ограничение навыка по путям файлов" выше), он остаётся вне этого списка, пока не будет затронут соответствующий файл. Полный набор всегда виден вам через slash-команду `/skills` и на диске.

Или просмотрите полный список с помощью slash-команды (всегда показывает каждый навык, включая навыки с ограничением по путям, которые ещё не активировались):

```text
/skills
```

Или проверьте файловую систему:

```bash
# Список личных навыков
ls ~/.nessy/skills/

# Список проектных навыков (если в каталоге проекта)
ls .nessy/skills/

# Просмотр содержимого конкретного навыка
cat ~/.nessy/skills/имя-навыка/SKILL.md
```

## Тестирование навыка

После создания навыка протестируйте его, задав вопросы, которые соответствуют вашему описанию.

Пример: если ваше описание упоминает "PDF файлы":

```text
Можешь помочь мне извлечь текст из этого PDF?
```

Модель автономно решает использовать ваш навык, если он соответствует запросу — вам не нужно явно вызывать его.

## Отладка навыка

Если Nessy CLI не использует ваш навык, проверьте эти распространённые проблемы:

### Сделайте описание конкретным

Слишком размыто:

```yaml
description: Помогает с документами
```

Конкретно:

```yaml
description: Извлекает текст и таблицы из PDF файлов, заполняет формы, объединяет документы. Использовать при работе с PDF, формами или извлечением документов.
```

### Проверьте путь к файлу

- Личные навыки: `~/.nessy/skills/<имя-навыка>/SKILL.md`
- Проектные навыки: `.nessy/skills/<имя-навыка>/SKILL.md`

```bash
# Личный
ls ~/.nessy/skills/имя-навыка/SKILL.md

# Проектный
ls .nessy/skills/имя-навыка/SKILL.md
```

### Проверьте синтаксис YAML

Невалидный YAML предотвращает корректную загрузку метаданных навыка.

```bash
cat SKILL.md | head -n 15
```

Убедитесь:

- Открывающий `---` на строке 1
- Закрывающий `---` перед Markdown содержимым
- Валидный синтаксис YAML (без табуляции, правильная индентация)

### Просмотр ошибок

Запустите Nessy CLI в режиме отладки, чтобы увидеть ошибки загрузки навыков:

```bash
nessy --debug
```

## Публикация навыка

Вы можете опубликовать навык через репозиторий проекта:

1. Добавьте навык под `.nessy/skills/`
2. Закоммитьте и отправьте
3. Товарищи по команде получают изменения

```bash
git add .nessy/skills/
git commit -m "Добавить командный навык для обработки PDF"
git push
```

## Обновление навыка

Редактируйте `SKILL.md` напрямую:

```bash
# Личный навык
code ~/.nessy/skills/имя-навыка/SKILL.md

# Проектный навык
code .nessy/skills/имя-навыка/SKILL.md
```

Изменения вступают в силу при следующем запуске Nessy CLI. Если Nessy CLI уже запущен, перезапустите его для загрузки обновлений.

## Удаление навыка

Удалите каталог навыка:

```bash
# Личный
rm -rf ~/.nessy/skills/имя-навыка

# Проектный
rm -rf .nessy/skills/имя-навыка
git commit -m "Удалить неиспользуемый навык"
```

## Лучшие практики

### Сохраняйте навыки сфокусированными

Один навык должен адресовать одну возможность:

- Сфокусировано: "Заполнение PDF форм", "Анализ Excel", "Сообщения коммитов Git"
- Слишком широко: "Обработка документов" (разделите на меньшие навыки)

### Пишите чёткие описания

Помогите модели обнаружить, когда использовать навыки, включая конкретные триггеры:

```yaml
description: Анализирует электронные таблицы Excel, создаёт сводные таблицы и генерирует диаграммы. Использовать при работе с файлами Excel, таблицами или данными .xlsx.
```

### Тестируйте с вашей командой

- Активируется ли навык, когда ожидается?
- Инструкции ли ясны?
- Есть ли отсутствующие примеры или граничные случаи?
