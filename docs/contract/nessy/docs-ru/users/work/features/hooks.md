# Хуки Nessy CLI

## Обзор

Хуки Nessy CLI предоставляют мощный механизм для расширения и кастомизации поведения приложения Nessy CLI. Хуки позволяют пользователям выполнять кастомные скрипты или программы в определённых точках жизненного цикла приложения, таких как перед выполнением инструмента, после выполнения инструмента, в начале/конце сессии и во время других ключевых событий.

Хуки включены по умолчанию. Вы можете временно отключить все хуки, установив `disableAllHooks` в `true` в вашем файле настроек (на верхнем уровне, рядом с `hooks`):

```json
{
  "disableAllHooks": true,
  "hooks": {
    "PreToolUse": [...]
  }
}
```

Это отключает все хуки без удаления их конфигураций.

## Что такое хуки?

Хуки — это пользовательские скрипты или программы, которые автоматически выполняются Nessy CLI в предопределённых точках потока приложения. Они позволяют пользователям:

- Мониторить и аудировать использование инструментов
- Обеспечивать политики безопасности
- Инжектировать дополнительный контекст в конверсации
- Кастомизировать поведение приложения на основе событий
- Интегрироваться с внешними системами и сервисами
- Модифицировать вводы инструментов или ответы программно

## Типы хуков

Nessy CLI поддерживает четыре типа исполнителей хуков:

| Тип        | Описание                                                                                         |
| :--------- | :----------------------------------------------------------------------------------------------- |
| `command`  | Выполнить команду оболочки. Получает JSON через `stdin`, возвращает результаты через `stdout`.   |
| `http`     | Отправить JSON как тело `POST`-запроса на указанный URL. Возвращает результаты через HTTP-ответ. |
| `function` | Напрямую вызвать зарегистрированную JavaScript-функцию (только хуки уровня сессии).              |
| `prompt`   | Использовать LLM для оценки ввода хука и вернуть решение.                                        |

### Хуки Command

Хуки Command выполняют команды через дочерние процессы. Входной JSON передаётся через stdin, вывод возвращается через stdout.

**Конфигурация:**

| Поле            | Тип                      | Обязательно | Описание                                       |
| :-------------- | :----------------------- | :---------- | :--------------------------------------------- |
| `type`          | `"command"`              | Да          | Тип хука                                       |
| `command`       | `string`                 | Да          | Команда для выполнения                         |
| `name`          | `string`                 | Нет         | Имя хука (для логирования)                     |
| `description`   | `string`                 | Нет         | Описание хука                                  |
| `timeout`       | `number`                 | Нет         | Таймаут в миллисекундах, по умолчанию 60000    |
| `async`         | `boolean`                | Нет         | Запускать ли асинхронно в фоне                 |
| `env`           | `Record<string, string>` | Нет         | Переменные окружения                           |
| `shell`         | `"bash" \| "powershell"` | Нет         | Используемая оболочка                          |
| `statusMessage` | `string`                 | Нет         | Сообщение статуса, отображаемое при выполнении |

**Пример:**

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "WriteFile",
        "hooks": [
          {
            "type": "command",
            "command": "$NESSY_PROJECT_DIR/.nessy/hooks/security-check.sh",
            "name": "security-check",
            "timeout": 10000
          }
        ]
      }
    ]
  }
}
```

### Хуки HTTP

Хуки HTTP отправляют ввод хука как POST-запросы на указанные URL. Они поддерживают белые списки URL, защиту от SSRF на уровне DNS, интерполяцию переменных окружения и другие функции безопасности.

**Конфигурация:**

| Поле             | Тип                      | Обязательно | Описание                                                        |
| :--------------- | :----------------------- | :---------- | :-------------------------------------------------------------- |
| `type`           | `"http"`                 | Да          | Тип хука                                                        |
| `url`            | `string`                 | Да          | Целевой URL                                                     |
| `headers`        | `Record<string, string>` | Нет         | Заголовки запроса (поддерживают интерполяцию переменных)        |
| `allowedEnvVars` | `string[]`               | Нет         | Белый список переменных окружения, разрешённых в URL/заголовках |
| `timeout`        | `number`                 | Нет         | Таймаут в секундах, по умолчанию 600                            |
| `name`           | `string`                 | Нет         | Имя хука (для логирования)                                      |
| `statusMessage`  | `string`                 | Нет         | Сообщение статуса, отображаемое при выполнении                  |
| `once`           | `boolean`                | Нет         | Выполнять только один раз на событие на сессию (только HTTP)    |

**Функции безопасности:**

- **Белый список URL**: Настройте разрешённые шаблоны URL через `allowedUrls`
- **Защита от SSRF**: Блокирует приватные IP (10.x.x.x, 172.16-31.x.x, 192.168.x.x и т.д.), но разрешает loopback-адреса (127.0.0.1, ::1)
- **Валидация DNS**: Проверяет разрешение домена перед запросами для предотвращения атак DNS rebinding
- **Интерполяция переменных окружения**: Синтаксис `${VAR}`, разрешает только переменные из белого списка `allowedEnvVars`

**Пример:**

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "*",
        "hooks": [
          {
            "type": "http",
            "url": "http://127.0.0.1:8080/hooks/pre-tool-use",
            "headers": {
              "Authorization": "Bearer ${HOOK_API_KEY}"
            },
            "allowedEnvVars": ["HOOK_API_KEY"],
            "timeout": 10,
            "name": "remote-security-check"
          }
        ]
      }
    ]
  }
}
```

### Хуки Function

Хуки Function напрямую вызывают зарегистрированные JavaScript/TypeScript функции. Они используются внутри системой Skill и в настоящее время не представлены как публичный API для конечных пользователей.

**Примечание**: Для большинства случаев использования применяйте **хуки command** или **хуки HTTP**, которые можно настроить в файлах настроек.

### Хуки Prompt

Хуки Prompt используют LLM для оценки ввода хука и возврата решения. Это полезно для принятия интеллектуальных решений на основе контекста, таких как определение, разрешить или заблокировать операцию.

**Как это работает:**

1. Ввод JSON хука инжектируется в ваш промпт с помощью плейсхолдера `$ARGUMENTS`
2. Промпт отправляется в LLM (по умолчанию: ваша текущая модель)
3. LLM возвращает JSON-ответ с решением
4. Nessy CLI обрабатывает решение и продолжает или блокирует выполнение соответственно

**Конфигурация:**

| Поле            | Тип        | Обязательно | Описание                                                            |
| :-------------- | :--------- | :---------- | :------------------------------------------------------------------ |
| `type`          | `"prompt"` | Да          | Тип хука                                                            |
| `prompt`        | `string`   | Да          | Промпт, отправляемый в LLM. Используйте `$ARGUMENTS` для ввода хука |
| `model`         | `string`   | Нет         | Модель для использования (по умолчанию: текущая модель)             |
| `timeout`       | `number`   | Нет         | Таймаут в секундах, по умолчанию 30                                 |
| `name`          | `string`   | Нет         | Имя хука (для логирования)                                          |
| `description`   | `string`   | Нет         | Описание хука                                                       |
| `statusMessage` | `string`   | Нет         | Сообщение статуса, отображаемое при выполнении                      |

**Формат ответа:**

LLM должен вернуть JSON со следующей структурой:

```json
{
  "ok": true,
  "reason": "Объяснение решения",
  "additionalContext": "Дополнительный контекст для инжектирования в конверсацию"
}
```

| Поле                | Описание                                                                             |
| :------------------ | :----------------------------------------------------------------------------------- |
| `ok`                | `true` для разрешения/продолжения, `false` для блокировки/остановки                  |
| `reason`            | Обязательно, когда `ok` равен `false`. Показывается модели для объяснения блокировки |
| `additionalContext` | Опционально. Дополнительный контекст для инжектирования в конверсацию при разрешении |

**Поддерживаемые события:**

Хуки Prompt можно использовать с большинством событий хуков, включая:

- `PreToolUse` — Оценить, разрешить ли вызов инструмента
- `PostToolUse` — Оценить результаты инструмента и потенциально инжектировать контекст
- `Stop` — Определить, продолжать или остановиться
- `SubagentStop` — Оценить результаты субагента
- `UserPromptSubmit` — Оценить или обогатить пользовательские промпты

**Пример: Хук Stop**

```json
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "prompt",
            "prompt": "Вы оцениваете, должен ли Nessy CLI прекратить работу. Контекст: $ARGUMENTS\n\nПроанализируйте конверсацию и определите:\n1. Все ли запрошенные пользователем задачи завершены\n2. Нужно ли addressed какие-либо ошибки\n3. Нужна ли последующая работа\n\nОтветьте JSON: {\"ok\": true} для разрешения остановки или {\"ok\": false, \"reason\": \"ваше объяснение\"} для продолжения работы.",
            "timeout": 30
          }
        ]
      }
    ]
  }
}
```

Когда `ok` равен `false`, Nessy CLI продолжит работу и использует `reason` как контекст для следующего ответа.

**Пример: Хук PreToolUse**

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "prompt",
            "prompt": "Оцените этот вызов инструмента на предмет проблем безопасности. Ввод инструмента: $ARGUMENTS\n\nПроверьте:\n- Опасные команды (rm -rf, curl | sh и т.д.)\n- Попытки несанкционированного доступа\n- Паттерны эксфильтрации данных\n\nОтветьте {\"ok\": true}, если безопасно, или {\"ok\": false, \"reason\": \"опасение\"}, если заблокировано.",
            "model": "sonnet",
            "timeout": 30,
            "name": "security-evaluator"
          }
        ]
      }
    ]
  }
}
```

## События хуков

Хуки срабатывают в определённых точках во время сессии Nessy CLI. Различные события поддерживают различные matchers для фильтрации условий срабатывания.

| Событие              | Когда срабатывает                          | Цель matcher                                             |
| :------------------- | :----------------------------------------- | :------------------------------------------------------- |
| `PreToolUse`         | Перед выполнением инструмента              | Имя инструмента (`WriteFile`, `ReadFile`, `Bash` и т.д.) |
| `PostToolUse`        | После успешого выполнения инструмента      | Имя инструмента                                          |
| `PostToolUseFailure` | После неудачи выполнения инструмента       | Имя инструмента                                          |
| `UserPromptSubmit`   | После отправки промпта пользователем       | Нет (всегда срабатывает)                                 |
| `SessionStart`       | При старте или возобновлении сессии        | Источник (`startup`, `resume`, `clear`, `compact`)       |
| `SessionEnd`         | При окончании сессии                       | Причина (`clear`, `logout`, `prompt_input_exit` и т.д.)  |
| `Stop`               | Когда Claude готовится завершить ответ     | Нет (всегда срабатывает)                                 |
| `SubagentStart`      | При старте субагента                       | Тип агента (`Bash`, `Explorer`, `Plan` и т.д.)           |
| `SubagentStop`       | При остановке субагента                    | Тип агента                                               |
| `PreCompact`         | Перед компакцией конверсации               | Триггер (`manual`, `auto`)                               |
| `Notification`       | При отправке уведомлений                   | Тип (`permission_prompt`, `idle_prompt`, `auth_success`) |
| `PermissionRequest`  | При отображении диалога разрешений         | Имя инструмента                                          |
| `TodoCreated`        | При создании нового элемента todo          | Нет (всегда срабатывает)                                 |
| `TodoCompleted`      | При отметке элемента todo как завершённого | Нет (всегда срабатывает)                                 |

### Шаблоны Matcher

`matcher` — это регулярное выражение, используемое для фильтрации условий срабатывания.

| Тип события          | События                                                                | Поддержка matcher | Цель matcher                                            |
| :------------------- | :--------------------------------------------------------------------- | :---------------- | :------------------------------------------------------ |
| События инструментов | `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `PermissionRequest` | ✅ Regex          | Имя инструмента: `WriteFile`, `ReadFile`, `Bash` и т.д. |
| События субагента    | `SubagentStart`, `SubagentStop`                                        | ✅ Regex          | Тип агента: `Bash`, `Explorer` и т.д.                   |
| События сессии       | `SessionStart`                                                         | ✅ Regex          | Источник: `startup`, `resume`, `clear`, `compact`       |
| События сессии       | `SessionEnd`                                                           | ✅ Regex          | Причина: `clear`, `logout`, `prompt_input_exit` и т.д.  |
| События уведомлений  | `Notification`                                                         | ✅ Exact match    | Тип: `permission_prompt`, `idle_prompt`, `auth_success` |
| События компакции    | `PreCompact`                                                           | ✅ Exact match    | Триггер: `manual`, `auto`                               |
| События todo         | `TodoCreated`, `TodoCompleted`                                         | ❌ Нет            | Н/Д                                                     |
| События промпта      | `UserPromptSubmit`                                                     | ❌ Нет            | Н/Д                                                     |
| События остановки    | `Stop`                                                                 | ❌ Нет            | Н/Д                                                     |

**Синтаксис matcher:**

- Пустая строка `""` или `"*"` соответствует всем событиям этого типа
- Поддерживается стандартный синтаксис regex (например, `^Bash$`, `Read.*`, `(WriteFile|Edit)`)

**Примеры:**

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "^Bash$",
        "hooks": [
          {
            "type": "command",
            "command": "echo 'bash check' >> /tmp/hooks.log"
          }
        ]
      },
      {
        "matcher": "Write.*",
        "hooks": [
          {
            "type": "command",
            "command": "echo 'write check' >> /tmp/hooks.log"
          }
        ]
      },
      {
        "matcher": "*",
        "hooks": [
          { "type": "command", "command": "echo 'all tools' >> /tmp/hooks.log" }
        ]
      }
    ],
    "SubagentStart": [
      {
        "matcher": "^(Bash|Explorer)$",
        "hooks": [
          {
            "type": "command",
            "command": "echo 'subagent check' >> /tmp/hooks.log"
          }
        ]
      }
    ]
  }
}
```

## Правила ввода/вывода

### Структура ввода хука

Все хуки получают стандартизированный ввод в формате JSON через stdin (command) или тело POST (http).

**Общие поля:**

```json
{
  "session_id": "string",
  "transcript_path": "string",
  "cwd": "string",
  "hook_event_name": "string",
  "timestamp": "string"
}
```

Поля, специфичные для события, добавляются в зависимости от типа хука. При запуске в субагенте дополнительно включаются `agent_id` и `agent_type`.

### Структура вывода хука

Вывод хука возвращается через `stdout` (command) или тело HTTP-ответа (http) в формате JSON.

**Поведение кодов выхода (хуки Command):**

| Код выхода | Поведение                                                                                     |
| :--------- | :-------------------------------------------------------------------------------------------- |
| `0`        | Успех. Парсить JSON в `stdout` для управления поведением.                                     |
| `2`        | **Блокирующая ошибка**. Игнорирует `stdout`, передаёт `stderr` как ошибку модели.             |
| Другой     | Неблокирующая ошибка. `stderr` показывается только в режиме отладки, выполнение продолжается. |

**Структура вывода:**

Вывод хука поддерживает три категории полей:

1. **Общие поля**: `continue`, `stopReason`, `suppressOutput`, `systemMessage`
2. **Решение верхнего уровня**: `decision`, `reason` (используется некоторыми событиями)
3. **Управление, специфичное для события**: `hookSpecificOutput` (должно включать `hookEventName`)

```json
{
  "continue": true,
  "decision": "allow",
  "reason": "Операция одобрена",
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "additionalContext": "Дополнительная контекстная информация"
  }
}
```

### Детали отдельных событий хуков

#### PreToolUse

**Назначение**: Выполняется перед использованием инструмента для проверок разрешений, валидации ввода или инъекции контекста.

**Поля, специфичные для события:**

```json
{
  "permission_mode": "default | plan | auto_edit | yolo",
  "tool_name": "имя выполняемого инструмента",
  "tool_input": "объект, содержащий входные параметры инструмента",
  "tool_use_id": "уникальный идентификатор для этого экземпляра использования инструмента"
}
```

**Опции вывода:**

- `hookSpecificOutput.permissionDecision`: "allow", "deny" или "ask" (ОБЯЗАТЕЛЬНО)
- `hookSpecificOutput.permissionDecisionReason`: объяснение решения (ОБЯЗАТЕЛЬНО)
- `hookSpecificOutput.updatedInput`: модифицированные входные параметры инструмента для использования вместо оригинальных
- `hookSpecificOutput.additionalContext`: дополнительная контекстная информация

**Примечание**: Хотя стандартные поля вывода хука, такие как `decision` и `reason`, технически поддерживаются базовым классом, официальный интерфейс ожидает `hookSpecificOutput` с `permissionDecision` и `permissionDecisionReason`.

**Пример вывода:**

```json
{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "deny",
    "permissionDecisionReason": "Политика безопасности блокирует запись в БД",
    "additionalContext": "Текущее окружение: production. Действуйте с осторожностью."
  }
}
```

#### PostToolUse

**Назначение**: Выполняется после успешного завершения инструмента для обработки результатов, логирования исходов или инъекции дополнительного контекста.

**Поля, специфичные для события:**

```json
{
  "permission_mode": "default | plan | auto_edit | yolo",
  "tool_name": "имя выполненного инструмента",
  "tool_input": "объект, содержащий входные параметры инструмента",
  "tool_response": "объект, содержащий ответ инструмента",
  "tool_use_id": "уникальный идентификатор для этого экземпляра использования инструмента"
}
```

**Опции вывода:**

- `decision`: "allow", "deny", "block" (по умолчанию "allow", если не указано)
- `reason`: причина решения
- `hookSpecificOutput.additionalContext`: дополнительная информация для включения

**Пример вывода:**

```json
{
  "decision": "allow",
  "reason": "Инструмент выполнен успешно",
  "hookSpecificOutput": {
    "additionalContext": "Изменение файла записано в аудит-лог"
  }
}
```

#### PostToolUseFailure

**Назначение**: Выполняется при неудаче выполнения инструмента для обработки ошибок, отправки оповещений или записи неудач.

**Поля, специфичные для события:**

```json
{
  "permission_mode": "default | plan | auto_edit | yolo",
  "tool_use_id": "уникальный идентификатор для использования инструмента",
  "tool_name": "имя инструмента, который не сработал",
  "tool_input": "объект, содержащий входные параметры инструмента",
  "error": "сообщение об ошибке, описывающее неудачу",
  "is_interrupt": "булево значение, указывающее, была ли неудача из-за прерывания пользователя (опционально)"
}
```

**Опции вывода:**

- `hookSpecificOutput.additionalContext`: информация об обработке ошибки
- Стандартные поля вывода хука

**Пример вывода:**

```json
{
  "hookSpecificOutput": {
    "additionalContext": "Ошибка: Файл не найден. Неудача записана в систему мониторинга."
  }
}
```

#### UserPromptSubmit

#### TodoCreated

**Назначение**: Выполняется при создании нового элемента todo через инструмент `todo_write`. Позволяет валидацию, логирование или блокировку создания todo.

Хуки todo выполняются в две фазы:

- `validation`: выполняется до сохранения. Используйте эту фазу только для валидации; возврат `block` или `deny` предотвращает запись.
- `postWrite`: выполняется после сохранения. Используйте эту фазу для побочных эффектов, таких как логирование или синхронизация; `block` или `deny` игнорируется в этой фазе.

**Поля, специфичные для события:**

```json
{
  "todo_id": "уникальный идентификатор для элемента todo",
  "todo_content": "содержимое/описание элемента todo",
  "todo_status": "pending | in_progress | completed",
  "all_todos": "массив всех элементов todo в текущем списке",
  "phase": "validation | postWrite"
}
```

**Опции вывода:**

- `decision`: "allow", "block" или "deny"
- `reason`: объяснение решения на понятном человеку языке (обязательно при блокировке)

**Поведение блокировки:**

Во время фазы `validation`, когда `decision` равен `block` или `deny` (код выхода 2), создание todo предотвращается. Список todo остаётся без изменений, и причина предоставляется как обратная связь модели.

Во время фазы `postWrite` todo уже сохранён. Хуки могут всё ещё возвращать вывод, но `block` / `deny` не отменяет запись и не должно использоваться для валидации.

**Пример вывода (разрешение):**

```json
{
  "decision": "allow",
  "reason": "Содержимое todo проверено успешно"
}
```

**Пример вывода (блокировка):**

```json
{
  "decision": "block",
  "reason": "Содержимое todo слишком короткое. Требуется минимум 5 символов."
}
```

**Пример скрипта хука:**

```bash
#!/bin/bash
# ~/.nessy/hooks/todo-validator.sh
# Валидирует содержимое todo перед созданием

INPUT=$(cat)
CONTENT=$(echo "$INPUT" | jq -r '.todo_content')

# Проверка минимальной длины
if [ ${#CONTENT} -lt 5 ]; then
  echo '{"decision": "block", "reason": "Содержимое todo должно быть не менее 5 символов"}'
  exit 2
fi

# Блокировка todo, связанных с тестированием
if [[ "$CONTENT" =~ "test" ]]; then
  echo '{"decision": "block", "reason": "Тестовые todo не разрешены в production"}'
  exit 2
fi

echo '{"decision": "allow"}'
exit 0
```

## Выполнение хука

### Параллельное vs последовательное выполнение

- По умолчанию хуки выполняются параллельно для лучшей производительности
- Используйте `sequential: true` в определении хука для обеспечения зависимого от порядка выполнения
- Последовательные хуки могут модифицировать ввод для последующих хуков в цепочке

### Асинхронные хуки

Только тип `command` поддерживает асинхронное выполнение. Установка `"async": true` запускает хук в фоне без блокировки основного потока.

**Особенности:**

- Не может возвращать управление решением (операция уже произошла)
- Результаты инжектируются в следующий оборот конверсации через `systemMessage` или `additionalContext`
- Подходит для аудита, логирования, фонового тестирования и т.д.

**Пример:**

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "WriteFile|Edit",
        "hooks": [
          {
            "type": "command",
            "command": "$NESSY_PROJECT_DIR/.nessy/hooks/run-tests-async.sh",
            "async": true,
            "timeout": 300000
          }
        ]
      }
    ]
  }
}
```

```bash
#!/bin/bash
INPUT=$(cat)
FILE_PATH=$(echo "$INPUT" | jq -r '.tool_input.file_path // empty')
if [[ "$FILE_PATH" != *.ts && "$FILE_PATH" != *.js ]]; then exit 0; fi
RESULT=$(npm test 2>&1)
if [ $? -eq 0 ]; then
  echo "{\"systemMessage\": \"Тесты пройдены после редактирования $FILE_PATH\"}"
else
  echo "{\"systemMessage\": \"Тесты не пройдены: $RESULT\"}"
fi
```

### Модель безопасности

- Хуки работают в окружении пользователя с привилегиями пользователя
- Хуки уровня проекта требуют статуса доверенной папки
- Таймауты предотвращают зависание хуков (по умолчанию: 60 секунд)

```bash
# Чтение ввода из stdin
INPUT=$(cat)

# Парсинг ввода для извлечения информации об инструменте
TOOL_NAME=$(echo "$INPUT" | jq -r '.tool_name')
TOOL_INPUT=$(echo "$INPUT" | jq -r '.tool_input')

# Проверка потенциально опасных операций
if echo "$TOOL_INPUT" | grep -qiE "(rm.*-rf|mv.*\/|chmod.*777)"; then
  echo '{
    "hookSpecificOutput": {
      "hookEventName": "PreToolUse",
      "permissionDecision": "deny",
      "permissionDecisionReason": "Политика безопасности блокирует опасную команду"
    }
  }'
  exit 2  # Блокирующая ошибка
fi

# Логирование операции
echo "INFO: Инструмент $TOOL_NAME выполнен безопасно в $(date)" >> /var/log/nessy-security.log

# Разрешение с дополнительным контекстом
echo '{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "allow",
    "permissionDecisionReason": "Проверка безопасности пройдена",
    "additionalContext": "Команда одобрена политикой безопасности"
  }
}'
exit 0
```

### Пример 3: Хук валидации пользовательского промпта

Хук UserPromptSubmit, который валидирует пользовательские промпты на чувствительную информацию и предоставляет контекст для длинных промптов:

**prompt_validator.py**

```python
import json
import sys
import re

# Загрузка ввода из stdin
try:
    input_data = json.load(sys.stdin)
except json.JSONDecodeError as e:
    print(f"Error: Invalid JSON input: {e}", file=sys.stderr)
    exit(1)

user_prompt = input_data.get("prompt", "")

# Список чувствительных слов
sensitive_words = ["password", "secret", "token", "api_key"]

# Проверка чувствительной информации
for word in sensitive_words:
    if re.search(rf"\b{word}\b", user_prompt.lower()):
        # Блокировка промптов, содержащих чувствительную информацию
        output = {
            "decision": "block",
            "reason": f"Промпт содержит чувствительную информацию '{word}'. Пожалуйста, удалите чувствительный контент и отправьте снова.",
            "hookSpecificOutput": {
                "hookEventName": "UserPromptSubmit"
            }
        }
        print(json.dumps(output))
        exit(0)

# Проверка длины промпта и добавление предупреждающего контекста, если слишком длинный
if len(user_prompt) > 1000:
    output = {
        "hookSpecificOutput": {
            "hookEventName": "UserPromptSubmit",
            "additionalContext": "Примечание: Пользователь отправил длинный промпт. Пожалуйста, прочитайте внимательно и убедитесь, что все требования поняты."
        }
    }
    print(json.dumps(output))
    exit(0)

# Нет обработки для нормальных случаев
exit(0)
```

## Диагностика

- Проверьте логи приложения для деталей выполнения хука
- Убедитесь в разрешениях скрипта хука и исполняемости
- Обеспечьте правильное форматирование JSON в выводах хука
- Используйте специфичные шаблоны matcher для предотвращения непреднамеренного выполнения хука
- Используйте режим `--debug` для просмотра детальной информации о сопоставлении и выполнении хука
- Временно отключите все хуки: добавьте `"disableAllHooks": true` в настройки
