# Agent Arena

> Отправляйте несколько AI-моделей одновременно на выполнение одной и той же задачи, сравнивайте их решения бок о бок и выбирайте лучший результат для применения к вашему workspace.

:::warning
Agent Arena экспериментален. Имеет [известные ограничения](#limitations) вокруг режимов отображения и управления сессиями.
:::

Agent Arena позволяет вам натравливать несколько AI-моделей друг на друга на одну и ту же задачу. Каждая модель запускается как полностью независимый агент в своём собственном изолированном Git worktree, поэтому операции с файлами никогда не мешают друг другу. Когда все агенты завершаются, вы сравниваете результаты и выбираете победителя для слияния обратно в ваш основной workspace.

В отличие от [subagents](sub-agents.md), которые делегируют сфокусированные подзадачи в рамках одной сессии, агенты Arena — это полные, независимые экземпляры агентов верхнего уровня — каждый со своей собственной моделью, контекстным окном и полным доступом к инструментам.

## Когда использовать Agent Arena

Agent Arena наиболее эффективен, когда вы хотите **оценить или сравнить**, как разные модели решают одну и ту же проблему. Сильнейшие варианты использования:

- **Бенчмаркинг моделей**: Оценивайте возможности разных моделей на реальных задачах в вашей фактической кодовой базе, а не на синтетических бенчмарках
- **Выбор лучшего из N**: Получайте несколько независимых решений и выбирайте лучшую реализацию
- **Исследование подходов**: Смотрите, как разные модели рассуждают о и решают одну и ту же проблему — полезно для обучения и понимания
- **Снижение риска**: Для критических изменений проверяйте, что несколько моделей сходятся на похожем подходе перед коммитом

Agent Arena использует значительно больше токенов, чем одна сессия (каждый агент имеет своё собственное контекстное окно и вызовы модели). Лучше всего работает, когда ценность сравнения оправдывает стоимость. Для рутинных задач, где вы доверяете своей модели по умолчанию, одна сессия более эффективна.

## Запуск сессии arena

Используйте slash-команду `/arena` для запуска сессии. Укажите модели, которые хотите заставить соревноваться, и задачу:

```
/arena --models qwen3.5-plus,glm-5,kimi-k2.5 "Рефакторинг модуля аутентификации для использования JWT-токенов"
```

Если вы опустите `--models`, появится интерактивный диалог выбора модели, позволяющий вам выбрать из настроенных провайдеров.

### Что происходит при запуске

1. **Настройка worktree**: Nessy CLI создаёт изолированные Git worktrees для каждого агента в `~/.nessy/arena/<session-id>/worktrees/<model-name>/`. Каждый worktree зеркально отражает состояние вашего текущего working directory точно — включая staged изменения, unstaged изменения и untracked файлы.
2. **Спавн агентов**: Каждый агент запускается в своём собственном worktree с полным доступом к инструментам и своей настроенной моделью. Агенты запускаются последовательно, но выполняются параллельно.
3. **Выполнение**: Все агенты работают над задачей независимо без общего состояния или коммуникации. Вы можете отслеживать их прогресс и взаимодействовать с любым из них.
4. **Завершение**: Когда все агенты завершаются (или падают), вы входите в фазу сравнения результатов.

## Взаимодействие с агентами

### Режимы отображения

Agent Arena в настоящее время поддерживает **in-process режим**, где все агенты выполняются асинхронно в рамках одного и того же процесса терминала. Панель вкладок внизу терминала позволяет вам переключаться между агентами.

:::note
**Режимы отображения с разделёнными панелями запланированы на будущее.** Мы планируем поддерживать макеты на основе tmux и iTerm2 с разделёнными панелями, где каждый агент получает свою собственную панель терминала для настоящего параллельного просмотра. В настоящее время доступно только переключение вкладок in-process.
:::

### Навигация между агентами

В in-process режиме используйте комбинации клавиш для переключения между представлениями агентов:

| Клавиша | Действие                                   |
| :------ | :----------------------------------------- |
| `Right` | Переключиться на следующую вкладку агента  |
| `Left`  | Переключиться на предыдущую вкладку агента |
| `Up`    | Переключить фокус на поле ввода            |
| `Down`  | Переключить фокус на панель вкладок агента |

Панель вкладок показывает текущий статус каждого агента:

| Индикатор | Значение             |
| :-------- | :------------------- |
| `●`       | Выполняется или idle |
| `✓`       | Успешно завершён     |
| `✗`       | Упал                 |
| `○`       | Отменён              |

### Взаимодействие с отдельными агентами

При просмотре вкладки агента вы можете:

- **Отправлять сообщения** — печатайте в области ввода, чтобы дать агенту дополнительные инструкции
- **Утверждать вызовы инструментов** — если агент запрашивает утверждение инструмента, диалог подтверждения появляется на его вкладке
- **Просматривать полную историю** — прокручивайте полную историю разговора агента, включая вывод модели, вызовы инструментов и результаты

Каждый агент — это полная, независимая сессия. Всё, что вы можете сделать с основным агентом, вы можете сделать с агентом arena.

## Сравнение результатов и выбор победителя

Когда все агенты завершаются, Arena входит в фазу сравнения результатов. Вы увидите:

- **Сводка статуса**: Какие агенты успешно завершились, упали или были отменены
- **Метрики выполнения**: Длительность, раунды рассуждений, использование токенов и количество вызовов инструментов для каждого агента
- **Сводка сравнения Arena**: Файлы, изменённые совместно vs. только одним агентом, количество изменений строк, эффективность токенов и высокоуровневое резюме подхода, сгенерированное из diff каждого агента, метрик и истории разговора

Диалог выбора представляет успешные агенты. Выберите один для применения его изменений к вашему основному workspace или отбросьте все результаты. Нажмите `p` для переключения быстрого предпросмотра для выделенного агента или `d` для переключения детального diff этого агента перед выбором победителя.

### Что происходит при выборе победителя

1. Изменения победившего агента извлекаются как diff против базовой линии
2. Diff применяется к вашему основному working directory
3. Все worktrees и временные ветки автоматически очищаются

Если вы хотите проверить полный путь рассуждений перед решением, полная история разговора каждого агента всё ещё доступна через панель вкладок, пока активен диалог выбора.

## Конфигурация

Поведение Arena может быть настроено в [settings.json](../configuration/settings.md):

```json
{
  "arena": {
    "worktreeBaseDir": "~/.nessy/arena",
    "maxRoundsPerAgent": 50,
    "timeoutSeconds": 600
  }
}
```

| Настройка                 | Описание                                              | Значение по умолчанию |
| :------------------------ | :---------------------------------------------------- | :-------------------- |
| `arena.worktreeBaseDir`   | Базовая директория для worktrees arena                | `~/.nessy/arena`      |
| `arena.maxRoundsPerAgent` | Максимальное количество раундов рассуждений на агента | `50`                  |
| `arena.timeoutSeconds`    | Таймаут для каждого агента в секундах                 | `600`                 |

## Лучшие практики

### Выбирайте модели, которые дополняют друг друга

Arena наиболее ценна, когда вы сравниваете модели со значимо разными сильными сторонами. Например:

```
/arena --models qwen3.5-plus,glm-5,kimi-k2.5 "Оптимизация слоя запросов БД"
```

Сравнение трёх версий одного и того же семейства моделей даёт меньше понимания, чем сравнение между провайдерами.

### Делайте задачи самодостаточными

Агенты Arena работают независимо без коммуникации. Задачи должны быть полностью описуемы в подсказке без необходимости back-and-forth:

**Хорошо**: "Рефакторинг платежного модуля для использования паттерна strategy. Обновить все тесты."

**Менее эффективно**: "Давайте обсудим, как улучшить платежный модуль" — это выигрывает от разговора, что лучше подходит для одной сессии.

### Ограничивайте количество агентов

До 5 агентов могут выполняться одновременно. На практике 2-3 агента обеспечивают лучший баланс ценности сравнения к стоимости ресурсов. Больше агентов означает:

- Более высокие затраты токенов (каждый агент имеет своё собственное контекстное окно)
- Более длительное общее время выполнения
- Больше результатов для сравнения

Начните с 2-3 и масштабируйтесь вверх, только когда ценность сравнения оправдывает это.

### Используйте Arena для решений с высоким воздействием

Arena сияет, когда ставки оправдывают запуск нескольких моделей:

- Выбор архитектуры для нового модуля
- Выбор подхода для сложного рефакторинга
- Проверка критического исправления бага с нескольких сторон

Для рутинных изменений, таких как переименование переменной или обновление конфигурационного файла, одна сессия быстрее и дешевле.

## Troubleshooting

### Агенты не запускаются

- Проверьте, что каждая модель в `--models` правильно настроена с валидными API-учётными данными
- Проверьте, что ваш working directory является Git-репозиторием (worktrees требуют Git)
- Убедитесь, что у вас есть права на запись в базовую директорию worktree (`~/.nessy/arena/` по умолчанию)

### Ошибки создания worktree

- Запустите `git worktree list` для проверки на устаревшие worktrees от предыдущих сессий
- Очистите устаревшие worktrees с `git worktree prune`
- Убедитесь, что ваша версия Git поддерживает worktrees (`git --version`, требуется Git 2.5+)

### Агент занимает слишком много времени

- Увеличьте таймаут: установите `arena.timeoutSeconds` в настройках
- Уменьшите сложность задачи — задачи Arena должны быть сфокусированными и хорошо определёнными
- Уменьшите `arena.maxRoundsPerAgent`, если агенты проводят слишком много раундов

### Применение победителя не удаётся

- Проверьте на uncommitted изменения в вашем основном working directory, которые могут конфликтовать
- Diff применяется как патч — возможны merge-конфликты, если ваш working directory изменился во время сессии

## Ограничения

Agent Arena экспериментален. Текущие ограничения:

- **Только in-process режим**: Отображение с разделёнными панелями через tmux или iTerm2 ещё не доступно. Все агенты выполняются в одном окне терминала с переключением вкладок.
- **Нет предпросмотра diff перед выбором**: Вы можете просматривать историю разговора каждого агента, но нет унифицированного просмотрщика diff для сравнения решений бок о бок перед выбором победителя.
- **Нет сохранения worktree**: Worktrees всегда очищаются после выбора. Нет опции сохранить их для дальнейшего осмотра.
- **Нет возобновления сессии**: Сессии Arena не могут быть возобновлены после выхода. Если вы закрываете терминал в середине сессии, worktrees остаются на диске и должны быть очищены вручную через `git worktree prune`.
- **Максимум 5 агентов**: Жёсткий лимит 5 одновременных агентов не может быть изменён.
- **Требуется Git-репозиторий**: Arena требует Git-репозиторий для изоляции worktree. Не может использоваться в не-Git директориях.

## Сравнение с другими режимами нескольких агентов

Agent Arena — один из нескольких запланированных режимов нескольких агентов в Nessy CLI. **Agent Team** и **Agent Swarm** ещё не реализованы — таблица ниже описывает их предполагаемый дизайн для справки.

|                  | **Agent Arena**                                                    | **Agent Team** (запланировано)                         | **Agent Swarm** (запланировано)                                          |
| :--------------- | :----------------------------------------------------------------- | :----------------------------------------------------- | :----------------------------------------------------------------------- |
| **Цель**         | Соревновательная: найти лучшее решение для _одной и той же_ задачи | Коллаборативная: решать _разные_ аспекты вместе        | Пакетный параллельный: динамически создавать воркеров для пакетных задач |
| **Агенты**       | Предварительно настроенные модели соревнуются независимо           | Товарищи по команде сотрудничают с назначенными ролями | Воркеры создаются на лету, уничтожаются по завершении                    |
| **Коммуникация** | Нет меж-агентной коммуникации                                      | Прямые peer-to-peer сообщения                          | Односторонняя: результаты агрегируются родителем                         |
| **Изоляция**     | Полная: отдельные Git worktrees                                    | Независимые сессии с общим списком задач               | Лёгкий эфемерный контекст на воркера                                     |
| **Вывод**        | Одно выбранное решение применяется к workspace                     | Синтезированные результаты с нескольких перспектив     | Агрегированные результаты из параллельной обработки                      |
| **Лучше для**    | Бенчмаркинг, выбор между подходами моделей                         | Исследование, сложная коллаборация, межслойная работа  | Пакетные операции, обработка данных, map-reduce задачи                   |

## Следующие шаги

Исследуйте связанные подходы для параллельной и делегированной работы:

- **Лёгкое делегирование**: [Subagents](sub-agents.md) обрабатывают сфокусированные подзадачи в рамках вашей сессии — лучше, когда вам не нужно сравнение моделей
- **Ручные параллельные сессии**: Запускайте несколько сессий Nessy CLI сами в отдельных терминалах с [Git worktrees](https://git-scm.com/docs/git-worktree) для полного ручного контроля
