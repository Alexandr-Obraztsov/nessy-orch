# Режим утверждения (Approval Mode)

Nessy CLI предлагает четыре различных режима разрешений, которые позволяют вам гибко контролировать, как AI взаимодействует с вашим кодом и системой в зависимости от сложности задачи и уровня риска.

## Сравнение режимов разрешений

| Режим         | Редактирование файлов           | Команды оболочки                | Лучше всего подходит для                                                                                          | Уровень риска |
| ------------- | ------------------------------- | ------------------------------- | ----------------------------------------------------------------------------------------------------------------- | ------------- |
| **Plan**      | ❌ Только read-only анализ      | ❌ Не выполняются               | • Исследование кода <br/>• Планирование сложных изменений <br/>• Безопасный код-ревью                             | Самый низкий  |
| **Default**   | ✅ Требуется ручное утверждение | ✅ Требуется ручное утверждение | • Новые/незнакомые кодовые базы <br/>• Критические системы <br/>• Командная работа <br/>• Обучение и преподавание | Низкий        |
| **Auto-Edit** | ✅ Авто-одобрено                | ❌ Требуется ручное утверждение | • Ежедневные задачи разработки <br/>• Рефакторинг и улучшения кода <br/>• Безопасная автоматизация                | Средний       |
| **Auto**      | ✅ Оценивается классификатором  | ✅ Оценивается классификатором  | • Долгие автономные сессии <br/>• Когда Auto-Edit слишком осторожен                                               | Средний       |

### Краткое руководство

- **Начните в Plan Mode**: Отлично для понимания перед внесением изменений
- **Работайте в Default Mode**: Сбалансированный выбор для большинства задач разработки
- **Переключитесь на Auto-Edit**: Когда делаете много безопасных изменений кода
- **Попробуйте Auto Mode**: Когда хотите меньше прерываний, но всё ещё нужна безопасность для команд оболочки и сетевых вызовов — LLM-классификатор оценивает каждый вызов

:::tip
Вы можете быстро переключаться между режимами во время сессии с помощью **Shift+Tab** (или **Tab** на Windows). Статус-бар терминала показывает ваш текущий режим, поэтому вы всегда знаете, какие разрешения есть у Nessy CLI.
:::

## 1. Используйте Plan Mode для безопасного анализа кода

Plan Mode инструктирует Nessy CLI создавать план, анализируя кодовую базу с помощью **read-only** операций, идеально подходит для исследования кодовых баз, планирования сложных изменений или безопасного ревью кода.

### Когда использовать Plan Mode

- **Многошаговая реализация**: Когда ваша функция требует редактирования многих файлов
- **Исследование кода**: Когда вы хотите тщательно исследовать кодовую базу перед изменением чего-либо
- **Интерактивная разработка**: Когда вы хотите итерировать направление с Nessy CLI

### Как использовать Plan Mode

**Включите Plan Mode во время сессии**

Вы можете переключиться в Plan Mode во время сессии, используя **Shift+Tab** (или **Tab** на Windows) для переключения режимов разрешений.

Если вы в Normal Mode, **Shift+Tab** (или **Tab** на Windows) сначала переключается в `auto-edits` Mode, обозначается `⏵⏵ accept edits on` внизу терминала. Последующий **Shift+Tab** (или **Tab** на Windows) переключится в Plan Mode, обозначается `⏸ plan mode`.

**Используйте команду `/plan`**

Команда `/plan` предоставляет быструю команду для входа и выхода из Plan Mode:

```bash
/plan                          # Войти в plan mode
/plan refactor the auth module # Войти в plan mode и начать планирование
/plan exit                     # Выйти из plan mode, восстановить предыдущий режим
```

Когда вы выходите из Plan Mode с `/plan exit`, ваш предыдущий режим утверждения автоматически восстанавливается (например, если вы были в Auto-Edit перед входом в Plan Mode, вы вернётесь в Auto-Edit).

**Начните новую сессию в Plan Mode**

Чтобы начать новую сессию в Plan Mode, используйте `/approval-mode`, затем выберите `plan`

```bash
/approval-mode
```

**Запустите "headless" запросы в Plan Mode**

Вы также можете запустить запрос в Plan Mode напрямую с `-p` или `prompt`:

```bash
nessy --prompt "What is machine learning?"
```

### Пример: Планирование сложного рефакторинга

```bash
/plan I need to refactor our authentication system to use OAuth2. Create a detailed migration plan.
```

Nessy CLI входит в Plan Mode и анализирует текущую реализацию для создания комплексного плана. Уточняйте с follow-ups:

```
What about backward compatibility?
How should we handle database migration?
```

### Настройте Plan Mode по умолчанию

```json
// .nessy/settings.json
{
  "permissions": {
    "defaultMode": "plan"
  }
}
```

## 2. Используйте Default Mode для контролируемого взаимодействия

Default Mode — это стандартный способ работы с Nessy CLI. В этом режиме вы сохраняете полный контроль над всеми потенциально рискованными операциями — Nessy CLI будет запрашивать ваше утверждение перед внесением любых изменений файлов или выполнением команд оболочки.

### Когда использовать Default Mode

- **Новичок в кодовой базе**: Когда вы исследуете незнакомый проект и хотите быть особенно осторожным
- **Критические системы**: Когда работаете с продакшен-кодом, инфраструктурой или чувствительными данными
- **Обучение и преподавание**: Когда вы хотите понять каждый шаг, который делает Nessy CLI
- **Командная работа**: Когда несколько человек работают над одной кодовой базой
- **Сложные операции**: Когда изменения включают несколько файлов или сложную логику

### Как использовать Default Mode

**Включите Default Mode во время сессии**

Вы можете переключиться в Default Mode во время сессии, используя **Shift+Tab** (или **Tab** на Windows) для переключения режимов разрешений. Если вы в любом другом режиме, нажатие **Shift+Tab** (или **Tab** на Windows) в конечном итоге вернётся к Default Mode, обозначается отсутствием любого индикатора режима внизу терминала.

**Начните новую сессию в Default Mode**

Default Mode — это начальный режим при запуске Nessy CLI. Если вы изменили режимы и хотите вернуться к Default Mode, используйте:

```
/approval-mode default
```

**Запустите "headless" запросы в Default Mode**

При запуске headless-команд Default Mode является поведением по умолчанию. Вы можете явно указать это с:

```
nessy --prompt "Analyze this code for potential bugs"
```

### Пример: Безопасная реализация функции

```
/approval-mode default
```

```
I need to add user profile pictures to our application. The pictures should be stored in an S3 bucket and the URLs saved in the database.
```

Nessy CLI проанализирует вашу кодовую базу и предложит план. Затем запросит утверждение перед:

1. Созданием новых файлов (контроллеры, модели, миграции)
2. Изменением существующих файлов (добавление новых столбцов, обновление API)
3. Запуском любых команд оболочки (миграции БД, установка зависимостей)

Вы можете просмотреть каждое предложенное изменение и утвердить или отклонить его индивидуально.

### Настройте Default Mode по умолчанию

```bash
// .nessy/settings.json
{
  "permissions": {
    "defaultMode": "default"
  }
}
```

## 3. Режим Auto Edits

Auto-Edit Mode инструктирует Nessy CLI автоматически утверждать редактирование файлов, требуя ручного утверждения для команд оболочки, идеально для ускорения рабочих процессов разработки при сохранении безопасности системы.

### Когда использовать режим Auto-Accept Edits

- **Ежедневная разработка**: Идеально для большинства задач кодирования
- **Безопасная автоматизация**: Позволяет AI изменять код, предотвращая случайное выполнение опасных команд
- **Командная работа**: Используйте в общих проектах, чтобы избежать непреднамеренного влияния на других

### Как переключиться в этот режим

```
# Переключить через команду
/approval-mode auto-edit

# Или использовать комбинацию клавиш
Shift+Tab (или Tab на Windows) # Переключить из других режимов
```

### Пример рабочего процесса

1. Вы просите Nessy CLI рефакторить функцию
2. AI анализирует код и предлагает изменения
3. **Автоматически** применяет все изменения файлов без подтверждения
4. Если тесты нужно запустить, запросит **утверждение** для выполнения `npm test`

## 4. Auto Mode — утверждение на основе классификатора

Auto Mode находится после Auto-Edit. LLM-классификатор оценивает каждую
команду оболочки, сетевой вызов и редактирование вне рабочего пространства и
автоматически одобряет те, которые считает безопасными, блокируя рискованные.
Большинство операций только для чтения и редактирования в рабочем пространстве
обходят классификатор ради скорости.

Полную документацию смотрите в [auto-mode.md](./auto-mode.md) (настройка
подсказок, устранение неполадок, FAQ).

### Когда использовать Auto Mode

- **Долгие автономные сессии**: когда Default Mode слишком часто прерывает.
- **Доверенные проекты**: внутренние кодовые базы, где агент должен
  продолжать работу, но вы всё ещё хотите страховку от разрушительных команд
  оболочки и исходящих сетевых вызовов.
- **Запуски без интерфейса / по расписанию**: где Auto-Edit недостаточно (агенту
  нужно выполнять команды оболочки), но вы хотите безопасности от `rm -rf /`,
  `curl ... | sh`, утечки учётных данных и т.п.

### Как использовать Auto Mode

**Включите Auto Mode во время сессии**

Нажмите **Shift+Tab** (или **Tab** на Windows) для переключения в Auto Mode.
Статус-бар показывает активный режим.

**Используйте команду `/approval-mode`**

```
/approval-mode auto
```

При первом входе в Auto Mode информационное сообщение объясняет, как он работает.
Уведомление больше не появляется.

**Начните новую сессию в Auto Mode**

```jsonc
// .nessy/settings.json
{
  "tools": {
    "approvalMode": "auto",
  },
}
```

### Что Auto Mode одобряет автоматически, а что блокирует

Классификатор склонен блокировать при сомнениях. Значения по умолчанию:

- **Авто-одобрено**: команды только для чтения (ls, cat, git status, grep, find),
  установка пакетов в cwd, команды сборки/тестирования, редактирование файлов
  внутри рабочего пространства, локальные операции.
- **Заблокировано**: необратимое разрушение (rm -rf /, fdisk, mkfs),
  выполнение кода извне (curl | sh, eval удалённого контента),
  утечка учётных данных, несанкционированная персистентность (редактирование
  .bashrc, crontab), ослабление безопасности, force-push в main/master.

Вы можете настроить суждение классификатора через подсказки на естественном
языке в settings.json. Смотрите [auto-mode.md](./auto-mode.md#configuring-hints).

### Страховочные ограничители

- **Жёсткие правила остаются в силе**: правила `permissions.deny` блокируют
  действия до запуска классификатора.
- **Слишком широкие правила allow отключаются в Auto Mode**: например,
  `permissions.allow: ["Bash"]` (разрешить все команды оболочки) обходит
  классификатор; вход в Auto Mode временно отключает такие правила, чтобы
  классификатор мог работать. Правила восстанавливаются при выходе из Auto
  Mode. Настройки на диске никогда не изменяются.
- **Отказ в закрытом состоянии**: когда API классификатора недоступен, действие
  блокируется, а не разрешается. После двух последовательных недоступных вызовов
  следующий вызов инструмента возвращается к ручному утверждению.
- **Защита от цикла**: после трёх последовательных блокировок политикой
  следующий вызов также возвращается к ручному утверждению, чтобы агент не
  застрял в цикле безрезультатного подхода.

### Пример

```
/approval-mode auto
Рефакторинг модуля аутентификации для использования OAuth2. Запустить полный набор тестов после.
```

Nessy CLI вносит изменения в файлы (редактирование в рабочем пространстве обходит
классификатор), запускает `npm test` (классификатор считает безопасным) и
показывает блокировку, если когда-либо пытается сделать что-то рискованное,
например `rm -rf /Users/me/.aws`. Вы можете просмотреть причину inline и решить,
переключаться ли в Default Mode для этого шага.

### Настройте Auto Mode по умолчанию

```jsonc
// .nessy/settings.json
{
  "tools": {
    "approvalMode": "auto",
  },
  "permissions": {
    "autoMode": {
      "hints": {
        "allow": ["Запуск pytest, mypy и ruff на этом Python-репозитории"],
        "deny": ["Любые сетевые вызовы на intranet.example.com"],
      },
      "environment": ["Open-source монорепозиторий; коммиты подписаны"],
    },
  },
}
```

## Переключение режимов и конфигурация

### Переключение комбинациями клавиш

Во время сессии Nessy CLI используйте **Shift+Tab** (или **Tab** на Windows) для быстрого переключения между четырьмя режимами:

```
Plan Mode → Default Mode → Auto-Edit Mode → Auto Mode → Plan Mode
```

### Постоянная конфигурация

```
// Проектный уровень: ./.nessy/settings.json
// Пользовательский уровень: ~/.nessy/settings.json
{
  "permissions": {
    "defaultMode": "auto-edit",  // или "plan", "default", "auto"
    "confirmShellCommands": true,
    "confirmFileEdits": true
  }
}
```

### Рекомендации по использованию режимов

1. **Новичок в кодовой базе**: Начните с **Plan Mode** для безопасного исследования
2. **Ежедневные задачи разработки**: Используйте **Auto-Edit** (режим по умолчанию), эффективно и безопасно
3. **Автономные сессии**: Используйте **Auto Mode** для баланса между автоматизацией и безопасностью
4. **Сложный рефакторинг**: Сначала используйте **Plan Mode** для детального планирования, затем переключитесь на соответствующий режим для выполнения
