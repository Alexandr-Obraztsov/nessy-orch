# Auto Mode

Auto Mode использует LLM-классификатор для оценки каждого вызова инструмента и принятия решения об автоматическом одобрении. Он находится между Auto-Edit (который автоматически одобряет только редактирование файлов) и YOLO (который автоматически одобряет всё).

Эта страница — справочник по настройке и диагностике Auto Mode. Введение см. в [Обзоре режимов одобрения](./approval-mode.md#4-auto-mode---classifier-driven-approval).

## Как это работает

Когда вы находитесь в Auto Mode и агент пытается запустить инструмент, Nessy CLI проходит три уровня по порядку:

1. **Быстрый путь acceptEdits** — Edit / Write, целевой путь которых находится в рабочем пространстве, автоматически одобряются без вызова классификатора.
2. **Список разрешений Safe-tool** — Встроенные инструменты только для чтения и метаданных (Read, Grep, Glob, LS, LSP, TodoWrite, AskUserQuestion и т.д.) автоматически одобряются без вызова классификатора.
3. **LLM-классификатор** — Всё остальное (shell-команды, web fetches, запуск sub-agent, редактирование вне рабочего пространства, MCP-инструменты) отправляется на двухэтапный классификатор:
   - **Этап 1 (быстрый)** — выдаёт только `{ shouldBlock }`. Около ~300 мс. Если `shouldBlock` равен `false`, действие разрешается и вызов продолжается.
   - **Этап 2 (обдумывание)** — запускается только когда Этап 1 сказал блокировать. Использует chain-of-thought обзор для уменьшения ложных срабатываний Этапа 1. Может понизить блокировку Этапа 1 до разрешения. Выдаёт видимое пользователю сообщение `reason` при блокировке.

Классификатор использует вашу настроенную быструю модель (`/model --fast`). Если быстрая модель не настроена, используется основная модель сессии.

## Жёсткие правила всё ещё главнее

Auto Mode **не заменяет** жёсткие правила разрешений. Перед запуском классификатора:

- Правила `permissions.deny` блокируют действие с причиной из правила. Классификатор никогда не видит это.
- Правила `permissions.allow` с конкретными спецификаторами (например `Bash(git status)`, `Read(./docs/**)`) всё ещё автоматически разрешаются без классификатора.
- Правила `permissions.ask` требуют ручного подтверждения даже в Auto Mode.

## Широкие правила разрешений удаляются в Auto Mode

Правила типа следующих позволили бы агенту выполнять произвольный код без проверки классификатором:

- `Bash` / `Bash(*)` / `Bash()` — автоматическое разрешение любой shell-команды
- `Bash(python:*)`, `Bash(node*)`, `Bash(bash*)` — wildcards интерпретаторов
- `Agent` / `Agent(coder)` — любое разрешение на инструмент `Agent`
- `Skill` / `Skill(pdf)` — любое разрешение на инструмент `Skill`

При входе в Auto Mode Nessy CLI временно удаляет эти правила из активного набора разрешений и выводит сообщение со списком. Правила возвращаются сразу после выхода из Auto Mode. `settings.json` никогда не модифицируется.

## Настройка подсказок

Auto Mode читает `permissions.autoMode` из вашего `settings.json`. Записи — это описания на естественном языке, не шаблоны правил — они внедряются аддитивно в системный промпт классификатора вместе со встроенными значениями по умолчанию.

```json
{
  "permissions": {
    "autoMode": {
      "hints": {
        "allow": [
          "Запуск poetry install и poetry update в этом Python-проекте",
          "Очистка артефактов сборки под ./dist или ./build",
          "Чтение любого файла под /Users/me/code/"
        ],
        "deny": [
          "Любой сетевой вызов к intranet.example.com endpoints",
          "Изменение чего-либо под ~/.ssh или ~/.aws",
          "Запуск скриптов миграции, касающихся production БД"
        ]
      },
      "environment": [
        "Это приватный монорепозиторий со строгой подписью коммитов",
        "Production учётные данные живут в 1Password, никогда в обычных файлах"
      ]
    }
  }
}
```

### Ограничения длины и количества

Чтобы системный промпт классификатора оставался небольшим:

- Каждая запись ограничена 200 символами (более длинные записи обрезаются с предупреждением).
- `hints.allow` и `hints.deny` принимают до 50 записей каждая.
- `environment` принимает до 20 записей.

### Объединение через файлы настроек

`autoMode` объединяется через системные / пользовательские / рабочие настройки так же, как другие настройки разрешений: массивы конкатенируются и дедуплицируются.

## Чтение решения

Когда классификатор блокирует действие, вызов инструмента падает с одним из следующих текстов ошибок:

- **`Blocked by auto mode policy: <reason>`** — классификатор счёл действие небезопасным. Причина поступает с Этапа 2 классификатора.
- **`Auto mode classifier unavailable; action blocked for safety`** — классификатор API недоступен, таймаут или вернул не парсящийся ответ. Это поведение fail-closed: при сомнениях — блокировать.

Основная LLM видит то же сообщение в результате инструмента и корректирует подход (спрашивает вас, переключает тактику, сдаётся).

### Язык причин классификатора

Причины классификатора выдаются LLM и не переводятся. Если нужны причины на другом языке, добавьте подсказку типа `Respond reasons in Chinese` в `permissions.autoMode.environment`.

## Возврат к ручному одобрению

Auto Mode защищает от зависаний:

- После **3 последовательных блокировок политики** следующий вызов инструмента возвращается к стандартному запросу ручного одобрения. Это ловит случай, когда агент продолжает пробовать минорные варианты запрещённой команды.
- После **2 последовательных недоступностей** (сбои API классификатора) следующий вызов инструмента также возвращается к ручному одобрению. Это избегает ожидания сломанного классификатора.

Сессия остаётся в Auto Mode — только один fallback вызов проходит через ручное одобрение. Счётчики сбрасываются при одобрении fallback или переключении режимов.

Если вы постоянно попадаете в fallback, наиболее вероятные причины — сбой API классификатора или подсказки нуждаются в настройке. Переключитесь на Default Mode для диагностики.

## Диагностика

**"Auto Mode продолжает блокировать мои команды"**

Посмотрите причину в сообщении об ошибке. Если классификатор слишком консервативен для вашего контекста, добавьте запись в `permissions.autoMode.hints.allow`, описывающую паттерн на естественном языке. Примеры:

- `"Сборка Docker-образов для этого проекта (docker build ...)"`
- `"Запуск миграций БД против локальной тестовой БД"`

**"Auto mode classifier unavailable"**

API классификатора не ответил. Возможные причины:

- Сетевая проблема между вами и endpoint модели.
- Настроенная быстрая модель больше недоступна — проверьте `/model --fast`.
- Транскрипт слишком длинный и превышает окно контекста быстрой модели.

Во время диагностики переключитесь на Default Mode: `/approval-mode default`.

**"Falling back to manual approval"**

Вы достигли либо 3-последовательных-блокировок, либо 2-последовательных-недоступностей. Одобрите или отклоните запрос как обычно. После одного одобренного fallback счётчик последовательных сбрасывается.

**Классификатор видит чувствительные данные в моих промптах**

Входы инструментов проецируются через метод `toAutoClassifierInput` каждого инструмента перед отправкой классификатору. Длинный контент редактирования, промпты web fetch и промпты sub-agent обрезаются. Результаты инструментов (содержимое файлов, веб-страницы) никогда не отправляются классификатору — только текст пользователя и вызовы использования инструментов ассистентом проходят через.

Если конкретный инструмент раскрывает поля, которые вы предпочли бы скрыть, создайте issue с именем инструмента; проекция на инструмент и предназначена для ужесточения со временем.

## Ограничения

- **Не работает офлайн.** Классификатор требует LLM-вызова.
- **Добавляет задержку на медленном пути.** `Allowlist` + acceptEdits покрывают большинство вызовов без задержки, но `run_shell_command` обычно добавляет ~300 мс (быстрый путь классификатора) или ~3-5 с (медленный путь с обдумыванием).
- **Не замена правилам `deny`.** Классификатор best-effort. Для команд, которые точно никогда не должны запускаться, поместите их в `permissions.deny`.
- **MCP-инструменты по умолчанию консервативно блокируются.** Сторонние MCP-инструменты (`mcp__*`) opt-in к пересылке аргументов через переопределение `toAutoClassifierInput`. Инструменты, не прошедшие opt-in, раскрывают классификатору только своё имя — большинство таких вызовов консервативно блокируются, если вы не написали явное правило `allow`. Это fail-closed по дизайну (учётные данные и объёмный контент не утекают в LLM классификатора). Если вы доверяете конкретному MCP-инструменту, добавьте `permissions.allow: ["mcp__server__tool"]`, чтобы он обходил классификатор полностью.

## FAQ

**Отправляет ли Auto Mode мой код третьей стороне?**

Auto Mode переиспользует вашу существующую конфигурацию модели — тот же endpoint, что и основной агент. Если вы настроили Nessy CLI на использование self-hosted модели, классификатор также запускается против этого endpoint.

**Попадут ли мои секреты / содержимое `.env` в классификатор?**

Классификатор видит только то, что раскрывает проекция `toAutoClassifierInput` каждого инструмента:

- `read_file` и другие инструменты только для чтения: не вызываются (они на быстром пути allowlist).
- `edit` / `write_file`: file_path плюс первые 80 символов старого/нового контента. Полный контент не пересылается.
- `run_shell_command`: полная команда (это необходимо — это то, что классификатор оценивает).
- `web_fetch`: только URL. Поле промпта не пересылается.
- `agent`: тип subagent плюс полный промпт. Промпт — это инструкция, которой будет следовать sub-agent, поэтому классификатору нужен он полностью для обнаружения атак, которые могли бы направить sub-agent к деструктивным действиям — та же причина, по которой `run_shell_command` пересылает полную команду.

Результаты инструментов (фактический контент, возвращённый инструментами) полностью удаляются из транскрипта классификатора.

MCP-инструменты (`mcp__*`) следуют более строгому значению по умолчанию: их параметры не пересылаются, если автор MCP-инструмента явно не opted-in через переопределение `toAutoClassifierInput`. Классификатор видит имя инструмента, но не аргументы, поэтому большинство вызовов MCP консервативно блокируются, если пользователь не написал явное правило allow. Это fail-closed по дизайну — сторонние инструменты не должны раскрывать учётные данные или объёмный контент файлов в LLM классификатора без намерения.

**Могу ли я отключить информационное сообщение первого раза?**

Оно показывается только один раз для файла пользовательских настроек. После отключения `ui.autoModeAcknowledged: true` устанавливается в ваших пользовательских настройках.

**Чем это отличается от Auto-Edit?**

Auto-Edit автоматически одобряет редактирование файлов и ничего больше — shell-команды всё ещё спрашивают. Auto Mode использует классификатор для также автоматического одобрения безопасных shell-команд и других вызовов инструментов, при этом блокируя рискованные.

**Чем это отличается от YOLO?**

YOLO автоматически одобряет всё без какой-либо проверки. Auto Mode использует классификатор и блокирует рискованные действия.
