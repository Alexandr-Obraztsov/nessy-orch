# Сводки использования инструментов

Nessy CLI может генерировать короткую метку в стиле заголовка `git`-коммита после завершения каждой группы инструментов, суммируя то, что группа выполнила. Метка появляется встроенной строкой в транскрипте и заменяет общий заголовок `Tool × N` в компактном режиме.

Это средство улучшения UX для параллельных вызовов инструментов: когда модель запускает несколько вызовов `Read` + `Grep` + `Bash` одновременно, сводка сообщает вам намерение с первого взгляда, вместо того чтобы заставлять вас просматривать список инструментов.

Функция включена по умолчанию и работает тихо в фоновом режиме. Требуется настроенная [быстрая модель](./followup-suggestions.md#быстрая-модель).

## Что вы видите

### Полный режим (по умолчанию)

Сводка появляется как тусклая строка-значок непосредственно под группой инструментов:

```
╭──────────────────────────────────────────────╮
│ ✓  ReadFile a.txt                            │
│ ✓  ReadFile b.txt                            │
│ ✓  ReadFile c.txt                            │
│ ✓  ReadFile d.txt                            │
╰──────────────────────────────────────────────╯

 ● Прочитано 4 текстовых файла
```

### Компактный режим (`Ctrl+O` или `ui.compactMode: true`)

Метка заменяет общий заголовок `Tool × N` в компактной одной строке:

```
╭────────────────────────────────────────────────╮
│✓  Прочитано `txt` файлов  · 4 инструмента      │
│Нажмите Ctrl+O для показа полного вывода        │
╰────────────────────────────────────────────────╯
```

Отдельные вызовы инструментов всё ещё находятся на расстоянии одного нажатия клавиши (`Ctrl+O` для переключения в полный режим).

## Как это работает

После завершения группы инструментов Nessy CLI выполняет асинхронный вызов к настроенной быстрой модели со следующими данными:

- Имена инструментов, усечённые аргументы и усечённые результаты (каждый ограничен 300 символами).
- Последний текстовый вывод ассистента (первые 200 символов) как префикс намерения.
- Системный промпт, инструктирующий модель вернуть метку в прошедшем времени длиной до 30 символов в стиле заголовка `git`-коммита.

Вызов выполняется параллельно с потоковой передачей `API` следующего хода, поэтому его задержка ~1 с скрыта за ответом основной модели. Когда метка становится готова, она добавляется в транскрипт как запись `tool_use_summary`.

Примеры меток: `Поиск в auth/`, `Исправлена NPE в UserService`, `Создан endpoint регистрации`, `Прочитан config.json`, `Запущены падающие тесты`.

## Когда появляется сводка

Сводка генерируется, когда выполняются **все** следующие условия:

- `experimental.emitToolUseSummaries` равен `true` (по умолчанию).
- Настроена `fastModel` (через настройки или `/model --fast`).
- Хотя бы один инструмент завершил выполнение в группе.
- Ход не был прерван до завершения инструментов.
- Быстрая модель вернула непустой ответ без ошибки.

Вызовы инструментов subagent не запускают генерацию сводки — только группы инструментов основной сессии.

## Когда сводка не появляется

Сводка молча пропускается (без ошибки, без изменений `UI`), когда:

- Не настроена быстрая модель.
- Вызов быстрой модели не удался, истёк по таймауту или вернул пустой результат.
- Модель вернула очевидную строку ошибки (например `Error: ...`, `I cannot ...`) — отфильтровано клиентом, чтобы UI не показывал вводящие в заблуждение метки.
- Ход был прерван (`Ctrl+C`) до завершения модели.

Во всех этих случаях группа инструментов отображается как обычно.

## Быстрая модель

Метка генерируется с использованием [быстрой модели](./followup-suggestions.md#быстрая-модель) — той же модели, которую вы настраиваете для подсказок и спекулятивного выполнения. Настройте её через:

### Через команду

```
/model --fast qwen3-coder-flash
```

### Через `settings.json`

```json
{
  "fastModel": "qwen3-coder-flash"
}
```

Когда быстрая модель не настроена, генерация сводок полностью пропускается — функция не работает, пока вы её не настроите.

## Конфигурация

Эти настройки могут быть настроены в `settings.json`:

| Настройка                           | Тип     | По умолчанию | Описание                                                                                                |
| ----------------------------------- | ------- | ------------ | ------------------------------------------------------------------------------------------------------- |
| `experimental.emitToolUseSummaries` | boolean | `true`       | Главный переключатель генерации сводок. Отключите, чтобы отключить дополнительный вызов быстрой модели. |
| `fastModel`                         | string  | `""`         | Быстрая модель для генерации сводок (совместно с подсказками). Требуется; не работает, если пусто.      |

### Переопределение через переменную окружения

`NESSY_CLI_EMIT_TOOL_USE_SUMMARIES` переопределяет настройку `experimental.emitToolUseSummaries` для текущей сессии:

- `NESSY_CLI_EMIT_TOOL_USE_SUMMARIES=0` или `=false` — принудительно отключить.
- `NESSY_CLI_EMIT_TOOL_USE_SUMMARIES=1` или `=true` — принудительно включить.
- Не установлено — использовать настройку `experimental.emitToolUseSummaries`.

### Пример

```json
{
  "fastModel": "qwen3-coder-flash",
  "experimental": {
    "emitToolUseSummaries": true
  }
}
```

## Область действия и жизненный цикл

Три момента, которые склонны запутывать при первом знакомстве с этой функцией:

1. **Одна генерация на группу, общая для обоих режимов отображения.** Вызов быстрой модели происходит ровно один раз в `handleCompletedTools`, когда группа инструментов завершается. Переключение `Ctrl+O` после этого **не** запускает новый вызов — оба режима читают из одной и той же записи истории `tool_use_summary`, которая была захвачена первый раз. Вы можете переключать компактный режим туда и обратно без дополнительной стоимости.

2. **Нет обратного заполнения при переключении или при возобновлении сессии.** `tool_group`, которая завершилась до включения функции (или до того, как вы включили настройку, или в возобновлённой сессии — `ChatRecordingService` не сохраняет записи сводок), никогда не получит метку. Нет прохода «обхода существующей истории». Если вы включите эту настройку в середине сессии, только _будущие_ группы покажут метку; старые группы сохранят отображение по умолчанию без индикатора того, что метка отсутствует.

3. **Только группы основного агента.** Триггер живёт в цикле хода основной сессии (`useGeminiStream`), поэтому:
   - ✅ `Shell`, MCP, файловые операции и вызов инструмента `Task` / `subagent` _сам по себе_ (как он появляется в основной группе) суммируются.
   - ❌ **Внутренние** группы инструментов subagent (запущенные через `packages/core/src/agents/runtime/`) не суммируются.

   Внешняя группа, которая _содержит_ инструмент `Task`, всё ещё будет помечена, но быстрая модель видит только вызов инструмента subagent и его агрегированный вывод — не отдельные вызовы инструментов внутри `subagent`. Ожидайте меток вроде `Запущен ``research`-agent``или`Делегирован поиск файлов`вместо`Поискано 14 файлов`. Это намеренно — суммирование внутренностей `subagent` умножило бы стоимость быстрой модели и поверхностный шум, который никогда не появляется в основном UI.

## Рекомендуемое сочетание: включите компактный режим

Для групп из 3+ параллельных вызовов инструментов сочетание этой функции с `ui.`compactMode`: true` даёт наиболее чистый транскрипт. Компактный вид сворачивает всю группу в одну помеченную строку (`✓  Прочитано txt файлов  · 4 инструмента`) вместо показа каждой строки инструмента плюс завершающей сводки. Детали остаются на расстоянии одного нажатия клавиши через `Ctrl+O`.

```json
{
  "fastModel": "qwen3-coder-flash",
  "ui": {
    "compactMode": true
  },
  "experimental": {
    "emitToolUseSummaries": true
  }
}
```

В полном режиме (по умолчанию) сводка отображается как завершающая строка `● <метка>` под группой инструментов — полезно для больших или разнородных групп, но для небольших однородных групп (например, ``Read` × 3`) метка может читаться как повторение видимых строк инструментов. Если это соответствует вашему обычному рабочему процессу, либо включите компактный режим как выше, либо полностью отключите сводку через `experimental.emitToolUseSummaries: false`.

## Мониторинг

Использование модели для сводок появляется в выводе `/stats` под общими токенами быстрой модели, с `prompt_id` `tool_use_summary_generation`, чтобы его можно было отличить от подсказок и других фоновых задач.

## Поток данных и конфиденциальность

Вызов сводки отправляет имя каждого успешного инструмента, усечённые `args` и усечённый результат (каждое поле ограничено 300 символами) в **быструю модель**, плюс первые 200 символов последнего текста ассистента как префикс намерения.

Если ваша быстрая модель настроена для того же провайдера/аутентификации, что и модель основной сессии, данные текут вдоль той же границы, которую уже использует основная сессия — никаких изменений в области доверия. Если вы настроили быструю модель от **другого провайдера**, входные и выходные данные инструментов (потенциально включая содержимое файлов, прочитанное через `read_file`, вывод команд из `shell`-вызовов или значения, полученные через инструменты MCP) будут отправлены этому другому провайдеру как часть промпта суммирования. Это строго большая область обмена данными, чем одна только основная сессия.

Если это важно для вашего рабочего процесса, у вас есть два чистых варианта:

- Настройте `fastModel` на модель под тем же провайдером, что и ваша основная сессия, чтобы вызов сводки не пересекал новую границу аутентификации/данных.
- Полностью отключите функцию через `experimental.emitToolUseSummaries: false` (или ``NESSY_CLI_EMIT_TOOL_USE_SUMMARIES`=0`).

Ограничение в 300 символов на поле ограничивает воздействие, но не устраняет его — секреты, обнаруженные в выводе инструментов во время окна ограничения, всё ещё могут быть отправлены. Относитесь к границе данных быстрой модели так же, как к границе основной модели.

## Стоимость

Один вызов быстрой модели на подходящую группу инструментов. Вход — небольшой фиксированный системный промпт плюс усечённые входы/выходы инструментов (каждое ограничено 300 символами на поле). Выход — одна короткая строка (ограничена 100 символами, обычно 20 токенов или меньше). На типичной быстрой модели это примерно $0,001 за группу.

Если вы не хотите дополнительной стоимости, отключите функцию через `experimental.emitToolUseSummaries: false` или ``NESSY_CLI_EMIT_TOOL_USE_SUMMARIES`=0`.

## Связанное

- [Подсказки](./followup-suggestions.md) — ещё одно улучшение UX, управляемое быстрой моделью, которое использует ту же настройку `fastModel`.
