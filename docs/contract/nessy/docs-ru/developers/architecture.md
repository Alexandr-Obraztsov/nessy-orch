# Обзор архитектуры Nessy CLI

Этот документ предоставляет высокоуровневый обзор архитектуры Nessy CLI.

## Основные компоненты

Nessy CLI в основном состоит из двух основных пакетов, а также набора инструментов, которые могут использоваться системой в ходе обработки командной строки:

### 1. CLI Package (`packages/cli`)

**Назначение:** Это содержит пользовательскую часть Nessy CLI, такую как обработка начального пользовательского ввода, представление конечного вывода и управление общим пользовательским опытом.

**Ключевые функции:**

- **Обработка ввода:** Обрабатывает пользовательский ввод через различные методы, включая прямой ввод текста, slash-команды (например, `/help`, `/clear`, `/model`), at-команды (`@file` для включения содержимого файла) и команды с восклицательным знаком (`!command` для выполнения команд оболочки).
- **Управление историей:** Поддерживает историю разговоров и включает такие функции, как возобновление сессии.
- **Отображение рендеринга:** Форматирует и представляет ответы пользователю в терминале с подсветкой синтаксиса и правильным форматированием.
- **Тема и кастомизация UI:** Поддерживает настраиваемые темы и элементы UI для персонализированного опыта.
- **Настройки конфигурации:** Управляет различными опциями конфигурации через JSON файлы настроек, переменные окружения и аргументы командной строки.

### 2. Core Package (`packages/core`)

**Назначение:** Это действует как бэкенд для Nessy CLI. Он получает запросы, отправленные из `packages/cli`, организует взаимодействия с настроенным модельным API и управляет выполнением доступных инструментов.

**Ключевые функции:**

- **API клиент:** Связывается с модельным API Nessy для отправки подсказок и получения ответов.
- **Конструирование подсказок:** Строит соответствующие подсказки для модели, включая историю разговора и определения доступных инструментов.
- **Регистрация и выполнение инструментов:** Управляет регистрацией доступных инструментов и выполняет их на основе запросов модели.
- **Управление состоянием:** Поддерживает информацию о состоянии разговора и сессии.
- **Серверная конфигурация:** Обрабатывает серверную конфигурацию и настройки.

### 3. Инструменты (`packages/core/src/tools/`)

**Назначение:** Это отдельные модули, которые расширяют возможности модельной системы Nessy, позволяя ей взаимодействовать с локальным окружением (например, файловая система, команды оболочки, веб-запросы).

**Взаимодействие:** `packages/core` вызывает эти инструменты на основе запросов от модельной системы Nessy.

**Распространённые инструменты включают:**

- **Файловые операции:** Чтение, запись и редактирование файлов
- **Команды оболочки:** Выполнение системных команд с одобрением пользователя для потенциально опасных операций
- **Инструменты поиска:** Поиск файлов и поиск содержимого в проекте
- **Веб-инструменты:** Получение контента из интернета
- **Интеграция MCP:** Подключение к серверам Model Context Protocol для расширенных возможностей

## Поток взаимодействия

Типичное взаимодействие с Nessy CLI следует этому потоку:

1.  **Пользовательский ввод:** Пользователь вводит подсказку или команду в терминал, что управляется `packages/cli`.
2.  **Запрос в Core:** `packages/cli` отправляет пользовательский ввод в `packages/core`.
3.  **Обработка запроса:** Core пакет:
    - Конструирует соответствующую подсказку для настроенного модельного API, возможно, включая историю разговора и определения доступных инструментов.
    - Отправляет подсказку в модельное API.
4.  **Ответ модельного API:** Модельное API обрабатывает подсказку и возвращает ответ. Этот ответ может быть прямым ответом или запросом на использование одного из доступных инструментов.
5.  **Выполнение инструмента (если применимо):**
    - Когда модельное API запрашивает инструмент, core пакет готовится выполнить его.
    - Если запрошенный инструмент может модифицировать файловую систему или выполнять команды оболочки, пользователю сначала предоставляются детали инструмента и его аргументов, и пользователь должен одобрить выполнение.
    - Операции только для чтения, такие как чтение файлов, могут не требовать явного подтверждения пользователя для продолжения.
    - После подтверждения или если подтверждение не требуется, core пакет выполняет соответствующее действие в соответствующем инструменте, и результат отправляется обратно в модельное API core пакетом.
    - Модельное API обрабатывает результат инструмента и генерирует окончательный ответ.
6.  **Ответ в CLI:** Core пакет отправляет окончательный ответ обратно в CLI пакет.
7.  **Отображение пользователю:** CLI пакет форматирует и отображает ответ пользователю в терминале.

## Опции конфигурации

Nessy CLI предлагает несколько способов конфигурирования своего поведения:

### Слои конфигурации (в порядке приоритета)

1. Аргументы командной строки
2. Переменные окружения
3. Файл проектных настроек (`.nessy/settings.json`)
4. Файл пользовательских настроек (`~/.nessy/settings.json`)
5. Системные файлы настроек
6. Значения по умолчанию

### Ключевые категории конфигурации

- **Общие настройки:** режим vim, предпочитаемый редактор, предпочтения автообновления
- **Настройки UI:** Кастомизация темы, отображение баннера, отображение футера
- **Настройки модели:** Выбор модели, лимиты оборотов сессии, настройки сжатия
- **Настройки контекста:** Имена файлов контекста, включение каталогов, фильтрация файлов
- **Настройки инструментов:** Режимы одобрения, песочница, ограничения инструментов
- **Настройки приватности:** Сбор статистики использования
- **Расширенные настройки:** Опции отладки, пользовательские команды отчётов об ошибках

## Ключевые принципы дизайна

- **Модульность:** Разделение CLI (фронтенд) от Core (бэкенд) позволяет независимую разработку и потенциальные будущие расширения (например, разные фронтенды для одного бэкенда).
- **Расширяемость:** Система инструментов предназначена для расширения, позволяя добавлять новые возможности через пользовательские инструменты или интеграцию MCP сервера.
- **Пользовательский опыт:** CLI фокусируется на предоставлении богатого и интерактивного терминального опыта с такими функциями, как подсветка синтаксиса, настраиваемые темы и интуитивные структуры команд.
- **Безопасность:** Реализует механизмы одобрения для потенциально опасных операций и опции песочницы для защиты системы пользователя.
- **Гибкость:** Поддерживает несколько методов конфигурации и может адаптироваться к разным рабочим процессам и окружениям.
