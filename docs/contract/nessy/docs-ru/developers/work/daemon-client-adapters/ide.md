# Адаптер IDE для демона (черновик)

## Цель

Позволить расширению-компаньону VS Code использовать Mode B, подключаясь из процесса расширения
к `nessy serve` через `DaemonSessionClient`.

Веб-представление не должно вызывать демона напрямую. Процесс расширения владеет URL демона,
токеном, ID сессии и состоянием повтора SSE, затем пересылает санированные события приложения
в веб-представление.

## Предлагаемая точка входа

Настройки VS Code:

```json
{
  "nessy-cli.experimentalDaemon.enabled": true,
  "nessy-cli.experimentalDaemon.url": "http://127.0.0.1:4170",
  "nessy-cli.experimentalDaemon.token": ""
}
```

Резервное окружение для локального использования:

```bash
NESSY_IDE_DAEMON_URL=http://127.0.0.1:4170 code .
```

## Минимальный поток

1. Процесс расширения создает `DaemonClient`.
2. Получает `/capabilities` и проверяет совместимость рабочего пространства.
3. Создает или прикрепляет через `DaemonSessionClient.createOrAttach()`.
4. Подписывается на `session.events()` в процессе расширения.
5. Преобразует события демона в существующие сообщения веб-представления.
6. Отправляет пользовательские запросы через `session.prompt()`.
7. Направляет отмену/переключение модели через `session.cancel()` и `session.setModel()`.
8. Направляет решения разрешений через `session.respondToPermission()`.

## Взаимосвязь с существующим подключением ACP

Первая реализация вводит дополнительный путь подключения, не заменяя `AcpConnection`:

```text
NessyAgentManager
  current default -> AcpConnection -> nessy --acp child
  experimental    -> DaemonIdeConnection -> nessy serve HTTP/SSE
```

Оба пути должны по возможности передавать одни и те же высокоуровневые обратные вызовы веб-представления.
Если событие еще не может быть точно сопоставлено, путь демона должен выдавать четкое предупреждение о неподдерживаемом состоянии, а не молчаливо притворяться паритетным.

Этот PR добавляет `DaemonIdeConnection` как локально верифицируемый адаптер процесса расширения.
Он еще не подключен к пути `NessyAgentManager` по умолчанию, поэтому существующее поведение VS Code остается основанным на подпроцессе ACP.

## Контракт сопоставления событий

| Событие демона                           | Обработка IDE                                              |
| ---------------------------------------- | ---------------------------------------------------------- |
| `session_update` / `agent_message_chunk` | Существующий обратный вызов потока ассистента              |
| `session_update` / `agent_thought_chunk` | Существующий обратный вызов потока размышлений             |
| `session_update` / `tool_call`           | Существующий обратный вызов обновления инструмента         |
| `permission_request`                     | Существующий обратный вызов UI утверждения                 |
| `permission_resolved`                    | Закрыть/обновить UI утверждения                            |
| `model_switched`                         | Существующий обратный вызов состояния модели, где возможно |
| `session_died`                           | Отключение UI + возможность переподключения                |

Неизвестные события должны игнорироваться или логироваться как отладочные метаданные.

## UX локальности выполнения

Расширение должно делать локальность демона видимой:

- workspace/files — это пути хоста демона
- MCP-серверы запускаются на хосте демона
- навыки загружаются из файловой системы демона
- учетные данные провайдера разрешаются в окружении процесса демона

Не следует подразумевать, что локальные расширения VS Code, локальный профиль браузера, локальные службы localhost или локальные учетные данные SSH/kube автоматически доступны демону.

## Явные не-цели

- Нет миграции по умолчанию от `AcpConnection`.
- Нет транспорта напрямую из веб-представления к демону.
- Нет CRUD файлов на стороне демона через IDE, пока не появятся границы файлового сервиса.
- Нет обратного RPC для редактора/браузера/буфера обмена.
- Нет полной интеграции удаленного управления.

## Безопасность слияния

- По умолчанию отключено за настройкой/переменной окружения.
- Дополнительный путь подключения.
- Существующий путь подпроцесса ACP VS Code без изменений.
- Токен демона никогда не пересекает границу в JavaScript веб-представления.

## План валидации

- Модульное тестирование подключения фабрики сессий демона и потребления SSE-событий.
- Модульное тестирование сопоставления событий демона с существующими обратными вызовами расширения.
- Модульное тестирование пересылки запросов, отмены, переключения модели и ответа на разрешения.
- Модульное тестирование разрешения настроек/окружения при подключении флага функции.
- Smoke-тест локального процесса расширения против `nessy serve`:
  - поток запросов в чат
  - отмена работает
  - UI разрешений может разрешить запрос
  - SSE reconnect использует отслеживаемый `Last-Event-ID`

## Блокеры перед миграцией по умолчанию

- Типизированная схема событий демона.
- Идентичность клиента с отметкой демона.
- Маршрут разрешений с областью сессии.
- Диагностика выполнения только для чтения.
- Граница FileSystemService и безопасные маршруты чтения файлов.
- Рефакторинг выходного приемника для паритета CLI/TUI.
