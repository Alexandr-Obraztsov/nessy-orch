# Адаптер веб-UI для демона

## Цель

Веб-чат и веб-терминальные клиенты должны использовать HTTP/SSE API демона `nessy serve`
и рендерить клиентскую транскрипцию. Нативные локальные интеграции TUI, каналов и IDE
пока сохраняют свои существующие пути по умолчанию.

## Общий контракт UI

Использовать экспорт UI демона TypeScript SDK как общую границу:

```ts
import {
  DaemonClient,
  DaemonSessionClient,
  createDaemonTranscriptStore,
  normalizeDaemonEvent,
} from '@nestor/nessy-cli-sdk/daemon';
```

Разделение:

- `DaemonClient` обрабатывает HTTP-маршруты демона.
- `DaemonSessionClient` владеет созданием/прикреплением сессии и повтором SSE.
- `normalizeDaemonEvent()` преобразует сетевые события демона в события UI.
- `createDaemonTranscriptStore()` уменьшает события UI в блоки транскрипции.

React-клиенты могут использовать необязательную привязку `@nestor/nessy-cli-webui`:

```tsx
import {
  DaemonSessionProvider,
  useDaemonActions,
  useDaemonConnection,
  useDaemonPendingPermissions,
  useDaemonTranscriptBlocks,
} from '@nestor/nessy-cli-webui';
```

Минимальная форма React:

```tsx
function App() {
  return (
    <DaemonSessionProvider baseUrl="http://127.0.0.1:4170">
      <Transcript />
      <PromptBox />
    </DaemonSessionProvider>
  );
}

function Transcript() {
  const blocks = useDaemonTranscriptBlocks();
  return blocks.map((block) => <RenderBlock key={block.id} block={block} />);
}
```

Провайдер создает или прикрепляет сессию демона, подписывается на SSE, хранит
ID последнего события в `DaemonSessionClient` и по умолчанию переподключает поток.
Вызывающие могут отключить это с `autoReconnect={false}` для тестов или пользовательского управления подключением.

## Формы развертывания браузера

### Same-Origin локальный POC

Страница, обслуживаемая демоном, может вызывать демона напрямую, потому что страница и API имеют один источник. Это предпочтительная форма раннего POC для локальной валидации веб-чата и веб-терминала.

### Удаленный веб-чат / веб-терминал

Продакшн-приложение удаленного веба должно обычно взаимодействовать с backend-for-frontend.
BFF владеет URL демона, токеном, маршрутизацией рабочих пространств и метаданными сессии,
затем пересылает безопасные для браузера события приложения в браузер. Это хранит токены-носители вне хранилища браузера и позволяет развертыванию решать, к какому демону/рабочему пространству пользователь может получить доступ.

### Локальный браузер против локального демона

Отдельный локальный dev-сервер имеет другой источник с `nessy serve`; он должен либо проксировать маршруты демона через один источник, либо обслуживаться демоном. Демон намеренно отклоняет произвольные запросы браузера с `Origin`.

## Обязанности рендеринга

Общая модель транскрипции семантическая, а не визуальная. UI-клиенты решают, как рендерить:

- блоки сообщений пользователя и ассистента
- свернутые блоки размышлений
- карточки статуса инструментов
- блоки вывода оболочки
- элементы управления запросами разрешений
- блоки статуса/ошибок/отладки

Веб-терминал — это семантический рендерер в браузере. Он должен выглядеть и ощущаться как терминал с моноширинной раскладкой, прокруткой, вводом запроса, горячими клавишами и потоковыми блоками, но это не прокси raw PTY и не требует рендеринга Ink на стороне сервера.

## Безопасность слияния

- Нативный TUI `nessy` остается прямым и без изменений.
- Пути `--acp`, каналов и IDE по умолчанию остаются без изменений.
- UI-ядро SDK является дополнительным.
- Привязка React WebUI необязательна и работает только в клиентах, которые ее импортируют.
- Удаленный код шипа TUI демона не следует рассматривать как миграцию продукта.

## Последующие шаги

- Добавить локальный POC `/web`, обслуживаемый демоном, или эквивалентное same-origin веб-приложение.
- Построить первоклассные рендереры чата и терминала поверх блоков транскрипции.
- Добавить более богатые типизированные события только там, где существующие события демона слишком низкоуровневые для стабильного поведения браузера.
- Рассмотреть выделенный пакет `@nestor/nessy-cli-daemon-ui-core`, если не-SDK потребителям нужно ядро UI как независимая зависимость.
