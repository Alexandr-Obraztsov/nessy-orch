# MCP серверы с Nessy CLI

Этот документ предоставляет руководство по конфигурированию и использованию Model Context Protocol (MCP) серверов с Nessy CLI.

## Что такое MCP сервер?

MCP сервер — это приложение, которое предоставляет инструменты и ресурсы CLI через Model Context Protocol, позволяя ему взаимодействовать с внешними системами и источниками данных. MCP серверы действуют как мост между моделью и вашей локальной средой или другими сервисами, такими как API.

MCP сервер позволяет CLI:

- **Обнаруживать инструменты:** Список доступных инструментов, их описаний и параметров через стандартизированные определения схем.
- **Выполнять инструменты:** Вызывать специфичные инструменты с определёнными аргументами и получать структурированные ответы.
- **Получать доступ к ресурсам:** Читать данные из специфичных ресурсов (хотя CLI в первую очередь фокусируется на выполнении инструментов).

С MCP сервером вы можете расширить возможности CLI для выполнения действий за пределами его встроенных функций, таких как взаимодействие с базами данных, API, пользовательскими скриптами или специализированными рабочими процессами.

## Архитектура интеграции

Nessy CLI интегрируется с MCP серверами через сложную систему обнаружения и выполнения, встроенную в основной пакет (`packages/core/src/tools/`):

### Слой обнаружения (`mcp-client.ts`)

Процесс обнаружения управляется `discoverMcpTools()`, который:

1. **Итерируется по настроенным серверам** из вашей конфигурации `mcpServers` в `settings.json`
2. **Устанавливает соединения** используя соответствующие механизмы транспорта (Stdio, SSE или Streamable HTTP)
3. **Получает определения инструментов** от каждого сервера используя протокол MCP
4. **Очищает и проверяет** схемы инструментов для совместимости с Nessy API
5. **Регистрирует инструменты** в глобальном реестре инструментов с разрешением конфликтов

### Слой выполнения (`mcp-tool.ts`)

Каждый обнаруженный MCP инструмент обёрнут в экземпляр `DiscoveredMCPTool`, который:

- **Управляет логикой подтверждения** на основе настроек доверия сервера и предпочтений пользователя
- **Управляет выполнением инструментов** вызывая MCP сервер с правильными параметрами
- **Обрабатывает ответы** как для контекста LLM, так и для отображения пользователю
- **Поддерживает состояние соединения** и обрабатывает таймауты

### Механизмы транспорта

CLI поддерживает три типа транспорта MCP:

- **Stdio Transport:** Запускает подпроцесс и общается через stdin/stdout
- **SSE Transport:** Подключается к Server-Sent Events эндпоинтам
- **Streamable HTTP Transport:** Использует HTTP streaming для общения

## Как настроить ваш MCP сервер

Nessy CLI использует конфигурацию `mcpServers` в вашем файле `settings.json` для поиска и подключения к MCP серверам. Эта конфигурация поддерживает несколько серверов с различными механизмами транспорта.

### Конфигурировать MCP сервер в settings.json

Вы можете конфигурировать MCP серверы в вашем файле `settings.json` двумя основными способами: через объект `mcpServers` верхнего уровня для специфичных определений серверов и через объект `mcp` для глобальных настроек, контролирующих обнаружение и выполнение серверов.

#### Глобальные настройки MCP (`mcp`)

Объект `mcp` в вашем `settings.json` позволяет вам определить глобальные правила для всех MCP серверов.

- **`mcp.serverCommand`** (string): Глобальная команда для запуска MCP сервера.
- **`mcp.allowed`** (array of strings): Список имён MCP серверов для разрешения. Если это установлено, только серверы из этого списка (соответствующие ключам в объекте `mcpServers`) будут подключены.
- **`mcp.excluded`** (array of strings): Список имён MCP серверов для исключения. Серверы в этом списке не будут подключены.

**Пример:**

```json
{
  "mcp": {
    "allowed": ["my-trusted-server"],
    "excluded": ["experimental-server"]
  }
}
```

#### Конфигурация специфичная для сервера (`mcpServers`)

Объект `mcpServers` — это где вы определяете каждый отдельный MCP сервер, к которому CLI должен подключиться.

### Структура конфигурации

Добавьте объект `mcpServers` в ваш файл `settings.json`:

```json
{ ...файл содержит другие объекты конфигурации
  "mcpServers": {
    "serverName": {
      "command": "path/to/server",
      "args": ["--arg1", "value1"],
      "env": {
        "API_KEY": "$MY_API_TOKEN"
      },
      "cwd": "./server-directory",
      "timeout": 30000,
      "trust": false
    }
  }
}
```

### Свойства конфигурации

Каждая конфигурация сервера поддерживает следующие свойства:

#### Обязательные (одно из следующего)

- **`command`** (string): Путь к исполняемому файлу для транспорта Stdio
- **`url`** (string): URL эндпоинта SSE (например, `"http://localhost:8080/sse"`)
- **`httpUrl`** (string): URL эндпоинта HTTP streaming

#### Опциональные

- **`args`** (string[]): Аргументы командной строки для транспорта Stdio
- **`headers`** (object): Пользовательские HTTP заголовки при использовании `url` или `httpUrl`
- **`env`** (object): Переменные окружения для процесса сервера. Значения могут ссылаться на переменные окружения используя синтаксис `$VAR_NAME` или `${VAR_NAME}`
- **`cwd`** (string): Рабочий каталог для транспорта Stdio
- **`timeout`** (number): Таймаут запроса в миллисекундах (по умолчанию: 600,000ms = 10 минут)
- **`trust`** (boolean): Когда `true`, обходит все подтверждения вызовов инструментов для этого сервера (по умолчанию: `false`)
- **`includeTools`** (string[]): Список имён инструментов для включения из этого MCP сервера. Когда указано, только перечисленные здесь инструменты будут доступны из этого сервера (поведение белого списка). Если не указано, все инструменты из сервера включены по умолчанию.
- **`excludeTools`** (string[]): Список имён инструментов для исключения из этого MCP сервера. Инструменты, перечисленные здесь, не будут доступны модели, даже если они предоставлены сервером. **Примечание:** `excludeTools` имеет приоритет над `includeTools` — если инструмент в обоих списках, он будет исключён.
- **`targetAudience`** (string): OAuth Client ID allowlisted на IAP-защищённом приложении, к которому вы пытаетесь получить доступ. Используется с `authProviderType: 'service_account_impersonation'`.
- **`targetServiceAccount`** (string): Email адрес Google Cloud Service Account для имитации. Используется с `authProviderType: 'service_account_impersonation'`.

### Поддержка OAuth для удалённых MCP серверов

Nessy CLI поддерживает аутентификацию OAuth 2.0 для удалённых MCP серверов используя транспорты SSE или HTTP. Это позволяет безопасный доступ к MCP серверам, требующим аутентификации.

#### Автоматическое обнаружение OAuth

Для серверов, поддерживающих обнаружение OAuth, вы можете опустить конфигурацию OAuth и позволить CLI обнаружить её автоматически:

```json
{
  "mcpServers": {
    "discoveredServer": {
      "url": "https://api.example.com/sse"
    }
  }
}
```

CLI будет автоматически:

- Обнаруживать, когда сервер требует аутентификации OAuth (ответы 401)
- Обнаруживать эндпоинты OAuth из метаданных сервера
- Выполнять динамическую регистрацию клиента, если поддерживается
- Обрабатывать поток OAuth и управление токенами

#### Поток аутентификации

При подключении к серверу с поддержкой OAuth:

1. **Начальная попытка подключения** не удаётся с 401 Unauthorized
2. **Обнаружение OAuth** находит эндпоинты авторизации и токенов
3. **Браузер открывается** для аутентификации пользователя (требуется локальный доступ к браузеру)
4. **Код авторизации** обменивается на токены доступа
5. **Токены хранятся** безопасно для будущего использования
6. **Повторное подключение** успешно с валидными токенами

#### Требования перенаправления браузера

**Важно:** OAuth аутентификация требует, чтобы перенаправляющий URI был доступен:

- **Поведение по умолчанию**: Перенаправление на `http://localhost:7777/oauth/callback` (работает для локальных настроек)
- **Пользовательский redirect URI**: Используйте `--oauth-redirect-uri` или настройте `redirectUri` в settings.json для указания другого URL

Для **удалённых/облачных развёртываний серверов** (например, веб-терминалы, SSH сессии, облачные IDE):

- Перенаправление `localhost` по умолчанию **НЕ будет работать**
- Вы **ДОЛЖНЫ** настроить пользовательский `redirectUri`, указывающий на публично доступный URL
- Браузер пользователя должен иметь возможность достичь этого URL и перенаправить обратно на сервер

Пример для удалённых серверов:

```bash
nessy mcp add --transport sse remote-server https://api.example.com/sse/ \
  --oauth-redirect-uri https://your-remote-server.example.com/oauth/callback
```

OAuth не будет работать в:

- Безголовых средах без доступа к браузеру
- Средах, где настроенный `redirectUri` недоступен из браузера пользователя

#### Управление аутентификацией OAuth

Используйте команду `/mcp auth` для управления аутентификацией OAuth:

```bash
# Список серверов, требующих аутентификации
/mcp auth

# Аутентификация с специфичным сервером
/mcp auth serverName

# Повторная аутентификация, если токены истекли
/mcp auth serverName
```

#### Свойства конфигурации OAuth

- **`enabled`** (boolean): Включить OAuth для этого сервера
- **`clientId`** (string): Идентификатор клиента OAuth (опционально с динамической регистрацией)
- **`clientSecret`** (string): Секрет клиента OAuth (опционально для публичных клиентов)
- **`authorizationUrl`** (string): Эндпоинт авторизации OAuth (автоматически обнаруживается, если опущен)
- **`tokenUrl`** (string): Эндпоинт токенов OAuth (автоматически обнаруживается, если опущен)
- **`scopes`** (string[]): Требуемые области OAuth
- **`redirectUri`** (string): Пользовательский URI перенаправления. **Критично для удалённых развёртываний**: По умолчанию `http://localhost:7777/oauth/callback`. При запуске Nessy CLI на удалённых/облачных серверах установите это в публично доступный URL (например, `https://your-server.com/oauth/callback`). Может быть настроено через `nessy mcp add --oauth-redirect-uri` или напрямую в settings.json.
- **`tokenParamName`** (string): Имя параметра запроса для токенов в SSE URL
- **`audiences`** (string[]): Аудитории, для которых токен валиден

#### Управление токенами

OAuth токены автоматически:

- **Хранятся безопасно** в `~/.nessy/mcp-oauth-tokens-v2.json` (AES-256-GCM зашифровано), с предпочтением keychain хранилища, когда доступно
- **Обновляются** при истечении (если токены обновления доступны)
- **Проверяются** перед каждой попыткой подключения
- **Очищаются** при недействительности или истечении

#### Тип провайдера аутентификации

Вы можете указать тип провайдера аутентификации используя свойство `authProviderType`:

- **`authProviderType`** (string): Указывает провайдера аутентификации. Может быть одним из следующего:
  - **`dynamic_discovery`** (по умолчанию): CLI будет автоматически обнаруживать конфигурацию OAuth из сервера.
  
#### Учётные данные Google

```json
{
  "mcpServers": {
    "googleCloudServer": {
      "httpUrl": "https://my-gcp-service.run.app/mcp",
      "authProviderType": "google_credentials",
      "oauth": {
        "scopes": ["https://www.googleapis.com/auth/userinfo.email"]
      }
    }
  }
}
```

#### Имитация учётной записи сервиса

Для аутентификации с сервером используя имитацию учётной записи сервиса, вы должны установить `authProviderType` в `service_account_impersonation` и предоставить следующие свойства:

- **`targetAudience`** (string): OAuth Client ID allowlisted на IAP-защищённом приложении, к которому вы пытаетесь получить доступ.
- **`targetServiceAccount`** (string): Email адрес Google Cloud Service Account для имитации.

CLI будет использовать ваши локальные Application Default Credentials (ADC) для генерации OIDC ID токена для указанной учётной записи сервиса и аудитории. Этот токен затем будет использован для аутентификации с MCP сервером.

#### Инструкции по настройке

1. **[Создать](https://cloud.google.com/iap/docs/oauth-client-creation) или использовать существующий OAuth 2.0 client ID.** Для использования существующего OAuth 2.0 client ID следуйте шагам в [How to share OAuth Clients](https://cloud.google.com/iap/docs/sharing-oauth-clients).
2. **Добавить OAuth ID в allowlist для [программного доступа](https://cloud.google.com/iap/docs/sharing-oauth-clients#programmatic_access) для приложения.** Поскольку Cloud Run ещё не поддерживаемый тип ресурса в gcloud iap, вы должны добавить Client ID в allowlist проекта.
3. **Создать учётную запись сервиса.** [Документация](https://cloud.google.com/iam/docs/service-accounts-create#creating), [Cloud Console Link](https://console.cloud.google.com/iam-admin/serviceaccounts)
4. **Добавить и учётную запись сервиса, и пользователей в IAP Policy** во вкладке "Security" самого сервиса Cloud Run или через gcloud.
5. **Предоставить всем пользователям и группам**, которые будут получать доступ к MCP серверу, необходимые разрешения для [имитации учётной записи сервиса](https://cloud.google.com/docs/authentication/use-service-account-impersonation) (т.е. `roles/iam.serviceAccountTokenCreator`).
6. **[Включить](https://console.cloud.google.com/apis/library/iamcredentials.googleapis.com) IAM Credentials API** для вашего проекта.

## Глубокое погружение в процесс обнаружения

Когда Nessy CLI запускается, он выполняет обнаружение MCP серверов через следующий детальный процесс:

### 1. Итерация серверов и подключение

Для каждого настроенного сервера в `mcpServers`:

1. **Начало отслеживания статуса:** Статус сервера устанавливается в `CONNECTING`
2. **Выбор транспорта:** На основе свойств конфигурации:
   - `httpUrl` → `StreamableHTTPClientTransport`
   - `url` → `SSEClientTransport`
   - `command` → `StdioClientTransport`
3. **Установление соединения:** MCP клиент пытается подключиться с настроенным таймаутом
4. **Обработка ошибок:** Ошибки подключения логируются, и статус сервера устанавливается в `DISCONNECTED`

### 2. Обнаружение инструментов

После успешного подключения:

1. **Список инструментов:** Клиент вызывает эндпоинт списка инструментов MCP сервера
2. **Проверка схемы:** Проверка декларации функции каждого инструмента
3. **Фильтрация инструментов:** Инструменты фильтруются на основе конфигурации `includeTools` и `excludeTools`
4. **Очистка имён:** Имена инструментов очищаются для соответствия требованиям Nessy API:
   - Недопустимые символы (не буквенно-цифровые, подчёркивание, точка, дефис) заменяются подчёркиваниями
   - Имена длиннее 63 символов усекаются с заменой в середине (`___`)

### 3. Разрешение конфликтов

Когда несколько серверов предоставляют инструменты с одинаковым именем:

1. **Первая регистрация побеждает:** Первый сервер, зарегистрировавший имя инструмента, получает имя без префикса
2. **Автоматическое добавление префикса:** Последующие серверы получают имена с префиксом: `serverName__toolName`
3. **Отслеживание реестра:** Реестр инструментов поддерживает отображение между именами серверов и их инструментами

### 4. Обработка схем

Схемы параметров инструментов проходят очистку для совместимости с API:

- **Свойства `$schema`** удаляются
- **`additionalProperties`** удаляются
- **`anyOf` с `default`** имеют свои значения по умолчанию удалёнными (совместимость с Vertex AI)
- **Рекурсивная обработка** применяется к вложенным схемам

### 5. Управление соединением

После обнаружения:

- **Постоянные соединения:** Серверы, успешно зарегистрировавшие инструменты, поддерживают свои соединения
- **Очистка:** Серверы, не предоставившие полезных инструментов, закрывают свои соединения
- **Обновления статуса:** Финальные статусы серверов устанавливаются в `CONNECTED` или `DISCONNECTED`

## Поток выполнения инструментов

Когда модель решает использовать MCP инструмент, происходит следующий поток выполнения:

### 1. Вызов инструмента

Модель генерирует `FunctionCall` с:

- **Имя инструмента:** Зарегистрированное имя (потенциально с префиксом)
- **Аргументы:** JSON объект, соответствующий схеме параметров инструмента

### 2. Процесс подтверждения

Каждый `DiscoveredMCPTool` реализует сложную логику подтверждения:

#### Обход на основе доверия

```typescript
if (this.trust) {
  return false; // Подтверждение не требуется
}
```

#### Динамическое внесение в белый список

Система поддерживает внутренние белые списки для:

- **Уровень сервера:** `serverName` → Все инструменты из этого сервера доверены
- **Уровень инструмента:** `serverName.toolName` → Этот специфичный инструмент доверен

#### Обработка выбора пользователя

Когда требуется подтверждение, пользователи могут выбрать:

- **Выполнить один раз:** Выполнить только этот раз
- **Всегда разрешать этот инструмент:** Добавить в белый список на уровне инструмента
- **Всегда разрешать этот сервер:** Добавить в белый список на уровне сервера
- **Отменить:** Прервать выполнение

### 3. Выполнение

После подтверждения (или обхода доверия):

1. **Подготовка параметров:** Аргументы проверяются против схемы инструмента
2. **MCP вызов:** Базовый `CallableTool` вызывает сервер с:

   ```typescript
   const functionCalls = [
     {
       name: this.serverToolName, // Оригинальное имя инструмента сервера
       args: params,
     },
   ];
   ```

3. **Обработка ответа:** Результаты форматируются как для контекста LLM, так и для отображения пользователю

### 4. Обработка ответа

Результат выполнения содержит:

- **`llmContent`:** Сырые части ответа для контекста языковой модели
- **`returnDisplay`:** Форматированный вывод для отображения пользователю (часто JSON в блоках кода markdown)

## Как взаимодействовать с вашим MCP сервером

### Использование команды `/mcp`

Команда `/mcp` предоставляет комплексную информацию о вашей настройке MCP серверов:

```bash
/mcp
```

Это отображает:

- **Список серверов:** Все настроенные MCP серверы
- **Статус подключения:** `CONNECTED`, `CONNECTING` или `DISCONNECTED`
- **Детали серверов:** Сводка конфигурации (исключая чувствительные данные)
- **Доступные инструменты:** Список инструментов из каждого сервера с описаниями
- **Состояние обнаружения:** Общий статус процесса обнаружения

### Пример вывода `/mcp`

```
MCP Servers Status:

📡 pythonTools (CONNECTED)
  Command: python -m my_mcp_server --port 8080
  Working Directory: ./mcp-servers/python
  Timeout: 15000ms
  Tools: calculate_sum, file_analyzer, data_processor

🔌 nodeServer (DISCONNECTED)
  Command: node dist/server.js --verbose
  Error: Connection refused

🐳 dockerizedServer (CONNECTED)
  Command: docker run -i --rm -e API_KEY my-mcp-server:latest
  Tools: docker__deploy, docker__status

Discovery State: COMPLETED
```

### Использование инструментов

После обнаружения MCP инструменты доступны модели Nessy как встроенные инструменты. Модель будет автоматически:

1. **Выбирать подходящие инструменты** на основе ваших запросов
2. **Представлять диалоги подтверждения** (если сервер не доверен)
3. **Выполнять инструменты** с правильными параметрами
4. **Отображать результаты** в удобном для пользователя формате

## Мониторинг статуса и устранение неполадок

### Состояния подключения

Интеграция MCP отслеживает несколько состояний:

#### Статус сервера (`MCPServerStatus`)

- **`DISCONNECTED`:** Сервер не подключён или имеет ошибки
- **`CONNECTING`:** Попытка подключения в процессе
- **`CONNECTED`:** Сервер подключён и готов

#### Состояние обнаружения (`MCPDiscoveryState`)

- **`NOT_STARTED`:** Обнаружение не началось
- **`IN_PROGRESS`:** В настоящее время обнаружение серверов
- **`COMPLETED`:** Обнаружение завершено (с ошибками или без)

### Распространённые проблемы и решения

#### Сервер не подключается

**Симптомы:** Сервер показывает статус `DISCONNECTED`

**Устранение неполадок:**

1. **Проверьте конфигурацию:** Убедитесь, что `command`, `args` и `cwd` правильные
2. **Проверьте вручную:** Запустите команду сервера напрямую, чтобы убедиться, что она работает
3. **Проверьте зависимости:** Убедитесь, что все требуемые пакеты установлены
4. **Просмотрите логи:** Ищите сообщения об ошибках в выводе CLI
5. **Проверьте разрешения:** Убедитесь, что CLI может выполнить команду сервера

#### Инструменты не обнаружены

**Симптомы:** Сервер подключается, но инструменты недоступны

**Устранение неполадок:**

1. **Проверьте регистрацию инструментов:** Убедитесь, что ваш сервер действительно регистрирует инструменты
2. **Проверьте протокол MCP:** Убедитесь, что ваш сервер реализует список инструментов MCP правильно
3. **Просмотрите логи сервера:** Проверьте вывод stderr на ошибки на стороне сервера
4. **Проверьте список инструментов вручную:** Протестируйте эндпоинт обнаружения инструментов вашего сервера вручную

#### Инструменты не выполняются

**Симптомы:** Инструменты обнаружены, но не выполняются

**Устранение неполадок:**

1. **Проверка параметров:** Убедитесь, что ваш инструмент принимает ожидаемые параметры
2. **Совместимость схем:** Убедитесь, что ваши входные схемы являются валидным JSON Schema
3. **Обработка ошибок:** Проверьте, не бросает ли ваш инструмент необработанные исключения
4. **Проблемы таймаута:** Рассмотрите увеличение настройки `timeout`

#### Совместимость с песочницей

**Симптомы:** MCP серверы не работают при включённой песочнице

**Решения:**

1. **Серверы на основе Docker:** Используйте Docker контейнеры, которые включают все зависимости
2. **Доступность путей:** Убедитесь, что исполняемые файлы серверов доступны в песочнице
3. **Доступ к сети:** Настройте песочницу для разрешения необходимых сетевых подключений
4. **Переменные окружения:** Убедитесь, что требуемые переменные окружения передаются

### Советы по отладке

1. **Включите режим отладки:** Запустите CLI с `--debug` для подробного вывода
2. **Проверьте stderr:** stderr MCP сервера захватывается и логируется (INFO сообщения фильтруются)
3. **Тестируйте изолированно:** Тестируйте ваш MCP сервер независимо перед интеграцией
4. **Инкрементальная настройка:** Начните с простых инструментов перед добавлением сложной функциональности
5. **Используйте `/mcp` часто:** Мониторьте статус серверов во время разработки

## Важные примечания

### Соображения безопасности

- **Настройки доверия:** Опция `trust` обходит все диалоги подтверждения. Используйте осторожно и только для серверов, которыми вы полностью управляете
- **Токены доступа:** Будьте внимательны к безопасности при конфигурировании переменных окружения, содержащих API ключи или токены
- **Совместимость с песочницей:** При использовании песочницы убедитесь, что MCP серверы доступны в среде песочницы
- **Частные данные:** Использование токенов личного доступа с широкой областью может привести к утечке информации между репозиториями

### Производительность и управление ресурсами

- **Постоянство соединения:** CLI поддерживает постоянные соединения с серверами, успешно зарегистрировавшими инструменты
- **Автоматическая очистка:** Соединения с серверами, не предоставляющими инструменты, автоматически закрываются
- **Управление таймаутом:** Настройте соответствующие таймауты на основе характеристик ответа вашего сервера
- **Мониторинг ресурсов:** MCP серверы запускаются как отдельные процессы и потребляют системные ресурсы

### Совместимость схем

- **Режим соответствия схемам:** По умолчанию (`schemaCompliance: "auto"`), схемы инструментов передаются как есть. Установите `"model": { "generationConfig": { "schemaCompliance": "openapi_30" } }` в вашем `settings.json` для конвертации моделей в формат Strict OpenAPI 3.0.
- **Преобразования OpenAPI 3.0:** Когда включён режим `openapi_30`, система обрабатывает:
  - Nullable типы: `["string", "null"]` → `type: "string", nullable: true`
  - Const значения: `const: "foo"` → `enum: ["foo"]`
  - Exclusive limits: числовые `exclusiveMinimum` → булева форма с `minimum`
  - Удаление ключевых слов: `$schema`, `$id`, `dependencies`, `patternProperties`
- **Очистка имён:** Имена инструментов автоматически очищаются для соответствия требованиям API
- **Разрешение конфликтов:** Конфликты имён инструментов между серверами разрешаются через автоматическое добавление префиксов

Это комплексное интегрирование делает MCP серверы мощным способом расширения возможностей CLI при сохранении безопасности, надёжности и простоты использования.

## Возврат богатого контента из инструментов

MCP инструменты не ограничены возвратом простого текста. Вы можете возвращать богатый, многокомпонентный контент, включая изображения, аудио и ссылки на ресурсы.

Все данные, возвращённые из инструмента, обрабатываются и отправляются модели как контекст для её следующей генерации, позволяя ей рассуждать о или суммировать предоставленную информацию.

### Как это работает

Для возврата богатого контента, ответ вашего инструмента должен соответствовать спецификации MCP для [`CallToolResult`](https://modelcontextprotocol.io/specification/2025-06-18/server/tools#tool-result). Поле `content` результата должно быть массивом объектов `ContentBlock`. CLI будет корректно обрабатывать этот массив, разделяя текст и бинарные данные и упаковывая их для модели.

Вы можете комбинировать различные типы блоков контента в массиве `content`. Поддерживаемые типы блоков включают:

- `text`
- `image`
- `audio`
- `resource` (встроенный контент)
- `resource_link`

### Пример: Возврат текста и изображения

Вот пример валидного JSON ответа от MCP инструмента, который возвращает и текстовое описание, и изображение:

```json
{
  "content": [
    {
      "type": "text",
      "text": "Вот логотип, который вы запросили."
    },
    {
      "type": "image",
      "data": "BASE64_ENCODED_IMAGE_DATA_HERE",
      "mimeType": "image/png"
    },
    {
      "type": "text",
      "text": "Логотип был создан в 2025 году."
    }
  ]
}
```

Когда Nessy CLI получает этот ответ, он будет:

1. Извлекать весь текст и объединять его в единую часть `functionResponse` для модели.
2. Представлять данные изображения как отдельную часть `inlineData`.
3. Предоставлять чистое, удобное для пользователя резюме в CLI, указывающее, что были получены и текст, и изображение.

Это позволяет вам создавать сложные инструменты, которые могут предоставлять богатый, многомодальный контекст модели Nessy.

## MCP подсказки как slash-команды

В дополнение к инструментам, MCP серверы могут предоставлять предопределённые подсказки, которые могут выполняться как slash-команды в Nessy CLI. Это позволяет вам создавать ярлыки для распространённых или сложных запросов, которые могут быть легко вызваны по имени.

### Определение подсказок на сервере

Вот небольшой пример stdio MCP сервера, который определяет подсказки:

```ts
import { McpServer } from '@modelcontextprotocol/sdk/server/mcp.js';
import { StdioServerTransport } from '@modelcontextprotocol/sdk/server/stdio.js';
import { z } from 'zod';

const server = new McpServer({
  name: 'prompt-server',
  version: '1.0.0',
});

server.registerPrompt(
  'poem-writer',
  {
    title: 'Poem Writer',
    description: 'Write a nice haiku',
    argsSchema: { title: z.string(), mood: z.string().optional() },
  },
  ({ title, mood }) => ({
    messages: [
      {
        role: 'user',
        content: {
          type: 'text',
          text: `Write a haiku${mood ? ` with the mood ${mood}` : ''} called ${title}. Note that a haiku is 5 syllables followed by 7 syllables followed by 5 syllables `,
        },
      },
    ],
  }),
);

const transport = new StdioServerTransport();
await server.connect(transport);
```

Это может быть включено в `settings.json` под `mcpServers` с:

```json
{
  "mcpServers": {
    "nodeServer": {
      "command": "node",
      "args": ["filename.ts"]
    }
  }
}
```

### Вызов подсказок

Как только подсказка обнаружена, вы можете вызвать её, используя её имя как slash-команду. CLI будет автоматически обрабатывать парсинг аргументов.

```bash
/poem-writer --title="Nessy CLI" --mood="reverent"
```

или, используя позиционные аргументы:

```bash
/poem-writer "Nessy CLI" reverent
```

Когда вы выполняете эту команду, CLI выполняет метод `prompts/get` на MCP сервере с предоставленными аргументами. Сервер отвечает за подстановку аргументов в шаблон подсказки и возвращение финального текста подсказки. CLI затем отправляет эту подсказку модели для выполнения. Это предоставляет удобный способ автоматизации и обмена распространёнными рабочими процессами.

## Управление MCP серверами с `nessy mcp`

Хотя вы всегда можете конфигурировать MCP серверы путём ручного редактирования вашего файла `settings.json`, CLI предоставляет удобный набор команд для программного управления вашими конфигурациями серверов. Эти команды упрощают процесс добавления, перечисления и удаления MCP серверов без необходимости прямого редактирования JSON файлов.

### Добавление сервера (`nessy mcp add`)

Команда `add` настраивает новый MCP сервер в вашем `settings.json`. На основе scope (`-s, --scope`), он будет добавлен либо в пользовательский конфиг `~/.nessy/settings.json`, либо в проектный конфиг `.nessy/settings.json`.

**Команда:**

```bash
nessy mcp add [options] <name> <commandOrUrl> [args...]
```

- `<name>`: Уникальное имя для сервера.
- `<commandOrUrl>`: Команда для выполнения (для `stdio`) или URL (для `http`/`sse`).
- `[args...]`: Опциональные аргументы для `stdio` команды.

**Опции (флаги):**

- `-s, --scope`: Область конфигурации (user или project). [по умолчанию: "project"]
- `-t, --transport`: Тип транспорта (stdio, sse, http). [по умолчанию: "stdio"]
- `-e, --env`: Установить переменные окружения (например, `-e KEY=value`).
- `-H, --header`: Установить HTTP заголовки для транспортов SSE и HTTP (например, `-H "X-Api-Key: abc123" -H "Authorization: Bearer abc123"`).
- `--timeout`: Установить таймаут подключения в миллисекундах.
- `--trust`: Доверять серверу (обходить все подсказки подтверждения вызовов инструментов).
- `--description`: Установить описание для сервера.
- `--include-tools`: Разделённый запятыми список инструментов для включения.
- `--exclude-tools`: Разделённый запятыми список инструментов для исключения.
- `--oauth-client-id`: OAuth client ID для аутентификации MCP сервера.
- `--oauth-client-secret`: OAuth client secret для аутентификации MCP сервера.
- `--oauth-redirect-uri`: OAuth redirect URI (например, `https://your-server.com/oauth/callback`). По умолчанию `http://localhost:7777/oauth/callback` для локальных настроек. **Важно для удалённых развёртываний**: При запуске Nessy CLI на удалённых/облачных серверах установите это в публично доступный URL.
- `--oauth-authorization-url`: OAuth authorization URL.
- `--oauth-token-url`: OAuth token URL.
- `--oauth-scopes`: OAuth scopes (разделённые запятыми).

#### Добавление stdio сервера

Это транспорт по умолчанию для запуска локальных серверов.

```bash
# Базовый синтаксис
nessy mcp add <name> <command> [args...]

# Пример: Добавление локального сервера
nessy mcp add my-stdio-server -e API_KEY=123 /path/to/server arg1 arg2 arg3

# Пример: Добавление локального python сервера
nessy mcp add python-server python server.py --port 8080
```

#### Добавление HTTP сервера

Этот транспорт для серверов, использующих streamable HTTP транспорт.

```bash
# Базовый синтаксис
nessy mcp add --transport http <name> <url>

# Пример: Добавление HTTP сервера
nessy mcp add --transport http http-server https://api.example.com/mcp/

# Пример: Добавление HTTP сервера с заголовком аутентификации
nessy mcp add --transport http secure-http https://api.example.com/mcp/ --header "Authorization: Bearer abc123"
```

#### Добавление SSE сервера

Этот транспорт для серверов, использующих Server-Sent Events (SSE).

```bash
# Базовый синтаксис
nessy mcp add --transport sse <name> <url>

# Пример: Добавление SSE сервера
nessy mcp add --transport sse sse-server https://api.example.com/sse/

# Пример: Добавление SSE сервера с заголовком аутентификации
nessy mcp add --transport sse secure-sse https://api.example.com/sse/ --header "Authorization: Bearer abc123"

# Пример: Добавление SSE сервера с поддержкой OAuth
nessy mcp add --transport sse oauth-server https://api.example.com/sse/ \
  --oauth-client-id your-client-id \
  --oauth-redirect-uri https://your-server.com/oauth/callback \
  --oauth-authorization-url https://provider.example.com/authorize \
  --oauth-token-url https://provider.example.com/token
```

### Управление серверами (`nessy mcp`)

Для просмотра и управления всеми MCP серверами, настроенными в настоящее время, используйте команду `manage` или просто `nessy mcp`. Это открывает интерактивный TUI диалог, где вы можете:

- Просматривать все MCP серверы с их статусом подключения
- Включать/отключать серверы
- Переподключаться к отключённым серверам
- Просматривать инструменты и подсказки, предоставляемые каждым сервером
- Просматривать логи серверов

**Команда:**

```bash
nessy mcp
# или
nessy mcp manage
```

Диалог управления предоставляет визуальный интерфейс, показывающий имя каждого сервера, детали конфигурации, статус подключения и доступные инструменты/подсказки.

### Удаление сервера (`nessy mcp remove`)

Для удаления сервера из вашей конфигурации используйте команду `remove` с именем сервера.

**Команда:**

```bash
nessy mcp remove <name>
```

**Пример:**

```bash
nessy mcp remove my-server
```

Это найдёт и удалит запись "my-server" из объекта `mcpServers` в соответствующем файле `settings.json` на основе scope (`-s, --scope`).
