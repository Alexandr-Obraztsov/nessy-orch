# Инструмент веб-запроса (`web_fetch`)

В этом документе описан инструмент `web_fetch` в Nessy CLI.

## Описание

Используйте `web_fetch`, чтобы получить содержимое указанного URL и обработать его с помощью модели ИИ. Инструмент принимает URL и промпт, загружает страницу и передаёт её содержимое вместе с промптом небольшой быстрой модели.

### Аргументы

`web_fetch` принимает три аргумента:

- `url` (строка, обязательный): URL загружаемой страницы. Это должен быть полный корректный URL, начинающийся с `http://` или `https://`.
- `prompt` (строка, обязательный): описание информации, которую нужно извлечь из содержимого страницы.
- `format` (строка, необязательный): управляет только заголовком `Accept`, отправляемым серверу, и сообщает предпочтительный формат содержимого. **Независимо от указанного формата всё загруженное содержимое нормализуется в обычный текст для обработки LLM.** По умолчанию используется `"auto"`.
  - `"auto"` (по умолчанию): через согласование содержимого предпочитает Markdown (`Accept: text/markdown, text/html`), но принимает HTML как запасной вариант. **Рекомендуется в большинстве случаев**, поскольку на поддерживающих Markdown серверах позволяет сократить расход токенов до 80%.
  - `"markdown"`: отправляет `Accept: text/markdown`. Используйте, если требуется явно запросить Markdown.
  - `"html"`: отправляет `Accept: text/html`. Используйте, если сервер требует HTML в заголовке Accept. Для обработки LLM содержимое всё равно преобразуется в обычный текст.
  - `"text"`: отправляет `Accept: text/plain`. Используйте, если нужен обычный текст.

## Использование `web_fetch` в Nessy CLI

Передайте URL и промпт с описанием данных, которые нужно извлечь. Перед загрузкой URL инструмент запросит подтверждение. После подтверждения он напрямую загрузит содержимое и обработает его с помощью модели ИИ.

Инструмент автоматически:

- преобразует HTML в текст, когда это необходимо;
- обрабатывает GitHub blob URL, преобразуя их в raw URL;
- заменяет HTTP на HTTPS для повышения безопасности;
- поддерживает согласование Markdown-содержимого, что значительно сокращает расход токенов.

Пример:

```
web_fetch(url="https://example.com", prompt="Кратко изложи основные тезисы статьи")
```

С явным форматом:

```
web_fetch(url="https://example.com", prompt="Получи исходное содержимое", format="markdown")
```

## Примеры `web_fetch`

Краткое изложение статьи:

```
web_fetch(url="https://example.com/news/latest", prompt="Кратко изложи основные тезисы этой статьи")
```

Извлечение конкретных сведений:

```
web_fetch(url="https://arxiv.org/abs/2401.0001", prompt="Каковы основные результаты и методология этой работы?")
```

Анализ документации на GitHub:

```
web_fetch(url="https://github.com/NessyLM/Nessy/blob/main/README.md", prompt="Каковы шаги установки и основные возможности?")
```

Получение Markdown с сервера, поддерживающего Markdown for Agents:

```
web_fetch(url="https://developers.cloudflare.com/fundamentals/reference/markdown-for-agents/", prompt="Извлеки ключевую информацию", format="markdown")
```

## Важные замечания

- **Обработка одного URL:** `web_fetch` обрабатывает по одному URL за вызов. Для анализа нескольких URL вызывайте инструмент отдельно для каждого адреса.
- **Формат URL:** для повышения безопасности инструмент автоматически заменяет HTTP на HTTPS, а GitHub blob URL преобразует в raw URL.
- **Согласование содержимого:** инструмент поддерживает согласование по протоколу Markdown for Agents. При `format="auto"` (по умолчанию) он отправляет заголовок `Accept: text/markdown, text/html`, поэтому поддерживающие Markdown серверы могут вернуть его напрямую вместо HTML. Это позволяет сократить расход токенов до 80%.
- **Обработка содержимого:** инструмент напрямую загружает содержимое и обрабатывает его моделью ИИ. Полученный HTML преобразуется в читаемый текст, а Markdown и обычный текст используются без изменений.
- **Качество результата:** качество вывода зависит от ясности инструкций в промпте.
- **Инструменты MCP:** если доступен инструмент web fetch от MCP, имя которого начинается с `mcp__`, предпочтительно использовать его — у него может быть меньше ограничений.

## Поддержка Markdown for Agents

Инструмент `web_fetch` в Nessy CLI поддерживает спецификацию [Markdown for Agents от Cloudflare](https://blog.cloudflare.com/markdown-for-agents/). Благодаря ей сайты могут передавать агентам Markdown напрямую, значительно сокращая расход токенов по сравнению с разбором HTML.

### Принцип работы

1. Параметр `format` управляет **только** заголовком `Accept`, отправляемым серверу, и не влияет на формат результата:
   - `format="auto"`: отправляет `Accept: text/markdown, text/html`;
   - `format="markdown"`: отправляет `Accept: text/markdown`;
   - `format="html"`: отправляет `Accept: text/html`;
   - `format="text"`: отправляет `Accept: text/plain`.
2. Если сервер поддерживает Markdown, он отвечает с `Content-Type: text/markdown`.
3. Markdown или обычный текст используется напрямую, без преобразования.
4. Если сервер возвращает HTML, инструмент преобразует его в читаемый текст.
5. Перед обработкой моделью ИИ любое содержимое нормализуется в текст.

### Преимущества

- **Экономия токенов:** Markdown обычно требует на 80% меньше токенов, чем эквивалентный HTML.
- **Улучшенная структура:** Markdown сохраняет семантическую структуру — заголовки, списки и другие элементы.
- **Обратная совместимость:** функция работает со всеми сайтами и даёт дополнительные преимущества на поддерживающих её серверах.

### Примеры серверов с поддержкой Markdown

- документация Cloudflare для разработчиков;
- блог Cloudflare;
- любой сайт с включённой функцией Cloudflare Markdown for Agents.
