# Инструменты Nessy CLI

Nessy CLI включает встроенные инструменты, которые модель использует для взаимодействия с вашим локальным окружением, доступа к информации и выполнения действий. Эти инструменты расширяют возможности CLI, позволяя ему выходить за рамки генерации текста и помогать с широким спектром задач.

## Обзор инструментов Nessy CLI

В контексте Nessy CLI инструменты — это конкретные функции или модули, которые модель может запросить для выполнения. Например, если вы попросите модель «Резюмировать содержимое `my_document.txt`», она, вероятно, определит необходимость прочитать этот файл и запросит выполнение инструмента `read_file`.

Основной компонент (`packages/core`) управляет этими инструментами, представляет их определения (схемы) модели, выполняет их по запросу и возвращает результаты модели для дальнейшей обработки в пользовательский ответ.

Эти инструменты предоставляют следующие возможности:

- **Доступ к локальной информации:** Инструменты позволяют модели получать доступ к вашей локальной файловой системе, читать содержимое файлов, перечислять каталоги и т.д.
- **Выполнение команд:** С помощью таких инструментов, как `run_shell_command`, модель может запускать команды оболочки (с соответствующими мерами безопасности и подтверждением пользователя).
- **Взаимодействие с веб-интернетом:** Инструменты могут получать контент с URL.
- **Выполнение действий:** Инструменты могут модифицировать файлы, записывать новые файлы или выполнять другие действия в вашей системе (опять же, обычно с защитными механизмами).
- **Обоснование ответов:** Используя инструменты для получения данных в реальном времени или конкретных локальных данных, ответы могут быть более точными, релевантными и обоснованными в вашем фактическом контексте.

## Как использовать инструменты Nessy CLI

Для использования инструментов Nessy CLI предоставьте подсказку CLI. Процесс работает следующим образом:

1.  Вы предоставляете подсказку CLI.
2.  CLI отправляет подсказку в core.
3.  Core вместе с вашей подсказкой и историей разговора отправляет список доступных инструментов и их описаний/схем в настроенное модельное API.
4.  Модель анализирует ваш запрос. Если она определяет, что инструмент нужен, её ответ будет включать запрос на выполнение конкретного инструмента с определёнными параметрами.
5.  Core получает этот запрос инструмента, проверяет его и (часто после подтверждения пользователя для чувствительных операций) выполняет инструмент.
6.  Вывод от инструмента отправляется обратно в модель.
7.  Модель использует вывод инструмента для формулирования окончательного ответа, который затем отправляется обратно через core в CLI и отображается вам.

Вы обычно будете видеть сообщения в CLI, указывающие, когда инструмент вызывается и успешен ли он или нет.

## Безопасность и подтверждение

Многие инструменты, особенно те, которые могут модифицировать вашу файловую систему или выполнять команды (`write_file`, `edit`, `run_shell_command`), разработаны с учётом безопасности. Nessy CLI обычно:

- **Требует подтверждения:** Запрашивает вас перед выполнением потенциально чувствительных операций, показывая, какое действие будет выполнено.
- **Использует песочницу:** Все инструменты подчиняются ограничениям песочницы (смотрите [Песочница в Nessy CLI](./sandbox.md)). Это означает, что при работе в песочнице любые инструменты (включая MCP-серверы), которые вы хотите использовать, должны быть доступны _внутри_ окружения песочницы. Например, для запуска MCP-сервера через `npx` исполняемый файл `npx` должен быть установлен внутри Docker-образа песочницы или быть доступен в окружении `sandbox-exec`.

Важно всегда внимательно просматривать подсказки подтверждения перед разрешением выполнения инструмента.

## Узнайте больше об инструментах Nessy CLI

Встроенные инструменты Nessy CLI можно широко классифицировать следующим образом:

- **[Инструменты файловой системы](./file-system.md):** Для взаимодействия с файлами и каталогами (чтение, запись, перечисление, поиск и т.д.).
- **[Инструмент оболочки](./shell.md) (`run_shell_command`):** Для выполнения команд оболочки.
- **[Инструмент мониторинга](./monitor.md) (`monitor`):** Для запуска долгоживущих команд оболочки, которые потоково передают вывод обратно как уведомления фоновой задачи.
- **[Инструмент веб-запросов](./web-fetch.md) (`web_fetch`):** Для получения контента с URL.
- **[Инструмент записи задач](./todo-write.md) (`todo_write`):** Для создания и управления структурированными списками задач во время сессий кодирования.
- **[Инструмент агента](./task.md) (`agent`):** Для делегирования сложных задач специализированным субагентам.
- **[Инструмент выхода из режима плана](./exit-plan-mode.md) (`exit_plan_mode`):** Для выхода из режима плана и продолжения с реализацией.

Дополнительно эти инструменты включают:

- **[MCP серверы](./mcp-server.md)**: MCP серверы действуют как мост между моделью и вашим локальным окружением или другими сервисами, такими как API.
  - **Руководство по быстрому запуску MCP**: Начните работу с MCP за 5 минут с практическими примерами
  - **Примеры конфигураций MCP**: Готовые к использованию конфигурации для распространённых сценариев
  - **[Управляемый Web Search Nestor](./nestor-web-search.md):** Архитектура стандартного веб-поиска для T-Bank.
  - **Тестирование и валидация MCP**: Тестирование и валидация настроек ваших MCP-серверов
- **[Песочница](./sandbox.md)**: Песочница изолирует модель и её изменения от вашего окружения для уменьшения потенциального риска.
