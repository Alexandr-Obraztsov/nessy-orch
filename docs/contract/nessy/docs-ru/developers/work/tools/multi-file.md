# Многофайловое чтение (`read_many_files`)

:::note

`read_many_files` ранее был представлен как отдельный инструмент, но был рефакторен во внутреннюю утилиту. Модель больше не вызывает его напрямую — вместо этого инструменты `read_file`, `glob` и `grep_search` покрывают индивидуальное и многофайловое чтение. Информация ниже сохранена для справки.

:::

## Описание

`read_many_files` читает содержимое из нескольких файлов, указанных путями или glob-паттернами. Поведение зависит от типов файлов:

- Для текстовых файлов этот инструмент конкатенирует их содержимое в одну строку.
- Для изображений (например, PNG, JPEG), PDF, аудио (MP3, WAV) и видео (MP4, MOV) файлов, он читает и возвращает их как base64-кодированные данные, при условии, что они явно запрошены по имени или расширению.

`read_many_files` может использоваться для выполнения задач, таких как получение обзора кодовой базы, поиск места реализации специфичной функциональности, рецензирование документации или сбор контекста из множества файлов конфигурации.

**Примечание:** `read_many_files` ищет файлы, следующие предоставленным путям или glob-паттернам. Путь к каталогу, такой как `"/docs"`, вернёт пустой результат; инструменту требуется паттерн, такой как `"/docs/*"` или `"/docs/*.md"` для определения соответствующих файлов.

### Аргументы

`read_many_files` принимает следующие аргументы:

- `paths` (list[string], обязательно): Массив glob-паттернов или путей относительно целевого каталога инструмента (например, `["src/**/*.ts"]`, `["README.md", "docs/*", "assets/logo.png"]`).
- `exclude` (list[string], опционально): Glob-паттерны для файлов/каталогов, которые нужно исключить (например, `["**/*.log", "temp/"]`). Они добавляются к исключениям по умолчанию, если `useDefaultExcludes` равен true.
- `include` (list[string], опционально): Дополнительные glob-паттерны для включения. Они объединяются с `paths` (например, `["*.test.ts"]` для специфичного добавления тестовых файлов, если они были широко исключены, или `["images/*.jpg"]` для включения специфичных типов изображений).
- `recursive` (boolean, опционально): Искать ли рекурсивно. Это в первую очередь контролируется `**` в glob-паттернах. По умолчанию `true`.
- `useDefaultExcludes` (boolean, опционально): Применять ли список исключений по умолчанию (например, `node_modules`, `.git`, не изображения/PDF бинарные файлы). По умолчанию `true`.
- `respect_git_ignore` (boolean, опционально): Уважать ли паттерны .gitignore при поиске файлов. По умолчанию true.

## Как использовать `read_many_files` с Nessy CLI

`read_many_files` ищет файлы, соответствующие предоставленным паттернам `paths` и `include`, уважая паттерны `exclude` и исключения по умолчанию (если включены).

- Для текстовых файлов: он читает содержимое каждого найденного файла (пытаясь пропустить бинарные файлы, не запрошенные явно как изображения/PDF) и объединяет его в одну строку с разделителем `--- {filePath} ---` между содержимым каждого файла. Использует кодировку UTF-8 по умолчанию.
- Инструмент вставляет `--- End of content ---` после последнего файла.
- Для изображений и PDF файлов: если явно запрошено по имени или расширению (например, `paths: ["logo.png"]` или `include: ["*.pdf"]`), инструмент читает файл и возвращает его содержимое как base64-кодированную строку.
- Инструмент пытается определить и пропустить другие бинарные файлы (те, которые не соответствуют распространённым типам изображений/PDF или не запрошены явно), проверяя наличие нулевых байтов в их начальном содержимом.

Использование:

```
read_many_files(paths=["Your files or paths here."], include=["Additional files to include."], exclude=["Files to exclude."], recursive=False, useDefaultExcludes=false, respect_git_ignore=true)
```

## Примеры `read_many_files`

Прочитать все TypeScript файлы в каталоге `src`:

```
read_many_files(paths=["src/**/*.ts"])
```

Прочитать основной README, все Markdown файлы в каталоге `docs` и специфичное изображение логотипа, исключая специфичный файл:

```
read_many_files(paths=["README.md", "docs/**/*.md", "assets/logo.png"], exclude=["docs/OLD_README.md"])
```

Прочитать все JavaScript файлы, но явно включить тестовые файлы и все JPEG в папке `images`:

```
read_many_files(paths=["**/*.js"], include=["**/*.test.js", "images/**/*.jpg"], useDefaultExcludes=False)
```

## Важные заметки

- **Обработка бинарных файлов:**
  - **Файлы изображений/PDF/аудио/видео:** Инструмент может читать распространённые типы изображений (PNG, JPEG и т.д.), PDF, аудио (mp3, wav) и видео (mp4, mov) файлы, возвращая их как base64-кодированные данные. Эти файлы _должны_ быть явно указаны паттернами `paths` или `include` (например, указав точное имя файла, как `video.mp4` или паттерн, как `*.mov`).
  - **Другие бинарные файлы:** Инструмент пытается определить и пропустить другие типы бинарных файлов, исследуя их начальное содержимое на наличие нулевых байтов. Инструмент исключает эти файлы из своего вывода.
- **Производительность:** Чтение очень большого количества файлов или очень больших отдельных файлов может быть ресурсоёмким.
- **Специфичность путей:** Убедитесь, что пути и glob-паттерны правильно указаны относительно целевого каталога инструмента. Для изображений/PDF файлов убедитесь, что паттерны достаточно специфичны для их включения.
- **Исключения по умолчанию:** Будьте осведомлены о паттернах исключений по умолчанию (как `node_modules`, `.git`) и используйте `useDefaultExcludes=False`, если вам нужно переопределить их, но делайте это осторожно.
