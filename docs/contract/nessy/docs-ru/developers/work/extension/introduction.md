# Nessy CLI Extensions

Расширения Nessy CLI упаковывают подсказки, MCP серверы, субагенты, навыки и пользовательские команды в знакомый и удобный формат. С расширениями вы можете расширить возможности Nessy CLI и поделиться этими возможностями с другими. Они разработаны для лёгкой установки и совместного использования.

Расширения и плагины из [Gemini CLI Extensions Gallery](https://geminicli.com/extensions/) и [Claude Code Marketplace](https://claudemarketplaces.com/) могут быть напрямую установлены в Nessy CLI. Эта кроссплатформенная совместимость даёт вам доступ к богатой экосистеме расширений и плагинов, драматически расширяя возможности Nessy CLI без требования от авторов расширений поддерживать отдельные версии.

## Управление расширениями

Мы предлагаем набор инструментов управления расширениями используя как CLI команды `nessy extensions`, так и slash-команды `/extensions` в интерактивном CLI.

### Управление расширениями во время выполнения (Slash-команды)

Вы можете управлять расширениями во время выполнения в интерактивном CLI используя slash-команды `/extensions`. Эти команды поддерживают горячую перезагрузку, означая, что изменения вступают в силу немедленно без перезапуска приложения.

| Команда                                | Описание                                                                       |
| -------------------------------------- | ------------------------------------------------------------------------------ |
| `/extensions` или `/extensions manage` | Управление всеми установленными расширениями                                   |
| `/extensions install <source>`         | Установить расширение из git URL, локального пути или маркетплейса             |
| `/extensions explore [source]`         | Открыть страницу источника расширений (Gemini или ClaudeCode) в вашем браузере |

### CLI управление расширениями

Вы также можете управлять расширениями используя CLI команды `nessy extensions`. Обратите внимание, что изменения, сделанные через CLI команды, будут отражены в активных CLI сессиях при перезапуске.

### Установка расширения

Вы можете установить расширение используя `nessy extensions install` из множества источников:

#### Из Claude Code Marketplace

Nessy CLI также поддерживает плагины из [Claude Code Marketplace](https://claudemarketplaces.com/). Установите из маркетплейса и выберите плагин:

```bash
nessy extensions install <marketplace-name>
# или
nessy extensions install <marketplace-github-url>
```

Если вы хотите установить специфичный плагин, вы можете использовать формат с именем плагина:

```bash
nessy extensions install <marketplace-name>:<plugin-name>
# или
nessy extensions install <marketplace-github-url>:<plugin-name>
```

Например, для установки плагина `prompts.chat` из маркетплейса [f/awesome-chatgpt-prompts](https://claudemarketplaces.com/plugins/f-awesome-chatgpt-prompts):

```bash
nessy extensions install f/awesome-chatgpt-prompts:prompts.chat
# или
nessy extensions install https://github.com/f/awesome-chatgpt-prompts:prompts.chat
```

Плагины Claude автоматически конвертируются в формат Nessy CLI во время установки:

- `claude-plugin.json` конвертируется в `nessy-extension.json`
- Конфигурации агентов конвертируются в формат субагента Nessy
- Конфигурации навыков конвертируются в формат навыка Nessy
- Отображения инструментов автоматически обрабатываются

Вы можете быстро просмотреть доступные расширения из различных маркетплейсов используя команду `/extensions explore`:

```bash
# Открыть маркетплейс Gemini CLI Extensions
/extensions explore Gemini

# Открыть маркетплейс Claude Code
/extensions explore ClaudeCode
```

Эта команда открывает соответствующий маркетплейс в вашем браузере по умолчанию, позволяя вам обнаружить новые расширения для улучшения вашего опыта Nessy CLI.

> **Кроссплатформенная совместимость**: Это позволяет вам использовать богатые экосистемы расширений как от Gemini CLI, так и от Claude Code, драматически расширяя доступную функциональность для пользователей Nessy CLI.

#### Из расширений Gemini CLI

Nessy CLI полностью поддерживает расширения из [Gemini CLI Extensions Gallery](https://geminicli.com/extensions/). Просто установите их используя git URL:

```bash
nessy extensions install <gemini-cli-extension-github-url>
# или
nessy extensions install <owner>/<repo>
```

Расширения Gemini автоматически конвертируются в формат Nessy CLI во время установки:

- `gemini-extension.json` конвертируется в `nessy-extension.json`
- TOML файлы команд автоматически мигрируют в формат Markdown
- MCP серверы, файлы контекста и настройки сохраняются

#### Из npm Registry

Nessy CLI поддерживает установку расширений из npm реестров используя именования пакетов с областью видимости. Это идеально для команд с приватными реестрами, у которых уже есть инфраструктура аутентификации, версионирования и публикации.

```bash
# Установить последнюю версию
nessy extensions install @scope/my-extension

# Установить специфичную версию
nessy extensions install @scope/my-extension@1.2.0

# Установить из кастомного реестра
nessy extensions install @scope/my-extension --registry https://your-registry.com
```

Только пакеты с областью видимости (`@scope/package-name`) поддерживаются во избежание неоднозначности с форматом GitHub shorthand `owner/repo`.

**Разрешение реестра** следует этому приоритету:

1. Флаг CLI `--registry` (явное переопределение)
2. Реестр с областью видимости из `.npmrc` (например, `@scope:registry=https://...`)
3. Реестр по умолчанию из `.npmrc`
4. Fallback: `https://registry.npmjs.org/`

**Аутентификация** обрабатывается автоматически через переменную окружения `NPM_TOKEN` или записи `_authToken` для специфичного реестра в вашем файле `.npmrc`.

> **Заметка:** Расширения npm должны включать файл `nessy-extension.json` в корне пакета, следуя тому же формату, что и любое другое расширение Nessy CLI. См. [Extension Releasing](./extension-releasing.md#выпуск-через-npm-registry) для деталей упаковки.

#### Из Git репозитория

```bash
nessy extensions install https://github.com/github/github-mcp-server
```

Это установит расширение github mcp server.

#### Из локального пути

```bash
nessy extensions install /path/to/your/extension
```

Обратите внимание, что мы создаём копию установленного расширения, поэтому вам нужно будет запустить `nessy extensions update` для внесения изменений как из локально определённых расширений, так и из тех, что на GitHub.

### Удаление расширения

Для удаления выполните `nessy extensions uninstall extension-name`, так, в случае примера установки:

```
nessy extensions uninstall nessy-cli-security
```

### Отключение расширения

Расширения по умолчанию включены во всех рабочих пространствах. Вы можете отключить расширение полностью или для специфичного рабочего пространства.

Например, `nessy extensions disable extension-name` отключит расширение на уровне пользователя, поэтому оно будет отключено везде. `nessy extensions disable extension-name --scope=workspace` отключит расширение только в текущем рабочем пространстве.

### Включение расширения

Вы можете включить расширения используя `nessy extensions enable extension-name`. Вы также можете включить расширение для специфичного рабочего пространства используя `nessy extensions enable extension-name --scope=workspace` из этого рабочего пространства.

Это полезно, если у вас есть расширение, отключённое на верхнем уровне и включённое только в специфичных местах.

### Обновление расширения

Для расширений, установленных из локального пути, git репозитория или npm реестра, вы можете явно обновить до последней версии с `nessy extensions update extension-name`. Для npm расширений, установленных без привязки к версии (например, `@scope/pkg`), обновления проверяют `latest` dist-tag. Для тех, что установлены со специфичным dist-tag (например, `@scope/pkg@beta`), обновления отслеживают этот тег. Расширения, привязанные к точной версии (например, `@scope/pkg@1.2.0`), всегда считаются обновлёнными.

Вы можете обновить все расширения с:

```
nessy extensions update --all
```

## Как это работает

При запуске Nessy CLI ищет расширения в `<home>/.nessy/extensions`

Расширения существуют как каталог, содержащий файл `nessy-extension.json`. Например:

`<home>/.nessy/extensions/my-extension/nessy-extension.json`

### `nessy-extension.json`

Файл `nessy-extension.json` содержит конфигурацию для расширения. Файл имеет следующую структуру:

```json
{
  "name": "my-extension",
  "version": "1.0.0",
  "mcpServers": {
    "my-server": {
      "command": "node my-server.js"
    }
  },
  "contextFileName": "NESSY.md",
  "commands": "commands",
  "skills": "skills",
  "agents": "agents",
  "settings": [
    {
      "name": "API Key",
      "description": "Ваш API-ключ для сервиса",
      "envVar": "MY_API_KEY",
      "sensitive": true
    }
  ]
}
```

- `name`: Имя расширения. Это используется для уникальной идентификации расширения и для разрешения конфликтов, когда команды расширения имеют то же имя, что и пользовательские или проектные команды. Имя должно быть в нижнем регистре или цифры и использовать тире вместо подчёркиваний или пробелов. Это то, как пользователи будут ссылаться на ваше расширение в CLI. Обратите внимание, что мы ожидаем, что это имя будет совпадать с именем каталога расширения.
- `version`: Версия расширения.
- `mcpServers`: Карта MCP серверов для конфигурирования. Ключ — имя сервера, значение — конфигурация сервера. Эти серверы будут загружены при запуске так же, как MCP серверы, настроенные в [`settings.json` файле](../../../users/work/configuration/settings.md). Если и расширение, и файл `settings.json` конфигурируют MCP сервер с одинаковым именем, сервер, определённый в файле `settings.json`, имеет приоритет.
  - Обратите внимание, что все опции конфигурации MCP сервера поддерживаются, кроме `trust`.
- `contextFileName`: Имя файла, содержащего контекст для расширения. Это будет использовано для загрузки контекста из каталога расширения. Если это свойство не используется, но файл `NESSY.md` присутствует в каталоге вашего расширения, тогда этот файл будет загружен.
- `commands`: Каталог, содержащий пользовательские команды (по умолчанию: `commands`). Команды — это `.md` файлы, определяющие подсказки.
- `skills`: Каталог, содержащий пользовательские навыки (по умолчанию: `skills`). Навыки автоматически обнаруживаются и становятся доступными через команду `/skills`.
- `agents`: Каталог, содержащий пользовательские субагенты (по умолчанию: `agents`). Субагенты — это `.yaml` или `.md` файлы, определяющие специализированных ИИ-ассистентов.
- `settings`: Массив настроек, которые требует расширение. При установке пользователям будет предложено предоставить значения для этих настроек. Значения хранятся безопасно и передаются MCP серверам как переменные окружения.
  - Каждая настройка имеет следующие свойства:
    - `name`: Отображаемое имя для настройки
    - `description`: Описание того, для чего используется эта настройка
    - `envVar`: Имя переменной окружения, которое будет установлено
    - `sensitive`: Булево значение, указывающее, должно ли значение быть скрытым (например, API-ключи, пароли)

### Управление настройками расширения

Расширения могут требовать конфигурацию через настройки (такие как API-ключи или учётные данные). Эти настройки могут управляться используя CLI команду `nessy extensions settings`:

**Установить значение настройки:**

```bash
nessy extensions settings set <extension-name> <setting-name> [--scope user|workspace]
```

**Перечислить все настройки для расширения:**

```bash
nessy extensions settings list <extension-name>
```

**Просмотреть текущие значения (пользователь и рабочее пространство):**

```bash
nessy extensions settings show <extension-name> <setting-name>
```

**Удалить значение настройки:**

```bash
nessy extensions settings unset <extension-name> <setting-name> [--scope user|workspace]
```

Настройки могут быть сконфигурированы на двух уровнях:

- **Уровень пользователя** (по умолчанию): Настройки применяются ко всем проектам (`~/.nessy/.env`)
- **Уровень рабочего пространства**: Настройки применяются только к текущему проекту (`.nessy/.env`)

Настройки рабочего пространства имеют приоритет над настройками пользователя. Чувствительные настройки хранятся безопасно и никогда не отображаются в открытом тексте.

Когда Nessy CLI запускается, он загружает все расширения и объединяет их конфигурации. Если есть какие-либо конфликты, конфигурация рабочего пространства имеет приоритет.

### Пользовательские команды

Расширения могут предоставлять [пользовательские команды](../../../users/work/features/commands.md#краткий-обзор) размещая Markdown файлы в подкаталоге `commands/` в каталоге расширения. Эти команды следуют тому же формату, что и пользовательские и проектные пользовательские команды и используют стандартные соглашения об именах.

> **Примечание:** Формат команд был изменён с TOML на Markdown. TOML файлы устарели, но всё ещё поддерживаются. Вы можете мигрировать существующие команды TOML используя автоматическую миграцию, которая появляется при обнаружении TOML файлов.

**Пример**

Расширение с именем `gcp` со следующей структурой:

```
.nessy/extensions/gcp/
├── nessy-extension.json
└── commands/
    ├── deploy.md
    └── gcs/
        └── sync.md
```

Предоставит эти команды:

- `/deploy` - Отображается как `[gcp] Custom command from deploy.md` в справке
- `/gcs:sync` - Отображается как `[gcp] Custom command from sync.md` в справке

### Пользовательские навыки

Расширения могут предоставлять пользовательские навыки размещая файлы навыков в подкаталоге `skills/` в каталоге расширения. Каждый навык должен иметь файл `SKILL.md` с YAML frontmatter, определяющим имя и описание навыка.

**Пример**

```
.nessy/extensions/my-extension/
├── nessy-extension.json
└── skills/
    └── pdf-processor/
        └── SKILL.md
```

Навык будет доступен через команду `/skills`, когда расширение активно.

### Пользовательские субагенты

Расширения могут предоставлять пользовательские субагенты размещая файлы конфигурации агентов в подкаталоге `agents/` в каталоге расширения. Агенты определяются используя YAML или Markdown файлы.

**Пример**

```
.nessy/extensions/my-extension/
├── nessy-extension.json
└── agents/
    └── testing-expert.yaml
```

Субагенты расширения появляются в диалоге менеджера субагентов в разделе «Extension Agents».

### Разрешение конфликтов

Команды расширения имеют наименьший приоритет. Когда происходит конфликт с пользовательскими или проектными командами:

1. **Нет конфликта**: Команда расширения использует своё естественное имя (например, `/deploy`)
2. **С конфликтом**: Команда расширения переименовывается с префиксом расширения (например, `/gcp.deploy`)

Например, если и пользователь, и расширение `gcp` определяют команду `deploy`:

- `/deploy` - Выполняет пользовательскую команду deploy
- `/gcp.deploy` - Выполняет команду расширения deploy (помечена тегом `[gcp]`)

## Переменные

Расширения Nessy CLI позволяют подстановку переменных в `nessy-extension.json`. Это может быть полезно, если, например, вам нужен текущий каталог для запуска MCP сервера используя `"cwd": "${extensionPath}${/}run.ts"`.

**Поддерживаемые переменные:**

| Переменная                    | Описание                                                                                                                                                                  |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `${extensionPath}`            | Полный путь расширения в файловой системе пользователя, например, '/Users/username/.nessy/extensions/example-extension'. Это не будет разворачивать символические ссылки. |
| `${workspacePath}`            | Полный путь текущего рабочего пространства.                                                                                                                               |
| `${/}` или `${pathSeparator}` | Разделитель путей (различается на ОС).                                                                                                                                    |
