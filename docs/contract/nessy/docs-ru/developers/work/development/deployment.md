# Выполнение и развёртывание Nessy CLI

Этот документ описывает, как запускать Nessy CLI и объясняет архитектуру развёртывания, которую использует Nessy CLI.

## Запуск Nessy CLI

Существует несколько способов запуска Nessy CLI. Выбор зависит от того, как вы намерены его использовать.

---

### 1. Стандартная установка (рекомендуется для обычных пользователей)

Это рекомендуемый способ для конечных пользователей установить Nessy CLI. Он включает загрузку пакета Nessy CLI из реестра NPM.

- **Глобальная установка:**

  ```bash
  npm install -g @nestor/nessy-cli
  ```

  Затем запускайте CLI из любого места:

  ```bash
  nessy
  ```

- **Выполнение через NPX:**

  ```bash
  # Выполнить последнюю версию из NPM без глобальной установки
  npx @nestor/nessy-cli
  ```

---

### 2. Запуск в песочнице (Docker/Podman)

Для безопасности и изоляции Nessy CLI может выполняться внутри контейнера. Это способ по умолчанию, которым CLI выполняет инструменты, которые могут иметь побочные эффекты.

- **Напрямую из реестра:**
  Вы можете запустить опубликованный образ песочницы напрямую. Это полезно для сред, где у вас есть только Docker и вы хотите запустить CLI.
  ```bash
  # Запустить опубликованный образ песочницы
  docker run --rm -it ghcr.io/nessylm/nessy:0.0.11
  ```
- **Использование флага `--sandbox`:**
  Если у вас установлен Nessy CLI локально (используя стандартную установку, описанную выше), вы можете поручить ему запуск внутри контейнера песочницы.
  ```bash
  nessy --sandbox -y -p "your prompt here"
  ```

---

### 3. Запуск из исходного кода (рекомендуется для участников Nessy CLI)

Участники проекта захотят запускать CLI напрямую из исходного кода.

- **Режим разработки:**
  Этот метод предоставляет горячую перезагрузку и полезен для активной разработки.
  ```bash
  # Из корня репозитория
  npm run start
  ```
- **Режим, подобный продакшену (связанный пакет):**
  Этот метод имитирует глобальную установку, связывая ваш локальный пакет. Это полезно для тестирования локальной сборки в рабочем процессе продакшена.

  ```bash
  # Связать локальный пакет cli с вашим глобальным node_modules
  npm link packages/cli

  # Теперь вы можете запускать вашу локальную версию используя команду `nessy`
  nessy
  ```

---

### 4. Запуск последнего коммита Nessy CLI с GitHub

Последнюю зафиксированную версию Nessy CLI можно запустить прямо из репозитория GitHub. Это удобно для проверки функций, которые ещё находятся в разработке.

```bash
# Выполнить CLI непосредственно из ветки main на GitHub
npx https://github.com/NessyLM/nessy
```

## Архитектура развёртывания

Описанные выше методы выполнения стали возможными благодаря следующим архитектурным компонентам и процессам:

**Пакеты NPM**

Проект Nessy CLI — это монорепозиторий, который публикует основные пакеты в реестр NPM:

- `@nestor/nessy-cli-core`: Бэкенд, логика обработки и выполнение инструментов.
- `@nestor/nessy-cli`: Пользовательский фронтенд.

Эти пакеты используются при выполнении стандартной установки и при запуске Nessy CLI из исходного кода.

**Процессы сборки и упаковки**

Существует два различных процесса сборки, в зависимости от канала распространения:

- **Публикация в NPM:** Для публикации в реестре NPM исходный код TypeScript в `@nestor/nessy-cli-core` и `@nestor/nessy-cli` транспилируется в обычный JavaScript с помощью компилятора TypeScript (`tsc`). Получившаяся директория `dist/` — это то, что публикуется в пакете NPM. Это стандартный подход для библиотек на TypeScript.

- **Выполнение с GitHub через `npx`:** При запуске последней версии Nessy CLI прямо с GitHub используется другой процесс, запускаемый скриптом `prepare` в `package.json`. Этот скрипт использует `esbuild`, чтобы собрать всё приложение и его зависимости в один самодостаточный JavaScript-файл. Этот бандл создаётся «на лету» на машине пользователя и не хранится в репозитории.

**Docker-образ песочницы**

Метод выполнения через Docker поддерживается контейнерным образом `nessy-sandbox`. Этот образ публикуется в реестре контейнеров и содержит предустановленную глобальную версию Nessy CLI.

## Процесс релиза

Процесс релиза автоматизирован с помощью GitHub Actions. Workflow релиза выполняет следующие действия:

1. Собирает NPM-пакеты с помощью `tsc`.
2. Публикует NPM-пакеты в реестр артефактов.
3. Создаёт релизы с собранными ресурсами (assets).
