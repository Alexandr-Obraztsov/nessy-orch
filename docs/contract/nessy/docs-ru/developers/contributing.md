# Как внести вклад

Мы будем рады принять ваши патчи и вклад в этот проект.

## Процесс внесения вклада

### Ревью кода

Все отправки, включая отправки участниками проекта, требуют ревью.

### Руководство по Merge Request

Чтобы помочь нам быстро ревьюить и мержить ваши MR, пожалуйста, следуйте этим рекомендациям. MR, которые не соответствуют этим стандартам, могут быть закрыты.

#### 1. Ссылка на существующий Issue

Все MR должны быть связаны с существующим issue в нашем трекере. Это гарантирует, что каждое изменение было обсуждено и согласовано с целями проекта до написания кода.

- **Для исправлений ошибок:** MR должен быть связан с issue отчёта об ошибке.
- **Для функций:** MR должен быть связан с issue запроса функции или предложения, которое было одобрено мейнтейнером.

Если issue для вашего изменения не существует, пожалуйста, **создайте его сначала** и дождитесь обратной связи перед началом написания кода.

#### 2. Делайте маленькими и сфокусированными

Мы предпочитаем маленькие, атомарные MR, которые адресуют одну конкретную проблему или добавляют одну конкретную функцию.

- **Нужно:** Создавайте MR, который исправляет одну конкретную ошибку или добавляет одну конкретную функцию.
- **Не нужно:** Объединяйте несколько несвязанных изменений (например, исправление ошибки, новую функцию и рефакторинг) в один MR.

Как правило, начинайте разделять MR, когда он превышает около 1200 изменённых строк. MR объёмом более 2000 изменённых строк должны быть либо разбиты на серию меньших, логичных MR, которые могут быть независимо ревьюены и смержены, либо объясните в описании MR, почему изменение должно быть применено вместе.

#### 3. Используйте Draft MR для работы в процессе

Если вы хотите получить раннюю обратную связь на вашу работу, пожалуйста, используйте функцию GitHub **Draft Merge Request**. Это сигнализирует мейнтейнерам, что MR ещё не готов к формальному ревью, но открыт для обсуждения и первоначальной обратной связи.

#### 4. Убедитесь, что все проверки пройдены

Перед отправкой вашего MR убедитесь, что все автоматические проверки пройдены, запустив `npm run preflight`. Эта команда запускает все тесты, линтинг и другие проверки стиля.

#### 5. Обновите документацию

Если ваш MR вносит пользовательское изменение (например, новую команду, модифицированный флаг или изменение поведения), вы также должны обновить соответствующую документацию в директории `/docs`.

#### 6. Пишите ясные сообщения коммитов и хорошее описание MR

Ваш MR должен иметь ясный, описательный заголовок и подробное описание изменений. Следуйте стандарту [Conventional Commits](https://www.conventionalcommits.org/) для ваших сообщений коммитов.

- **Хороший заголовок MR:** `feat(cli): Add --json flag to 'config get' command`
- **Плохой заголовок MR:** `Made some changes`

В описании MR объясните «почему» ваших изменений и сошлитесь на соответствующий issue (например, `Fixes #123`).

## Настройка разработки и рабочий процесс

Этот раздел направляет контрибьюторов о том, как собрать, модифицировать и понять настройку разработки этого проекта.

### Настройка окружения разработки

**Необходимые условия:**

1.  **Node.js**:
    - **Разработка:** Пожалуйста, используйте Node.js `>=22`. Ink 7 (используемый TUI) требует Node 22, а `react@^19.2.0` — совместимая peer-зависимость. Вы можете использовать инструмент, такой как [nvm](https://github.com/nvm-sh/nvm), для управления версиями Node.js.
    - **Продакшн:** Для запуска CLI в продакшн-окружении приемлема любая версия Node.js `>=22`.
2.  **Git**

### Процесс сборки

Для клонирования репозитория:

```bash
git clone https://gitlab.tcsbank.ru/nestor/nessy-cli.git # Или URL вашего форка
cd nessy-cli
```

Для установки зависимостей, определённых в `package.json`, а также корневых зависимостей:

```bash
npm install
```

Для сборки всего проекта (всех пакетов):

```bash
npm run build
```

Эта команда обычно компилирует TypeScript в JavaScript, собирает ассеты и подготавливает пакеты к выполнению. Обратитесь к `scripts/build.js` и скриптам `package.json` для получения дополнительной информации о том, что происходит во время сборки.

### Включение песочницы

[Песочница](#песочница) настоятельно рекомендуется и требует как минимум установки `NESSY_SANDBOX=true` в вашем `~/.env` и обеспечения доступности провайдера песочницы (например, `macOS Seatbelt`, `docker` или `podman`). Смотрите [Песочница](#песочница) для деталей.

Для сборки как утилиты `nessy` CLI, так и контейнера песочницы, запустите `build:all` из корневого каталога:

```bash
npm run build:all
```

Для пропуска сборки контейнера песочницы вы можете использовать `npm run build` вместо этого.

### Запуск

Для запуска приложения Nessy CLI из исходного кода (после сборки) выполните следующую команду из корневого каталога:

```bash
npm start
```

Если вы хотите запустить исходную сборку вне папки nessy-cli, вы можете использовать `npm link path/to/nessy/packages/cli` (смотрите: [документация](https://docs.npmjs.com/cli/v9/commands/npm-link)) для запуска с `nessy-cli`.

### Запуск тестов

Этот проект содержит два типа тестов: модульные тесты и интеграционные тесты.

#### Модульные тесты

Для выполнения набора модульных тестов проекта:

```bash
npm run test
```

Это запустит тесты, расположенные в директориях `packages/core` и `packages/cli`. Убедитесь, что тесты пройдены перед отправкой любых изменений. Для более комплексной проверки рекомендуется запустить `npm run preflight`.

#### Интеграционные тесты

Интеграционные тесты предназначены для валидации функциональности Nessy CLI от начала до конца. Они не запускаются как часть команды `npm run test` по умолчанию.

Для запуска интеграционных тестов используйте следующую команду:

```bash
npm run test:e2e
```

Для получения более подробной информации о фреймворке интеграционного тестирования пожалуйста, смотрите [документацию по интеграционным тестам](./work/development/integration-tests.md).

### Линтинг и префлайт проверки

Для обеспечения качества кода и согласованности форматирования запустите префлайт проверку:

```bash
npm run preflight
```

Эта команда запустит ESLint, Prettier, все тесты и другие проверки, как определено в `package.json` проекта.

_ProTip_

после клонирования создайте файл git precommit хука для обеспечения чистоты ваших коммитов.

```bash
echo "
# Запуск npm build и проверка ошибок
if ! npm run preflight; then
  echo \"npm build failed. Commit aborted.\"
  exit 1
fi
" > .git/hooks/pre-commit && chmod +x .git/hooks/pre-commit
```

#### Форматирование

Для отдельного форматирования кода в этом проекте выполните следующую команду из корневого каталога:

```bash
npm run format
```

Эта команда использует Prettier для форматирования кода согласно руководствам по стилю проекта.

#### Линтинг

Для отдельного линтинга кода в этом проекте выполните следующую команду из корневого каталога:

```bash
npm run lint
```

### Соглашения о кодировании

- Пожалуйста, придерживайтесь стиля кодирования, паттернов и соглашений, используемых во всей существующей кодовой базе.
- **Импорты:** Обратите особое внимание на пути импортов. Проект использует ESLint для обеспечения ограничений на относительные импорты между пакетами.

### Структура проекта

- `packages/`: Содержит отдельные суб-пакеты проекта.
  - `cli/`: Интерфейс командной строки.
  - `core/`: Основная бэкенд-логика для Nessy CLI.
- `docs/`: Содержит всю документацию проекта.
- `scripts/`: Утилиты для сборки, тестирования и задач разработки.

Для получения более подробной архитектуры смотрите `docs/architecture.md`.

## Разработка документации

Этот раздел описывает, как разрабатывать и просматривать документацию локально.

### Необходимые условия

1. Убедитесь, что у вас установлен Node.js (версии 22+)
2. Имейте доступ к npm или yarn

### Настройка сайта документации локально

Для работы над документацией и предварительного просмотра изменений локально:

1. Перейдите в директорию `docs-site`:

   ```bash
   cd docs-site
   ```

2. Установите зависимости:

   ```bash
   npm install
   ```

3. Свяжите содержимое документации из основной директории `docs`:

   ```bash
   npm run link
   ```

   Это создаёт символическую ссылку из `../docs` в `content` в проекте docs-site, позволяя содержимому документации обслуживаться сайтом Next.js.

4. Запустите сервер разработки:

   ```bash
   npm run dev
   ```

5. Откройте [http://localhost:3000](http://localhost:3000) в вашем браузере для просмотра сайта документации с живыми обновлениями по мере внесения изменений.

Любые изменения, сделанные в файлах документации в основной директории `docs`, будут немедленно отражены на сайте документации.

## Отладка

### VS Code:

0.  Запустите CLI для интерактивной отладки в VS Code с `F5`
1.  Запустите CLI в режиме отладки из корневого каталога:
    ```bash
    npm run debug
    ```
    Эта команда запускает `node --inspect-brk dist/index.js` в директории `packages/cli`, приостанавливая выполнение до подключения отладчика. Затем вы можете открыть `chrome://inspect` в вашем браузере Chrome для подключения к отладчику.
2.  В VS Code используйте конфигурацию запуска «Attach» (найдена в `.vscode/launch.json`).

В качестве альтернативы вы можете использовать конфигурацию запуска «Launch Program» в VS Code, если предпочитаете запускать текущий открытый файл напрямую, но «F5» обычно рекомендуется.

Для попадания в точку останова внутри контейнера песочницы запустите:

```bash
DEBUG=1 nessy-cli
```

**Примечание:** Если у вас есть `DEBUG=true` в файле `.env` проекта, это не повлияет на nessy из-за автоматического исключения. Используйте файлы `.nessy-cli/.env` для специфичных настроек отладки nessy-cli.

### React DevTools

Для отладки основанного на React UI CLI вы можете использовать React DevTools. Ink, библиотека, используемая для интерфейса CLI, совместима с React DevTools версии 4.x.

1.  **Запустите приложение Nessy CLI в режиме разработки:**

    ```bash
    DEV=true npm start
    ```

2.  **Установите и запустите React DevTools версии 4.28.5 (или последнюю совместимую версию 4.x):**

    Вы можете установить его глобально:

    ```bash
    npm install -g react-devtools@4.28.5
    react-devtools
    ```

    Или запустить напрямую с помощью npx:

    ```bash
    npx react-devtools@4.28.5
    ```

    Ваше работающее приложение CLI должно затем подключиться к React DevTools.
