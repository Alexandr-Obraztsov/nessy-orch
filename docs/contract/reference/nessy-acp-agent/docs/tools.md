# Инструменты (Tools)

Все инструменты реализованы по паттерну стратегии: каждый инструмент содержит упорядоченный список реализаций, и `BaseTool.exec()` выбирает первую, у которой `isAvailable()` возвращает `true`.

## Типы реализаций

| Тип               | Описание                                                                             | Проверка доступности                                    |
| ----------------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------- |
| `mcp`             | Делегирует вызов MCP-серверу                                                         | MCP-клиент существует и предоставляет данный инструмент |
| `acp_advertising` | Вызывает `connection.extMethod("_tools/<name>", ...)`                                | `capabilities.tools["<name>"] === true`                 |
| `acp_basic`       | Использует встроенные методы ACP (`readTextFile`, `createTerminal`, `sessionUpdate`) | Зависит от конкретной capability                        |
| `local`           | Выполняется локально через Node.js                                                   | Всегда доступен                                         |

## Приоритет реализаций

Реализации проверяются в указанном порядке (побеждает первая доступная):

| Инструмент              | Приоритет                     |
| ----------------------- | ----------------------------- |
| `read_file`             | acp_basic → local             |
| `write_to_file`         | acp_basic → local             |
| `list_files`            | mcp → acp_advertising → local |
| `replace_in_file`       | mcp → acp_advertising → local |
| `search_files`          | mcp → acp_advertising → local |
| `execute_command`       | mcp → acp_basic → local       |
| `ask_followup_question` | acp_basic                     |
| `plan_mode_respond`     | acp_basic                     |

## Разрешения (permissions)

Каждый инструмент имеет свойство `permissionRequired`. При создании сессии инструменты с `permissionRequired = false` автоматически получают разрешение `allow_always` через `PermissionService.loadDefaultPermissions()`.

| Инструмент              | `permissionRequired` |
| ----------------------- | -------------------- |
| `read_file`             | `true`               |
| `write_to_file`         | `true`               |
| `list_files`            | `true`               |
| `replace_in_file`       | `true`               |
| `search_files`          | `true`               |
| `execute_command`       | `true`               |
| `ask_followup_question` | `false`              |
| `plan_mode_respond`     | `false`              |

## read_file

Читает содержимое текстового файла.

**Аргументы:**

| Поле         | Тип    | Обязательное          | Описание                                          |
| ------------ | ------ | --------------------- | ------------------------------------------------- |
| `path`       | string | да                    | Путь к файлу (абсолютный или относительный к cwd) |
| `start_line` | number | вместе с `end_line`   | Первая строка (с 1, включительно)                 |
| `end_line`   | number | вместе с `start_line` | Последняя строка (включительно)                   |

**Возвращает:** без диапазона — содержимое файла в виде строки с прежним лимитом 300 КиБ. С диапазоном — обычную строку с заголовком о фактических границах, общем числе строк и следующей доступной строке, затем не более 1000 строк и 49 КиБ непрерывного содержимого. Специальных полей в общем A2A `ToolResult` нет.

**Реализации:**

- **acp_basic** — `connection.readTextFile({ sessionId, path })`; ACP-agent применяет диапазон к полученному тексту, поэтому VS Code и JetBrains не требуют отдельного расширения ACP-протокола и сохраняют поддержку несохранённого содержимого редактора. Доступен при `capabilities.fs.readTextFile`.
- **local** — чтение диапазона потоково через `fs.createReadStream`; без диапазона — `fs.readFile(path, "utf8")`. Доступен всегда.

## write_to_file

Записывает содержимое в текстовый файл, создавая родительские директории при необходимости.

**Аргументы:**

| Поле      | Тип    | Обязательное | Описание                                          |
| --------- | ------ | ------------ | ------------------------------------------------- |
| `path`    | string | да           | Путь к файлу (абсолютный или относительный к cwd) |
| `content` | string | да           | Содержимое для записи                             |

**Возвращает:** `"File written successfully"` или сообщение об ошибке.

**Реализации:**

- **acp_basic** — `connection.writeTextFile({ sessionId, path, content })`. Доступен при `capabilities.fs.writeTextFile`.
- **local** — `fs.writeFile(path, content)` с рекурсивным `mkdir`. Доступен всегда.

---

## list_files

Выводит список файлов и директорий по указанному пути.

**Аргументы:**

| Поле        | Тип    | Обязательное | Описание                                                  |
| ----------- | ------ | ------------ | --------------------------------------------------------- |
| `path`      | string | нет          | Путь к директории (по умолчанию `"."`)                    |
| `recursive` | string | нет          | `"true"` для рекурсивного обхода (по умолчанию `"false"`) |

**Возвращает:** список записей, разделённых переводом строки. Директории оканчиваются на `/`. Пути относительны к cwd. Директории отсортированы первыми, затем файлы — в алфавитном порядке.

**Ограничения локальной реализации:** `LIST_FILES_LIMIT=200`. При превышении лимита возвращается предупреждение с частичным списком.

**Реализации:**

- **mcp** — `client.callTool("list_files", { path, recursive })`. Доступен, если MCP-клиент предоставляет `list_files`.
- **acp_advertising** — `connection.extMethod("_tools/list_files", { sessionId, path, recursive })`. Доступен при `capabilities.tools["list_files"]`.
- **local** — Рекурсивный или нерекурсивный обход через `fs.readdir`. Доступен всегда.

## replace_in_file

Применяет блоки поиска/замены к файлу.

**Аргументы:**

| Поле   | Тип    | Обязательное | Описание                                               |
| ------ | ------ | ------------ | ------------------------------------------------------ |
| `path` | string | да           | Путь к файлу (абсолютный или относительный к cwd)      |
| `diff` | string | да           | Один или несколько блоков SEARCH/REPLACE (формат ниже) |

**Формат diff:**

```
<<<<<<< SEARCH
[искомое содержимое]
=======
[содержимое для замены]
>>>>>>> REPLACE
```

Несколько блоков могут быть объединены и применяются последовательно.

**Возвращает:** сообщение об успехе с обновлённым содержимым, или ошибку с напоминанием о формате.

**Реализации:**

- **mcp** — `client.callTool("replace_in_file", { path, diff })`. Доступен, если MCP-клиент предоставляет `replace_in_file`.
- **acp_advertising** — `connection.extMethod("_tools/replace_in_file", { sessionId, path, diff })`. Доступен при `capabilities.tools["replace_in_file"]`.
- **local** — Парсит блоки diff через regex, читает файл, применяет замены, записывает файл. Доступен всегда.

## search_files

Ищет содержимое файлов по регулярному выражению в дереве директорий.

**Аргументы:**

| Поле           | Тип    | Обязательное | Описание                                                        |
| -------------- | ------ | ------------ | --------------------------------------------------------------- |
| `path`         | string | да           | Директория для поиска (абсолютный или относительный путь к cwd) |
| `regex`        | string | да           | Паттерн регулярного выражения                                   |
| `file_pattern` | string | нет          | Glob-паттерн для фильтрации файлов (по умолчанию `"*"`)         |

**Возвращает:** отформатированные результаты, сгруппированные по файлам с контекстными строками, или `"No results found"`.

**Ограничения локальной реализации:** `MAX_RESULTS=300`, `MAX_SYMBOLS=60000`, `CONTEXT_LINES=1`, `CONCURRENCY=16`. Пропускает `node_modules`, `.git`, `dist`, `build`, `out`, бинарные файлы и т.д.

**Реализации:**

- **mcp** — `client.callTool("search_files", { path, regex, [file_pattern] })`. Доступен, если MCP-клиент предоставляет `search_files`.
- **acp_advertising** — `connection.extMethod("_tools/search_files", { sessionId, path, regex, [file_pattern] })`. Доступен при `capabilities.tools["search_files"]`.
- **local** — Рекурсивный обход файлов + поиск по regex с контекстом. Доступен всегда.

## execute_command

Выполняет shell-команду.

**Аргументы:**

| Поле      | Тип    | Обязательное | Описание                     |
| --------- | ------ | ------------ | ---------------------------- |
| `command` | string | да           | Shell-команда для выполнения |

**Возвращает:** объединённый вывод stdout/stderr. Включает код выхода и информацию о сигнале при ненулевом завершении.

**Реализации:**

- **mcp** — `client.callTool("execute_command", { command, cwd })`. Доступен, если MCP-клиент предоставляет `execute_command`.
- **acp_basic** — `connection.createTerminal({ sessionId, command, cwd })` → `waitForExit()` → `currentOutput()` → `release()`. Доступен при `capabilities.terminal`.
- **local** — `child_process.spawn(command, { shell, cwd })`. Путь к shell берётся из `IEnvironmentService`. Доступен всегда.

## ask_followup_question

Отправляет вопрос пользователю. Ответ пользователя приходит в следующем prompt-цикле.

**Аргументы:**

| Поле       | Тип      | Обязательное | Описание                     |
| ---------- | -------- | ------------ | ---------------------------- |
| `question` | string   | да           | Текст вопроса                |
| `followup` | string[] | нет          | Предлагаемые варианты ответа |

**Возвращает:** отформатированное сообщение, отправленное пользователю.

При наличии `followup` варианты добавляются в виде нумерованного списка:

```
Какой подход выбрать?
1. Вариант A
2. Вариант B
```

**Реализации:**

- **acp_basic** — `connection.sessionUpdate()` с `agent_message_chunk`. Доступен всегда.

## plan_mode_respond

Отображает план/ответ пользователю. При необходимости реализации ожидает подтверждение пользователя в следующем prompt-цикле.

**Аргументы:**

| Поле                       | Тип    | Обязательное | Описание                                                                     |
| -------------------------- | ------ | ------------ | ---------------------------------------------------------------------------- |
| `response`                 | string | да           | Текст плана для отображения                                                  |
| `is_implementation_needed` | string | нет          | `"true"`, если требуется подтверждение пользователя (по умолчанию `"false"`) |

**Возвращает:**

- `"Plan displayed to user. Continuing with current workflow."` — когда `is_implementation_needed` не равно `"true"`
- `"Plan displayed to user. Waiting for user approval to proceed with implementation."` — когда `is_implementation_needed` равно `"true"`

**Реализации:**

- **acp_basic** — `connection.sessionUpdate()` с `agent_message_chunk`. Доступен всегда.
