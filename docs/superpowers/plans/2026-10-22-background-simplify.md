# Окно «Фон»: упрощение (22.10.2026)

Решения пользователя после проверки на моках: интерфейс слишком сложный, основной интерфейс сломан (⋯ в списке агентов не по правому краю), у фона ошибок для человека нет — ретраи бесконечные.

## Что делаем

**Основной интерфейс.** Из шапки списка агентов убрать чип плейбука и меню «⋯» обучения (вернуть шапку как до этапа 3). С кнопки «Роли» убрать значок внимания (значка нет вообще: ошибок для человека нет). Меню «Сессия → Фон…» и ⇧⌘B остаются.

**Ошибок нет, ретраи бесконечные.** Фоновые задания не переходят в `error`: после провала — `queued` с паузой `min(30 с × попытка, 10 мин)`. Раздела «Ошибки», кнопки «Повторить» и значка нет. Кейс не переходит в `error` из-за провала задания.

**Окно «Фон»: четыре раздела** — «В процессе», «Кейсы», «Плейбуки», «Журнал». Настроек в окне нет: вкладка «Фон» в окне настроек приложения (`Settings`), в окне «Фон» в углу (низ боковой панели) маленькая иконка-шестерёнка открывает окно настроек на этой вкладке.

**«В процессе».** Слева список из двух групп одна под другой: «Ждут обработки» (сессии в очереди) и «Обрабатываются» (сессии с идущим заданием описания). Клик по обрабатываемой — справа блок с агентом из двух вкладок:
- «Чат» — как чат агента в блоке «Агенты» (существующий `AgentChat`), но внизу вместо плана — прогресс чтения сессии (прочитано N из M событий). Можно писать агенту; сообщение **сразу прерывает** агента (`interrupt: true`), а не ждёт конца хода.
- «Результат» — промежуточный результат: то, что агент уже вытянул из сессии и сохранил (черновик описания, markdown, обновляется по событиям).
Агент — обычный агент nessy со специальными инструментами: он **сам тянет текст сессии блоками** (`nessy-orch case read`) и сохраняет черновик (`nessy-orch case draft`). Имя и заголовок агента = название сессии. После окончания сессия уходит в «Кейсы» (из «В процессе» пропадает).

**«Кейсы».** Все обработанные сессии. Слева список (поиск), клик — справа блок с описанием сессии (read-only). Все блоки (цели, действия, источники, поправки, вопросы) сворачиваются и разворачиваются. Редактора, заметок, чата, «Пересобрать» нет; остаётся «Удалить».

**«Плейбуки».** Слева список: готовые плейбуки (active/trial) и «в процессе» (draft/review, идущие сборка/ревью), поиск по заголовку и описанию. Клик — справа **весь контент плейбука** блоками (сворачиваются): «Скилл» (SKILL.md целиком), правила (с ▲▼), этапы, файлы, **инструменты** (скрипты `tools/*`, если сборщик их создал). Редакторов, ревью-UI, истории, чата нет. Для плейбука в статусе `review` — две кнопки «Одобрить»/«Отклонить», и «Удалить» (меню).

**«Журнал».** Просто лента всех записей, по дням, без разворотов и откатов.

## Контракт сервера (изменения)

- `JobStatus`: `error` больше не выдаётся (тип остаётся для совместимости). Поле `JobView.error` — последняя ошибка (не показывать).
- `JobView` +: `title: string | null` (название сессии, = имя агента), `progress: { read: number; total: number } | null` (прочитано / всего событий кейса для идущего `collect`/`close`).
- `CaseDetail` +: `draft: string` (черновик, пусто, если нет), `progress`.
- Новые маршруты (оператор и агент по ключу):
  - `GET /learning/cases/:id/read?maxChars=<n>` → `{ text: string, from: number, until: number, total: number, remaining: number, done: boolean }` — следующий блок событий кейса (формат как в порции сборщика), сервер сам двигает указатель чтения идущего задания; `done` — всё прочитано.
  - `POST /learning/cases/:id/draft { text }` → `{ ok: true }` — сохранить черновик описания (промежуточный результат), событие `learning_case` не нужно, но `learning_job` с обновлённым `progress` публикуется.
- CLI: `nessy-orch case read <id> [--max-chars N]`, `nessy-orch case draft <id> [--file F | stdin]`.
- Промпт сборщика: события не вставляются в промпт, агент читает блоки инструментом; после каждого блока сохраняет черновик; в конце отвечает как раньше (`<summary>`, `<meta>`).
- `PlaybookDetail` +: `files: Record<string, string>` (все файлы плейбука: `SKILL.md`, `stages/*`, `rules.md`, `tools/*`…), `PlaybookView` +: `tools: Array<{ name: string; description: string; content: string }>`.
- Сборщик плейбука может создавать инструменты (`tools` в ответе builder): скрипты кладутся в `tools/<name>` плейбука и упоминаются в `SKILL.md` (раздел «Tools»).
