# Фон v3: очередь по событиям, крупные блоки, сопоставитель с `fold`, плейбук как документ

Решения пользователя (22.10.2026), все согласованы:

1. **Единица — сессия.** Кейс = сессия (цепочка `/clear`), цели внутри описания — разделы. Сопоставитель группирует пары «сессия + цель».
2. **Законченная сессия:** вызван `SessionEnd` **или** закрыта вкладка **или** не было работы `idleMin` минут (по умолчанию 120, настройка). Законченные сессии сразу ставятся в очередь. Живой обработки по ходам нет: хуки `Stop`/`UserPromptSubmit` только обновляют «последнюю работу» (`lastActivityAt`) сессии. Незаконченная сессия нигде не показывается.
3. **Очередь:** два состояния — «в очереди» и «обрабатывается». Свободный слот (`maxAgents`) сразу занимает следующий из очереди (FIFO): при постановке, при завершении любого задания. Опроса нет. Единственные таймеры — одноразовые и из настроек: срок простоя сессии (один таймер на ближайший срок, пересчёт на событиях) и повтор после ошибки.
4. **Ошибка:** задание остаётся «обрабатывается» (держит слот), ошибка видна в диалоге агента (системное событие), повтор каждые `retrySec` (60) без конца: сообщение тому же агенту «в прошлый раз: <причина>, продолжай»; агента нет — новый. Статуса «ждёт повтор» нет.
5. **Зависший агент:** `stallMin` (0 — не снимать; по умолчанию 20) — нет событий агента столько минут → задание снимается и повторяется. Только по активности агента.
6. **Сборщик:** блоки крупнее (`blockEvents` 80, `blockChars` 40000), ответы краткие: суть, что решалось, чем кончилось, поправки, ссылки; подробности — следующий этап. В финальной консолидации — блок `## Brief` (суть, сущности, скелет) для сопоставителя. Гейты мягче: покрытие ссылками остаётся, плотность/факты/поправки — предупреждения.
7. **Сопоставитель** (агент кейсов) — при каждом новом законченном кейсе: **обзор целиком + углубление**: в промпте карточки всех плейбуков и кейсов (~500 знаков, из `## Brief`), инструменты `case show`, `playbook show`; BM25-список — подсказка, не фильтр; решение проверяет второй проход (читает полные описания группы). Типы решений: новая группа ≥3, добавить в плейбук, слить кейсы в плейбук, слить кейс и плейбук в обновлённый плейбук.
8. **`fold`** — отдельная задача по цели: влитая цель уходит из описания сессии; кейс исчезает, когда влиты все цели; в плейбуке строка «основан на сессии: название, дата». Полное описание удаляется, сырые события — в скрытый архив на диске (`archiveDays` 30, 0 — не хранить), в контекст агентов не попадают.
9. **Плейбук — markdown-документ** (как окно «Роли»): смотреть, править, сохранять. Правила в разделе `## Rules`, у каждого маркер `<!-- r-3 -->`; сохранение: текст изменился — то же правило (счётчики сохраняются), маркер пропал — правило в архив, строка без маркера — новое активное правило. Счётчики ▲▼ и ссылки на кейсы лежат рядом, не в тексте.
10. **Настройки** (вкладка «Фон» окна настроек, редактируемые): `enabled`, `maxAgents`, `idleMin`, `retrySec`, `stallMin`, `blockEvents`, `blockChars`, `archiveDays`; тихие подписи с единицами.

## Контракты

**`LearningSettings`** (`shared/types/learning.ts`): `enabled, maxAgents, idleMin, retrySec, stallMin, blockEvents, blockChars, archiveDays, disabledSessions`; прежние `autoReview`, `intervalMin` остаются в типе для совместимости (не используются). Границы: `idleMin` 5–10080, `retrySec` 5–3600, `stallMin` 0–720, `blockEvents` 10–400, `blockChars` 4000–200000, `archiveDays` 0–365, `maxAgents` 1–6. Значения по умолчанию — как выше. Файл `learning.json`, горячая перезагрузка.

**Хуки → сервер:** `POST /learning/signal { event: 'activity' | 'end', session, chatId, transcriptPath? }` (оператор или хук приложения; ответ `{ ok: true }` быстро, без ожидания работы). `event: 'end'` и `POST /sessions/:id/closed` ставят сессию в очередь немедленно.

**`JobView`:** состояния только `queued`, `running`; поля `retryAt`, `waiting` удаляются (приложение читает мягко); ошибка попытки — событие в диалоге агента и запись в журнале.

**Документ плейбука:** `PlaybookDetail.markdown: string` (полный документ: описание, параметры, источники, этапы, правила с маркерами, поведение, заметки); `PUT /learning/playbooks/:id/markdown { text, baseVersion }` → `PlaybookDetail` | 409 `stale` | 400 `lint` (замечания в `error` через `\n`).

**`CaseView`:** + `foldedGoals: number`; кейс без остаточных целей удаляется сервером с записью в журнал. `PlaybookView.sources`: список `{ session: string; date: string }` («основан на сессии»).
