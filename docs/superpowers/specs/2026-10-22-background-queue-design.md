# Фон: очередь и состояния, управляемые событиями (22.10.2026)

Решения пользователя: у задания два состояния — **в очереди** и **в работе**; никаких «повтор скоро», пауз и гигантских таймаутов; сессия попадает в очередь **по хукам**, а не по опросу.

## Принципы
1. **Событие → очередь сразу.** Ничего не ждёт тика: источник события сам ставит работу в очередь и запускает диспетчер.
2. **Два состояния.** `queued` → `running` → (удалено из очереди, запись в журнал). Провал — возврат в **конец** очереди (`queued`), без статуса «ждёт повтор» и без видимых пауз. Внутренняя защита от горячего цикла при мгновенных сбоях — задержка 2 с → 4 → … до 30 с, она **не состояние** и в интерфейсе не видна.
3. **Нет таймаутов-часов.** Конец работы агента — событие (агент перешёл в простой / завершил ход / процесс упал), а не `waitTimeoutSec`. Зависание ловится по **активности агента** (нет событий агента 3 минуты → снять, вернуть в очередь), а не по времени задания.
4. **Один источник правды о прогрессе** — принятые чекпоинты протокола чтения (`coveredUntil`); повтор продолжает с них.

## Поток
```
Claude Code (терминал приложения)
  ├─ хук Stop        (конец каждого хода)  ──► POST /learning/signal {event:'stop', session, chatId, transcriptPath}
  ├─ хук SessionEnd  (/clear, выход)       ──► POST /learning/signal {event:'end', …}
  └─ вкладка закрыта (POST /sessions/:id/closed) ─► то же, что 'end'
                         │
        LearningService.signal(): синхронно
          1. кейс цепочки (создать, если нет), путь транскрипта
          2. ingest: события ленты (после курсора) + транскрипт (после смещения) → raw/
          3. есть необработанные события → enqueue(collect | close), диспетчер
                         │
                 очередь (FIFO, по одному заданию на объект)
                         │ слот свободен — сразу
                         ▼
           агент-сборщик: case read → case draft (строгий протокол) → … → --final
```
- `collect` ставится на каждый `stop`, если по кейсу нет задания; идёт задание — кейс помечается `dirty`, после завершения задания ставится следующее (без пауз). Так один кейс = не больше одного задания.
- `close` (итог) — по `end`, закрытию вкладки или простою `idleMin` (подстраховка, см. ниже).
- Подстраховка раз в минуту (`sweep`, без агентов, дешёвая): досбор событий для кейсов, у которых хук не пришёл (сервер был выключен); закрытие по простою `idleMin`; восстановление после рестарта. Это не поллинг очереди.
- Хуки плагина `nessy` (только в терминале приложения, как остальные): `Stop` → `nessy-orch hook stop`, `SessionEnd` → `nessy-orch hook end`; бюджет 1,5 с, тихие (ничего в stdout), любая ошибка — код 0. Хук читает `session_id`, `transcript_path`, `cwd` из stdin.

## Состояния
| Объект | Состояния | Переходы |
|---|---|---|
| Задание | `queued`, `running` | `queued → running` — диспетчер, как только есть слот (`maxAgents`) и нет задания того же объекта в работе; `running → удалено` — завершено или снято; снятое/упавшее → `queued` в конец |
| Кейс | `collecting`, `closing`, `ready` | `collecting ⇄ closing → ready`; новое событие у `ready` → `collecting` |

## Что убираем
`retryAt`/`waiting` у задания и «повтор скоро» в интерфейсе; Hub-подписка с debounce и 30-секундный `tick` как источник работы; `waitTimeoutSec` и сторож по времени задания; паузы повторов > 30 с.
