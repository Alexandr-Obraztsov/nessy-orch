# UI v3: панель управления поручениями (проект)

Цель: с одного взгляда видно, **что требует меня**, **что сейчас делается и насколько продвинулось**, **что уже
готово**. Подробности (шаги, переписка) открываются по клику и не мешают обзору.

Основано на разборе аналогов (Devin, Cursor Agents, GitHub Copilot Agents, Codex, Jules, Conductor, Vibe Kanban,
Claude Squad, LangSmith, GitHub Actions, Temporal, Linear/Slack Inbox). Что у них общего:
- список задач со статусами и секция «нужно внимание» сверху;
- детали одной задачи справа: шаги, лог, результат;
- план как отдельный объект с прогрессом;
- результат — главное в задаче, а не последняя реплика в чате;
- **общей ленты всех реплик нет ни у кого**: она смешивает «ответ мне» с «агент А попросил агента Б» и прячет
  важное в потоке.

## 1. Модель

| Понятие | Что это | Откуда берётся |
|---|---|---|
| **Поручение** | Задача, которую вы (или Claude) дали: корневой агент + все агенты, которых он породил | Вычисляется в UI по `parent` (новой серверной сущности нет) |
| **Агент** | Исполнитель внутри поручения | как сейчас |
| **Ход** | Одно сообщение агенту → его работа → ответ | `UserEvent` … `reply`; время — `turnStartedAt` |
| **План** | Чек-лист шагов агента: `pending / in_progress / completed` | **новое**: агент сообщает план (см. §5) или ACP `plan` |
| **Результат** | Последний ответ агента на ваше сообщение | `reply` к `you` |
| **Внимание** | То, что ждёт вашего решения или взгляда | разрешения, ошибки, новые результаты |

Статус поручения сводится из статусов его агентов по приоритету:
**ждёт вас** (есть запрос разрешения) → **ошибка** → **в работе** → **готово** (все ответили, лежат в архиве)
→ **пауза** (свободны, без результата).

### 2.1 Верхняя строка
- Счётчики **являются фильтрами**: клик по «▲ 2 ждут вас» оставляет в списке только такие поручения.
- «+ Поручение» открывает диалог: что сделать, роль (с подсказкой по описанию), пространство, имя (по умолчанию из роли).
- Поиск ищет по поручениям, агентам, ролям и тексту результатов.
- Бейдж «авто-разрешения» показывается, если `autoApprove` включён: тогда секция разрешений пустая, и это должно
  быть понятно.

### 2.2 Внимание (левая колонка)
Очередь того, что ждёт вас. Порядок секций соответствует срочности:
1. **Разрешения** — агент заблокирован. Кнопки «Разрешить / Отклонить» прямо в строке.
2. **Ошибки** — ход упал. Кнопки «Открыть» и «Повторить»: повторно отправляет последнее сообщение.
3. **Результаты** — агент ответил вам. Две строки превью, кнопки «Открыть» и «Готово» (отметить просмотренным).

У элемента три состояния: новый (жирный), просмотрен, обработан. Обработанные исчезают, разрешения и ошибки
обрабатываются сами, как только ситуация разрешилась. Отметки о просмотре хранятся в браузере (localStorage).
Счётчик попадает в заголовок вкладки браузера: `(3) nessy-orch`.

### 2.3 Поручения (центр)
- Карточка поручения:
  - заголовок — первая строка задачи или displayName;
  - сводный статус, общее время, прогресс-бар, число агентов.
- Прогресс-бар показывается, только когда есть знаменатель:
  - план корневого агента: «4/5»;
  - или «завершено агентов N из M».
  - Без знаменателя бар не рисуем. Вместо него пульс работы и «шагов: 14».
- Строки агентов внутри карточки (одна строка — один агент, 32 px):
  - иконка статуса (форма + цвет, различима без цвета);
  - имя и роль;
  - **текущее действие** (`lastTool.title` или «думает…»);
  - мини-прогресс плана;
  - число шагов в ходе, таймер хода, «+N в очереди».
- Таймер желтеет, если от агента нет событий дольше 5 минут: возможно, завис.
- Сортировка: ждёт вас → ошибка → в работе (свежие сверху) → пауза → готово.
  Готовые поручения уходят в свёрнутую группу «Завершённые сегодня / ранее».
- Группировка переключается: по поручениям (по умолчанию) / по пространствам / по ролям / плоский список.
- Клавиатура:
  - `j` / `k` — вниз / вверх по строкам;
  - `Enter` — открыть детали;
  - `a` — разрешить;
  - `x` — прервать;
  - `/` — поиск;
  - `n` — новое поручение.

### 2.4 Детали агента (правая колонка, 420–520 px, можно закрыть)
Сверху вниз:
1. **Шапка**: имя, роль, пространство, родитель и дети (ссылками), статус и таймер, кнопки «Прервать»,
   «В архив / Вернуть», меню (копировать id, удалить).
2. **Сейчас**: запрос разрешения с кнопками, текущий инструмент с длительностью, «+N в очереди».
3. **План**: чек-лист с прогрессом (если агент его сообщил).
4. Вкладки:
   - **Результат** (по умолчанию после ответа): последний ответ крупно, markdown, «копировать»; ссылки на MR, Jira
     и Wiki в ответе превращаются в чипы.
   - **Шаги**: таймлайн вызовов инструментов, у каждого длительность, статус, ввод и вывод по клику. Ошибка
     раскрыта сразу.
   - **Чат**: полная переписка с агентом, размышления свёрнуты.
5. **Поле ввода**: «Написать агенту». Галочка «прервать текущий ход» включена по умолчанию, когда агент работает.
   Если её снять, сообщение встанет в очередь (`--queue`).

### 2.5 Журнал (нижний ящик)
Сюда переезжает нынешняя «Лента».
- В свёрнутом виде — одна строка с последним событием.
- Развёрнутый — хронология всех сообщений и системных событий с фильтрами: агент, поручение, тип (сообщение,
  ответ, ошибка, служебное).
- Нужен для вопроса «что происходило, пока меня не было» и для разбора цепочек агент → агент.
- Главным экраном журнал не является.

### 2.6 Узкие экраны (< 900 px)
- Нижние вкладки: **Внимание** / **Поручения** / **Журнал**.
- Детали агента открываются на весь экран со стрелкой «назад».
- Счётчики сводки — горизонтальная полоса чипов под заголовком.

### 2.7 Роли и пространства
Это справочники, в рабочий экран они не входят. Открываются из меню (⚙): страница «Роли» с прежним редактором и
страница «Пространства». В диалоге «+ Поручение» роль выбирается списком с описаниями.

## 3. Визуальный язык статусов

| Состояние | Иконка | Цвет | Где видно |
|---|---|---|---|
| Ждёт вас (разрешение) | ▲ | жёлтый, мягкий пульс | Внимание, строка, сводка, заголовок вкладки |
| Ошибка | ✖ | красный | Внимание, строка, сводка |
| В работе | ◐ вращается | акцент | строка + текущее действие + таймер |
| Думает | ◐ + «думает…» | акцент | строка |
| Запуск | ◌ | синий | строка |
| Пауза (свободен, без результата) | ○ | серый | строка |
| Готово (ответил, в архиве) | ✓ | зелёный | строка, Внимание → Результаты |
| В очереди сообщения | +N | серый бейдж | строка, Сейчас |

Правила:
- Одна иконка на объект, форма и цвет вместе.
- Движение только у того, что реально идёт сейчас (вращение «в работе», пульс «ждёт вас»).
- При `prefers-reduced-motion` анимации заменяются статичными иконками.

## 4. Уведомления
- Внутри приложения:
  - всплывашки только для «ждёт вас» и ошибок;
  - результаты без всплывашек, просто попадают во «Внимание»;
  - одинаковые склеиваются: «+3 результата».
- Системные уведомления браузера — только по явному согласию и только когда вкладка скрыта. Текст ответа в них не
  показываем, только «jira-report: результат готов».
- Звук выключен по умолчанию.
- «Пока вас не было»: после возвращения на вкладку — сводка новых элементов внимания.

## 5. Что нужно добавить на сервере

1. **План агента.**
   - Хранение: `AgentView.plan: { entries: { content, status: pending|in_progress|completed }[], updatedAt } | null`.
   - Источник 1: агент сообщает план сам, через shell, как уже делает с `send`:
     `nessy-orch plan --from <id> "- [x] шаг 1" "- [~] шаг 2" "- [ ] шаг 3"`. План целиком заменяется,
     как в ACP.
   - Вводная агента и роли просят вести план, если в задаче больше двух шагов.
   - Источник 2: ACP `sessionUpdate: "plan"` (entries: content, priority, status). Разбираем в маппере на будущее:
     сейчас nessy его, судя по контракту, не шлёт.
   - API: `POST /agents/:ref/plan`, событие `agent` с обновлённым видом. План сбрасывается при новом поручении,
     а не при уточнении.
2. **Счётчик шагов хода**: `AgentView.turnSteps: number` — число вызовов инструментов в текущем или последнем ходе.
3. **Последний результат**: `AgentView.lastReply: { msgId, ts, failed? } | null`, чтобы не искать по всей ленте.
4. Остальное (поручения, внимание, прогресс дерева) вычисляется в UI из имеющихся данных.

## 6. Что убираем
- Граф. Его заменяют группировка поручений и ссылки «родитель/дети» в деталях агента.
- Общую ленту как вкладку: она становится журналом.
- Строку вкладок: детали агента и справочники открываются панелью или страницей.

## 7. Порядок работ
1. Сервер: план, счётчик шагов, последний результат, CLI `plan`, вводная и роли. Плюс тесты.
2. UI:
   - каркас (верхняя строка, три колонки, ящик журнала, мобильная раскладка);
   - модель поручений и внимания (чистые функции + тесты);
   - список поручений;
   - детали агента;
   - внимание;
   - журнал.
