# Архитектура v4: TClaude-Orch — оболочка над Claude Code с агентами nessy

Статус: **проект на ревью**, код не менялся. Решения владельца: главный агент — только Claude Code (nessy как главный агент не поддерживается);
исполнители — агенты nessy; никаких фоновых сборщиков и россыпи хуков; экономия токенов — требование, а не пожелание.

## 1. Роли и границы

| Кто | Что делает | Где живёт |
|---|---|---|
| **Приложение** (SwiftUI) | окно, вкладки проектов, терминал с Claude, панель агентов, **доставка ответов в терминал**, стартовый экран | процесс приложения |
| **Оркестратор** (TS, сервис launchd) | реестр агентов, лента сообщений, сессии, бюджеты, доступ, процессы `nessy serve` | `127.0.0.1:4337` |
| **Claude Code** (главный агент) | разговор с человеком, планирует, ставит поручения агентам, сводит результат | PTY вкладки |
| **Агенты nessy** (исполнители) | долгая автономная работа с инструментами GitLab/Jira/Sage/Wiki; пишут друг другу и главному | сессии `nessy serve` |
| **CLI `nessy-orch`** | единственный интерфейс Claude и агентов к оркестратору | PATH терминала / Bash агента |

Нет: фоновых `inbox`-сборщиков, хуков SessionStart/UserPromptSubmit/SessionEnd, привязки чата по хуку, установки плагина в `~/.claude`.

## 2. Модель данных (минимум)

- **Сессия** = один проект в приложении (вкладка): `id`, `cwd`, `chatId` (uuid чата Claude), `title`, `status`. Создаёт приложение при запуске терминала.
  Все агенты вкладки принадлежат её сессии. `/clear`, `/resume` внутри Claude сессию не меняют.
- **Агент**: `id`, имя, роль, `session`, `parent`, состояние (`working|idle|error`, плюс «закрыта по простою»), секретный `key`.
- **Лента**: сообщения `from → to` (`you` — главный агент, `user` — человек из приложения, агенты, `system`). Ответ агента главному агенту — запись
  `to: you` с полем `session`; непрочитанное определяется курсором сессии.

## 3. Запуск проекта (пример 1)

Человек открывает папку `~/work/shop` (или продолжает сессию со стартового экрана).

```
приложение: POST /sessions {cwd, chatId: <новый uuid>}             → сессия S1
приложение: PTY, env: NESSY_ORCH_SESSION=S1, NESSY_ORCH_TOKEN=…, PATH+=<app>/orch/bin
            claude --session-id <uuid>                 # продолжение: --resume <chatId>
                   --plugin-dir <app>/orch/plugin       # скилл nessy-orch, только на эту сессию
                   --append-system-prompt "<10 строк правил + id сессии>"
                   --settings '{"hooks":{"Stop":[{"hooks":[{"type":"command","command":"nessy-orch hook idle"}]}]}}'
```

Ничего не пишется в `~/.claude`. Нет вкладки без сессии и сессии без вкладки (кроме сохранённых для `--resume`).

## 4. Делегирование и ответы (пример 2 — основной цикл)

```
человек:   «проверь MR !512 и найди причину падения CI»
Claude:    nessy-orch spawn-many "mr|reviewer|Проверь MR !512…" "ci|debugger|Найди причину падения CI…"
           → «Запустил 2 агентов (mr, ci). Жду их ответы.»  — ход закончен, Claude свободен
хук Stop:  nessy-orch hook idle → POST /sessions/S1/lead-state {idle}     (приложение: вкладка S1 = idle)
агент ci:  ход закончен → ответ → лента (to: you, session: S1)             (через ~2 мин)
приложение: получило событие, вкладка S1 idle, пользователь не печатал ≥3 с
            GET /sessions/S1/digest → {text, cursor}
            ввод в PTY: вставка (bracketed paste) + Enter                   вкладка S1 = busy
            POST /sessions/S1/ack {cursor}
Claude:    видит новое сообщение «[nessy-orch] ответ агента ci …» → разбирается; ответ mr придёт следом одним сообщением, если успел за ~1,5 с
```

Claude не вызывает `inbox`, не держит фоновых команд, не опрашивает. Токены на ожидание = 0.

## 5. Занятость главного агента (пример 3 — защита от ввода в диалог)

Приложение ведёт у вкладки `busy | idle`: `busy` — пользователь нажал Enter в терминале или приложение ввело текст; `idle` — хук `Stop`.
Claude показывает запрос разрешения (`busy`): ответ агента приходит → ввод откладывается до `Stop`. Текст не попадёт в диалог и не подтвердит его.

Запасной признак «свободен» (если `Stop` не пришёл): ≥ 20 с без вывода PTY и без ввода **и** вкладка не показывает диалог (эвристика по последнему
экрану: нет строки выбора «❯ 1.»/«Do you want»). Если не уверены — не вводим, показываем пользователю бейдж «есть ответы агентов» на вкладке.

## 6. Сообщения человека агенту (пример 4)

В панели человек пишет агенту `ci`: «проверь ещё интеграционные тесты».

```
приложение: POST /agents/ci/send {from: "user", text}     — работающего агента не прерывает: mid-turn-message (иначе очередь)
агент ci:   ответ → to: user (человек видит в панели)
сервер:     главному агенту — служебная запись «пользователь написал агенту ci: …» и копия ответа (≤300 знаков) → доставка как в §4
```

## 7. Агенты nessy и экономия ресурсов (пример 5)

- Агент закончил ход и ничего не ждёт → через 2 мин сессия nessy закрывается (контекст на диске, слот демона свободен). Сообщение поднимает её `/load`.
- Нет места у демона (503) → агент ждёт `Retry-After`, а не падает. Бюджеты: глубина 2, одновременно ≤12, всего ≤40 в сессии; завершённые удаляются через 6 ч.
- Агент пишет другому агенту/главному только `nessy-orch send --from <id> --key <ключ>`; ключ из вводной, оператор — по токену из окружения терминала.
- Повторного прохода по вводной нет: вводная один раз на контекст; напоминание про план — только в первом промпте.

## 8. Закрытие, возобновление, сбои (пример 6)

| Событие | Что происходит |
|---|---|
| Человек закрыл проект | `POST /terminals/:key/closed`: работающие агенты останавливаются, сессия остаётся для `--resume` |
| Выход из Claude (`/exit`, Ctrl+D) | процесс завершился → проект закрывается целиком (как закрытие), если за <3 с и с ошибкой — экран «Агент не запустился» |
| Продолжить со стартового экрана | та же сессия S1, `claude --resume <chatId>`; агенты S1 на месте, закрытые по простою просыпаются по сообщению |
| Рестарт приложения | вкладки не восстанавливаются, сессии на диске; непрочитанные ответы ждут и доставляются после следующего запуска проекта |
| Рестарт оркестратора | незавершённые ходы агентов помечаются потерянными (ответ-ошибка), очереди сохраняются |
| Упал `nessy serve` | ходы закрываются с ошибкой, сессии поднимаются при следующем сообщении |

## 9. Безопасность

- Оператор (приложение, терминал Claude) — по токену `NESSY_ORCH_TOKEN` (файл `<home>/token`, 0600). Агенты nessy его не имеют (окружение демона).
- Агент действует только от своего имени (`--from --key`); не может выдать себя за оператора, другого агента или человека.
- Ответы агентов в тексте для Claude — данные, а не команды; служебные метки внутри обезврежены; ввод — только вставка, без управляющих символов.

## 10. Что удаляем из кода

Сервер/CLI: `/sessions/bind`, `source`/`reason`, `lead-state: working|ended` (остаётся `idle`), `watching`, `claimed/holds`, `updates?consume`, `ack`-через-хук,
тексты `startContext/watchReminder/stopDecision`, ветвление `NESSY_ORCH_LEAD`, хуки start/prompt/end/stop-failure, `hook.commands.ts` → одна команда `hook idle`,
флаги `inbox --wait` (команда остаётся для ручной отладки без ожидания).
Приложение: `PluginInstaller`, `NessyLeadInstaller`, автоустановка плагина, переключатели «подключать к Claude/nessy», `LeadCommand.kind`.
Скилл и подсказки: всё про фоновый сборщик, коды 0/3/4, `--queue`, `watching`.

## 11. План работ

1. Сервер: `GET /sessions/:id/digest`; `POST /sessions` с `cwd`/`chatId`; `hook idle`; удаление §10.
2. Приложение: сессия при запуске, флаги Claude, `busy/idle`, доставка вставкой + `ack`, бейдж «есть ответы», удаление установщиков.
3. Скилл и правила: цикл «запустил → закончил ход → ответы придут»; `--wait` только для коротких вопросов.
4. Тесты: доставка (busy/idle/печатает/диалог), склейка, повтор без `ack`, запуск с `--session-id/--resume`, сессия при перезапуске.
5. Проверка живьём: вставка с Enter в Claude Code, поведение `--settings` с `--plugin-dir`, `Stop` при остановке пользователем (Esc).

## 12. Критерии приёмки (требования владельца как проверяемые условия)

| Требование | Условие, которое проверяем |
|---|---|
| Без лишних вызовов и спама | за поручение главного агента — 1 вызов `spawn`/`spawn-many`; вызовов «посмотреть, не ответили ли» — 0; хуков с выводом в контекст — 0; одно сообщение с ответами на пачку агентов (склейка) |
| Основной чат не блокируется | каждая команда `nessy-orch` возвращается ≤ 2 с (без `--wait`); нет фоновых процессов-ожиданий в Claude; ввод ответов не мешает печати пользователя и не попадает в диалоги |
| Простое и удобное общение | человек пишет агенту из панели без команд; главный агент пишет агенту `send <имя> "…"`; агент — главному `send you "…"`; везде имена, а не id |
| Всё отслеживаемо | у каждого сообщения статус доставки: `в ленте → доставлено агенту → ответ получен → показано главному агенту`; в панели виден статус агента, токены, число вызовов; бейдж «есть непрочитанные ответы» на вкладке; журнал решений доставки (почему отложено: занят/печатает/диалог) |
| Все ошибки обрабатываются | каталог ошибок (§13): у каждой — обнаружение, что видит пользователь, что делает система сама, что делать вручную; «тихих» отказов нет |

## 13. Каталог ошибок и реакций

| Ошибка | Реакция системы | Что видит человек / Claude |
|---|---|---|
| Claude не запустился (команда не найдена, мгновенный выход) | экран «Агент не запустился», «Повторить», «Закрыть» | причина и код |
| Вставка в PTY не удалась / вкладка закрыта | курсор не двигается, ответы ждут, повтор при следующем `idle` | бейдж на вкладке |
| Хук `Stop` не приходит | запасной признак «свободен» осторожнее; иначе ответы ждут, бейдж | «ответы ждут: Claude занят» |
| Пользователь печатает | доставка откладывается до паузы ≥3 с | — |
| Оркестратор недоступен | CLI: понятная ошибка и код выхода ≠0 за ≤2 с; приложение: баннер, повтор | «оркестратор недоступен» |
| Нет токена/ключа (403) | команда отклонена с подсказкой | текст ошибки в выводе команды |
| Лимиты (глубина, число агентов) | 429 с подсказкой: переиспользовать, удалить завершённых | текст ошибки |
| Агент nessy упал / сессия потеряна | ход закрыт ошибкой → ответ главному `⚠ ошибка…`; следующая отправка пересоздаёт сессию | в панели красный статус, ответ с причиной |
| Нет места у демона (503) | ожидание `Retry-After`, до 12 повторов, затем ошибка агента | «жду свободное место» в чате агента |
| Рестарт оркестратора посреди хода | ход помечается потерянным, отправитель получает ответ-ошибку | сообщение в ленте |
| Диск полон / ошибка записи | работаем в памяти, предупреждение раз в минуту | запись в логе |
| Ответ агента огромен или враждебен | обрезка с подсказкой `show`, обезвреженные метки, ввод только вставкой | блок в сообщении |
