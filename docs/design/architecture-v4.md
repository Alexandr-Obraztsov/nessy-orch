# Архитектура v4.2: TClaude-Orch — оболочка над Claude Code с агентами nessy

Статус: **проект после ревью (Opus)**, код не менялся. Решения владельца: главный агент — только Claude Code (nessy как главный агент **не поддерживается**);
исполнители — агенты nessy с малым окном контекста; никаких фоновых сборщиков и россыпи хуков; экономия токенов, отсутствие спама и блокировок,
полная отслеживаемость и обработка ошибок — требования, а не пожелания (критерии — §11, ошибки — §12).

Пометки: **[проверено]** — по документации Claude Code или коду репозитория; **[спайк]** — решение зависит от проверки на живом `claude` (§13).

## 1. Роли

| Кто | Что делает | Где |
|---|---|---|
| **Приложение** (SwiftUI) | окно, вкладки проектов, терминал с Claude, панель агентов, **доставка ответов в терминал**, стартовый экран | процесс приложения |
| **Оркестратор** (TS, launchd) | реестр агентов, лента, сессии, бюджеты, доступ, процессы `nessy serve`, сводка ответов (`digest`) | `127.0.0.1:4337` |
| **Claude Code** | разговор с человеком, декомпозиция, поручения, сведение результата | PTY вкладки |
| **Агенты nessy** | узкая автономная работа с GitLab/Jira/Sage/Wiki; переписываются через `send` | сессии `nessy serve` |
| **CLI `nessy-orch`** | интерфейс Claude и агентов к оркестратору | PATH терминала / shell агента |

## 2. Модель

- **Сессия = вкладка проекта**: `id`, `cwd`, `chatId` (uuid чата Claude), `title`, `unread` (число непрочитанных ответов — считает сервер по курсору).
  Создаёт приложение при запуске терминала. Все агенты вкладки — в её сессии. `/clear`, `/resume` внутри Claude сессию не меняют; `chatId` обновляет хук Stop (§4).
  Удаляется всё про «семейства сессий»: `origin`, `WindowSessions`, привязка по хуку.
- **Агент**: `id`, имя, роль, `session`, `parent`, состояние (`working|idle|error`; «закрыта по простою»), `context.usedPct`, секретный `key`.
- **Лента**: сообщения `from → to` (`you` — Claude, `user` — человек из приложения, агенты, `system`). Для Claude значимы `to: you` вида `reply` (ответы) **и `msg`** (вопросы агентов).

## 3. Запуск проекта (пример 1)

```
приложение: POST /sessions {cwd, chatId: <новый uuid>}                  → S1
PTY, env:   NESSY_ORCH_SESSION=S1  NESSY_ORCH_TOKEN=…  PATH+=<app>/orch/bin
            claude --session-id <uuid>            # продолжение: claude --resume <chatId>
                   --plugin-dir <app>/orch/plugin  # скилл + ОДИН хук Stop (`${CLAUDE_PLUGIN_ROOT}/bin/nessy-orch hook idle` либо type:http с токеном — без node на каждый ход); никаких --settings
                   --append-system-prompt-file <app>/orch/lead-prompt.md   # ~10 строк правил; id сессии не нужен — он в окружении
```

В `~/.claude` ничего не пишется. Настройка «Команда агента» → «Путь к `claude`» (флаги выше есть только у него). Хуки плагина объединяются с пользовательскими:
в плагине остаётся **только Stop** (старые SessionStart/UserPromptSubmit/SessionEnd из `plugins/nessy/hooks/hooks.json` удаляются).

## 4. Цикл «запустил → закончил ход → ответы пришли» (пример 2)

```
человек:   «проверь MR !512 и найди причину падения CI»
Claude:    nessy-orch spawn-many "mr|reviewer|…" "ci|debugger|…"   → «Запустил двух агентов, жду»      ход закончен
Stop:      nessy-orch hook idle → POST /sessions/S1/lead {chatId, idle}      (chatId из stdin хука: session_id)
агент ci:  закончил → лента (to: you)  → сервер: unread=1
приложение: событие SSE → DeliveryGate: можно вводить? → GET /sessions/S1/digest → {text, cursor}
            ввод: НАБРАТЬ строку «Ответы агентов nessy — разбери и продолжи:», затем ВСТАВИТЬ тело (bracketed paste), Enter
            POST /sessions/S1/ack {cursor = последний реально показанный}
Claude:    разбирается; «ещё работают: mr» в хвосте digest не даёт ему подвести итог раньше времени
```

Digest (одно сообщение на пачку): для каждого ответа — `агент · поручение (≤80 знаков) · статус` и «Итог» (полный текст — `show`), затем «ещё работают: …».
Включает и **вопросы агентов главному** (`to: you, kind: msg`), на них отвечает `nessy-orch reply <msgId> "…"`. Ответ, уже возвращённый вызову `--wait`, в digest не попадает.
Склейка — 3–5 с (каждый ввод = отдельный ход Claude с перечитыванием контекста).

## 5. DeliveryGate: когда можно вводить (пример 3)

Чистая функция в NessyKit (тестируется без терминала): вход — статус Claude, нажатия клавиш, `unread`, время; выход — `deliver | hold | badge`.

| Сигнал | Источник |
|---|---|
| статус `working / blocked / idle` | **OSC 7501** (Claude Code ≥ 2.1.295 сообщает терминалу сам; SwiftTerm `registerOscHandler`) **[спайк S1]**; запасной — хук Stop = `idle` |
| черновик пользователя не пуст | переопределённый `send(source:data:)` в `AgentTerminalView`: непустой после любого печатного ввода, сброс на `\r`/Ctrl+C |
| пользователь печатал недавно | время последней клавиши ≥ 3 с |
| экран (`ScreenProbe` по буферу SwiftTerm) | последний рубеж: внизу строка ввода, нет `❯ 1.` / `Do you want` (диалоги `/model`, `/resume`, доверие папке, MCP, rewind); не уверены — только бейдж |
| первый достоверный `idle` | до него **ничего не вводим** (диалог доверия папке, вход, выбор темы подтвердились бы вводом) |

Занят ли Claude, сам по себе вводу не мешает: сообщение, набранное во время хода, Claude Code ставит в очередь (между вызовами инструментов — в тот же ход). Опасны **открытый диалог** и **черновик**. Автономные ходы (завершение фоновой задачи, `/loop`) идут без Enter и без Stop-сигнала в нужный момент — поэтому источник статуса OSC, а не «Enter = busy».

Правила: `blocked` (диалог разрешения) → `hold`; черновик не пуст → `badge` с кнопкой «Вставить ответы (⌘⏎)»; `working` и поле пусто → можно вводить (сообщение, отправленное во время
работы, Claude берёт в тот же ход между вызовами инструментов — минус лишний ход) **[спайк S2]**; `idle` и поле пусто → вводим. Нет достоверного сигнала → только бейдж.
**`ack` — только после подтверждения** доставки (OSC показал `working` или строка ввода опустела ≤ 2 с после Enter); иначе бейдж и повтор, курсор не двигаем. Между двумя вводами — минимальный интервал (≥ 5 с), вставка ≤ 8 КБ (больше — «N ответов, полностью: `nessy-orch inbox --session S`»). Журнал решений (`defer: dialog/draft/typing/unsure`) — в панели.
Бейдж «N ответов» и кнопка — основной запасной канал (переживает рестарт и потерю SSE: `unread` хранит сервер).

## 6. Безопасность ввода

- Текст ответа агента — недоверенные данные: Claude Code сам помечает вставленное как данные, поэтому **служебная строка набирается, тело вставляется** (инструкции из тела не исполняются).
- Фильтр (сервер в `digest`, приложение — последним): удалить C0/C1 кроме `\n`, **ESC** (иначе `ESC[201~` выводит текст из вставки и он превращается в нажатия клавиш: `\r`, `ESC[Z`
  переключает режим разрешений), bidi/zero-width/tag-символы (Claude не отправит такую вставку по первому Enter), метки `[TClaude-Orch]` в теле обезвреживаются.
- Токен оператора (`NESSY_ORCH_TOKEN`, `<home>/token`) — у приложения и терминала Claude; агенты nessy не имеют его и действуют только `--from <id> --key <ключ>`.
- Политики организации (`allowManagedHooksOnly`, `disableAllHooks`): хука нет → работают OSC и ручной бейдж.

## 7. Человек пишет агенту (пример 4)

```
панель → POST /agents/ci/send {from: "user"}   работающего не прерывает (mid-turn-message, иначе очередь)
агент ci: ответ → to: user (видит человек); Claude — короткая служебная запись и копия ответа (≤300 знаков) в digest
```

## 8. Агенты nessy: маленькие, чистые, дешёвые (пример 5)

1. **Делить, а не нагружать**: независимые части — разным агентам параллельно (`spawn-many`); один агент — одна цель; поручение короткое и самодостаточное.
2. **Новая задача — новый агент с чистым контекстом**; прежнего — только для уточнения той же задачи и пока окно < 50 %.
3. **Метрика окна**: берём `usage.input` из `turn_complete` (уже разбирается) / размер окна из конфига (`ORCH_CONTEXT_WINDOW`) → `AgentView.context.usedPct`; **[спайк]**: это размер промпта последнего вызова или сумма за ход (сумма завысит %), и не сжимает ли Qwen Code чат сам. Панель и `ls` показывают «контекст N %»; при ≥ 50 % `send` отвечает подсказкой «для новой задачи создай нового». **Жёсткого отказа на 80 % нет**: сервер не знает, новая это задача или уточнение, а отказ стоил бы главному агенту лишнего хода; хватает правила в скилле и подсказки.
4. **Минимум служебного текста**: вводная ≤ ~600 токенов, напоминание про план только в первом промпте, ответ ≤ ~250 слов; **один скилл вместо шести** (рецепты — в `references/`),
   чтобы в каждом ходе не лежали шесть описаний.
5. **Что в коде этому противоречит и чиним**: вводная сейчас 2–3 тыс. токенов (базовый текст ~2 КБ, роль до ~5 КБ, список **всех** соседей с id/пространством/ролью → O(N)) → соседей убрать, роль — выжимка ≤ 1 КБ (полный текст файлом по требованию), `planReminder` только в первом промпте (сейчас в каждом); тексты скилла и ошибки `too_many_agents` советуют «переиспользуй» → перевернуть; лимит агентов считает архивных → считать только неархивных (или вытеснять самого старого архивного); имена глобальны → уникальность и разрешение внутри сессии, автосуффикс вместо 409 `name_taken`/`ambiguous_agent`; «копия ≤ 300 знаков» (§7) пока идёт полным текстом → обрезать.
6. **Дёшево жить**: пул заготовленных сессий, закрытие по простою (2 мин; `/load` поднимает контекст), автоудаление завершённых (6 ч), бюджеты: глубина 2, одновременно ≤ 12, всего ≤ 60 в сессии.
7. Скилл Claude (переворот прежнего правила): «независимое — параллельно разным агентам; новая задача — новый агент; тому же — только уточнение; ответы приходят сами, не жди и не опрашивай».

## 9. Закрытие, возобновление, сбои (пример 6)

| Событие | Что происходит |
|---|---|
| Человек закрыл проект | `POST /sessions/:id/closed`: работающие агенты останавливаются (они без хозяина жгли бы токены), сессия остаётся для `--resume` |
| **Выход из приложения / его падение** | агентов **не** останавливаем: PTY завершился, но ответы накапливаются (`unread`) и доставляются при следующем запуске проекта |
| `/exit`, Ctrl+D в Claude | процесс завершён → проект закрывается как в строке 1; мгновенный выход с ошибкой (<3 с) → экран «Агент не запустился» |
| Продолжить сессию | `claude --resume <chatId>` (актуальный `chatId` — из последнего Stop); `--session-id` только для нового чата. Системный промпт старого чата не обновляется до компактизации — правила держим в скилле |
| `/clear`, `/resume` внутри Claude | сессия та же; `chatId` обновится по Stop |
| Рестарт оркестратора | незавершённые ходы агентов — потерянные (ответ-ошибка); очереди и непрочитанное сохраняются |
| Упал `nessy serve` | ходы закрываются ошибкой, сессии поднимаются при следующем сообщении |

Остаётся: `inbox` (в том числе `--wait` и коды 0/3/4) — для главного агента вне TClaude-Orch (CLAUDE.md репозитория, обычный Claude Code): одна секция скилла «вне приложения»;
`ack`, курсоры, токены и ключи, `mid-turn-message`, закрытие по простою, бюджеты. Добавляем: `claim` ответов, уже вернувшихся вызову `--wait` (в коде его сейчас **нет**).
Миграция: первая версия с удалением **сначала** выполняет `uninstall` (`~/.claude/skills/nessy`, записи `nessy-orch` в `~/.nessy/settings.json`), потом убирает установщики.

## 11. Критерии приёмки

| Требование | Проверяемое условие |
|---|---|
| Без лишних вызовов и спама | на поручение 1 вызов `spawn`/`spawn-many`; вызовов «не ответили ли» — 0; хуков с выводом в контекст — 0; одно сообщение на пачку ответов (склейка 3–5 с) |
| Чат не блокируется | команды без `--wait` ≤ 2 с; фоновых процессов-ожиданий в Claude нет; ввод не мешает печати, не попадает в диалоги и в черновик |
| Просто и удобно | человек пишет агенту из панели; главный агент — `send <имя>`; агент — `send you`/`reply`; везде имена |
| Отслеживаемо | у сообщения статус пути (лента → агенту → ответ → показано Claude); в панели статус, токены, вызовы, контекст %; бейдж `unread`; журнал причин отсрочки доставки |
| Ошибки обработаны | таблица §12, «тихих» отказов нет |
| Малый контекст агентов | доля агентов с контекстом > 80 % в обычной работе ≈ 0; поручение делится на независимые части |

## 12. Ошибки и реакции

| Ошибка | Реакция | Что видно |
|---|---|---|
| `claude` не запустился | экран «Агент не запустился», «Повторить» | причина, код |
| Вставка не удалась / вкладка закрыта | курсор не двигается, повтор при следующем «можно» | бейдж |
| Нет сигнала занятости (хук отключён политикой, OSC не приходит) | только бейдж и ручная кнопка | «ответы ждут» |
| Черновик не пуст / пользователь печатает | отсрочка, бейдж | — |
| Оркестратор недоступен | CLI: ошибка ≤ 2 с, код ≠ 0; приложение: баннер, повтор | текст |
| 403 (нет токена/ключа) | отказ с подсказкой | в выводе команды |
| Лимиты (глубина, число, контекст агента) | 429 с советом: новый агент / удалить завершённых | текст |
| Агент nessy упал | ход закрыт ошибкой → `⚠ ошибка…` главному; следующая отправка пересоздаёт сессию | красный статус |
| Нет места у демона (503) | ожидание `Retry-After`, до 12 повторов | «жду место» |
| Рестарт оркестратора посреди хода | ход потерян → ответ-ошибка | сообщение |
| Диск полон | работа в памяти, предупреждение раз в минуту | лог |
| Ответ огромен или враждебен | обрезка (`show`), фильтр символов, ввод вставкой | блок в digest |

## 13. План работ и спайки (каждый этап проверяется живьём до следующего)

0. **Спайки на реальном `claude` во временной папке, без продуктового кода** (тратят квоту аккаунта: ~10 коротких запусков). **Первым — S0: официальные «каналы» Claude Code (channels)** как замена вводу в PTY: MCP-сервер `nessy-orch channel` шлёт `notifications/claude/channel`, события копятся и приходят пачкой в следующем ходе, диалогов и черновика нет, текст помечен как данные. Цена: research preview, `--dangerously-load-development-channels server:<имя>` с подтверждением при запуске, нужен вход claude.ai/Console (не Bedrock), для Team/Enterprise — `channelsEnabled`, подтверждения доставки нет. Если подходит аккаунт владельца — основной канал, ввод в PTY становится запасным. Далее:
   S1 — OSC 7501: какие состояния приходят (idle/working/blocked, `/model`, Esc, `/clear`, `/compact`, фон), нужен ли `TERM_PROGRAM`;
   S2 — ввод: набранная строка + вставка + Enter (одной записью или раздельно), тело > 800 знаков, невидимые символы, вставка при `working`, вставка в диалог;
   S3 — Stop: Esc, `/clear`, `/compact`, хук плагина из `--plugin-dir`, http-хук с токеном; S4 — `--session-id` повторно, `--resume`, `session_id` после `/clear`;
   S5 — `usage.input` у nessy (промпт последнего вызова или сумма за ход). По результату — выбор источника занятости и режима ввода.
1. **Сервер рядом со старым**: `digest` (+`msg` к `you`, без дублей `--wait`, фильтр символов, поручение, «ещё работают»), `reply`, `POST /sessions {cwd, chatId}`, `lead {idle, chatId}`, `unread`,
   метрика контекста агента и пороги. Проверка: `npm run check`, сценарии через `curl`.
2. **Приложение, ручная доставка**: флаги запуска, плагин с одним Stop, бейдж и «Вставить», `AgentTerminalView` (черновик, OSC). Проверка: первый запуск, `/clear`, закрытие/возобновление.
3. **Автодоставка (`DeliveryGate`) за настройкой**. Проверка: печатаю во время ответа, диалог, `/model`, 5 агентов вперемешку.
4. **Удаление старого** (§10) с миграцией; тесты; README/CLAUDE.md. Проверка: `npm run check`, `swift test`, рестарты.
5. **Скилл**: цикл без ожидания, правила декомпозиции, один скилл вместо шести. Проверка: 3 реальные задачи, токены до и после.
