# Архитектура v5: что реализовано

Главный агент — только Claude Code (`claude`, `tclaude`…). Исполнители — агенты nessy с малым окном контекста. Ввода в терминал Claude нет:
результаты доставляются штатными средствами Claude Code (хук Stop и завершение фоновой команды). Документ описывает реализованное; история решений
и отвергнутые варианты (PTY, OSC 7501, каналы) — в [architecture-v4.md](architecture-v4.md).

## Роли компонентов

| Кто | Что делает |
|---|---|
| Приложение (SwiftUI) | окно, вкладки-проекты, терминал с Claude, панель агентов, бейдж непрочитанных; создаёт сессию вкладки; ничего не вводит в терминал |
| Оркестратор (TS, `127.0.0.1:4337`) | реестр агентов, лента, сессии, бюджеты, повтор ошибок, `digest` и ожидание пачки |
| Claude Code | разговор, декомпозиция, поручения, сведение результата |
| Агенты nessy | узкая автономная работа с GitLab/Jira/Sage/Wiki |
| CLI `nessy-orch` + плагин | интерфейс Claude и агентов к оркестратору; скилл, хук Stop |

## Поток

```
вкладка:   POST /sessions {cwd, chatId} → S;  claude --session-id <chatId>   (повторно: --resume <chatId>);  env NESSY_ORCH_SESSION=S
Claude:    spawn-many "…" "…"  (возвращается сразу) → «запустил, жду», ход закончен
Stop:      hook stop → GET /sessions/S/digest
             есть ответы/вопросы        → exit 2 + сводка в stderr (Claude продолжает), ack после записи
             агенты работают, ожидания нет → один раз просьба: «запусти в фоне inbox --session S --all --wait 1500»
             иначе                      → остановиться;  POST /sessions/S/lead {idle, chatId}
фон:       inbox --all → GET /sessions/S/wait (long-poll) → вернётся один раз: вся пачка ответила / вопрос агента / таймаут
Claude Code будит Claude по завершении фоновой команды; сводка — в её выводе
```

Сводка (`domain/digest.ts`): ответы и вопросы агентов одной пачкой, ≤4000 знаков, поручение (≤80), статус, «ещё работают»; из текста вычищены
управляющие и невидимые символы, служебные метки обезврежены; ответ на вызов с `--wait` в сводку не попадает. Курсор двигает только `ack`.
Ожидание на сессию одно (второе отказывается, код 5). Хук Stop не зацикливается: просьба об ожидании один раз (`stop_hook_active`).

## Сессия = вкладка проекта
`id`, `cwd`, `chatId` (обновляет Stop после `/clear`), `unread` (по курсору). Закрытие вкладки: `POST /sessions/:id/closed` останавливает работающих
агентов; сессия остаётся для `--resume`; пустая сессия удаляется. Приложение при запуске убирает хуки и скиллы прежних версий из `~/.nessy`.

## Агенты и малые окна
Много маленьких агентов, новая задача — новый агент; `send` только для уточнения. Метрика контекста (`contextTokens`, `contextPct` из `usage.input`,
окно `ORCH_CONTEXT_WINDOW`) видна в `ls`. Бюджеты: глубина, активных, всего. Ход, оборвавшийся ошибкой nessy, повторяется 2 раза с растущей паузой
и пометкой в промпте (`ORCH_TURN_RETRIES`); ответ с ошибкой — только после повторов. Копия ответа человеку для Claude ≤300 знаков.

## Роли-пакеты
Роль: `roles/<id>.md` или папка `roles/<id>/` с `role.md` и файлами (скрипты, шаблоны). Папка копируется в `~/.nessy-orch/role-packages/<id>`,
`{{role_dir}}` в инструкциях заменяется путём. MCP и права на роль задать нельзя: `POST /session` их игнорирует, конфиг общий на демон.
Встроенная роль `html-writer` рисует HTML-сводки в стиле артефактов (стили, каркас, каталог компонентов, скрипты `new.py`, `check.py`, `open.sh`).

## Проверено и не проверено
Проверено автотестами: сервер (291 тест), Swift (59). Не проверено на живом tclaude 2.1.280: блокировка Stop (`exit 2`) и вид фонового пробуждения
в цепочке целиком; оформление интерфейса глазами.
