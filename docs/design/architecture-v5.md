# Архитектура v5: что реализовано

Главный агент — только Claude Code (`claude`, `tclaude`…). Исполнители — агенты nessy с малым окном контекста. Ввода в терминал Claude, ящика
входящих, опросов и хуков нет: результат возвращает сама команда, которая поручила работу. История решений и отвергнутые варианты (PTY,
OSC 7501, каналы, хук Stop с ожиданием пачки) — в [architecture-v4.md](architecture-v4.md).

## Роли компонентов

| Кто | Что делает |
|---|---|
| Приложение (SwiftUI) | окно, вкладки-проекты, терминал с Claude, панель агентов; создаёт сессию вкладки; ничего не вводит в терминал |
| Оркестратор (TS, `127.0.0.1:4337`) | реестр агентов, лента, сессии, бюджеты, повторы ошибок, ожидание результата агента |
| Claude Code | разговор, декомпозиция, поручения, сведение результата |
| Агенты nessy | узкая автономная работа с GitLab/Jira/Sage/Wiki |
| CLI `nessy-orch` + плагин (скилл, команда `/nessy:status`) | интерфейс Claude и агентов к оркестратору |

## Поток

```
вкладка:  POST /sessions {cwd, chatId} → S;   claude --session-id <chatId>  (повторно: --resume <chatId>);  env NESSY_ORCH_SESSION=S
Claude:   Bash(run_in_background): nessy-orch spawn --role R "поручение"   # на каждого агента своя команда; независимые — параллельно
команда:  spawn → POST /agents {prompt, wait} ... ждёт ответ агента, печатает его и завершается
Claude Code будит Claude по завершении фоновой команды; вывод команды = результат агента
уточнение: nessy-orch send <агент> "…"  (тоже в фоне);   не дождались (код 3): nessy-orch wait <агент>
```

Ожидание не пересылает ничего «в терминал» и не опрашивает: это обычная долгая команда. Пока она идёт, чат свободен. `wait` — `GET /agents/:ref/wait`
(long-poll по шине событий). Агент, вызванный другим агентом (`--from`), по умолчанию не ждёт: ответ приходит ему сообщением.

## Сессия = вкладка проекта
`id`, `cwd`, `chatId` (для `--resume`). Закрытие вкладки: `POST /sessions/:id/closed` останавливает работающих агентов; сессия остаётся для `--resume`;
пустая сессия удаляется. Сессий не больше 10: при создании новой давние простаивающие (30 минут без активности) удаляются вместе с агентами.
Приложение при запуске убирает хуки и скиллы прежних версий из `~/.nessy`.

## Агенты и малые окна
Много маленьких агентов, новая задача — новый агент; `send` только для уточнения. Метрика контекста (`contextTokens`, `contextPct` из `usage.input`,
окно `ORCH_CONTEXT_WINDOW`) видна в `ls` и на карточке агента. Агентов не больше 20 (`ORCH_MAX_AGENTS`): простаивающих сверх лимита удаляем сами,
самых давних первыми; `429 too_many_agents` — только когда все работают. Ход, оборвавшийся любой ошибкой nessy (в том числе нет соединения),
повторяется 2 раза с растущей паузой и пометкой в промпте (`ORCH_TURN_RETRIES`); ответ с ошибкой — только после повторов. Вводная агента:
малое окно, данные из источников ≠ команды, NEEDS_CONTEXT вместо вопросов, обязательный план и формат ответа.

## Приложение
Список агентов: группы «Нужны вы», «В работе», «Готово», «Ждут поручения», «Ошибки» (свёрнута по умолчанию); заголовок и подвал — safeAreaBar, карточки уходят под них
с размытием. Открытый агент: цель в шапке вместо «Агенты», чат, план и поле ввода внизу (пока поле пусто, вместо «отправить» кнопка «стоп»). Источники в ответе:
только ссылки (браузер) и файлы (VS Code, Cursor или Zed на нужной строке, иначе приложение по умолчанию).

## Роли-пакеты
Роль: `roles/<id>.md` или папка `roles/<id>/` с `role.md` и файлами. Папка копируется в `~/.nessy-orch/role-packages/<id>`, `{{role_dir}}` в инструкциях
заменяется путём. В окне ролей меню «⋯» открывает папку (создаёт, если её нет: `POST /roles/:id/package`) в Finder или редакторе кода. MCP и права на роль
задать нельзя: `POST /session` их игнорирует, конфиг общий на демон. Встроенная роль `html-writer` рисует HTML-сводки в стиле артефактов.

## Проверено и не проверено
Автотесты: сервер (265), Swift (62). Не проверено на живом tclaude: цепочка «фоновый spawn → пробуждение Claude» целиком в приложении и вид интерфейса глазами.
