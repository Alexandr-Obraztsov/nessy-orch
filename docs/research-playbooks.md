# Исследование: кейсы, плейбуки и обучение на сессиях — что взять в nessy-orch

Дата: 2026-10-17. Собрано девятью исследователями (Haiku) по открытым источникам: README и файлы репозиториев,
официальная документация, issues. Часть данных — по сниппетам поиска и сводкам WebFetch (не дословно), такие места помечены «(по поиску)».
Звёзды — GitHub API на дату исследования.

Цель: после задачи сохранять всю работу (сообщения и правки пользователя, поручения, ответы агентов, изменения кода) как **кейс**,
а из нескольких похожих кейсов собирать **плейбук** — план для оркестратора, правила и требования, которые подгружаются постепенно.

## 1. Кто что делает (лучшее)

| Источник | Что интересно |
|---|---|
| **obra/superpowers** | Скиллы-процессы с жёсткими гейтами: brainstorming (ничего не строится до одобрения), writing-plans (задачи 2–5 мин с путями файлов), subagent-driven-development (свежий агент на задачу, два ревью, ledger-файл), verification-before-completion |
| **everything-claude-code** (~282k ★, победа на хакатоне — по сторонним источникам) | continuous-learning-v2: хуки PreToolUse/PostToolUse пишут каждое наблюдение, фоновый Haiku разбирает их раз в 5 мин при ≥20 наблюдениях; «инстинкты» с уверенностью 0.3–0.9, в глобальные — при повторе в 2+ проектах и средней ≥0.8. Сводка сессии (Stop) отдельно от обучения. Память — «недоверенный контекст, не политика» |
| **CrossBeam** (1 место Built with Opus 4.6) | Только скиллы; один скилл с 28 reference-файлами — агент читает нужный |
| **oh-my-claudecode** (~40k ★) | Конвейер team: plan → prd → exec → verify → fix с петлёй; `deep-interview` до кода; ревьюеры пишут вердикт файлом; friction report — признаки раздувания контекста |
| **wshobson/agents** (~41k ★), **VoltAgent subagents** (~26k ★) | Роль = файл с frontmatter `tools`, `model`; read-only ревьюеры; «один владелец на файл»; скилл = справка, команда = вызываемый процесс |
| **SuperClaude** (~24k ★) | Case-Based Learning: удачные формулировки и метрики между сессиями; PLANNING/TASK/KNOWLEDGE.md на старте |
| **spec-kit** | constitution → specify → plan → tasks → implement; `[NEEDS CLARIFICATION: …]` в спеке; задачи `[ID] [P?] [Story]`; «нет проверки — не исправлено» |
| **Kiro** | `requirements/design/tasks.md`; steering с `inclusion: always / fileMatch / manual / auto` |
| **Devin** | Playbook: Overview, Procedure, Specifications (постусловия), Advice, Forbidden Actions, What's Needed From User. **Плейбук из ссылок на сессии**, доработка по провалившейся сессии, версия на каждое сохранение и откат |
| **GitHub Copilot memory** | Агент сам пишет факт **с цитатами** (файл и строка); перед применением цитаты перепроверяются, при расхождении факт исправляется; срок жизни 28 дней (по поиску). Merge rate 83% → 90% |
| **Cursor Bugbot** | Правила-кандидаты из реакций на ревью, включаются или гаснут по накопленному сигналу |
| **claude-reflect**, **claude-diary** | Ловят поправки пользователя в промптах, очередь → `/reflect` с Apply / Edit / Skip; правило — только при повторе ≥2 |
| **claude-mem** | 6 хуков, SQLite + FTS; поиск в 3 слоя: search (~50–100 токенов) → timeline → get (~500–1000) |
| **Letta Code** | Память в git; «dreaming» — фоновые агенты сводят уроки и чистят дубли |
| **Исследования** | ExpeL: инсайты с ADD/UPVOTE/DOWNVOTE/EDIT; Agent Workflow Memory: подпрограммы из траекторий, +24–51% успеха; Voyager: библиотека навыков без пересмотра (устаревает) |

## 2. Самые сильные приёмы (по файлам)

| Приём | Где | Зачем |
|---|---|---|
| Таблица отговорок с опровержением | superpowers: systematic-debugging, using-superpowers | модель заранее видит свои рационализации |
| «3+ неудачных фикса — вопрос к архитектуре» | systematic-debugging | останавливает бесконечные попытки |
| «Готово» только со свежим выводом команды | verification-before-completion | убирает ложные отчёты |
| Задача = единица, которую ревьюер отклонит отдельно; запрет «TBD» | writing-plans | план исполним без раздумий |
| Ledger-файл: память разговора не переживает компакцию | subagent-driven-development | прогресс в файле, а не в чате |
| BLOCKED → изменить условия, повтор запрещён; 1–3 правки тот же исполнитель, 4–5 свежий на сильной модели | subagent-driven-development | нет зацикливания |
| «Ноль находок — нормально», порог уверенности >80%, для HIGH нужен сценарий отказа | ECC code-reviewer | меньше шума |
| `description` — главный триггер, пишется «настойчиво»; SKILL.md ≤500 строк, остальное в references | anthropics skill-creator | скилл срабатывает и не раздувает контекст |
| `[NEEDS CLARIFICATION]` вместо догадки | spec-kit | неизвестное видно |
| Блок через хук (exit 2), а не просьбой | block-no-verify, config-protection | правило нельзя забыть |

## 3. Уроки

1. **Захват — детерминированный, разбор — отдельный.** Записывает код (сервер, хук), а не модель; LLM разбирает потом, фоном и повторяемо (ECC, claude-mem).
2. **Поправки пользователя — главный сигнал.** Все системы обучения строятся на них (claude-reflect, ECC, Bugbot, Devin).
3. **Правило — только по повторам и с человеком.** Порог ≥2 кейса, ревью Apply / Edit / Skip; одно ошибочное правило вредит в каждой сессии.
4. **У знания есть доказательства и срок.** Ссылка на кейс или код, перепроверка перед применением, понижение от поправок, протухание (Copilot, ECC).
5. **Процедура и знание — разные сущности.** Плейбук (шаги, постусловия, запреты) отдельно от правил (короткие факты) (Devin, wshobson).
6. **Плейбук — из нескольких сессий и проверяется на новой задаче** (Devin, AWM). Доработка — по провалу.
7. **Загрузка по уровням** с бюджетом и видимостью: что загружено, что обрезано. Лимиты везде 12–49 KB, обрезка молча (Codex, Augment).
8. **Состояние этапов — в файлах** с фиксированными именами (Kiro, spec-kit, OMC, superpowers ledger).
9. **Гейты и проверки — механические**, где можно (хуки, вердикт verifier файлом); инструкции модель может пропустить.
10. **Агенты не общаются напрямую**: связь через оркестратора, результат — резюме + ссылка на дифф (Amp, Claude subagents).

## 4. Безотказная запись сессии

`SessionEnd` ненадёжен: по issues не срабатывает при `/exit`, Ctrl+C, `claude -p`, ошибках API и в хуках плагинов, бюджет 1.5 с;
транскрипты Claude Code удаляются через `cleanupPeriodDays` (30 дней) (по поиску). Поэтому запись не должна зависеть ни от модели, ни от одного события.

| Слой | Как | Почему надёжно |
|---|---|---|
| Агенты nessy | уже пишутся сервером: `messages.jsonl`, `agents/<id>.jsonl`, `sources/` | полны по построению |
| Транскрипт Claude | хук SessionStart (уже есть) передаёт `transcript_path` в `/sessions/attach`; **сервер сам** копирует файл инкрементально (по смещению) в архив сессии | сервер — служба launchd, работает всегда; не зависит от хуков конца |
| Догоняющий проход | сервер периодически сверяет mtime транскриптов привязанных сессий и докопирует | покрывает падения, пропущенные хуки, `/clear` |
| Сообщения пользователя | `UserPromptSubmit` (async) дублирует промпт в лог сессии | страховка, если транскрипт пропадёт |
| Сборка кейса | по `session done`, **или** по закрытию вкладки (`POST /sessions/:id/closed`), **или** по простою (например, 24 ч) | не ждёт, что модель вспомнит `done` |
| Разбор (LLM) | отдельная фоновая задача, идемпотентная, с повтором; статусы кейса: captured → summarized → reviewed | сбой разбора не теряет данные |

Цепочка `/clear` → новая сессия уже связана `successor`: кейс собирается по всей цепочке.
Перед записью — вычистка секретов (токены, ключи). Проверить руками матрицу выходов: `/exit`, Ctrl+C, закрытие окна, `/clear`, падение.

## 5. Что взять (по убыванию ценности)

| # | Предложение | Откуда |
|---|---|---|
| 1 | **Архив сессии**: копия транскрипта Claude + события агентов, сервер копирует сам (раздел 4) | ECC, claude-mem, issues SessionEnd |
| 2 | **Кейс** `cases/<session>/`: `story.md` (хроника без внутренностей агентов), `corrections.md` (поправки пользователя), `changes.md` (дифф, MR), `meta.json` (тип задачи, репо, пакеты, исход, плейбук), `raw/` | SuperClaude, Devin |
| 3 | **Тип задачи** у кейса: предлагает оркестратор, подтверждает пользователь — по нему ищутся похожие | Devin, ECC (scope) |
| 4 | **Формат плейбука** по Devin + уровни: `SKILL.md` (когда, этапы строкой) → `stages/NN-*.md` (по этапу, с критерием «готово» и ⛔) → `templates/` (поручения по ролям) → `rules.md` (у каждого правила ссылка на кейсы и счётчик подтверждений) → `checklist.md` (для verifier) | Devin, Kiro, superpowers, ExpeL |
| 5 | **`playbook build <тип>`** из 2+ кейсов → черновик, неактивен до одобрения; **`playbook refine`** по кейсу-провалу → дифф плейбука | Devin, AWM |
| 6 | **Отклонения от плейбука** в кейсе (где пользователь поправил предложенное) — сигнал для refine и понижения правил | ECC, Bugbot |
| 7 | **Агенту — только его этап**: шаблон поручения + нужные правила; бюджет инструкций и список загруженного в `ls` | Codex, Augment, Amp |
| 8 | **Вердикт verifier файлом** со сверкой Specifications плейбука; INCOMPLETE → вернуть исполнителю (петля fix с лимитом раундов) | OMC, superpowers, spec-kit |
| 9 | **Роли**: `tools` (read-only для explorer/reviewer) и `model` в frontmatter; «ноль находок — нормально» в ревьюерах | VoltAgent, ECC |
| 10 | **Фоновая чистка** правил: дубли, противоречия, протухшие (нет подтверждений N кейсов) — предложением, без удаления | Letta, claude-reflect, `/doctor` |
| 11 | **Метрика пользы**: повторные поправки пользователя по одной теме до и после плейбука | Copilot (A/B), memory-исследование |

## 6. Чего избегать

- Правил из одной сессии и автоприменения без ревью — раздувание и ложные правила.
- Regex-ловли поправок без смыслового фильтра («no», «actually» в обычной речи).
- Числовой уверенности без описанного порога — выглядит точно, но не откалибрована.
- Состояния этапов только в чате; гейтов, которые агент проходит сам.
- Прямой переписки между агентами и общих файлов у параллельных исполнителей.
- Опоры на `SessionEnd` и на дисциплину модели (`session done`).

## Не проверено

- Поведение хуков на текущей версии Claude Code (issues закрыты без указания версии); удаление транскриптов по `cleanupPeriodDays`.
- Точные пути артефактов BMAD v6, Agent OS; Factory Missions, Cursor Memories, Copilot prompt files.
- Цитаты из файлов superpowers / ECC / spec-kit — по сводкам WebFetch, дословно не сверены.
