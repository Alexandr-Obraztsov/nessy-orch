# Нативное приложение nessy-orch для macOS: дизайн

Статус: проект (до кода). Стек: SwiftUI, macOS 15+, без сторонних зависимостей; Liquid Glass на macOS 26 с деградацией.
Код — `app/` (SwiftPM: `NessyKit` — модель, API, SSE, состояние; `NessyOrch` — UI).

## 1. Аудит: дыры текущего дизайна (веб UI v5 и первый набросок приложения)

Критичные — без них приложение остаётся «смотрелкой», которой не доверяют.

| # | Дыра | Почему больно | Решение |
|---|---|---|---|
| 1 | **Нет канала человек → оркестратор (Claude).** Человек может писать только агенту напрямую, а это ломает план Claude | Claude не узнаёт, что вы приняли/отвергли результат, передумали, добавили условие | Заметка к задаче: `POST /tasks/:id/notes` → попадает в `inbox --task` Claude как сообщение от `you`. Кнопки «Принять», «Доработать…», «Остановить задачу» отправляют заметки |
| 2 | **Внимание почти всегда пусто.** `autoApprove=1` по умолчанию → запросов прав нет, остаются только ошибки | Нет доверия: что агенты на самом деле делали с правами? | Политика прав вместо флага (§4): `allow`/`ask`/`deny` по инструменту и шаблону команды; журнал «авто-разрешено» с поиском |
| 3 | **Разрешение одним кликом слепо.** Команда обрезана, нет оценки риска | Опасно жать «Разрешить» из уведомления | Полная команда моно-шрифтом, подсветка опасного (`rm -rf`, `push --force`, `curl \| sh`, запись вне space), «Разрешить один раз» ≠ «Всегда для этой команды» (создаёт правило) |
| 4 | **Пустой результат ≠ «готово».** Статус `DONE/BLOCKED/NEEDS_CONTEXT` — просто текст | `BLOCKED` выглядит как успех | Программный разбор статуса в ядре (`AgentView.reportStatus`); `BLOCKED/NEEDS_CONTEXT` попадают во «Внимание» с полем ответа |
| 5 | **Зависшие и брошенные задачи.** Claude закрылся, задача `active` навсегда | Список задач зарастает, нельзя отличить живое от мёртвого | `staleAfter`: нет событий > 30 мин и нет работающих агентов → «Заброшена» (серым), действие «Закрыть», автоскрытие через 24 ч. Человек может закрыть/переоткрыть/удалить |
| 6 | **Очередь невидима.** `queued: 3` — а что именно? `cancel` молча стирает очередь | Потеря сообщений | `GET /agents/:ref/queue` + удаление отдельного сообщения; перед «Остановить» — подтверждение со списком теряемого |
| 7 | **Агент↔агент скрыт** после удаления графа | Не понять, почему агент висит: кто кого ждёт, дедлок, hops | Вкладка «Переписка» в задаче: треды по парам, `--wait`-связи стрелкой «ждёт», счётчик hops/rate-limit |
| 8 | **Нет первого запуска и офлайн-состояний** | Пустой экран, непонятно что делать | Состояния: нет демона (кнопка «Запустить» = `launchctl kickstart`, лог), версия API не совпала, space упал (причина + «Перезапустить»), нет `nessy` бинаря, нет ни одной задачи (онбординг: «как Claude начинает работу» + кнопка копирования команды установки плагина) |
| 9 | **Нет поиска и истории.** Лента держит 5000 сообщений | Итог задачи недельной давности не найти | Поиск ⌘F по задачам, агентам, ролям, итогам и ответам (клиентский по снапшоту, позже — серверный); «Экспорт итога» (markdown в буфер/файл) |
| 10 | **Ёмкость и «убежавшие» агенты.** `max-sessions 20` на space; нет бюджета времени | Спавн молча упирается в лимит | Индикатор ёмкости space (`n/20`), предупреждение > 80 %; «долго без событий» (> 5 мин) жёлтым; по умолчанию лимит длительности хода — настройка |
| 11 | **Уведомления без политики.** Шум или пропуски | Уведомления отключают навсегда | Приоритеты: ждёт решения (громко, кнопки) · ошибка · BLOCKED · итог задачи; обычные ответы агентов не уведомляют, а копятся (бейдж Dock + «пока вас не было»). Склейка, Focus-режим, mute на задачу, не показывать, если окно задачи на экране |
| 12 | **Состояние «просмотрено» только в браузере** | Веб и приложение расходятся, у двух Claude разные курсоры | Хранить `seen` на сервере (`POST /seen`), курсор per-task уже есть; приложение пишет туда |
| 13 | **Доступность и клавиатура не продуманы** | Цвет — единственный носитель статуса; мышь обязательна | Форма + цвет + слово; VoiceOver-описания карточек; Dynamic Type (системные стили); Reduce Motion/Transparency; полный клавиатурный путь (§3.6) |
| 14 | **Чат: потоковая ерунда** | Прыжки скролла, 40 вызовов инструментов забивают чат, гигантский вывод | Якорь внизу только если вы внизу + плашка «К новым»; подряд идущие инструменты схлопываются в «14 шагов» (раскрытие); вывод усечён, «показать целиком»; throttling чанков 30 Гц; размышления свёрнуты |
| 15 | **Черновики и состояние окон теряются** | Потерян недописанный ответ | Черновик на агента, восстановление окон/выбора/сворачиваний (`SceneStorage`/`AppStorage`) |
| 16 | **Безопасность API.** Любой локальный процесс управляет агентами с автоправами | Приложение удобно, но поверхность атаки та же | Токен `~/.nessy-orch/token` (0600), приложение и CLI читают; HTTP требует `Authorization` (включается флагом, по умолчанию — после миграции) |
| 17 | **Роли/пространства — «справочники без жизни»** | Не видно, где используется роль; нельзя безопасно удалить | Использование роли (сколько агентов, последние), импорт из `roles/*.md`, предпросмотр вводной; space: ёмкость, лог, рестарт |

## 2. Принципы

1. **Сначала «что требует меня», потом «что происходит», потом «что готово».** Остальное — по запросу.
2. **Результат важнее переписки.** Агент в карточке — это его итог и статус, чат — вторично.
3. **Человек — не наблюдатель, а второй пилот:** может поручить, ответить, принять, остановить; но каждое действие,
   влияющее на Claude, идёт через задачу (заметка), а не обходом через агента.
4. **Нативность, а не копия веба:** системные цвета и шрифты (SF; serif New York только в заголовках задач),
   `NavigationSplitView`, `inspector`, `Table`/`List`, `Toolbar`, меню-бар и команды меню, `.searchable`,
   drag&drop, Quick Look-подобный просмотр, акцент терракота как `AccentColor` (системный выбор пользователя уважаем).
5. **Движение объясняет изменение, не украшает:** пружина при смене порядка карточек, прогресс плана, пульс «ждёт»;
   всё отключается при Reduce Motion.
6. **Любое состояние спроектировано:** пусто / загрузка / офлайн / ошибка / очень много / очень длинно.

## 3. Структура приложения

### 3.1 Сцены
- **Главное окно** (`Window`, одно) — три колонки: сайдбар · доска задачи · инспектор агента (скрываемый).
- **Окно агента** (`WindowGroup(for: agentID)`) — чат на весь экран, двойной клик по карточке / ⌘O.
- **Окно задачи** (`WindowGroup(for: taskID)`) — для параллельной работы нескольких Claude на нескольких экранах.
- **Menu bar** (`MenuBarExtra`, стиль окно) — быстрый доступ (§3.4). Политика Dock: «в Dock и menu bar» (по умолчанию) или «только menu bar».
- **Быстрая панель** (`NSPanel`, глобальный хоткей ⌃⌥Пробел) — поручение/вопрос за секунды (§3.5).
- **Настройки** (⌘,): Основные, Уведомления, Права (политики), Сервер, Пространства, Роли.

### 3.2 Сайдбар
`Внимание` (бейдж) · `Все агенты` · `Лента прав` (журнал авто-разрешений) · **Задачи** (активные; цветная точка состояния,
владелец, счётчики; «Заброшенные» свёрнуто) · **Завершённые** (свёрнуто, поиск) · `Без задачи` · внизу: связь с демоном
(точка + версия), «+ Задача». Контекстное меню задачи: закрыть/переоткрыть, открыть в окне, копировать id/ссылку,
удалить (если не занята).

### 3.3 Доска задачи (центр)
- Шапка: заголовок (serif), владелец, возраст, сводка состояний чипами-фильтрами, кнопки «Заметка Claude…», «Закрыть задачу».
- Итог задачи (`summary`) — раскрываемая карточка наверху, markdown, «Принять» / «Доработать…».
- Сетка карточек агентов (`LazyVGrid`, адаптивная от 320 pt); группы «Требуют вас» → «Работают» → «Ошибки» → «Ждут поручения» →
  «Выполнено» (свёрнута). Режимы: карточки / компактный список (`Table` с сортировкой) / переписка (§1.7).
- Карточка: состояние (форма+цвет+слово), имя, роль-чип, таймер, поручение (3 строки), план (до 4 шагов + полоса),
  «сейчас» (инструмент моно), блок решения (разрешение/ошибка/BLOCKED) с кнопками прямо в карточке, итог (2 строки) + источники-чипы.
- Пустая задача, задача без агентов, 100+ агентов (виртуализация, «свернуть выполненные»), все выполнено (сводка + «Принять»).

### 3.4 Menu bar
Иконка: форма меняется по самому срочному состоянию (спокойная · пульс «ждёт» · ошибка · вращение «работает»), число рядом.
Панель: «Требуют вас» (кнопки действий прямо в панели), «В работе» (прогресс), поле «Спросить…» (Enter → поручение),
низ: «Открыть», «Новая задача», настройки, пауза уведомлений на 1 ч/до завтра. Офлайн — карточка «Демон недоступен» + «Запустить».

### 3.5 Быстрая панель
Поле поручения (многострочное), роль (⌘1…), пространство (по последнему/по активному проекту), задача: «новая» или выбрать;
⏎ — запустить, ⌘⏎ — запустить и открыть; перетаскивание файлов/папок добавляет пути в поручение.

### 3.6 Клавиатура
⌘N задача · ⌘⇧N поручение · ⌘K палитра команд (переход к задаче/агенту, действия) · ⌘F поиск · ⌘1…9 задачи ·
J/K и ↑/↓ по карточкам · ⏎ открыть · ⌘⏎ разрешить · ⌘⌫ отклонить · ⌘. остановить · ⌘⇧A архив · ⌘[ / ⌘] назад/вперёд · Esc закрыть.

### 3.7 Окно агента
Шапка (имя, роль, space, состояние, таймер, действия), план, «сейчас». Вкладки: **Итог** (по умолчанию после ответа: markdown,
статус-бейдж, источники-чипы, «Копировать», «Принять», «Доработать…») · **Ход** (таймлайн инструментов, длительность, вход/вывод, diff) ·
**Чат** · **Очередь** (§1.6). Поле ввода: ⏎ отправить, ⇧⏎ строка, переключатель «прервать ход» (вкл., если работает),
вложить файл-путь перетаскиванием, черновик сохраняется.

## 4. Что менять в ядре (нужно приложению)

| # | Изменение | Зачем |
|---|---|---|
| C1 | `POST /tasks/:id/notes {text}` → событие в `inbox --task` Claude (`from:you`, `kind:'note'`), CLI `nessy-orch inbox` показывает | §1.1 |
| C2 | Политика прав: `permissions.json` (`allow/ask/deny` по `tool` + glob по команде/пути, scope space/task), `POST /agents/:ref/permission/:id {approve, remember}`; журнал `GET /permissions/log` | §1.2–1.3 |
| C3 | `AgentView.reportStatus: DONE\|DONE_WITH_CONCERNS\|BLOCKED\|NEEDS_CONTEXT\|null` + `reportReason` — разбор последней строки ответа | §1.4 |
| C4 | `TaskView.stale: boolean`, `lastActivityAt`; `PATCH {status:'active'}` для переоткрытия; `DELETE` заброшенной | §1.5 |
| C5 | `GET /agents/:ref/queue`, `DELETE /agents/:ref/queue/:msgId` | §1.6 |
| C6 | `SpaceView.sessions`, `SpaceView.maxSessions` | §1.10 |
| C7 | `POST /seen {task?, upTo}` / `AgentView.unseen` | §1.12 |
| C8 | Токен авторизации, `X-Nessy-Orch-Version` | §1.16, §1.8 |
| C9 | `GET /search?q=` (задачи, итоги, ответы) | §1.9 |

C1, C3, C5 — малые, делаются первыми; C2 — отдельная работа (доработка `Agent.handlePermission` и UI).

## 5. Этапы
1. **NessyKit + каркас приложения**: модели, REST, SSE (`/stream`, поток агента), состояние, тесты; главное окно, сайдбар, доска, карточки, окно агента (чат, итог), menu bar, уведомления, офлайн-состояния. *Работает со старым ядром.*
2. **Действия**: быстрая панель, новая задача, роли, пространства, палитра команд, поиск, клавиатура, настройки, deep link.
3. **Ядро C1, C3, C5 + заметки/очередь/BLOCKED в приложении.**
4. **Политика прав (C2), журнал; токен (C8); ёмкость (C6); seen (C7); поиск на сервере (C9).**
5. Полировка: доступность (аудит VoiceOver), Reduce Motion, производительность на 200 агентах, иконка приложения, подпись.

## 6. Что сознательно не делаем
Виджеты WidgetKit (нет живого SSE), iOS-версия, редактор репозитория внутри приложения, встроенный терминал,
облачная синхронизация.
