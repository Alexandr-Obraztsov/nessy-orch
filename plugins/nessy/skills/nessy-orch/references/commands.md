# Справочник команд nessy-orch

Все команды поддерживают `--json`. `--timeout СЕК` задаёт ожидание (по умолчанию 1500 с).

**`spawn`, `send`, `ask`, `wait` ждут результат: запускай их в фоне** (Bash с `run_in_background: true`), завершение разбудит тебя с выводом.

Сессия одна на вкладку приложения (`NESSY_ORCH_SESSION`); `--session <id>` нужен только вне приложения.

## Агенты

| Команда | Что делает |
|---|---|
| `spawn [--title "заголовок"] [--role R] [--space P] [--no-wait] [--timeout СЕК] "поручение"` | Создать агента в каталоге чата Claude и отправить поручение; ждёт ответ и печатает его. `--title` — короткий понятный заголовок (3–7 слов), цель — само поручение; имя агента назначает оркестратор и печатает в выводе (`✓ агент <имя> …`). `--space P` — другой каталог (только по просьбе). Без текста поручения агент создаётся пустым |
| `send <агент> "текст" [--no-wait] [--interrupt]` | Написать агенту (по имени или id) и дождаться ответа. Свободного агента запускает в работу, работающего не прерывает (сообщение уходит в идущий ход или встаёт в очередь); `--interrupt` прерывает. В архиве агента будит с прежним контекстом |
| `wait <агент> [--timeout СЕК]` | Дождаться, пока агент освободится, и вывести его последний ответ (код 3 — ещё работает) |
| `ask <путь\|пространство> "задача"` | Короткий путь: spawn в другом каталоге |
| `ls [--all] [--session S]` | Агенты: состояние, роль, **КОНТЕКСТ %**, последнее действие; `--all` — и архивные |
| `show <агент> [-n 40]` | Последние события агента — только когда нужна причина (ошибка, застрял); длинный вывод |
| `plan <агент>` | План агента (шаги `x/y`) |
| `cancel <агент>` | Прервать текущий ход |
| `archive <агент>` / `restore <агент>` / `kill <агент>` | В архив / вернуть / удалить |
| `watch <агент>` | Живой поток событий агента (для пользователя; тебе обычно хватает `show`) |
| `feed [-n 30]` | Общая лента переписки |

## Сессии (вне приложения)

| Команда | Что делает |
|---|---|
| `session new "<заголовок>" [--owner X] [--id slug]` | Завести сессию: печатает id и ссылку `nessy-orch://session/<id>` |
| `session ls [--all]`, `session show <id>`, `session sources <id>` | Сессии, агенты сессии, ссылки и файлы, собранные за сессию |
| `session done <id> [--summary "…" \| --summary-file F]`, `session reopen <id>`, `session rm <id>` | Закрыть с итогом / вернуть / удалить |

## Роли

| Команда | Что делает |
|---|---|
| `role ls` / `role show <id>` | Роли и их инструкции |
| `role import [путь] [--force] [--dry-run]` | Загрузить готовые роли из `roles/` (файлы и папки-пакеты); `role export <id>` — обратно |
| `role add <имя> --file F \| --instructions T [--description D] [--id ID]`, `role rm <id>` | Завести/удалить роль (только если пользователь просит) |

Роль может быть пакетом: папка с `role.md` и файлами (скрипты, шаблоны); агент получает путь к ним во вводной.

## Прочее

`status` (жив ли оркестратор), `space ls|add|rm` (обычно не нужны: пространство создаётся по каталогу), `open [<id сессии>]` (открыть в приложении).

## Ошибки

| Симптом | Действие |
|---|---|
| «оркестратор недоступен» | Сам не запускай (ты в песочнице): попроси пользователя выполнить в обычном терминале `bin/nessy-orch install` |
| Код выхода 3 | Время ожидания вышло, агент ещё работает: `nessy-orch wait <агент>` в фоне |
| `[no_session]` | Сессии нет: вне приложения `session new`; в приложении сообщи пользователю (вкладку могли убрать) |
| `[no_agent]` | Проверь имя или id через `ls` |
| `[too_many_agents]`, `[too_many_active]` | Все агенты заняты: дождись ответов (`wait`) или `cancel` лишнего |
| `[no_role]` | Проверь `role ls` |
| `[busy]` | `archive` работающего агента нельзя: дождись ответа или `cancel` |
| `[hop_limit]`, `[rate_limit]`, `[deadlock]` | Остановись, не повторяй в цикле, переформулируй задачу или сообщи пользователю |
| Ответ с пометкой ошибки | Сервер уже повторил ход дважды. `show <агент>` для причины; можно написать агенту снова |
| Код выхода 2 | Ошибка в аргументах: сверься с `nessy-orch --help` |
