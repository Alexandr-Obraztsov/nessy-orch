# Рецепт: вопрос по коду чужого репозитория

Сначала загрузи скилл `nessy-orch` и иди по его циклу: шаг 0 (ссылка на панель <http://127.0.0.1:4337>),
`ls --all`, `role ls`. Здесь — только то, что специфично для вопроса по коду. Сам репозиторий не клонируешь
и не читаешь: это делает агент.

## Когда

- Нужен ответ по коду репозитория, которого у тебя нет (GitLab, чужая команда, другой сервис).
- Нужна оценка влияния: кто вызывает функцию, какие места затронет правка.
- Несколько репозиториев → по агенту на репозиторий, параллельно.

## Роли

| Шаг | Роль | Когда |
|---|---|---|
| Ответ | `code-explorer` | всегда |
| Проверка | `verifier` | вывод пойдёт в решение (правка, оценка, ответ другой команде) или ответ выглядит неуверенно |

Агент по этому репозиторию уже есть в `ls --all` — спрашивай его через `send`: клон удалён, но контекст остался.

## Поручения

```bash
nessy-orch spawn --space ~/tmp --role code-explorer --name <тема>-explorer "
Цель: <вопрос одним предложением> — чтобы <зачем: оценить правку / ответить команде / найти место бага>.
Контекст: репозиторий <группа/проект> в GitLab, ветка <main>. Известно: <что уже знаем, если есть>.
Границы: только чтение, ничего не коммитить и не пушить; клон удалить в конце.
Результат: 3–5 предложений + список файл:строка с пояснением + цепочка вызовов от <точки входа> до <места>.
Готово, когда: <найдена функция X и все её вызывающие / ясно, где и как Y>.
В конце: строка «Статус: …»."
```

После `spawn` — фоновый `nessy-orch inbox --wait 1500` (`run_in_background`), ответ придёт уведомлением.
`--space` для `code-explorer` — любой каталог: репозиторий агент скачает сам. Несколько репозиториев —
несколько таких `spawn` без `--wait`, затем фоновый `inbox --wait 1500`, пока не придут все.

Проверка (отдельным агентом, не тем же):

```bash
nessy-orch spawn --space ~/tmp --role verifier --name <тема>-verify "
Цель: независимо проверить ответ про код <группа/проект> (ветка <main>).
Заявлено: <краткий ответ explorer со ссылками файл:строка>.
Границы: только чтение; клон удалить в конце. Не доверяй ответу — открой каждую ссылку и проверь цепочку.
Результат: что подтверждено (с доказательством), что нет, чего не хватает.
В конце: строка «Статус: …»."
```

## Сводка пользователю

1. Ответ на вопрос в 2–4 предложениях.
2. Ключевые места: `файл:строка` — что там.
3. Цепочка вызовов или схема влияния, если спрашивали.
4. Что проверено (`verifier` или ты по ссылкам) и что осталось допущением. Имя агента — для продолжения.

## Красные флаги

| Мысль | Как на самом деле |
|---|---|
| «Склонирую сам и поищу rg» | Нет: это работа `code-explorer`, ты только ставишь вопрос и проверяешь |
| «Вопрос размытый, агент разберётся» | Сформулируй конкретно: что найти, в каком репозитории и ветке, в каком виде ответ |
| «Ответ без файл:строка, но звучит убедительно» | Попроси ссылки через `send` или проверь `verifier` |
| «Спрошу нового агента про тот же репозиторий» | Пиши прежнему через `send`: у него контекст |
